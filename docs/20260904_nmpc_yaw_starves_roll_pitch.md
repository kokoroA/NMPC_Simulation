# 0904_v1.csv 解析 — 「もっさり」の正体はヨーが制御量の 85 % を食っていること

- **ログ**: `Benzen_NMPC/tools/0904_v1.csv`（10 Hz、643 点 / 73.8 s、自由飛行 59.3 s）
- **図**: `plots/0904_v1_analysis.png`, `plots/0904_v1_summary.png`
- **この版**: `N=14`, `R_u=120`, `Q_phi=Q_theta=100`, `Q_p=Q_q=20`, `Q_r=20`, `T_max=1.04`
  （`mass` は飛行時 0.32、解析後に 0.35 へ更新済み。`Ct` は飛行時の値がログに残っていないため不明）
  ロール/ピッチ指令は **±54°** に統一済み（`0.3f*π`）。**ヨー率指令は ±144 deg/s のまま**
- **症状**: ヨーが少し流れる。ロール/ピッチの追従が弱く「もっさり」

---

## 0. 結論

**重みより先に、ヨーの指令スケールを下げてください。**

| 所見 | 値 |
|---|---|
| **Δu の分散のうちヨーが占める割合** | **84.7 %**（ロール 6.4 % / ピッチ 7.6 % / common 1.3 %） |
| ロール/ピッチの追従振幅比 | **0.09 / 0.05**（0.2 Hz まで下げても改善しない） |
| どれかのモータが上限 0.95 に到達している時刻 | **39 %**（下限 0.005 到達はほぼ皆無） |
| ロール追従: 飽和なし / あり | **0.125 / 0.013**（飽和で 10 分の 1 に崩れる） |
| ヨー: 指令中立時の実測 `r` | **+16 deg/s**（これがドリフト） |
| `u_base` 平均 | **0.640** → 上向き余裕 0.31 / 下向き 0.64（**2.1 : 1 の非対称**） |

**NMPC 自体は正しく働いています。** 姿勢誤差と指令トルクの相関はロール **+0.75**、ピッチ **+0.52**。
誤差 30° に対して 555 deg/s² 相当のトルクを指令しています。
**問題は、その指令を出すための duty がヨーに先に食われて上限に張り付くこと**です。

## 1. なぜヨーが食うのか

| 軸 | 指令トルク rms | 必要な duty 差動 |
|---|---|---|
| ロール | 0.0130 N·m | 0.062 |
| ピッチ | 0.0138 N·m | 0.078 |
| **ヨー** | **0.0326 N·m** | **0.214** |

- **ヨーだけ指令が 2.5 倍**大きい。理由は 2 つ。
  1. **ヨー率指令のスケールが ±144 deg/s のまま。** ロール/ピッチは ±54° に下げたのに、
     `Psi_ref` は `0.8f*π` のままです。実際 `psi_ref` は rms 28 / 最大 85 deg/s 出ています。
  2. **+16 deg/s の定常ドリフト**があり、制御器が常に打ち消しに行っています。
     しかも追従振幅比は 0.24 しかなく、**勝てない相手に力を注ぎ続けている**状態です。
- 上向き余裕は 0.31 しかないので、**ヨーに 0.214 使うとロール/ピッチには 0.1 も残りません。**
  これが 39 % の飽和と、飽和時の追従崩壊（0.125 → 0.013）を生んでいます。

## 2. 調整方針（この順で、1 回に 1 つ）

### 【第一手】ヨー率指令のスケールを揃える

```cpp
// control.cpp  update_attitude_refs_from_sticks()
Psi_ref = Psi_trim + 0.3f * (float)M_PI * ... ;   // 0.8f → 0.3f （±144 → ±54 deg/s）
```

- **重みを一切触らずに、ヨーの要求量を 2.7 分の 1 にできます。**
- ヨーの duty 消費が減った分がそのままロール/ピッチに回ります。
- **ヨーのドリフト対策を弱めるわけではありません**（`Q_r` は据え置き）。両方の不満に効きます。
- 副作用: ヨーの回頭が遅く感じます。足りなければ 0.4f（±72 deg/s）へ。

### 【第二手】ヨーのドリフトを源から潰す

**+16 deg/s の定常ドリフトは制御で消すものではありません。**

- プロペラの回転方向とモータ配置（`kS = [-1,+1,+1,-1,-1,+1]`）が実機と合っているか
- **`C_QT = CQ/Ct` が怪しい。** `CQ = 3.0e-8` は**未測定の仮値**です
  （`Ct` は既に GEMFAN-3630-3 の `5.21e-7` に更新済み）。
  `C_QT = 3.0e-8 / 5.21e-7 = 0.0576` に対し、ベンチの電流と推力から推定すると **0.011** で、
  **5.2 倍の過大評価**です。詳細は
  [`thrust_sysid_f1404.md §7`](../program/pico/pico-sdk2/pico-sdk/Benzen_NMPC/docs/thrust_sysid_f1404.md)
- 機体の物理的な非対称（モータ取付角、プロペラの個体差）

### 【第三手】ロール/ピッチの重み

第一手・第二手で飽和が減ってから。**飽和している間は重みを変えても効果を測れません。**

```cpp
constexpr float Q_phi   = 300.0f;   // 100 → 300
constexpr float Q_theta = 300.0f;   // 100 → 300
// Q_p / Q_q = 20、R_u = 120 は据え置き
```

- 姿勢誤差 → 目標角速度のゲインは概ね `sqrt(Q_angle / Q_rate)`。
  現在 `sqrt(100/20) = 2.24 /s`。一般的なマルチコプタの姿勢ループは **5–10 /s** なので**明らかに低い**
- 300 にすると `sqrt(300/20) = 3.87 /s`（1.7 倍）
- **`Q_p`/`Q_q` を下げる案は採りません。** これは角速度の減衰項で、
  0831_v1 の 4 Hz 発振はこの減衰が足りずに起きました。**角度側だけ上げるのが安全です**
- **`R_u` を下げる案も後回し。** これは高周波までゲインを上げるので発振に直結します

## 3. もう一つの制約 — 機体が重い

`u_base` 平均 0.640 を同定した推力マップに当てると

```
T(0.640) = 0.626 N × 6 発 = 3.76 N = 383 g
```

**`nmpc_params.hpp` の `mass = 0.32f`（320 g）より 20 % 重い。**

- 推力マージンは 533 g / 383 g = **1.39**（`T_max` 同定時の 1.50 から悪化）
- 上向き余裕 0.31 はこの重さの直接の帰結です。**軽くすれば全部が楽になります**
- `mass` は FTC の `U_ref` シフト計算にも使われるので、**実測値に更新してください**
  （本解析の後に 0.32 → **0.35** へ更新されました。u_base からの逆算 383 g とはまだ 33 g の差があります）

## 4. フェイルセーフが 1 回作動しています

```
t=73.79  nmpc=0  u_base=0.000  failsafe=4 (FS_RATE)
```

- **着陸後**（スロットルを切った t=73.28 以降）に、角速度 300 deg/s 超で作動しました。
  接地時のバウンドと思われます。**飛行中ではないので無害**です
- ただし**ラッチ式**なので、着陸のたびに作動すると再アームが必要になります。
  頻発するようならしきい値か、`Arm_flag==2` かつ `common_duty >= Disable_duty` のときだけ
  判定する、といった条件の追加を検討してください
- ログの 10 Hz サンプルには 300 deg/s 超が写っていません（`p` 最大 55.9、`q` 最大 110.8）。
  **瞬間値はログに出ない**ので、作動の有無は `failsafe` 列でしか分かりません

## 5. 検証できたこと / できていないこと

**確認済み**

- Δu の軸別分解（common / roll / pitch / yaw の直交基底へ最小二乗）で **ヨー 84.7 %**
- 追従振幅比は 0.2 Hz まで下げても改善しない → **帯域の問題ではなくゲインと権限の問題**
- 姿勢誤差と指令トルクの相関 +0.75 / +0.52 → **NMPC は誤差に正しく反応している**
- 飽和は**上限側のみ**（下限到達 3 回 / 上限到達 310 回）

**未検証**

- ヨードリフトの原因（`C_QT` か物理的非対称か）は**切り分けていません**。
  ただし `C_QT` が 5.2 倍過大であることは別途推定済み（同上 §7）
- 機体重量 383 g は `u_base` からの逆算で、**実測ではありません**
- 第一手〜第三手の効果は**すべて未検証**
