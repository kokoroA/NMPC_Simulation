# 第 I 部 アルゴリズム解説

## 1. 何を解いているのか

### 1.1 普通の制御との違い

PID は「いま誤差がこれだけあるから、比例・積分・微分で舵をこれだけ出す」という**その場の計算**である。
対して MPC（Model Predictive Control, モデル予測制御）は、

> **これから 0.14 秒先までの舵の打ち方を全部決める最適化問題を、毎 0.01 秒解き直す**

という方法をとる。毎回「未来の舵の列」を求めるが、**実際に使うのは最初の 1 手だけ**で、
次の周期ではまた最新の状態から解き直す。この「解いて 1 手だけ使い、また解く」枠組みを
**receding horizon（後退ホライズン）**と呼ぶ。

> 📘 **なぜ未来まで考えるのか**
> アクチュエータには限界がある（モータの duty は 0〜0.95 しか出せない）。PID は限界を知らないので
> 「いま最大限倒す」指令を出し、あとで足りなくなる。MPC は**制約を最適化問題の中に書ける**ので、
> 「いま少し我慢して、あとで倒す」という配分ができる。本機のように 6 発のモータで
> ロール・ピッチ・ヨー・推力の 4 つを同時に作る系では、この配分能力が本質的に効く。

### 1.2 この機体で解いている問題

- **状態** `x = [φ, θ, p, q, r]`（5 次元）
  - `φ`(ファイ) ロール角、`θ`(シータ) ピッチ角 [rad]
  - `p, q, r` 機体座標系での角速度 [rad/s]（ロール・ピッチ・ヨー方向）
  - ⚠ **ヨー角 ψ は状態に入っていない。** 制御するのはヨー**角速度** `r` だけである。
- **入力** `u = [u_FR, u_FL, u_MR, u_ML, u_RR, u_RL]`（6 次元、各モータの duty ∈ [0, 0.95]）
- **予測ホライズン** `N = 14` ステップ、刻み `dt = 0.01 s` → **0.14 秒先まで**予測する
- **制御周期** 100 Hz（10 ms ごとに解き直す）

> 📘 **なぜ高度と位置を制御しないのか**
> 本研究の主張は「位置制御を意図的に捨て、状態を姿勢 5 次元に縮約することで、
> IMU と安価なマイコンだけでフル非線形 MPC を実時間で回す」ことにある。
> スロットル（共通推力）は NMPC ではなくスティック直結で、姿勢だけを最適化する。
> これが成立する理由は §2.3 の `B_c · 1 = 0` にある。

## 2. モデル

### 2.1 運動方程式

`nmpc_model.cpp` の `model_f()` が実装している連続時間の状態方程式 `ẋ = f(x, u)`：

```
φ̇ = p + q·sinφ·tanθ + r·cosφ·tanθ          … 姿勢角の運動学
θ̇ = q·cosφ − r·sinφ

ṗ = [B_c·u]₂ + ( −(Iz−Iy)·q·r − Cp·p·|p| ) / Ix   … 剛体の回転の動力学
q̇ = [B_c·u]₃ + ( −(Ix−Iz)·r·p − Cq·q·|q| ) / Iy
ṙ = [B_c·u]₄ + ( −(Iy−Ix)·p·q − Cr·r·|r| ) / Iz
```

**3 つの非線形性**がある。これが「N」MPC の N（Nonlinear）である。

1. **運動学の三角関数** `sinφ·tanθ` — 角速度から姿勢角の変化率への変換。姿勢が傾くほど混ざる。
2. **ジャイロ結合項** `(Iz−Iy)·q·r` など — 剛体が回転しながら別軸に回されると生じる見かけの力。
   慣性モーメントが軸で違うほど強い。
3. **空力減衰** `Cp·p·|p|` — 角速度の 2 乗に比例する抵抗。符号を保つため `p·|p|` と書く。

> 📘 **`smooth_abs`**
> `|p|` は `p = 0` で微分できない。ヤコビアンを計算する必要があるので、実装では
> `√(p² + ε²)`（ε = 1e-3）で滑らかに近似している。これを **smoothing（平滑化）**という。
> 非線形最適化では「微分できること」が計算の前提なので、こういう細工がしばしば要る。

### 2.2 入力行列 `B_c`

6 個のモータの duty が、どれだけロール・ピッチ・ヨーのトルクを生むかを表す行列。

```
B_c(2, k) = −kYm[k] · T_max / Ix        ← ロール（k 番モータの y 座標）
B_c(3, k) = +kXm[k] · T_max / Iy        ← ピッチ（x 座標）
B_c(4, k) = +kS[k]  · C_QT · T_max / Iz ← ヨー（回転方向 ±1 × 反トルク比）
```

実機のモータ配置（順序は `[FR, FL, MR, ML, RR, RL]`）：

| | FR | FL | MR | ML | RR | RL |
|---|---|---|---|---|---|---|
| `kXm` [m]（前後） | +0.085 | +0.085 | 0 | 0 | −0.085 | −0.085 |
| `kYm` [m]（左右） | +0.050 | −0.050 | +0.10 | −0.10 | +0.050 | −0.050 |
| `kS`（回転方向） | −1 | +1 | +1 | −1 | −1 | +1 |

- ロール／ピッチは**推力 × 腕の長さ**でトルクを作る（直感どおり）
- ヨーは**プロペラの反トルク**で作る。`C_QT = CQ / Ct` は「推力 1 N あたりの反トルク [N·m]」で、
  値は 0.02〜0.03 程度。**腕の長さ 0.085 m より 3〜4 倍小さい** ＝ **ヨーは構造的に弱い軸**である。
  これは第 II 部で何度も問題になる。

### 2.3 推力と姿勢が分離する理由

`B_c` の 2〜4 行（トルクの行）について、全モータを同じだけ上げる方向 `1 = [1,1,1,1,1,1]ᵀ` を入れると

```
Σ kXm = 0,  Σ kYm = 0,  Σ kS = 0   →   B_c · 1 = 0
```

**「全部同じだけ上げる」はどのトルクも生まない。** つまり
**共通モード（推力）と差分モード（姿勢）が直交している**。
だからスロットルを NMPC の外（スティック直結）に置いても姿勢制御と干渉しない。

> ⚠ 逆に言えば、**この 0 は 6 発が正常であることに依存している**。1 発止めると成り立たなくなり、
> 姿勢を保つだけで推力が犠牲になる。耐故障制御が難しいのはこれが理由である。

## 3. 予測と凝縮形（condensing）

### 3.1 線形化

非線形モデルのまま 14 ステップ先まで最適化するのは重すぎる。そこで
**いまの軌道のまわりで 1 次近似（テイラー展開の 1 次まで）する**。

```
A_c = ∂f/∂x,   B_c = ∂f/∂u      （ヤコビアン行列＝多変数関数の微分）
```

これを前進オイラー法で離散化する：

```
A_d = I + A_c·dt,   B_d = B_c·dt
x_{k+1} ≈ A_d·x_k + B_d·u_k
```

> 📘 **ヤコビアン (Jacobian)**
> スカラー関数の微分を多変数・多出力に拡張したもの。`f: R⁵×R⁶ → R⁵` なら
> `∂f/∂x` は 5×5 行列、`∂f/∂u` は 5×6 行列になる。「その点でどちらへどれだけ動くか」を表す。

### 3.2 凝縮（condensing）

漸化式 `x_{k+1} = A_d x_k + B_d u_k` を `k = 0, 1, …, N−1` について展開すると、
**未来の状態列は初期状態と入力列だけで書ける**：

```
X = Sx · x₀ + Su · U
```

- `X = [x₁; x₂; …; x_N]` … 100 次元（5 × 14）
- `U = [u₀; u₁; …; u_{N−1}]` … 120 次元（6 × 14）
- `Sx` は 100×5、`Su` は 100×120 の行列（`Su` は**下三角ブロック構造**：未来の入力は過去の状態に効かない）

`full_rebuild_sx_su()` が、軌道を前進シミュレーションしながらこの 2 つを組み立てている。

> 📘 **なぜ「凝縮」と呼ぶか**
> 状態 `X` を変数から消して、**入力 `U` だけの問題に縮める**からである。
> 消さない定式化（sparse/multiple shooting）もあり、そちらは変数は増えるが行列が疎になる。
> 変数が 120 個程度なら凝縮形の方がマイコン向きである。

## 4. コスト関数と QP

### 4.1 何を最小化するか

```
J(U) = ½ (X − X_ref)ᵀ Q̄ (X − X_ref) + ½ (U − U_ref)ᵀ R̄ (U − U_ref)
```

- 第 1 項 = **目標姿勢からのずれ**のペナルティ（`Q̄` は対角、重み `Q_φ, Q_θ, Q_p, Q_q, Q_r`）
- 第 2 項 = **舵を振ること自体**のペナルティ（`R̄` は対角、重み `R_u`）
- 最終ステップだけ `terminal_scale = 10` 倍（**終端コスト**。ホライズンの端で暴れないための定石）

**`Q` と `R` の比が設計の本体である。**

- `Q` を上げる／`R` を下げる → 誤差に厳しく、舵をよく振る（速いが荒れやすい）
- `Q` を下げる／`R` を上げる → 舵を惜しむ（穏やかだが目標に届かない）

第 II 部で `R_u` が 28 → 120 → 320 → 800 → 620 と何度も動くのは、この綱引きの調整である。

### 4.2 QP への帰着

`X = Sx x₀ + Su U` を代入して `U` について整理すると、**`U` の 2 次関数**になる：

```
J(U) = ½ Uᵀ H U + cᵀ U + (定数)

  H = Suᵀ Q̄ Su + R̄          ← ヘッセ行列（120×120、対称正定値）
  c = Suᵀ Q̄ (Sx x₀ − X_ref) − R̄ U_ref    ← 定数項（U に依存しない）
```

> 📘 **QP (Quadratic Programming, 二次計画問題)**
> 「2 次関数を、線形の制約のもとで最小化する」問題のこと。制約が無ければ `∇J = HU + c = 0`
> を解くだけ（連立 1 次方程式）で、これは最小二乗と同じ構造である。
> MPC の計算の大半はこの QP を解くことに費やされる。

> ⚠ **`c` の定義を間違えると壊れる。** `c` は `U` に依存しない。第 II 部 §2 で扱う重大バグは、
> ここを「勾配から逆算」しようとしたことが原因だった。

### 4.3 制約

```
u ∈ [0, 0.95]   （各モータの duty）
```

実装では**ホバー duty `u_hover` からの差分 `Δu`** を変数にしているので

```
Δu ∈ [−u_hover, 0.95·η − u_hover]
```

`η`（イータ）は**モータ健全度**で、正常なら 1、故障させたいモータは 0 にする。
`η = 0` にすると box の上限＝下限＝`−u_hover` となり、そのモータの duty が 0 に固定される。
**耐故障制御を「制約の縮小」だけで表現している**のがこの設計の要点である
（故障パターンごとの分岐を一切書かない）。

## 5. ADMM — 制約つき QP をどう解くか

制約が無ければ `H U = −c` を解くだけだが、box 制約があるとそうはいかない。
本実装は **ADMM (Alternating Direction Method of Multipliers, 交互方向乗数法)** を使う。

### 5.1 考え方

「最小化したい 2 次関数」と「box に入っていてほしい」を**別々の変数に分けて交互に押し付ける**。

```
変数を 2 つ用意する:  U（2 次関数を小さくしたい） と z（box に入っていてほしい）
本当は U = z であってほしい → そのずれを λ（ラグランジュ乗数）で罰する
```

反復は 3 行しかない（`nmpc.cpp` の `admm_solve()`）：

```cpp
U = (H + ρI)⁻¹ · ( −c + ρ(z − λ) );   // ① 2 次関数側を解く（box は無視）
z = clamp(U + λ, box);                // ② box へ射影するだけ
λ = λ + (U − z);                      // ③ ずれを λ に溜める
```

- ① は**連立 1 次方程式**。行列 `M = H + ρI` は毎周期同じなので、
  **コレスキー分解**（`M = L Lᵀ`、`L` は下三角）を持っておけば前進・後退代入で解ける。
- ② は各要素を上下限で切るだけ。**ほぼ計算量ゼロ。**
- ③ で「① が box を無視して出したはみ出し」を記憶し、次の反復で ① を box 側へ引っ張る。

> 📘 **ラグランジュ乗数 λ の役割**
> 「制約を破った分だけ罰金を上げる」係数である。box に当たり続けると λ は毎周期積み上がり、
> ① の右辺 `ρ(z − λ)` を通じて `U` を押し戻す。**逆に言えば λ は発散しうる**。
> 実装に `admm_lambda_max = 30` で λ を 0 に戻す安全弁が入っているのはこのためである（第 II 部 §2）。

### 5.2 パラメータ

- `ρ (admm_rho) = 1.0` … ①と②を結ぶ強さ。大きいと box へ強く引くが収束が鈍る。
- `admm_max_iter = 4` … **毎周期 4 反復しか回さない**。

> ⚠ **4 反復で「解」は出ない。** ADMM は収束が遅い部類の解法で、厳密解には数十〜数百反復要る。
> ここが次節の RTI の考え方につながる。

## 6. RTI — 「解かない」という戦略

**RTI (Real-Time Iteration, 実時間反復)** は、

> **毎周期 QP を解ききるのを諦め、1 反復だけ進めて次の周期へ渡す**

という考え方である。制御周期 10 ms のあいだに 120 変数の QP を厳密に解くのは無理だが、
**状態は 10 ms でたいして変わらない**ので、前周期の解（warm start, 温かい初期値）から
1 反復進めるだけでも実用上は追いつく。

```
周期 k:   前周期の U, z, λ から出発 → 4 反復 → 最初の 1 手 u₀ を出力 → 次へ持ち越す
```

> 📘 **warm start（温かい初期値）**
> 前回の解を今回の初期値に使うこと。最適化では常套手段だが、
> **前回の解が壊れていると壊れたまま引き継ぐ**という弱点がある。
> 第 II 部で扱う墜落の多くは、この warm start の中身（`U_lin` や `λ`）が発散したことが原因だった。

## 7. TR1 と SR2 — 行列を作り直さない工夫

### 7.1 なぜ必要か

`Sx`, `Su` を作り直すには 14 ステップ分のヤコビアン計算と行列積が要り、さらに
`H = SuᵀQ̄Su + R̄`（120×120）とそのコレスキー分解が要る。実測で **約 37 ms**。
制御周期 10 ms に対して **3.7 倍**で、毎周期やるのは不可能である。

そこで **「前周期の行列を、今周期の情報で少しだけ修正する」**。これが準ニュートン法の発想である。

> 📘 **準ニュートン法 (Quasi-Newton)**
> ヘッセ行列を毎回計算する代わりに、
> 「入力を `s` だけ動かしたら出力が `y` だけ動いた」という**実測（割線条件, secant condition）**から
> 行列を低ランク更新していく手法。BFGS や SR1 が有名。**行列を作らずに育てる**。

### 7.2 TR1 — `[Sx | Su]` のランク 1 更新

`tr1_update_sx_su()` がやっていること：

```
s = [x₀ − x₀_prev ; U_lin − U_lin_prev]      … 前周期から何が動いたか
残差 = X_nl − X_lin_prev − Sx·s_x − Su·s_u   … 線形予測と非線形シミュの食い違い
u_rk1 = 残差 / ‖s‖²

Sx ← Sx + u_rk1 · s_xᵀ                        ← 外積を足すだけ
Su ← Su + u_rk1 · s_uᵀ
```

**「予測が外れた分を、動いた方向に押し付ける」**という Broyden 法そのものである。
外積（ランク 1 行列）を足すだけなので `O(100×120)` で済み、**37 ms が 1 ms 未満**になる。

> 📘 **ランク 1 更新**
> `u vᵀ` の形の行列を足すこと。この行列は階数（rank）が 1 しかない＝「1 方向にだけ効く修正」。
> 情報が 1 方向分しか無いのだから、修正も 1 方向分にとどめるのが理にかなっている。

### 7.3 SR2 — `H` のコレスキー因子のランク 2 パッチ

`Su` が `Su + u sᵀ` に変わったら `H = SuᵀQ̄Su + R̄` はどう変わるか。展開すると

```
ΔH = s aᵀ + a sᵀ + c · s sᵀ      （a = Suᵀ Q̄ u,  c = uᵀ Q̄ u）
```

これは**対称なランク 2 の修正**である。さらに平方完成すると 2 本の外積の差に書ける：

```
ΔH = p pᵀ − q qᵀ
  p = a + ½(c+1)s,   q = a + ½(c−1)s
```

`H` を作り直さなくても、**コレスキー因子 `L` を直接 2 回パッチする**だけで済む
（Eigen の `llt.rankUpdate(p, +1)` と `rankUpdate(q, −1)`）。これが **SR2** である。

> ⚠ **`rankUpdate(q, −1)`（引く方）が危ない。** 引きすぎると `H` が正定値でなくなり
> コレスキー分解が壊れる。実装には `llt_is_healthy()` の検査があり、壊れたらフル再構築に落ちる。
> 第 II 部 §4 の「再構築嵐」はこの検査が過敏だったことが原因である。

### 7.4 定期フル再構築

差分更新だけを続けると数値誤差が溜まる。そこで **`reset_period = 100` 周期（= 1 秒）に 1 回**
フル再構築して洗い流す。ただし **1 回 37 ms かかり、その間 100 Hz ループが止まる**。
「溜めるか、止めるか」のトレードオフが、第 II 部で何度も論点になる。

## 8. 1 周期の流れ（まとめ）

100 Hz の `angle_control()` が毎周期やること：

```
1. EKF で姿勢を推定（加速度＋地磁気＋ジャイロ）
2. x₀ を作る（φ, θ, p, q, r）
3. 【遅れ補償】直近 6 周期の duty で x₀ を 60 ms 前方予測  ← 第 II 部 §5 で追加
4. スティックから X_ref（目標姿勢）を作る
5. c = Suᵀ Q̄ (Sx x₀ − X_ref) − R̄ U_ref を直接計算       ← 第 II 部 §2 の修正点
6. フル再構築するか？（1 秒周期 or 異常検知） → する / TR1+SR2 で差分更新
7. ADMM 4 反復 → Δu
8. 安全弁 1: |λ| > 30 なら λ をゼロに
   安全弁 2: 非有限なら warm start ごと破棄
   安全弁 3: |U_lin| > 1.0 が 5 周期続いたら warm start を畳む  ← 第 II 部 §9 で追加
9. duty = u_hover + Δu を出力（400 Hz の core0 が clamp して PWM 化）
```

**コア分担**: core1 = 100 Hz（EKF・NMPC）、core0 = 400 Hz（clamp・フェイルセーフ・ZOH 出力）。
NMPC が止まっている間も core0 は最後の duty を保持して出し続ける。

## 9. 耐故障制御（FTC）で NMPC が効く理由

ここまでは「健全な機体を飛ばす」話だった。この研究の本題は耐故障制御なので、
**なぜ FTC に NMPC を使うのか**を、従来手法と比べて整理しておく。

### 9.1 1 発止まると何が「足りなくなる」のか

ヘキサは **入力 6（各モータの duty）** で **制御量 4（合計推力・ロール・ピッチ・ヨー）** を作る。
入力の方が多いので **冗長**である。

> 📘 **冗長（over-actuated）**
> 入力の数が制御したい量の数より多い状態。同じ結果を出す入力の組み合わせが無数にある。

1 発止まっても入力は 5 で、まだ 5 > 4。**足りなくなるのは数ではなく大きさ**である。
Phase 9.2 のとおり、FR を止めると残り 4 発が `mg/4 = 0.822 N` を負担し、
1 発の上限 `0.841 N` に対し**余裕は +2.3%** しかない。

### 9.2 従来のやり方 — 混合行列（制御配分）

> 📘 **制御配分（control allocation）**
> 姿勢制御器が出した「望みのモーメント `τ_des`」を、各アクチュエータの指令 `u` へ翻訳する処理。

`τ = B u` で `B` は 4×6 の効果行列。`u` を求めるのは式 4 本・未知数 6 個の **劣決定系**なので、
普通は **擬似逆行列**で「一番小さい `u`」を選ぶ。

> 📘 **劣決定系** — 式より未知数が多く解が一意でない連立方程式。
> 📘 **擬似逆行列 `B⁺`** — `τ = Bu` を満たす解のうち `‖u‖` 最小のものを与える（最小ノルム解）。

故障したら `B` の該当列を消して 4×5 にし、擬似逆を取り直す。
**健全時ならこれで十分**で、問題は故障時にだけ現れる。

### 9.3 優位性① — 制約が「効いている」ときの再配分

擬似逆行列は **`u` の上下限を知らない**。範囲外が出たら後から切る（クリップする）しかない。

実際に計算した。FR 故障・ホバー中（4 発が 0.822 N、余裕 0.019 N）に **ロール 0.020 N·m** を要求：

| 達成した量 | 要求 | **(a) 擬似逆＋クリップ** | **(b) box 制約つき最適化** |
|---|---|---|---|
| 合計推力 [N] | 3.2864 | **3.2555**（**0.031 N の揚力損失**） | 3.2861 |
| ロール [N·m] | 0.0200 | 0.0169（85%） | 0.0186（93%） |
| ヨー [N·m] | 0 | +0.0009 | +0.0016 |

(a) では ML が上限に張り付いてクリップされ、**その 1 チャンネルの切り落としが
ロールだけでなく推力とヨーにも漏れている**。`τ = Bu` は「切る前の `u`」で成り立っていた関係なので、
**1 つでも切った瞬間に全軸で崩れる。**

いちばん怖いのは**推力の損失**である。ロールが 15% 足りないのは少し傾くだけだが、
揚力が減るのは高度が落ちるということで、余裕 +2.3% の状況では致命的になる。

(b) は最初から `0 ≤ u ≤ u_max` を条件に入れた **QP** を解くので、範囲外の解を出さない。

> 📘 **box 制約** — 各変数に独立な上下限 `l ≤ u ≤ h` があるだけの制約。最も扱いやすい制約の形。
> 📘 **QP（二次計画問題）** — 二次関数を線形制約下で最小化する問題。凸なら最適解が一意。
>   この機体では ADMM 4 反復・約 7.4 ms で解いている（§5）。

### 9.4 優位性② — 足りないとき「何を捨てるか」を設計者が決められる

要求が権限を超えたらどこかを諦めるしかない。問題は**どこを**である。
同じ要求（ロール 0.020 N·m、達成不可能）に対し、重みだけ変えて解き直すと：

| 重みの置き方 | ロール | ピッチ | **ヨー** | 推力 |
|---|---|---|---|---|
| 等重み（素朴な最小二乗） | 0.0187（93%） | −0.0023 | +0.0018 | 3.2862 |
| **実機の比 `Q_φ : Q_r = 1000 : 40`** | **0.0199（99.5%）** | −0.0002 | **+0.0048** | 3.2863 |

**同じ機体・同じ制約でも、重みを変えると誤差の行き先が変わる。**
実機の重み比では、達成できない分がほぼ全部ヨーへ押し付けられ、ロールは 99.5% 確保された。

FTC では**「ヨーを捨ててでもロール・ピッチと推力を守る」が正解**である。
機首がゆっくり回るのは困るが、傾いて落ちるよりはるかにマシだからだ。
擬似逆行列には「最小ノルム」という答えが 1 つあるだけで、この選択肢が無い。
この考え方を極限まで押し進めたものが **relaxed hover**（ヨーを完全に諦めて回りながら浮く。Phase 9.3）である。

### 9.5 優位性③ — 故障の「程度」を連続量として扱える

混合行列の表は本質的に**「生きている／死んでいる」の 2 値**で、「出力が 6 割」は表に無い。
NMPC では box の幅を縮めるだけでよい。

```
0 ≤ u_i ≤ η_i · u_max        η_i = 1（健全） … 0（完全故障）
```

実装も、故障パターンごとの分岐が**一切無い**。`control.cpp` は `Motor_eta[]` を box に渡すだけで、
「FR が死んだときはこう配る」というコードがどこにも存在しない。

実験上もこれが効く。いきなり `η = 0` にせず **`1.0 → 0.8 → 0.6 → 0.4 → 0` と段階的に下げて
安全域を測る**ことができる ── 混合行列表ではこの実験自体が組めない。

### 9.6 優位性④ — 配分と制御則が分離していない ★ここが NMPC 固有

従来は**階層型**である。

```
姿勢制御器（PID/LQR） → 望みのモーメント τ_des → 配分器 → 各モータ指令
```

弱点は、**姿勢制御器が配分器の限界を知らない**こと。配分器が「その `τ` は無理です」と言っても
上流はそれを見ていないので要求を出し続け、積分器が溜まる（**ワインドアップ**）。

> 📘 **ワインドアップ** — アクチュエータが飽和しているのに制御器の積分器が誤差を溜め続け、
> 飽和が解けた後に大きく行き過ぎる現象。

NMPC にはこの分離が無い。**状態は `[φ,θ,p,q,r]`、最適化変数は 6 発の duty そのもの**なので、
配分と姿勢制御が 1 つの最適化問題になっている。結果として NMPC は
**「実現可能な入力で到達できる姿勢の軌道」しか作らない。**
「無理な要求を出してから諦める」という段階が存在しない。

さらに **予測ホライズン**がある（§1.1）。静的な配分器は「いま」しか見ないが、
NMPC は 0.14 秒先まで制約を見ているので、**飽和する前から配分を変え始められる。**

### 9.7 ⚠ 正直な境界線 — NMPC でなくてもできること

ここを曖昧にすると主張が崩される。

**9.3 と 9.4 は NMPC でなくても達成できる。** 制約付き制御配分という分野があり、
**redistributed pseudo-inverse (RPI)**、**weighted least squares allocation**、
**LP/QP ベースの配分**（Härkegård の active set 法など）はいずれも上下限を陽に扱い、
重みで優先順位も付けられる。しかも NMPC よりずっと軽い。

**NMPC 固有と言えるのは次の 3 点である。**

| | 内容 |
|---|---|
| (a) | **予測ホライズン** — 飽和する前に動ける |
| (b) | **非線形の姿勢ダイナミクスを同じ最適化の中で扱う** — 配分だけでなくジャイロ結合まで含めて解く |
| (c) | **配分と制御則が一体** — ワインドアップという概念自体が存在しない |

**主張はこの 3 点に寄せた方が強い。**
「混合行列を人が作らなくてよい」は事実だが、6 通りの擬似逆を事前計算するのは難しくないので、
優位性としては最も弱い。

### 9.8 この研究で検証できる予言

Phase 9.2 の厳密解より、**`η_FR = 0` にしたら NMPC は誰にも教えられずに
RL も ≈0 に落とし、残り 4 発を揃えるはず**である。
そうならなければ、混合行列かソルバか `U_ref` の扱いが間違っている。
**治具固定・低 duty なら飛行リスクゼロのまま、FTC の中核仮説を反証できる。**

一方で NMPC は万能ではない。§7.4 のとおり v10 のヨー追従は「誤差/目標」で 4.04 と
ロール（1.17）の 4 倍悪く、これは `B_c` の構造的な弱さ（ヨーの権限はロールの 1/5.7）に由来し、
最適化では埋まらない。

📌 **最適化は「配れるものを最適に配る」だけで、無いものは作れない。**

## Phase 1 — 50 Hz チャタリングの発見（2026-09-04）

### 1.1 100 Hz ログを入れて初めて見えた

それまでのログは 10 Hz で、**ナイキスト周波数 5 Hz** だった。
機内リングバッファ方式の 100 Hz ログを実装して、初めて次が見えた：

- 指令 duty が **1 制御周期（10 ms）ごとに上下に振れている**。Δu のラグ 1 自己相関 **−0.82〜−0.96**。
- Δu を「毎周期反転する成分 E」と「滑らかな成分 S」に分けると **E rms 0.138 / S rms 0.043**
  ＝ **指令変動の 91 % が反転成分**。
- E の **86.7 % は 6 発ミキサのヌル空間**（力もモーメントも生まない方向）。
  row space に入る分の 57 % は共通モードで、`B_c·1 = 0` より姿勢に効かない。
  → **E の約 94 % は機体に対して無意味**。
- E の主方向が生むモーメントは roll −0.008 / pitch −0.007 / **yaw +0.401**
  ＝ **チャタリングはほぼヨー軸だけに出る**。
- モータ一次遅れ（τ≈50 ms、コーナー 3.2 Hz）が 50 Hz を潰すので、
  **機体が感じるのは 2 サンプル平均**。それで評価すると飽和率 2.2 % → **0.0 %**。

**結論**: 追従不足の原因はアクチュエータ飽和ではなく `R_u` が舵を出させていないこと。
ただし**`R_u` はこの反転成分を抑えている唯一の項**なので、下げると今度はチャタリングが育つ。

- 📌 この時点では**原因が特定できていない**。「ADMM の未収束か」という推測に留めた。
  正体が分かるのは 5 日後（Phase 2）である。

## Phase 2 — 勾配バグ ★最大の山場（2026-09-09）

### 2.1 正体の特定

50 Hz チャタリングの原因がついに分かった。**ADMM の右辺の作り方**である。

ADMM の主変数更新は本来

```
(H + ρI) U = −c + ρ(z − λ)       c = Suᵀ Q̄ (Sx x₀ − X_ref) − R̄ U_ref
```

だが、実装は `c` の代わりに **`U_lin` における勾配 `g = H·U_lin + c`** を使い、
`rhs = −g + ρ(z − λ)` としていた。制約が効いていない状態で展開すると

```
U_new = −H⁻¹(H U_lin + c) = −U_lin − H⁻¹c
```

**`U_lin → −U_lin` という固有値 −1 の写像**になる。つまり

- 毎周期符号が反転する（= **50 Hz のディザ**、100 Hz 制御の 2 周期で 1 往復）
- 不動点は `U* = −H⁻¹c / 2` ＝ **真の最適解のちょうど半分**
- ヌル空間成分は減衰も励起もされず、**符号だけ反転し続けて雑音で積み上がる**

観測されていた 3 つの症状（毎周期反転・実効ゲインが低い・ヌル空間に溜まる）が
**1 つの式で全部説明できた**。

- → `20260909_admm_gradient_bug_root_cause.md`

### 2.2 ⚠ 最初の修正が墜落を呼んだ

**修正案 A（採用してしまった）**: `c = H_SR2 · U_lin − g_exact` と**逆算**する。

- **結果**: 離陸数秒で振動して裏返る（0909_v5 / 0909_100Hz_v2）。
- **原因**: `H_SR2` は SR2 で育てた**近似**ヘッセ行列で、真の `H_exact` とは違う。逆算すると
  ```
  c_計算 = c_真 + (H_SR2 − H_exact) · U_lin
  ```
  となり、**誤差が `U_lin` に比例して増幅される**。`U_lin` が大きいほど `c` が狂い、
  `c` が狂うほど `U_lin` が大きくなる ── **正のフィードバック**である。
- **修正案 B（正しい）**: `c` を**定義どおり直接計算**する。`c` は `U` に依存しないのだから
  `U_lin` は一切現れてはいけない。これで `g` の計算自体が不要になった。

```cpp
// 正しい実装（compute_neg_const_term）
grad_dx  = Sx·x₀ − X_ref;
grad_Qdx = −Q̄ ⊙ grad_dx;
admm_neg_c = Suᵀ · grad_Qdx + R̄ ⊙ U_ref;   // = −c
```

- 📌 **教訓**: **数学的に等価な式でも、近似行列を挟むと等価でなくなる。**
  「`g` から `c` を戻せる」は `H` が正確なときだけ成り立つ。
- → `20260909_admm_const_term_backsolve_divergence.md`

### 2.3 ⚠ 修正したはずのソースが巻き戻っていた

- **症状**: 修正を入れたのに挙動が変わらない。
- **調査**: 実ソースがバックアップ（`scratchpad/bk3/`）と**バイト単位で一致**。
  mtime を見ると**ビルドの後に復元されていた**。
  決定的証拠は `control.cpp:2175` が**復元後のヘッダには存在しないフィールドを参照**していたこと
  ── **そのソースでは今のバイナリはコンパイルできない**。
- 📌 **教訓**: 「ビルドした」と報告する前に、**成果物がソースより新しいか**を確認する。
  既存の成果物を見て「ビルド済み」と判断してはいけない。
- → `20260909_solver_fix_reverted_by_backup_restore.md`

### 2.4 ⚠ バグを直したらゲインが上がって墜落した

- **症状**: `c` を正しくしたら、今度はゲインが高すぎて墜落。
- **原因**: **バグが実質的にゲインを半分にしていた**（不動点が最適解の半分）。
  直すと**実効ゲインが 1.61 倍**になる。バグの上で調整された `R_u = 120` はもう合わない。
- **対処**: `R_u` を上げてループゲインを合わせ直す（120 → 320 → …）。
- 📌 **教訓**: **バグの上でチューニングされたパラメータは、バグを直した瞬間に無効になる。**
  「直す」と「合わせ直す」は必ずセットで計画する。
- → `20260909_solver_fix_caused_crash_gain_and_timing.md`

## Phase 3 — 三重の交絡（2026-09-10）

修正後も墜落が続いた。**3 回の墜落に 3 つの別原因**があり、切り分けに数日かかった。

### 3.1 EKF が「墜落姿勢のまま凍結」していた

- **症状**: 再アームして飛ばすと、水平なのに機体が傾いていると推定される（偽の傾き）。
- **原因**: `Arm_flag == 3`（ディスアーム）の間、**100 Hz の `angle_control()` が 1 度も呼ばれない**
  （`sem_release` が `Arm_flag == 1/2` の枝にしかない）。つまり
  **EKF は墜落したときの姿勢のまま凍結**し、再アームすると「転倒姿勢から水平へ収束し始める」。
- **対処**:
  - アーム時に**加速度から姿勢を作り直す** `ekf_reinit_on_arm()`（ヨーは保持）
  - **離陸ゲート**: 再初期化後 1.5 s の暖機 + ドリフト < 1 deg/s が 1.0 s 継続するまで
    **モータを回さない**（実測の待ち時間 ≈ 2.49 s）
- **結果**: 0910_v12 で偽の傾きが消えた（ドリフト −0.78/+0.35 deg/s）。
- 📌 **教訓**: 内部状態を持つ推定器は「止まっていた区間」を疑う。再開時に明示的に初期化する。
- → `20260910_v11_post_crash_ekf_and_slow_mode.md` / `20260910_arm_gate_and_ekf_reinit_ru800.md`

### 3.2 プロペラ交換で機体ゲインが 2 倍になっていた

- **症状**: 制御器側のゲインを 3 回合わせ直しても振動が消えない。
- **原因**: 途中で **D90S → GEMFAN** にプロペラを替えており、**機体（プラント）側のゲインが 2 倍**に
  なっていた。ループゲイン = 制御器 × 機体 なので、制御器だけ合わせても半分しか合っていない。
- 📌 **教訓**: **ゲインを合わせるなら「制御器」ではなく「制御器 × 対象」で合わせる。**
  ハードを触った日を必ず記録する。
- → `20260910_v7_prop_change_doubled_plant_gain.md`

### 3.3 「飛べていた」のはディザのおかげだった

- **発見**: 旧版（バグあり）が飛べていたのは、**50 Hz ディザが実効ループゲインを下げていた**から。
  旧飛行の指令の 70–80 % がディザ（状態と無相関な成分）で、
  機体に効く**コヒーレント成分**（状態と相関する成分）だけを取り出すと、
  総量 |Δu| で合わせるのは間違いだと分かった。
- **対処**: **回帰係数で合わせる**方式に変更（`R_u` 320 → 800）。
- 📌 **教訓**: 合わせるべきは総量ではなく**状態と相関する成分**。
  ディザ・雑音は「量」には入るが「効き」には入らない。
- → `20260910_dither_was_masking_the_real_loop_gain.md`

### 3.4 SR2 の健全性検査が「再構築嵐」を起こしていた

- **症状**: `R_u = 800` でも墜落。
- **原因**: TR1 の割線更新が大きすぎるとき、**その場で 37 ms のフル再構築を同期実行**していた。
  飛行中 **5 回/秒**発生し、墜落直前は**時間の 52 % が制御停止（ホールド）**だった。
- **対処**: 大きすぎる更新は**その周期の更新を捨てるだけ**にする（`tr1_c_max = 1e6`）。
  ただし捨て続けると線形化が古くなるので、**連続 5 回で 1 度だけ**フル再構築する
  （`tr1_skip_max_run = 5`）。
- **結果**: 再構築が 80 回 → 20 回に。
- 📌 **教訓**: **異常を検知したら再計算」は、再計算が高価なら異常より害になる。**
- → `20260910_sr2_bad_c_rebuild_storm.md`

### 3.5 ⚠ 「`Q_p` を下げる」提案が実は「ゲインを上げる」提案だった

- **経緯**: 正弦掃引で測って「`Q_p` を 20 → 1 にすればゲインが下がる」と提案した。
- **結果**: 実機は**離陸すらしなかった**。実際は**ゲインが 1.93 倍**になっていた。
- **原因**: 正弦掃引では `φ` と `p` が常に一緒に動くので、**角度ゲインと角速度ゲインを分離できない**。
  「角度誤差があって角速度がゼロ」という条件を測っていなかった。
- **対処**: 測定条件を 2 つに分ける（①角度誤差のみ ②角速度のみ）。
- 📌 **教訓**: **入力が相関している実験では、分離したい 2 つの量を分離できない。**
  掃引の前に「この実験で何と何が独立に動くか」を確認する。
- → `20260910_qp_reduction_was_a_gain_increase.md`

## Phase 4 — 遅れ補償と帯域の設計（2026-09-10 〜 09-11）

### 4.1 残ったのは「遅れ限界モード」だった

推定器も再構築も安全弁も健全な状態で、なお **3–5 Hz の振動**が残った。

- **性質**: 減衰比は悪化していないのに発振周波数が上がっている ＝ **ゲインではなく位相の問題**。
- **正体**: 実効遅れ **40–50 ms**（モータ一次遅れ + 計算 + 出力の ZOH）。
  遅れの位相損失は `2πfT` なので、交差周波数が上がるほど効いてくる。
- **なぜゲインを下げても直らないか**: 遅れによる位相損失は**ゲインと無関係**。
  ゲインを下げれば発振は止まるが、それは「速さを諦めた」だけである。
- → `20260910_residual_4hz_mode_is_the_real_blocker.md` / `20260910_v8_lag_limited_mode_persists_at_old_loop_gain.md`

### 4.2 遅れ補償（`x₀` の前方予測）

**対策**: 制御器に渡す `x₀` を、**直近に出した duty で 40–60 ms だけ前方予測**する。

```cpp
// nmpc_delay_predict(): RK2、1 周期あたり 4 substep
for (i = 0; i < n; ++i)          // n = delay_comp_steps
  for (s = 0; s < 4; ++s) {
      model_f(x, hist[i], k1);
      xm = x + 0.5h·k1;
      model_f(xm, hist[i], k2);
      x += h·k2;
  }
```

- **安全装置**: 予測が飛んだら（|Δφ| > 0.35 rad など）**予測を捨てて生の `x₀` を使う**。
  リプレイで 1e9 deg まで発散したので、4 substep 化と併せて必須だった。
- **効果**: 2–5 Hz 帯の占有率 **82 % → 15–21 %**。
- 📌 **教訓**: **帯域を上げる変更と、むだ時間補償は「組」で動かす。**
- → `20260910_delay_compensation_new_solver.md`

### 4.3 帯域の設計 — 「レギュレータのようで舵が効かない」

- **0911_v2（`Q_phi = 150`）**: 水平は保つが**スティックに全く追従しない**。
  測ると閉ループ時定数 **0.87 s** ＝ 帯域 **0.22 Hz**。人間の操作より遅い。
- **0911_v3（`Q_phi = 600`）**: 時定数 **0.30 s** に改善し、浮上 13.6 s（当時の最長）。
  ただし代償として **2 Hz の遅れ限界モード**が出た（p ピーク 1.99 Hz、2–5 Hz 帯 41 %）。
- **対処**: `delay_comp_steps` 4 → **6**（40 → 60 ms）。
  ホストで「静的剛性 1.02e-3 を保ったまま外乱 rms 24.3° → 4.0°」を確認して採用。
- 📌 **教訓**: 「指令が効かない」と言われたら、ゲインではなく**閉ループ帯域**を測る。
- → `20260911_v2_attitude_bandwidth_too_low_for_stick.md` / `20260911_v3_...md`

## Phase 5 — モデル同定（2026-09-11）

### 5.1 ヨー権限がモデルの 2.6〜3.0 倍あった

- **測定**: 飛行ログで「指令トルク proxy → ヨー角加速度」を回帰。
  実測 **572 / 667 deg/s²/unit** に対しモデル **220**。
- **意味**: `R_u` 支配の領域では制御ゲイン `K ∝ B_model` なので、
  **`B_model` が 1/3 なら ヨーのループゲインも 1/3**。
  ヨー軸だけ極端に弱く、外乱に負けてドリフトの**符号すら飛行ごとに変わって**いた
  （+2.7 / −1.4 / −20.7 / +5.0 / −6.8 deg/s）。
- **対処**: `CQ` 5.8e-9 → **1.2e-8**（実測比 3 倍のうち**2 倍だけ**寄せる）。
- ⚠ **「`CQ` という物理量が 2 倍だった」という主張ではない。**
  飛行が測れるのは `B_c(4,k) = kS·C_QT·T_max/Iz` という**ひとかたまり**だけで、
  `CQ` はその調整代として使っているにすぎない。`CQ = 5.8e-9` は電気入力経路と運動量理論経路の
  **独立 2 経路が一致した**推定値なので、乖離の犯人は `Iz` や `Cr` の可能性の方が高い。
- **結果**: 0911_v4 で実測/モデル比が **2.53 → 0.95** に。**補正は当たっていた。**
- → `20260911_cq_lumped_yaw_authority_and_delay_comp6.md` / `20260911_v4_...md`

### 5.2 `T_max` は `B_c` 全軸に掛かるスケールである

- **変更**: `T_max` 1.04 → 0.81（実機ホバー測定に基づく）。
- **見落としやすい点**: `T_max` は `nmpc_model.cpp` の 3 行にしか出てこないが、
  **ロール・ピッチ・ヨーの全部に掛かる**。実機は変わらないので、
  モデルを 0.779 倍すると**ループゲインがそのまま 22 % 落ちる**。
- **対処**: `R_u` 800 → **620**（ホストの外乱釣り合い剛性が 1.0168e-3 → 1.0010e-3 で一致）。
  ヨーも道連れになるので `CQ` 1.2e-8 → **1.54e-8**（`C_QT·T_max` を不変に保つ）。
- ⚠ 素朴な比例則 `800 × 0.779 × (500/600) = 519` は行き過ぎ（剛性が +7 % 超過）。
  `H = SuᵀQ̄Su + R̄` の `Su` 項が無視できないため、実測で決める必要があった。
- → `20260911_tmax081_requires_ru620_and_cq_rescale.md`

## Phase 6 — ハードウェア要因（2026-09-11）

### 6.1 ヨーが「全く追従しない」

- **症状**: 反時計回りのヨー指令を出しても機体が回らない。
- **測定**: 準定常区間で
  - `psi_ref` −10〜−15 deg/s に対し実 `r` は **+0.3〜+9.0 deg/s（逆向き）**
  - 制御は `Σ kS·u = −0.112` を出している（指令どおり負、モデル上 −51 deg/s²）
  - 実 `ṙ ≈ 0` → **釣り合っている未説明トルクが +40〜+80 deg/s²**
- **原因の切り分け**: ヨー率ループの静的ゲインは実測 **0.00688 /(deg/s)** で、
  ホストの **0.00706** とほぼ一致。**制御器は設計どおり動いていた。**
  ホストに同じ外乱を入れると追従率が **98 % → −41 %** となり、実機と同じ症状が再現した。
- **結論**: **積分器が無いので、定常外乱は必ず定常誤差になる。**
  `Q_r` を 8 倍にしても追従は 39 % までしか戻らない（必要な差動 0.10 は外乱で決まり `Q_r` では減らない）。
- → `20260911_v5_yaw_untrackable_steady_disturbance_not_gain.md`

### 6.2 ★ 原因はソフトではなくハードだった

- **物理量への換算**: +46 deg/s² は `Iz` を掛けて **2.4e-3 N·m**。これは
  **CW/CCW 推力差 0.081 N ＝ 全推力の 2.5 %**、または**全モータの 0.42° の傾き**に相当する。
  「工作精度の範囲」で説明できる大きさだった。
- **実機**: ユーザが**緩んでいたモータ 1 個を締め直した**。
- **結果（0911_v6）**:

| | v5（緩み） | **v6（締め直し後）** |
|---|---|---|
| `r` 平均 | −12.10 deg/s | **−0.99** |
| `r` と `psi_ref` の相関 | −0.06 | **+0.55** |
| \|Σ kS·u\|（ヨーに使った操作量） | 0.0782 | **0.0574** |

**追従するようになり、しかも使う操作量は減った。**

- 📌 **教訓**: 制御で解けない定常誤差は、まず**物理量に換算してみる**。
  「2.5 % の推力差」と言われれば、ソフトを触る前にネジを見に行ける。

### 7.4 ⚠ v10 に残った最大の弱点 — ヨー角速度の追従

v10 は「飛ぶ」ところまで来たが、**ヨーだけは明確に追従できていない**。
ゼミ用の図（`docs/figs/v10_tracking`）で (c) だけ形が合っていないのはこれである。

#### 症状を同じ土俵に載せる

| 軸 | RMS 誤差 | 目標の変動（std） | **誤差 / 目標** |
|---|---|---|---|
| ロール φ | 4.71 deg | 4.03 deg | 1.17 |
| ピッチ θ | 5.10 deg | 5.04 deg | 1.01 |
| **ヨー率 r** | **9.12 deg/s** | **2.26 deg/s** | **4.04** |

RMS 誤差だけ見ると「ヨーは 9、ロールは 4.7 で 2 倍悪い」に見えるが、
**目標がどれだけ動いているかで割ると 4 倍悪い。** 単位が違う量は正規化しないと比較できない。

#### 先に「起きていないこと」を潰す

| 疑い | 測ったもの | 結果 |
|---|---|---|
| 発振している | 誤差のスペクトル | **0.2 Hz 以下に 67%、0.5 Hz 以下に 88%、2 Hz 以上は 1.2%**。振動ではなく**ゆっくり負けている** |
| ソルバがヨーを無視している | 誤差 → ヨー指令 `Σ kS·u` の相関 | **−0.87**。ちゃんと舵を当てている |
| ロール・ピッチに舵を食われている | 誤差 RMS と `\|p\|+\|q\|` の相関 | **+0.15**、忙しい半分 / 静かな半分 = **1.1 倍**。v10 では主因ではない |

3 つ目は重要で、**`Q_r = 60` だった 0904 では実際に食っていた**
（`20260904_yaw_starves_roll_pitch.md`）。`Q_r` を 40 に下げてこの経路は既に塞いである。

#### 起きていること — DC ゲインが足りない

1. **構造**: `B_c` の各行の大きさ（1 duty あたり rad/s²）は
   **ロール 31.8 / ピッチ 29.6 / ヨー 8.0** で、**ヨーはロールの 1/4.0**。
   ロール・ピッチは腕の長さ 0.05〜0.10 m で効くのに対し、
   ヨーは `C_QT ≈ 0.030`（推力 1 N あたりの反トルク [m]）でしか効かない ──
   **実質「腕の長さ 3 cm」相当**しかない。
   さらに 2026-09-14 の吊り試験で実機の `C_QT` はモデルの 1/1.44 と分かったので、**実際は 1/5.7**。
2. **重み**: `Q_r = 40` に対し `Q_phi = Q_theta = 1000` ── **1/25**。
3. **積分作用が無い**: Phase 8 で入れたが v12 の墜落で撤収した。

→ **有限の DC ループゲイン＋積分なし**なので、**定常的なヨー外乱はそのまま定常偏差として残る。**
誤差が低周波に偏る（67% が 0.2 Hz 以下）のはこの帰結であって、帯域不足の別の顔ではない。

#### 外乱が実在する証拠は「目標値」そのものにある

`psi_ref`（ラダースティック由来のヨー**角速度**指令）は全区間ほぼ負で、
**平均 −7.1 deg/s、範囲 −14〜−3 deg/s**。つまり

> **操縦者がラダーを当てっぱなしにして、ヨードリフトと手で戦っている。**

この「目標値」は機動指令ではなく**人手による外乱補償**である。
そして実測の平均は **−3.0 ± 2.5 deg/s**＝指令の **42 ± 35 %** しか出ていない。
⚠ 1 便 20 秒・誤差の相関時間 0.86 s で有効標本は 12 個しかないため、
**「半分も出ていない」程度の主張が限界**で、42% という数字を precise に扱ってはいけない。

#### ⚠ 直し方がどれも素直ではない

| 手 | 何が起きるか |
|---|---|
| `Q_r` を上げる | 6 発の duty を取り合うので**ロール・ピッチが悪化**する。`Q_r` 60 → 40 で最大 `\|r\|` が 126 → 29 deg/s、飽和率が 16.6 → 5.5 % になった経緯がある（`20260904_v8_ftc_airborne_no_go.md`） |
| `C_QT` を実測値（1/1.44）に直す | **ヨーは悪化する。** `R_u` 支配域では制御ゲイン `K ∝ B_model` なので、ループゲイン `K·B_plant ∝ B_model` が 1/1.44 に落ちる。**いまの過大な `C_QT` はヨーのループゲインを底上げしている**（2026-09-11 に `CQ` を上げてヨーが改善したのは、物理が合ったからではなくループゲインが上がったから） |
| 積分作用を入れる | Phase 8 で試し、v12 の墜落（`\|U_lin\|` 暴走）で撤収 |
| ハードを直す | v6 で**緩んだモータを締め直したらヨードリフトが収まった**実績がある（Phase 6）。外乱そのものを減らす方向は、実は一番効いた |

#### 構造的な結論

ヘキサの姿勢制御には **「腕の長さで効く 2 軸」と「反トルクでしか効かない 1 軸」という非対称**がある。
`C_QT ≈ 0.03 m` は腕の長さ 3 cm 相当で、ロール・ピッチの 5〜10 cm に構造的に負ける。
**これは重みでもモデル修正でも埋まらない。** ヨーを良くしたければ
(a) 外乱そのものを減らす（機体の組み付け）、(b) 積分作用を安全に入れ直す、
(c) ヨーを諦める設計にする（`ψ` を状態に持たない現行方針はすでにその方向）のいずれかになる。

📌 **教訓**: **弱い軸は「弱いなりに設計されているか」を確認する。**
ヨーの追従が悪いこと自体は設計どおり（`Q_r` を意図的に下げている）で、
問題は**それが許容できる弱さなのかを誰も数値で決めていなかった**ことである。

## Phase 8 — v10 の先（積分の試行と撤収）

v10 でも残っていた症状：**姿勢を保持していると、じわじわ目標から垂れる**。

### 8.1 外乱は「状態」ではなく「状態の積分」に比例していた

未説明トルクを **θ（傾き）** と **∫θdt（速度の代理）** で回帰すると：

| | θ の係数 | **∫θdt の係数** | R²（両方） | R²（θのみ） |
|---|---|---|---|---|
| roll | +3.2 | **−41.1** | 0.469 | **0.010** |
| pitch | −3.5 | **−12.4** | 0.133 | **0.013** |

**θ 単独ではほぼ何も説明できないのに、∫θdt を入れると R² が一桁上がる。**
これは**速度安定（ブローバック）** ── 傾けて速度が乗るほど、傾きを戻すモーメントが増える現象。
**姿勢 5 次元モデルには並進状態が無いので、原理的に入っていない。**

### 8.2 `R_u` では解けなかった

| | 実機 K角 [e-3/deg] | 減衰 [e-3/(deg/s)] | **率/角 [s]** |
|---|---|---|---|
| R_u=620 | 0.852 | 0.216 | 0.25 |
| R_u=800 | 0.665 | 0.175 | 0.26 |
| R_u=1000 | 0.420 | 0.121 | 0.29 |

**`R_u` は角度ゲインと角速度ゲインを同じ比で下げるだけで、相対減衰は動かない。**
つまり `R_u` を上げてもオーバーシュートは直らず、剛性を失うだけだった。

📌 **教訓**: 1 つのノブが 2 つの指標を同じ比で動かすなら、そのノブで
トレードオフは調整できない。**別の構造（積分項・状態追加）が要る。**

### 8.3 積分作用の実装 — と撤収

- **最初の実装（`U_ref` をずらす）は効かなかった。** `U_ref` は `R̄` 項からしか効かないので、
  `Q_phi = 1000` / `R_u = 620` のように状態コストが支配的だとソルバが潰してしまう。
  実測：剛性から 12 deg 相当のはずのトリムが **0.29 deg しか動かなかった**。
- **採用した方式（`X_ref` をずらす）**: 定常外乱で +2.5 deg 高い所で釣り合うなら、
  内部の目標を −2.5 deg ずらす。状態コストの中で効くので `Q/R` 比に依存しない。
- **結果（v11）**: ロールは少し改善したが、**同じ重みの v10 と比べるとピッチが悪化**
  （相関 0.47 → 0.29、水平保持 2.19 → **10.44 deg**）。ソルバ健全性も低下（`ulin` 最大 2.17 → 4.08）。
- **v12 で墜落**: `|U_lin|` が発散し、**ピッチ誤差 2.5 deg でフルの機首上げ**を出して背面に入った。

### 8.4 安全弁 3 — `|U_lin|` のガード

v12 の墜落を解析すると、`λ`・遅れ予測・TR1 割線更新には検知と棄却があるのに、
**線形化点 `|U_lin|` にだけ何も無かった**（0.1 → 6.1 まで誰にも止められずに育った）。

- **追加**: `|U_lin| > 1.0` が **5 周期連続**したら warm start を畳んでフル再構築を要求する。
- **しきい値の決め方**: 実飛行 6 便の「`|U_lin|>1.0` が連続した最大周期数」から決めた
  ── 健全便 0〜5 に対し **v12 は 71**。健全便で誤発火ゼロ、v12 では `q` が跳ねる **0.08 秒前**に発火。
- **方針**: 積分は撤収（`trim::enable = 0`）して **v10 へ戻し**、耐故障制御へ進む。
  積分のコードは残置してある。

# Phase 9 — 耐故障制御の前に立ちはだかったのは推力だった（2026-09-14）

v10 で健全飛行が固まり、次は耐故障（FTC）である。
その前提として、ずっと仮値のままだった **ヨー減衰 `Cr`** を実測しに行った。
ところが同定の途中で、**`Cr` 以前に推力が足りない**ことが分かってしまった。ここがいまの壁である。

## 9.1 吊り試験で取れたもの・取れなかったもの

機体を**上下逆さに吊り**（プロペラ下向き＝推力が糸を張る向き）、
ヨー軸だけスイベルで自由にして、6 発の duty に差動 `u_i = u0 + s_i·Δ` を入れて回した。

**取れたもの。**

| 量 | 値 | 質 |
|---|---|---|
| **`C_QT/Iz`**（ヨー入力ゲイン） | **6.19 ± 0.30**（3 本、5%） | 開ループ、R² 0.998 |
| モータ OFF ベースライン | `tau_f/Iz = 2.0e-2`, `b/Iz = 6.5e-3` | 独立 3 本で 2〜6% 再現 |
| 軸受摩擦 `tau_f` | 5.9e-5 N·m（`Iz=3.0e-3`） | ボールベアリング級。治具は合格 |
| モータ一次遅れ | **≲ 20 ms** | 要領書の仮定 50 ms は過大。ただし `C_QT` には 1.3% しか効かない |
| **`Cr`** | **9.5e-5**（`Iz=3.0e-3`）／ 3.7e-4（`Iz=11.6e-3`） | `nmpc_params.hpp` の `0.005` は **13〜50 倍過大** |

`C_QT/Iz` は **`B_c(4,k) = kS·C_QT·T_max/Iz` というかたまりそのもの**なので、
`Iz` が 3.9 倍不確かでも比は動かない。**ファームのヨー権限は実測の 1.44 倍**と出た。

**取れなかったもの。**

`Cr` の**関数形**。超過分 9 点に `C + b·|r|`（線形＝H 力）と `C + a·r²`（二乗）を当てると
残差 3.96 vs 3.88 で**区別がつかない**。400 deg/s へ外挿すると 44 vs 89 deg/s² と 2 倍違う。

⚠ さらに、フェーズ④の前提「差動を 0 に戻せば `tau_z = 0`」が**この治具では偽**だった。
`r` の符号を反転させた 3 本ずつの対を取ると、`|r(t)|` の 2 群が**完全に分離**した
（+ 側は 8 秒で 70 deg/s しか落ちず、− 側は 200 deg/s 落ちる）。
`r` の符号に依らない**偶のトルクが 11〜19 deg/s²** 残っている。機構は未特定
（傾いた機体が自分の吹き降ろしの中で回ること、が唯一の候補）。

## 9.2 ★ 水平のまま 1 発止めると、実質 4 発になる

`f_FR = 0` として、鉛直・ロール・ピッチ・ヨーの 4 拘束を実機の混合行列で解く。
未知 5、拘束行列の階数 4。

```
ピッチ式 : f_FL = f_RR + f_RL
ロール式 : f_MR = f_ML + f_RL
ヨー式   : 上 2 式を代入すると 3·f_RL = 0
→ f_RL = 0、  f_FL = f_MR = f_ML = f_RR = mg/4
```

**FR を止めると、対角の RL も自動的に 0 になる。** 近似ではなく配置から出る厳密解である。

1 発の上限は `T(0.95) = 0.8407 N`。

| 質量 | 必要 `mg/4` | 上限比 | 余裕 |
|---|---|---|---|
| 390 g | 0.9565 N | 113.8% | **−12.1%（不可）** |
| 356 g | 0.8731 N | 103.9% | **−3.7%（不可）** |
| **335 g** | 0.8216 N | **97.7%** | **+2.3%** |
| 320 g | 0.7848 N | 93.4% | +7.1% |
| 308 g | 0.7554 N | 89.9% | +11.3% |

**4 発で 4 自由度（推力・ロール・ピッチ・ヨー）を担うので、この余裕がそのまま制御権限である。**
335 g の +2.3% は「解はあるが動かす余地がゼロ」。

> **平面ヘキサ X は、1 発止まると構造的に 2 発失う。** 制御則では回避できない配置の性質であり、
> ヘキサの冗長性が見かけより弱い理由でもある。
> （X8・同軸ヘキサ・8 発機なら故障発のモーメントを複数発へ分散できるので事情が変わる）

## 9.3 relaxed hover は効く。ただし実測 `Cr` では 660 deg/s が要る

**relaxed hover（回転ホバー）** は heading `ψ` を捨て、重力軸と平行な軸まわりに定常回転させる解法。
`φ, θ` は一定のまま `ψ` だけ進む。

```
p = −Ω sinθ,  q = Ω sinφ cosθ,  r = Ω cosφ cosθ

τ_x = (Iz−Iy)·q·r + Cp·p|p|
τ_y = (Ix−Iz)·r·p + Cq·q|q|
τ_z = (Iy−Ix)·p·q + Cr·r|r|
Σf·cosφ·cosθ = mg
```

**なぜ効くか。** 定常回転（`ω̇ = 0`）でも `ω` が主軸に載っていなければ**ジャイロ項が残る**ので、
釣り合いに必要なモーメントが 0 でなくなる。9.2 で `f_RL = 0` を強制していたのは
「必要モーメントが全部 0」だったからで、それが崩れると **`f_RL > 0` を含む配分が可能**になり、
荷重が 4 発ではなく 5 発に散る。代償は傾いた分の合計推力増（`Σf = mg/cosφcosθ`）。

⚠ **私はここを一度間違えた。** 傾き 0 で解いて「回転を許しても余裕は増えない」と結論したが、
傾き 0 は必要モーメントを全部 0 にしてしまい、**relaxed hover の機構そのものを消していた。**

⚠ 一次記録 `20260904_relaxed_hover_equilibrium_design.md` 本文の
「`fmax = 0.84 N` では解無し（鉛直力 0.070 N の不足）」も同じ罠だった。
その **0.070 N は `4×(mg/4 − fmax)` に一致**する ── 探索が傾き ≈ 0 の解に捕まって抜け出せていない。
同 decision の追記が外側／内側分解へ方式を変え、`fmax = 0.84` のまま解を得ている。

**そして実測 `Cr` がこれを厳しくした。** `Cr` が小さいほどヨー減衰が弱く、
同じ不釣り合いに対する平衡回転数が上がる ── **ジャイロ項で稼ぐには速く回さねばならない。**

余裕 `rho`（`fmax = 0.8407 N`、実測 `C_QT`）:

| `Ω` 上限 | 356 g | **335 g** | 320 g | 308 g |
|---|---|---|---|---|
| 0（＝ 9.2 の静的解） | −3.8% | **+2.2%** | +7.0% | +11.2% |
| 300 deg/s | −2.3% | **+4.0%** | +9.1% | +13.4% |
| 360 deg/s | −0.6% | +6.0% | +11.2% | +15.7% |
| **660〜680 deg/s** | +12.7% | **+20.4%** | +27.2% | +32.6% |
| （参考）旧仮値 `Cr=5e-4`・300 deg/s | +3.6% | **+11.2%** | +17.4% | +22.9% |

**`Ω ≤ 300 deg/s` の 335 g で `+11.2% → +4.0%`。`Cr` の同定は relaxed hover の旨みを 2/3 削った。**
無制約に最適化すると `φ=−6°, θ=−8°, Ω = 660〜680 deg/s`（約 1.9 回転/秒）へ行く。

**そこには壁が 4 つある。**

1. `FS_RATE = 360 deg/s` に抵触する
2. **ホライズン `N·dt = 0.14 s` の間に 90〜100° 回る。** 5 状態オイラーモデルの線形化が horizon 内で意味を失う
3. 一次記録の所見「**relaxed hover は上昇能力をほとんど持たない**。`az = +1 m/s²` で余裕が消える」
4. 安全（毎秒約 2 回転で回るヘキサ）

## 9.4 ⚠ そして質量そのものが未確定である

リポジトリ内に **0.300 / 0.335 / 0.356 / 0.390 kg** の 4 通りが併存している。
さらに `20260904_v8_ftc_airborne_no_go.md` の「健全飛行の 6 発 duty 合計 平均 **4.052**」を
推力に直すと `6·T(0.675) = 3.92 N ≈ 400 g 相当`で、**335 g より重い側を示唆している。**

**9.2 の表より、356 g 以上なら水平も relaxed（`Ω ≤ 360`）も成立しない。**
**この 1 つの数字が、FTC 実験が成立するかどうかを単独で決めている。**

## 9.5 いまの結論

- **推力余裕を上げるレバーは質量だけ。** `Ω = 0` を含む全ての `Ω` で効く
- 目標: **最低 −27 g（→308 g, 上限比 90%）、目標 −44 g（→291 g, 85%）**
- **`Cr` の測り直しはしない。** 必要 `Ω` は `Cr^(−1/2)` で効くので、残りの不確かさ（2 倍）だけ動いても
  `Ω ≈ 470〜960 deg/s` の範囲で、いずれも実用外。**いま持っている推定で判定がつく**
- **`CQ` / `Cr` は params に反映しない。** モデルの 2 つの誤差は逆向きで打ち消し合っている
  （`Cr` 53 倍過大 → 指令 +36%、`C_QT` 1.44 倍過大 → 指令 0.69 倍、積 **0.94**）。
  v10 はその相殺の内側で調整されており、**片方だけ直すと 30〜40% ずれる**
- ⚠ **`ftc=1` の実測ログはいまだに 0 件。** FTC 経路はプロペラを外した机上確認すらされていない
- オフラインの平衡計算では**逆にファームの値を使ってはいけない**。`C_QT/Iz = 6.19` が実測

📌 **教訓**: **制御則を磨く前に、その制御則が動かす対象に余力があるかを確かめる。**
最適化は「配れるものを最適に配る」だけで、無いものは作れない。

# 第 IV 部 この開発から得た一般的な教訓

制御に限らず使えるものを抜き出す。出所は各 decision。

## 4.1 原因の切り分け

1. **症状と同時に起きている異常は、原因とは限らない。**
   その機構だけを机上で再現して症状が出るか確かめる。実例では 40 ms のストールを
   4 回/秒 人工的に注入しても追従誤差は 3.55 → 3.57 deg しか動かず、最有力仮説が 5 分で消えた。
2. **「重い処理のせいでは」と疑われたら、まず頻度が症状と合うか見る。**
   「数秒に一回」の症状に対し、疑われたフル再構築は **1 秒に 3.4 回**起きていた。桁が違えば主因ではない。
3. **先行・後行は包絡線の相互相関で決める。** 実例では |ヨー率| が |ロール率| の包絡を
   **0.8 秒先行**して相関 0.82 で、どちらが上流かが一目で決まった。
3b. **単位の違う量を比べるときは「誤差 / 目標の振幅」で正規化する。**
    RMS 誤差の生値ではロールが 4.7 deg、ヨー率が 9.1 deg/s で「2 倍悪い」に見えるが、
    目標の変動で割ると 1.17 対 **4.04** で 4 倍悪い。どの軸を直すべきかの順位が変わる。
4. **ログが「どの状態で書かれているか」を確認してから沈黙を解釈する。**
   ログが特定の状態でしか書かれないなら、現れない状態は「起きなかった」ではなく「記録できなかった」。

## 4.2 測定と同定

5. **実験が測れるのは「かたまり」であって、その中の 1 個の物理定数ではない。**
   `a·b/c` の形でしか効かない量を逆算して「a が n 倍だった」と言ってはいけない。
6. **閉ループの運転データから「対象のゲイン」を同定しようとしない。**
   検算法：モデル定数を X 倍にした 2 便で同じ推定手順を回す。本当に測れているなら
   「実測/モデル比」は 1/X 倍になるはず。ならなければ、その推定量は対象を測っていない。
7. **入力が相関している実験では、分離したい 2 つの量を分離できない。**
   正弦掃引では角度ゲインと角速度ゲインが分離できなかった。
8. **比較は「1 つだけ違う相手」とやる。** 条件が 2 つ以上違う相手と比べると符号すら逆に読める。
8b. **同定の前提が成り立っているかを、同定の前に測る。** 「差動を 0 に戻せば入力トルクは 0」は
    自明に見えるが、この治具では偽だった。`±` 両方向で同じ実験を回し、`|出力|` の波形が
    重なるかを見れば、前提の破れ（`r` の符号に依らない残留項）が 1 回の比較で出る。
8c. **式の中で「0 になる」と置いた項は、0 にした瞬間に機構が消えていないか確かめる。**
    relaxed hover を傾き 0 で評価して「効かない」と結論したが、傾き 0 は必要モーメントを
    全部 0 にしてしまい、**効く仕組みそのものを消していた**。最適化が「解無し」を返したら、
    まず探索が退化した部分空間に捕まっていないかを疑う。

## 4.3 設計

9. **ゲインを合わせるなら「制御器」ではなく「制御器 × 対象」で合わせる。**
10. **遅れで限界にあるループは、ゲインを下げても直らない。** 位相の問題だから。
    見分け方：減衰比は悪化していないのに発振周波数が上がっているなら位相。
11. **1 つのノブが 2 つの指標を同じ比で動かすなら、そのノブでトレードオフは調整できない。**
12. **積分（トリム）は「入力の参照」ではなく「出力の目標」側に入れる。**
    入力コストの重みを通してしか効かないと、状態コストが支配的な設計ではオプティマイザに潰される。
13. **積分器には必ずリークを入れる。** 上限に張り付いたままは「消せない外乱」の証拠であり、
    かつ「指令から一定量ずれた目標を追い続ける」だけの害になる。
14. **外乱が「状態」でなく「状態の積分」に比例していないか確かめる。**
    「最初は追従するのに保持していると戻る」はゲインではなく積分器の問題。

## 4.4 実装と運用

15. **内部状態のうち「ガードが付いていないもの」を数え上げる。** 事故は必ずそこで起きる。
16. **状態機械の表示ルーチンには必ず `else` を置く。**
    「どの枝にも当たらない」が正常表示に化けるのが最悪。
17. **予測器を実機ログで走らせてから出荷する。** 正常域で正しくても異常域で爆発する。
18. **「ビルドした」と言う前に、成果物がソースより新しいかを確認する。**
19. **パラメータ 2 つを同時に変えるなら、単独効果の和ではなく「組み合わせ」も測る。**
    実例では遅れ補償単独ではステップが遅くなる（0.74 → 1.07 s）のに、
    ヨーのモデル誤差を同時に直すと 0.56 s と**元より速く**なった。
20. **副作用で動いている系は、副作用の片側だけを消せない。**
21. **モデル誤差は 1 つずつ直すと悪化しうる。** 実測で `Cr` が 53 倍過大、`C_QT` が 1.44 倍過大と
    分かっても、両者は指令に対して逆向き（+36% と ×0.69、積 0.94）で、調整はその相殺の内側で
    行われている。**「測ったから直す」の前に、その誤差が何と釣り合っているかを見る。**
22. **制御則を磨く前に、その制御則が動かす対象に余力があるかを確かめる。**
    最適化は「配れるものを最適に配る」だけで、無いものは作れない。
    9 日かけてソルバのバグと重みを詰めた末に、律速が**グラム単位の質量**だったと分かった。
23. **「冗長な機体」の冗長度は、発数ではなく配置で決まる。**
    平面ヘキサ X は 1 発止まると対角も強制的に 0 になり、**構造的に 2 発失う**。
