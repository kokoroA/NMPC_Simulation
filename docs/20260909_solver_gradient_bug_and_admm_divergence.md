# 4 課題の原因調査 — 50 Hz チャタリングは勾配の使い方のバグ、NaN は ADMM 双対の発散

- **対象**: `Benzen_NMPC/nmpc.cpp`（`compute_gradient` / `admm_solve`）, `nmpc_params.hpp`（`admm_rho`, `admm_max_iter`, `T_max`）
- **手法**: **実機のソルバをそのままホストでビルドして閉ループ実験**（`nmpc.cpp` + `nmpc_model.cpp` を macOS でコンパイル）
- **依頼**: ①`T_max` を焼く前にピッチとヨーを落ち着かせる ②50 Hz チャタリングの原因 ③NaN からの復帰 ④ピッチ 1–3 Hz の切り分け

---

## 0. 結論（4 課題は 2 つのバグに集約された）

| # | 課題 | 原因 |
|---|---|---|
| ② | 50 Hz チャタリング | **勾配の使い方のバグ。写像の固有値がちょうど −1** |
| ③ | NaN 固着 | **ADMM 双対変数 λ の発散**（box が効いた瞬間に 1 周期で 10–50 倍） |
| ① | `T_max` を焼く前に | **②のバグが実効ゲインを半分にしている。**直すとゲインが 2 倍、`T_max` でさらに 1.28 倍 |
| ④ | ピッチ 1–3 Hz | **操縦者由来ではない**（指令の 1–3 Hz は 1.1 %、相関 −0.08）。②の影響下の閉ループモード |

## 1. ② 50 Hz チャタリング — 勾配の使い方のバグ

### 症状の再現

**実機のソルバをホストでビルドし、プラントもモデルと同じ式（＝モデル誤差ゼロ）で閉ループを回した。**
それでもチャタリングが完全に再現した。

```
  k   phi     th      r  |  du_FR   du_FL   du_MR   du_ML   du_RR   du_RL
400   3.04  -3.03    8.7 | -0.0408 -0.2723 -0.0189  0.0333 -0.1439 -0.0521
401   2.89  -3.18    8.4 | -0.0309  0.3294  0.1118 -0.1261  0.0854  0.1235
402   2.74  -3.33    9.5 | -0.0398 -0.2658 -0.0190  0.0330 -0.1376 -0.0503
403   2.58  -3.47    9.1 | -0.0301  0.3222  0.1114 -0.1253  0.0793  0.1198
```

**状態（phi, th, r）は完全に滑らかなのに、Δu だけが毎周期反転する。**
ラグ 1 自己相関 **−0.962**。**原因は機体でもセンサでもなく、ソルバの中にある。**

### 原因

コストは `J(U) = 0.5 (Sx x0 + Su U − X_ref)ᵀ Q̄ (…) + 0.5 (U − U_ref)ᵀ R̄ (U − U_ref)` で、

```
∇J(U) = H·U + c          H = Suᵀ Q̄ Su + R̄,   c = Suᵀ Q̄ (Sx x0 − X_ref) − R̄ U_ref
```

[`compute_gradient`](../program/pico/pico-sdk2/pico-sdk/Benzen_NMPC/nmpc.cpp) は
**`U_lin` における完全な勾配 `g = H·U_lin + c`** を計算している（コメントどおり）。
ところが [`admm_solve`](../program/pico/pico-sdk2/pico-sdk/Benzen_NMPC/nmpc.cpp) は

```cpp
ctx.scratch.rhs = -g + rho * (ctx.ws.z - ctx.ws.lambda);
ctx.ws.U = ctx.llt.solve(ctx.scratch.rhs);          // M = H + rho*I
```

と、**その `g` を「絶対解を求める右辺」として使っている**。ADMM の U 更新は本来

```
(H + rho I) U = -c + rho (z - lambda)          ← c であって g ではない
```

である。`g` を入れると余分に `-H·U_lin` が乗り、`M ≈ H`（`rho=1` に対し `diag(M) ≈ 186`）なので

```
U_new  ≈  -U_lin  -  H⁻¹c
```

**固有値がちょうど −1 の写像**になる。**減衰しない周期 2 振動が必ず出る。これが 50 Hz チャタリングの正体。**

さらに、その不動点は `U = -H⁻¹c / 2`、すなわち **正しい解のちょうど半分**。
**実効的な制御ゲインが半分になっている。**

### 観測との整合

| これまでの観測 | 説明 |
|---|---|
| ラグ 1 自己相関 ≈ −0.9 | 固有値 −1 |
| フル再構築で消えない | `H` を作り直しても写像の固有値は −1 のまま |
| 指令の大きさに比例 | 振幅 ∝ `|U_lin|` ∝ 指令 |
| 追従振幅比が 0.4–0.7 と低い | 平均が正しい解の半分 |

⚠ 以前の decision [`20260904_duty_chatter_50hz_nullspace.md`](ai/decisions/20260904_duty_chatter_50hz_nullspace.md) で
「ADMM 未収束だけでは説明が付かない」と書いたのは**正しかったが、原因の当たりを ADMM に置いていた点が誤り**だった。
**ADMM ではなく勾配の使い方である。**

### 修正と効果（ホスト実験）

```cpp
// c = g - H*U_lin   (H = M - rho*I)
rhs = (M * U_lin) - rho * U_lin - g + rho * (z - lambda);
```

| | ラグ1 | Δu rms | \|Δduty\|/周期 |
|---|---|---|---|
| 現行 | **−0.962** | 0.2526 | 0.4289 |
| 修正 | **+1.000** | **0.0361** | **0.0006（715 分の 1）** |

追従（プラント＝モデル）:

| | roll 振幅比 | pitch | yaw | roll 相関 | pitch | yaw | 飽和 |
|---|---|---|---|---|---|---|---|
| 現行 | 0.418 | 0.480 | 0.531 | +0.24 | +0.27 | +0.51 | **23.4 %** |
| 修正 | 0.496 | 0.509 | **0.797** | +0.41 | +0.46 | **+0.88** | **0.0 %** |

**追加コストは `H·U_lin` の 120×120 matvec 1 回（14,400 MAC）**で、LLT solve 1 回分と同程度。

## 2. ③ NaN 固着 — ADMM 双対 λ の発散

**⚠ 勾配だけ直すと 43 周期で NaN になる。** ホスト実験で λ のノルムを追うと:

```
k=36  |U|=1.2      |lambda|=0.15     ← box に当たり始めた瞬間
k=37  |U|=3.8      |lambda|=3.9
k=38  |U|=25.1     |lambda|=45.6
k=39  |U|=1133.6   |lambda|=2372.5
k=40  NaN
```

**box が有効になった瞬間から λ が 1 周期で 10–50 倍に発散し、4 周期で float を溢れて NaN になる。**

原因は `admm_rho = 1.0` に対し **`diag(M) ≈ 186`**（ホストで実測）であること。
U 更新は `rho (z − lambda)` の形でしか λ を見ないので、**λ の影響が 1/186 に薄まる**。
一方 `lambda += U − z` は毎回フルに足し込むので、**主変数が追いつけず双対だけが走る。**

現行コードで λ が 0 のままなのは、**勾配バグのチャタリングが `|U|` を小さく保ち box に当たらないから**である。
**片方だけ直すと必ず NaN になる。**

### 実機の NaN 固着はこれで説明できる

飛行では飽和が 7–23 % 起きている。そこで λ が育ち、墜落時の連続飽和で溢れて NaN。
duty が NaN になると [`control.cpp:1579`](../program/pico/pico-sdk2/pico-sdk/Benzen_NMPC/control.cpp) の
NaN ガードが `minimum_duty = 0.1` に置き換えるので、**全 6 発が duty 0.1 で回り続ける**。
再アームしても λ も姿勢推定も壊れたままなので直らず、**電源を抜くまで戻らない。**

### 対策（ホストで検証済み）

| 設定 | \|λ\|max | NaN |
|---|---|---|
| 勾配修正 + `rho=1`, `iter=2` | 1.57e+03 | **k=39** |
| 勾配修正 + `rho=200`, `iter=2` | 293 | k=122 |
| **勾配修正 + `rho=200`, `iter=5`** | **20.8** | **なし** |
| **勾配修正 + `rho=1000`, `iter=5`** | **3.4** | **なし** |

**`rho` を `diag(M)` と同じ桁（200〜1000）に上げ、`admm_max_iter` を 2 → 5 にする。**
`iter` を増やすと LLT solve が 2 回 → 5 回になる。**実機での時間計測が必須**（現状 `iter` 平均 6.4 ms）。

**加えて、無条件の安全弁を入れること。**

- `λ` のノルム上限（例: `|λ| > 1e3` で `λ.setZero()`）
- `U`/`z`/`λ` の非有限検出 → `ws.valid = false` で warm-start ごと破棄
- 姿勢推定の非有限・発散検出 → EKF 再初期化（現状 `control.cpp` に `isnan`/`isfinite` の使用は **0 箇所**）

⚠ `do_full_rebuild()` は `ws.lambda` を触らない。**周期フル再構築では λ はリセットされない。**
リセットされるのは `nmpc_mark_external_rebuild()`（`ws.valid = false`）を通る経路だけで、
これはスロットルを下げたときにしか呼ばれない。

## 3. ① `T_max` を焼く前に

**現行コードは勾配バグで実効ゲインが半分になっている。**
バグを直すとゲインは約 2 倍、そこへ `T_max` 1.04 → 0.81 でさらに **1.28 倍**。**合計 2.6 倍。**

モータ遅れ 50 ms を入れたプラントでの実験:

| 設定 | ラグ1 | 振幅比 R/P/Y | 相関 R/P/Y | 飽和 | NaN |
|---|---|---|---|---|---|
| 現行 | −0.485 | 0.50/0.49/0.60 | 0.32/0.30/0.68 | 0.0 % | なし |
| **現行 + `T_max` 1.28 倍** | **−0.718** | 0.51/0.50/0.67 | 0.38/0.31/0.74 | 0.9 % | なし |
| 勾配修正のみ | — | — | — | — | **k=43** |
| **勾配修正 + `rho=1000`,`iter=5`** | **+0.999** | 0.52/0.51/**0.81** | 0.40/0.38/**0.84** | 0.0 % | なし |
| 勾配修正 + 上記 + `T_max` 1.28 倍 | — | — | — | — | **k=538** |

**読み方。**

1. **現行のまま `T_max` を焼くと、チャタリングが悪化する**（ラグ1 −0.485 → −0.718）。機体は落ちないが操作量がさらに失われる。
2. **勾配だけ直すと 43 周期で NaN。絶対に単独で入れない。**
3. **勾配修正 + ADMM 修正の組で初めて健全になる**（チャタリング消滅、ヨー追従 0.60 → 0.81、相関 0.68 → 0.84）。
4. **その状態でも `T_max` 1.28 倍を重ねると 538 周期で NaN。**
   **`T_max` はソルバを直して実機で確認したあと、`R_u` を上げるなどゲインを戻す手当と対で入れること。**

**推奨する順序**: 勾配修正 + ADMM 修正 → 机上（プロペラ無し）で duty 波形確認 →
係留 → 自由飛行で再評価 → そのうえで `T_max` を `R_u` と対で調整。

## 4. ④ ピッチ 1–3 Hz は操縦者由来ではない

| 信号 | rms | 0–1 Hz | **1–3 Hz** | 3–6 Hz |
|---|---|---|---|---|
| `phi_ref` | 4.18° | 89.6 % | 2.4 % | 0.6 % |
| `theta_ref` | 5.45° | **96.6 %** | **1.1 %** | 0.1 % |
| `phi` | 2.94° | 82.0 % | 3.7 % | 0.9 % |
| `theta` | 5.78° | 60.0 % | **23.3 %** | 1.3 % |

**指令 `theta_ref` の 1–3 Hz は 1.1 %（rms 0.95°）しかないのに、応答 `theta` は 23.3 %（rms 2.17°）。**
1–3 Hz 帯だけに絞った相関は **−0.08**（ロールは +0.40）。

**＝ 操縦者が振っているのではなく、機体・制御器側が自分で振っている。**
PIO ではないので、スティックの操作法や指令のレート制限では直らない。

**②のバグで実効ゲインが半分になり、応答が鈍い（ピッチの遅れ 400 ms）状態で
閉ループが低減衰の 1–2 Hz モードを持ってしまった、という説明と整合する。**
ピッチ軸はモータ 4 発（FR/FL/RR/RL、MR/ML は `kX = 0`）でしか作れないぶん、
飽和とチャタリングの影響を受けやすい。

**したがって `Q_theta` を下げる前に、まず②③を直して測り直すこと。**
バグを抱えたまま重みを合わせ込むと、直した瞬間に全部やり直しになる。

## 5. まとめ — やる順序

```
1. 勾配の修正 (rhs = H*U_lin - g + rho(z-lambda))
   + ADMM の修正 (rho を 200-1000、admm_max_iter を 5)
   + 安全弁 (lambda ノルム上限、非有限検出で warm-start 破棄、EKF 再初期化)
   ※ 3 つは 1 組。片方だけ入れない
        ↓
2. 実機で iter/loop の時間を測る（iter が 5 回になる分の余裕確認）
        ↓
3. プロペラ無し → 係留 → 自由飛行で、チャタリングが消えたことを 100 Hz ログで確認
        ↓
4. そのうえで ピッチ 1-3 Hz が残るか再評価（残れば初めて Q_theta を検討）
        ↓
5. 最後に T_max = 0.81 を R_u と対で入れる
```

⚠ **本資料の数値はすべてホスト（macOS）での閉ループ実験であり、実機では未検証。**
プラントは同じ剛体モデル + 一次遅れであって、実機の空力・センサノイズ・
50 Hz ESC 応答は含まない。**傾向と原因の特定は信用してよいが、絶対値は実機で確認すること。**
