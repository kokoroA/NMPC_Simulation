飛行中の周期フル再構築を復活させました。**これは決定的な実験であると同時に、そのまま対策になり得ます。**

**なぜ今なら 58 ms の停止に耐えられる見込みがあるか**:
v1 で 58 ms が危険だったのは、**その時点で既に 100–200 deg/s で発振していたから**です
（58 ms × 150 deg/s ≈ 9° の無制御漂流）。
`R_u=120` で q rms 13 deg/s まで静かになった今、同じ 58 ms は **約 0.8°** にしかなりません。
**危険性は絶対値ではなく機体の状態で決まります。**「常に危険」と判断したのが早すぎました。

## 3. 未解決の問題（優先度順）

### P1【最優先】TR1/SR2 の数値漂流と、それを洗い流す手段

`0831_v3.csv` で `cycles_since_reset` と姿勢誤差の相関 **+0.704**、
指令のばらつきが **0.02 → 0.84** へ単調増加。

| 証拠 | 値 | 意味 |
|---|---|---|
| `cnt_tr1` / `cnt_tr1_ok` / `cnt_tr1_skip` | 888 / 888 / **0** | `secant_min_norm = 1e-6` のガードが**一度も働いていない** |
| `cnt_sr2_c` | **1**（888 周期中） | SR2 健全性チェックが漂流を検出できていない |

ホバー中は割線対 (s, y) がノイズ同然に小さいはずで、それを 888 周期連続で
float32 のランク更新に流し込めば `Su`/`H` が真値から離れます。

⚠ **因果は未確定。** `cycles` と経過時間がこのログでは同一直線上にあり
（経過時間との相関も +0.713 でほぼ同じ）、電池電圧の低下・機体が離陸点から離れる・
地面効果からの離脱と切り分けられていません。§2 の実験で決着します。

### P2【最優先】制御周期が 10 ms を超えている

`loop_us` 平均 **10.3 ms**（v3）。`iter_us` 8.5 ms。`dt = 0.01` 前提と食い違っています。
フル再構築時は **58 ms**（制御周期の約 6 倍）。

### P3 `T_max` / `Ct` / `C_QT` が同定値と合っていない

| | 現行 | [同定値](../program/pico/pico-sdk2/pico-sdk/Benzen_NMPC/docs/thrust_sysid_f1404.md) |
|---|---|---|
| `T_max`（ホバー接線 dT/du） | 1.04f | **0.80**（M=0.32 なら 0.82） |
| `Ct` | 6.13e-7f（betaFPV-D90s-3） | **5.21e-7**（GEMFAN-3630-3） |
| `C_QT = CQ/Ct` | 0.0361 | Ct 更新で **0.0576**（+60 %）。`CQ` 自体が未測定 |

⚠ **`T_max` を 1.04 → 0.80 にするとゲインが 1.3 倍になります。** 発振が収まってから。
`T_max` は物理量であって減衰の調整ノブではありません。**耐故障の再配分がこの値の正しさに依存します。**

### P4 定常トルク外乱（重心オフセット）と積分器の不在

`0831.csv` から機首上げ **+0.056 N·m**（総推力 3.49 N で **重心 16 mm 後方**相当）を推定。
NMPC に積分器が無いため、一定外乱には必ず定常偏差が残ります。

- **機械的に重心を合わせるのが最も効きます**（16 mm は大きく、かつ簡単に直せる）
- 正攻法は offset-free MPC（外乱を状態に加えて推定）。ただし状態次元が増えるので P2 の後
- 暫定策として `U_ref_stack` に前後差動のトリム定数を入れる手もあります

### P5 ヨーが片方向に流れる

`0831_v3.csv` で `r` の平均 **−16.7 deg/s**、rms 28。`psi_ref` はほぼ 0。
反トルクの不均衡か `C_QT` の誤りが疑われますが、**ロール/ピッチが飽和している間は切り分け不能**です。
先に P1・P2 を片付けてから。

### P6 受信機フェイルセーフと脱出条件が無い

- SBUS のフラグバイトは `Chdata[16] = sbus_data[23]` として**取得済みだが未参照**。
  受信途絶のタイムアウトも無く、**リンクが切れると最後のスロットルで回り続けます**
- \|θ\|>45° / \|q\|>300 deg/s での `motor_stop()` が未実装

### P7 OverG 保護が数値的に発火しない

閾値 `acc_norm > 800.0`（m/s² ≈ 81.5 g）に対し、`LSM9DS1_16g` の最大は 157 m/s²（3 軸合成で約 272）。
**絶対に到達しません。**

### P8 `ESC_calib` が 2 か所で設定されている

`pwm.cpp:7` が 1、`pico_copter.cpp:55` が 0 で上書き。
**このファームでは ESC キャリブレーションを実行できません**（逆アセンブルで確認済み）。
ESC を交換・リセットしたら詰みます。

### P9 推力マージンが 1.50 しかない

ホバー duty 0.51–0.58 に対し上限 0.95。**上向きの余裕は 0.37 しかありません**（下向きは 0.58）。
制御余裕が非対称で薄く、飽和しやすい構造です。

## 4. 根治策

### 4-A【本命】`N` の短縮

**フル再構築コストは概ね `N³`。17→12 で約 20 ms、17→10 で約 12 ms。**
**`loop_us` が平均 10.3 ms で予算超過している問題と同じノブで両方解けます。**

| N | ホライズン | フル再構築（58 ms から換算） | 効果 |
|---|---|---|---|
| 17（現行） | 0.17 s | 58 ms | 制御周期の 6 倍 |
| 12 | 0.12 s | **約 20 ms** | 2 周期 |
| 10 | 0.10 s | **約 12 ms** | ほぼ 1 周期 |

支配項は `H = Suᵀ Q̄ Su + R̄`（102×102 を 85×102 から）と LLT 分解で、どちらも `N³` に比例します。
`repository_rules.md` が「`N` は計算時間とメモリの両方に効く最重要ノブ」と書いているのはこのことです。

⚠ ホライズンを縮めると制御性能も変わります。**変えたら必ず実測し直すこと。**

### 4-B `secant_min_norm` の見直し — ただし計装が先

**`secant_min_norm` の見直しも有効ですが、先に `|s|` / `|y|` / `H` の対角を計装してください。**
**今は「悪化した」ことは分かっても「何が壊れたか」が見えません。**

`cnt_tr1_skip = 0` は「ガードが健全」ではなく「ガードが一度も効いていない」証拠です。
テレメトリに `|s|`, `|y|`, `H` の対角の最小/最大あたりを足せば、漂流を直接観測できます。
そのうえで閾値を決めれば、**必要なときだけ再構築する**という本来の設計に戻せます。

### 4-C core0 でシャドウ再構築 → アトミック差し替え（後回し）

core1 は再構築中も TR1/SR2 で 100 Hz を回し続けられるので、**停止がゼロになります。**

**ただし `H`+LLT だけで約 83 kB 必要**で、
**bss 402 kB / SRAM 520 kB から core0 スタック 32 kB を引くと残り約 86 kB。**
**成立するか未検証なので後回しを勧めます。**（`Su` も二重化するならさらに 35 kB 必要で、まず入りません。）

### 4-D「静かな時だけ再構築」（§2 でガクつきが出た場合）

```cpp
const bool calm = (fabsf(Wp-Pbias) < 1.0f) && (fabsf(Wq-Qbias) < 1.0f)
               && (fabsf(Wr-Rbias) < 1.0f) && !any_motor_saturated;   // 1.0 rad/s ≈ 57 deg/s
```

58 ms の穴を「開いても影響が小さい瞬間」に寄せる方法です。
`reset_period` を少し伸ばして（例 150）、静かな瞬間を待つ余裕を作るとより確実です。
