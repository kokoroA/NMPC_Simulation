# モータ6状態ではなく3軸角加速度状態へ縮約し、NX=8 / N=12で一次遅れを予測する

- **日付**: 2026-09-20
- **種別**: design
- **対象**: `Benzen_NMPC/nmpc_model.*`, `nmpc_params.hpp`, `nmpc.cpp`, `control.cpp`
- **タグ**: #Benzen_NMPC #一次遅れ #モータ遅れ #NX8 #N12 #delay_comp #DC6 #位相余裕 #計算時間 #SRAM

## 背景 / 症状

0919_v8 は `delay_comp_steps=6`、`pred_nonfinite=0` でも、FR 上限張り付き後に
2–3 Hz の発散へ移行した。DC6 は純遅れ近似の前方予測であり、一次遅れの周波数依存位相を
予測モデル内に持っていない。一方、6 モータの実効推力を全て状態化する NX=11 / N=14 は、
主要静的配列が約 63 KiB 増え、通常周期とフル再構築の余裕を削る見込みだった。

## 原因 / 判断根拠

全モータの時定数が共通なら、実効推力 `ω∈R⁶` と姿勢入力行列 `B_att` に対して
`a=B_attω` と置くことで、`a_dot=(B_att u-a)/τ` が厳密に成立する。
姿勢限定制御が必要とするのは個別 `ω` ではなく3軸角加速度 `a` なので、
6状態ではなく3状態だけを追加すればよい。

凝縮後の最適化次元は `NU·N` で決まる。NX=8 と同時に N=14→12 とすると、
状態スタックは 70→96 に増えるが入力スタックは 84→72 に減り、Hessian/LLT は
84×84→72×72 になる。主要静的配列の概算は現行比約 −5 KiBで、NX=11/N=14より安全である。

## 対応

- 最終構成を `x=[φ,θ,p,q,r,a_p,a_q,a_r]`, `NX=8`, `N=12` とする。
- 初版の `Q_a` は0とし、物理モデル変更とゲイン調整を混ぜない。
- アクチュエータ部分は exact ZOH、剛体非線形項は現行の1次離散化を維持する。
- DC6 は二重補償を避けるため初期値0。必要なら純遅延1–2周期だけを別途検証する。
- `a_hat` は400 Hz出力段のフェイルセーフ・clamp・デサチュレーション後 duty で伝播する。
- `η` は従来どおり box だけへ入れ、`B_att` へ重ねて掛けない。
- 原因分離のため NX=8/N=14 を先に測り、その後 N=12を別コミットで適用する。

## 次に触る人へ

- `τ` を入れたまま DC6 を残さない。40–50 ms は実効遅れであり、二重計上の危険がある。
- `Relax_x_eq[5]` と `build_cost_diag()` の5要素配列はNX変更で必ず破綻する。
- observer入力はNMPC指令ではなく、400 Hz段で実際にPWMへ渡した最終 dutyにする。
- N短縮と状態拡張を同じ測定結果だけで評価せず、NX8/N14→NX8/N12の順で差分を取る。
