# 加振 `u0` を 0.60 → 0.35 に下げる。ヨートルクは減るどころか増える。併せて立ち上げランプと `r` 上限を追加

- **日付**: 2026-09-14
- **種別**: design | tuning
- **対象**: `Benzen_NMPC/control.cpp`（`bench_excite_update` と加振設定ブロック）、`control.hpp`
- **タグ**: #Benzen_NMPC #bench #ヨー吊り #u0 #sysid #Cr #FS_RATE #振り子

## 背景 / 症状

人が糸で吊る以上、機体は完璧な水平にはならない（`0914_yaw_V1` の実測で **7.5°**、
速度に依らず一定＝固定的な幾何の傾き:
[`20260914_yaw_v1_baseline_offset_ok_fs_rate_latched.md`](20260914_yaw_v1_baseline_offset_ok_fs_rate_latched.md)）。
`Bench_u0 = 0.60` だと合計推力 3.57 N（364 g）の横成分がその傾きに乗り、ロール・ピッチが崩れる。
**`u0` を下げたい。**

## 原因 / 判断根拠

### `u0` を下げるコストはほぼ無い

推力曲線 `T(u) = -0.2265u² + 1.0525u + 0.0452`（`docs/thrust_sysid_f1404.md`）、
`T'(u) = -0.453u + 1.0525`、`C_QT = CQ/Ct = 1.54e-8/5.21e-7 = 0.02956`、自重 3.29 N（335 g）:

| `u0` | 合計推力 | `T'(u0)` | `tau_z` @Δ=0.05 | 対 0.60 | 糸張力 |
|---|---|---|---|---|---|
| 0.60 | 3.57 N (364 g) | 0.781 | 0.00692 N·m | ±0 | 6.86 N |
| 0.45 | 2.84 N (289 g) | 0.849 | 0.00753 | 推力 −21% / **トルク +9%** | 6.12 N |
| **0.35** | **2.31 N (236 g)** | **0.894** | **0.00793** | 推力 **−35%** / **トルク +15%** | 5.60 N |
| 0.25 | 1.77 N (180 g) | 0.939 | 0.00833 | 推力 −51% / トルク +20% | 5.05 N |

1. **逆さ吊りなので推力 0 でも自重 3.29 N が糸を張る。** 緩む心配が無い（要領書 §2 の逆さ吊りの利点）
2. **`T'(u)` は `u0` が小さいほど大きい。** `tau_z ≈ 6·C_QT·T'(u0)·Δ` なので
   **`u0` を下げるとヨートルクはむしろ増える**（0.60→0.35 で +15%）
3. `Δ` は**ロール／ピッチ／推力に厳密に中立**（`Σ kS = Σ kS·kXm = Σ kS·kYm = 0`、数値確認済み）。
   2 次項による合計推力の変化も `6·T''·Δ²/2 = −0.0034 N`（0.15%）。
   → ⚠ **傾きが気になるからと `Δ` を下げても無意味。効くのは `u0` だけ。**

### 下限は 0.25

推力曲線の較正範囲が **duty 0.25–1.00**（目盛 6..18 → 1300..1900 µs、`thrust_sysid_f1404.md` §3-2）。
`u0 < 0.25` は外挿で `T'(u0)` が信用できず、`tau_z` が決まらない。

### 唯一の実質的なコスト：動作点がずれる

`Cr` は「どのロータ回転数での値か」に依存する。欲しいのは
**健全ホバー duty 0.540** と **1 発停止 relaxed hover duty 0.681**（`T(u)` の逆解、335 g）。
`u0 = 0.35` はその下側なので外挿になる。
→ 要領書フェーズ⑤どおり `u0` を数水準振って傾向を取り、外挿する。これは元々の計画。

### 副次的に判明：推力ステップ自体が振り子を蹴っている

旧実装は `t = 0` で全発いきなり `u0`。**3.57 N が撃力として振り子に入る。**
`u0` を下げてもステップである限り残る。傾いた機体では、これがロール・ピッチの崩れの
少なくとも一因（機構の同定は未実施）。

### 副次的に判明：`r` の歯止めが消えている

[`20260914_bench_disable_fs_rate.md`](20260914_bench_disable_fs_rate.md) で加振モードの
`FS_RATE` を外した結果、**回転速度に自動の上限が無くなった。**
`u0` を下げるとロータ由来の減衰が減るので、同じ `Δ` でも `r` はより速く育つ。
ホスト検証（`Cr/Iz = 0.0333` 仮定）で、`Bench_r_max` を無効にすると
`t_step = 6 s` の終わりに **481 deg/s** に達した。要領書 §10 の中断目安 250 deg/s の約 2 倍。

⚠ さらに、**要領書 §6 の設計値表は古い `C_QT = 0.01113` に基づいており、現行 0.02956 では
`rdot(0)` が 2.65 倍**（50 → 133 deg/s²、`u0=0.35` の `T'` 増分も入れると 151 deg/s²）。
要領書の想定より `r` は 3 倍速く育つ。

## 対応

`control.cpp` の加振設定ブロックと `bench_excite_update()` を変更した。

| 項目 | 旧 | 新 | 理由 |
|---|---|---|---|
| `Bench_u0` | 0.60 | **0.35** | 合計推力 −35%、ヨートルクは +15% |
| `Bench_u_start` | — | **0.20** | ランプ開始 duty |
| `Bench_t_ramp` | — | **1.5 s** | `u_start → u0` の直線ランプ。**0 で従来のステップ** |
| `Bench_r_max` | — | **250 deg/s** | `|r|` が超えたらフェーズ(2)を打ち切る。**0 で無効** |

**ランプを 0 からではなく `u_start = 0.20` から始めるのは、0 から立ち上げると ESC が起動し
損ねて片発だけ回らない恐れがあるため。** 片発欠けは姿勢を崩すので、この試験では最悪の失敗。
0.20 のステップでも合計 1.48 N で、従来の 3.57 N より小さい。

`r` 上限に達したときは **`Δ` を 0 にするだけでなくフェーズ(2)自体をその時刻で終わらせる**
（`t2e = rmax_t`、自由減衰は `t_decay` を丸ごと取り直す）。`Δ = 0` にしてフェーズ表示を 2 の
ままにすると、物理的には自由減衰なのにログ上は加振中に見え、**解析側の窓の切り方を誤らせる**。
一度切ったら `r` が減っても再投入しない（`tau_z = 0` の前提が壊れる）。

### 却下した案

- **`Δ` を下げる**: `Δ` はロール／ピッチに厳密中立なので傾きの問題に効かない。ヨートルクだけ失う
- **`t_step` を短くして `r` を抑える**: `Cr` が未知（それが測定目的）なので、正しい `t_step` は
  事前に決められない。**測った `r` で打ち切る**方が条件に依らず正しい
- **`FS_RATE` を加振モードで復活させて歯止めにする**: 手回し（軸受チェック）で必ず踏む。
  `20260914_bench_disable_fs_rate.md` を覆すことになる。シーケンス側で持つのが正しい
- **終了時の 0 への落とし込みもランプにする**: フェーズ(4) の開始時刻が曖昧になり、
  モータ停止後のベースライン継続観測の起点が読めなくなる。**ステップのまま残す**

## 検証結果

- **ビルド成功**（`arm-none-eabi-gcc`、`make -j8`、警告なし、`pico_copter.uf2` 生成）
- **`bench_excite_update()` の本体をソースから機械的に抜き出してホストでシーケンス検証**（`/tmp/bt2.cpp`）。
  1 次減衰モデル（`Cr/Iz = 0.0333` 仮定）と組み合わせて:

| 設定 | フェーズ遷移 |
|---|---|
| 既定（`r_max=250`, `t_ramp=1.5`） | 0.00→(1) duty 0.200 / 4.50→(2) / **6.31→(3) r=250.2 で打ち切り** / 26.31→(4) |
| `r_max = 0`（無効） | 4.50→(2) / 10.50→(3) **r=481 deg/s** / 30.50→(4) |
| `t_ramp = 0`（無効） | 0.00→(1) duty **0.350 いきなり** / 3.00→(2) / 4.81→(3) / 24.81→(4) |

  ランプ（0.200 → 0.350 を 1.5 s）、`u0` 保持 3 s、打ち切りラッチの非再投入、
  無効化パスが旧挙動に戻ることを確認。
- ⚠ **実機未検証。** 傾きが実際に改善するか、`u_start = 0.20` で 6 発とも確実に起動するかは未確認。
- ⚠ `tau_z` の予測値（0.00793 N·m）は **`CQ = 1.54e-8` が飛行で合わせ込んだ調整値**であることに注意
  （`nmpc_params.hpp` の注記：測れるのは `kS·C_QT·T_max/Iz` のかたまりだけ）。
  桁の目安として使い、**この試験の出力で置き換えるべき値**。循環参照にしないこと。

## 次に触る人へ

- ⚠ **`u0` の下限は 0.25。** それ以下は推力曲線の較正範囲外で `tau_z` が決まらない。
- ⚠ **`Δ` を下げて姿勢を改善しようとしないこと。** 中立なので効かない。効くのは `u0` だけ。
- 実機で `u_start = 0.20` から起動しない発があったら、**下げるのではなく上げる**（0.25 など）。
  片発欠けの方が推力ステップよりはるかに悪い。
- `Bench_phase` はまだ**どのログにも出ていない**（10 Hz シリアルにもリングログにも列が無い）。
  duty の並びから読むしかない。観測性を上げるなら 1 列足す価値がある。**未実施。**
- 傾き 7.5° 自体は治具側の問題で未解決。3 本の長さを揃えて 2° 以下にするのが本筋。
