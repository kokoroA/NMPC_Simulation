# 姿勢トリム（積分作用）を実装。U_ref をずらす実装は効かず、X_ref をずらす方式に変えた

- **日付**: 2026-09-11
- **種別**: design | bugfix
- **対象**: `Benzen_NMPC/nmpc_params.hpp`(namespace trim), `control.cpp`(att_trim_*), ベンチログ
- **タグ**: #Benzen_NMPC #積分作用 #トリム #定常誤差 #アンチワインドアップ #U_ref #X_ref #ブローバック

## 背景 / 症状

[`20260911_v8v9_ru_up_loses_stiffness_droop_is_speed_stability.md`](20260911_v8v9_ru_up_loses_stiffness_droop_is_speed_stability.md)
で、外乱が**速度比例**（ブローバック）であり、比例項だけのコストでは必ず定常誤差になること、
`R_u` も `Q_p` も「剛性」と「相対減衰」を交換するだけで両立できないことを示した。その対処。

⚠ 本実装の時点で、ユーザは既に **`Q_phi=Q_theta=1000`, `Q_p=Q_q=80`, `R_u=620`**（前回提案の F）を適用済み。

## 原因 / 判断根拠

### ⚠ 最初の実装（U_ref をずらす）は効かなかった — ホストで捕まえた

当初は FTC 再配分と同じ経路、つまり **`U_ref`（入力の参照）に duty シフトを足す**実装にした。
`U_ref` は box 制約を通るので安全で、筋が良いと思っていた。**効かなかった。**

`c = Su^T Q̄ (Sx x0 − X_ref) − R̄ U_ref` で、`U_ref` は `R̄` 項からしか効かない。
**`Q_phi=1000` / `R_u=620` のように状態コストが支配的だと、ソルバは `U_ref` のずれを
「打ち消すべきもの」として潰してしまう。**

ホスト実測（ロール +12 deg 保持、一定外乱 50 deg/s²）:

| | 定常 | trim |
|---|---|---|
| 積分なし | +14.52 deg (121 %) | — |
| 積分あり（U_ref 方式） | +14.23 deg (119 %) | −0.012（**上限に飽和**） |

剛性 1.0e-3/deg から逆算すれば trim=0.012 は **12 deg 相当**のはずが、**0.29 deg しか動かなかった。**
一方**ヨーは `Q_r=40` と小さいので U_ref でも効いた**（−41 % → +73 %）。**軸ごとに効き方が違う。**

### 採用した方式: 状態参照 `X_ref` をずらす

定常外乱で機体が +2.5 deg 高い所で釣り合うなら、**内部の参照を −2.5 deg ずらせば実際の姿勢が指令値に乗る。**
状態コストの中で効くので `Q/R` の比に依存しない。単位はロール/ピッチ [rad]、ヨー [rad/s]。

### 積分帯を 25 deg → 8 deg に狭めた理由（これもホストで捕まえた）

帯（＝この誤差を超えると積分を凍結する閾値）を 25 deg にすると、
**外乱ゼロでも行き過ぎが 0 % → 16 % に増えた。** 12 deg のステップ直後に誤差 12 deg をそのまま
積んでしまうため。**積分の仕事は「小さな定常のずれを消すこと」であって大舵の補助ではない。**
8 deg / 20 deg/s に狭めて 16 % → 9 % に低減。外乱がある条件では行き過ぎは据え置きか改善する。

## 対応

`nmpc_params.hpp` に `namespace trim`（`enable`, `att_ki`, `yaw_ki`, `att_max`, `yaw_max`,
`att_err_max`, `yaw_err_max`）。`control.cpp` に `att_trim_reset/update/apply_ref`。

- 積分ゲインは **時定数 2 s**（`ki = 0.5`）。姿勢ループの時定数 0.3 s より 1 桁遅くして干渉させない。
- 上限は **ロール/ピッチ ±6 deg、ヨー ±25 deg/s**（実測の定常誤差 3 deg / 15 deg/s の約 2 倍）。
- アンチワインドアップ: 帯の外では積まない／飽和中は**外へ出る向きだけ**凍結（戻る向きは常に許す）。
- リセット: **アーム時**（`ekf_reinit_on_arm()`）と **NMPC 非実行時**（ゲート閉・低スロットル含む）。
- 誤差は**遅れ補償前の実測値**を使う（積分は遅いので予測は不要、かつ予測の誤りを溜めない）。
- ベンチログに `trim_roll` / `trim_pitch` / `trim_yaw` を追加（53 → 56 列）。

ホスト（出荷ソース、`control.cpp` の積分ロジックをハーネスに同じ式で再現）。

**安全確認**

- **実機がモデルの 0.7 / 1.0 / 2.0 / 3.0 倍**（同定の不確かさの幅）で外乱 100:
  いずれも**破綻なし**、定常 100–106 %、行き過ぎは積分なしと同等か改善（56→50, 40→37, 21→21, 14→16 %）。
- **外乱が途中で消えた場合**（8 s で 100 → 0）: トリムは −4.83 deg → **−0.02 deg** まで解け、
  定常 98 %。**巻き上がったまま残らない。**
- ヨー外乱 80 で実機 2 倍: −24 % → **100 %**。
- ビルド: `cmake --build build_fresh -j8` **警告・エラー ゼロ**。`text 683672 / bss 422388`
  （積分なし版から +1368 / +24 byte）。CRLF 3382/3382 行で維持。

**実機では未検証。**

## 次に触る人へ

- **初飛行では `trim_roll` / `trim_pitch` / `trim_yaw` を必ず見ること。**
  - **上限（±6 deg / ±25 deg/s）に張り付いたままなら、積分では埋められない外乱が残っている。**
    上限を上げる前に、それが本当に定常成分なのか（速度比例で増え続けていないか）を確かめる。
  - 符号が飛行ごとに反転するなら外乱側が非定常。機械的なトリム（CG・モータ傾き）を疑う。
- ⚠ **速度比例の外乱は原理的に積分では消せない。** 一定の傾きを保てば速度は増え続け、
  必要なトリムも増え続ける。実際ホストで「外乱 = −41·∫φdt」を入れると、どんな有限のトリムでも
  +12 deg は保持できなかった（物理的に正しい: バンクし続ければ加速し続ける）。
  **積分が消せるのは「一定の外乱」だけ**であり、CG ずれ・モータ傾き・反トルク非対称がその対象。
- **積分が入ったので、初めて「R_u を上げて穏やかにする」ことが試せる。** 今までは剛性を失うだけだったが、
  定常分を積分が持つなら比例ゲインを下げても垂れない。**次は R_u を 620 → 800 に戻して再評価する価値がある。**
- `enable = 0` にすれば従来動作に戻せる（リセットも走る）。切り分け用に残してある。
