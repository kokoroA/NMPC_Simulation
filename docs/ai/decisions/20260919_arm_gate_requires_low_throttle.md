# 離陸ゲートの開放条件に「スロットルが下がっていること」を追加した（開いた瞬間に duty が 0 → common_duty へ跳ぶのを断つ）

- **日付**: 2026-09-19
- **種別**: design | bugfix
- **対象**: `Benzen_NMPC/control.cpp`(`ekf_drift_update` の離陸ゲート, `led_control` のコメント, `debug_stream_poll`, `log_output` ヘッダ)
- **タグ**: #Benzen_NMPC #arm_gate #g_arm_gate_ok #スロットル #急回転 #安全 #motor_stop #Disable_duty

## 背景 / 症状

ユーザー報告（2026-09-19、最初の報告の後半）:

> スロットルを上げても反応しない時にもう少しスロットルを上げると急にスラスターが急回転しました。

LED 凍結の件（[`20260919_led_blink_counter_runaway.md`](20260919_led_blink_counter_runaway.md)）とは
**独立した機構**で、そちらを直しても残る。

## 原因 / 判断根拠

### 機構（ソースから確定）

`motor_stop()` は `set_duty_*(0.0)`。**`Disable_duty`(0.1) ではなく完全な 0。**
離陸ゲートが閉じている間、400Hz 出力段は `common_duty` に関係なく `motor_stop()` を出し続ける。

```
T_ref       = 0.5 × BATTERY_VOLTAGE(7.4) × (Chdata[2] − CH3MIN) / (CH3MAX − CH3MIN)
common_duty = T_ref × T_ref_coe(0.7) = 2.59 × スティック割合
```

| スティック | Chdata[2] | common_duty |
|---|---|---|
| 3.9 % | 417 | 0.10 ← ここで初めて出力される |
| 21 % | 638 | 0.55（ホバー相当） |
| **37 %** | **834** | **0.95（上限飽和）** |

⚠ **停止から上限飽和までがスティックの 4〜37 %。残り 63 % は全部 0.95。**

したがって「回らないから」とスティックを上げたまま 2.5 秒のカウントダウンを待つと、
**ゲートが開いた次の 400Hz 周期（2.5 ms）で duty が 0 から common_duty へ跳ぶ。**
ランプもソフトスタートも無い。スティック 32 % 程度でもホバーの 1.5 倍に達する。

### なぜ今まで露呈しなかったか

`sticks_neutral()` が**アーム操作時**に `Chdata[2] < CH3MIN + 400` を要求しているので、
「高スロットルのままアームする」経路は塞がれていた。
⚠ **塞がれていなかったのは「アーム成立後・ゲート開放前」の 2.5 秒間。** ここは誰も見ていなかった。

## 対応

`ekf_drift_update()` の離陸ゲート判定に **`(T_ref * T_ref_coe) < Disable_duty`** を追加した。

実装上の注意:
- **`g_arm_gate_hold` は飽和させるだけにして、開放判定と分けた。** 同じ `if` に押し込むと
  スロットルで弾かれるたびに EKF の収束実績（1 秒の連続成立）が捨てられ、
  スロットルを下げた後にまた 1 秒待たされる。**下げた瞬間に開く**のが正しい。
- **ベンチ加振モードは対象外**（スロットルがデッドマンスイッチ。そもそも 400Hz 側は
  ベンチではゲートを見ない）。

**採用しなかった案（②）: ゲート開放後に duty をランプさせる。**
姿勢制御の立ち上がりが遅れ、離陸直後の外乱応答が変わる。
①は操作手順が「アーム後にスロットルを一度下げる」だけで済み、
`sticks_neutral()` が既に同じことを要求しているので一貫性がある。

**観測性**: ゲートが開かない理由を `g_dbg_gate_why` として `#dbg` 行に `gwhy=` で出すようにした。
`0`=開 `1`=warm-up `2`=EKF 残差大 `3`=連続成立待ち **`4`=スロットルを下げれば開く**。
⚠ **LED は理由を区別できない**（どれも赤 5Hz 点滅）。`led_control()` のコメントを
「赤が消えないならセンサ異常」から「まずスロットルを確認、それでも消えないならセンサ異常」に直した。

## 検証結果

- ビルド: `text 686728 → 687168`。**実機未検証。**
- ⚠ 「急回転が止まること」は未確認。次の卓上試験で `gwhy=4` が出ること、
  スロットルを下げた瞬間に `gate=1` になることを確認する。

## 次に触る人へ

- ⚠ **`T_ref` は `rate_control()`（400Hz）でしか更新されず、`rate_control()` は
  `Arm_flag==2` の枝からしか呼ばれない。** よって `Arm_flag==1`（起動直後のバイアス取得中）の
  ゲートはスロットルを見ずに開く。実害は無い（その状態ではモータは止まっており、
  アームには `sticks_neutral()` の低スロットルが要る）が、**この前提が崩れる変更をしないこと。**
- ⚠ **赤点滅が止まらない＝センサ異常、とは限らなくなった。** まず `gwhy` を見ること。
