# v12 の墜落は空力ではなくソルバの発散。`|U_lin|` にだけガードが無かった

- **日付**: 2026-09-11
- **種別**: investigation
- **対象**: `tools/0911_100Hz_v12.csv`, `nmpc.cpp`(admm/U_lin), `nmpc_params.hpp`(admm_lambda_max, tr1_skip_max_run)
- **タグ**: #Benzen_NMPC #飛行実験 #0911_v12 #墜落 #ADMM #U_lin #発散 #box #lambda #ガード #積分作用

## 背景 / 症状

`R_u=800` + 積分トリム（リーク付き）で飛行。ユーザ報告: **「ピクつきは一回しか起きなかったが、
急に姿勢が崩れて墜落した」**。`lambda_reset=41`（v11 は 4）、`pred_nonfinite=23`（v11 は 0）。

⚠ **添付のベンチログ `0911_v12.csv` は 49 列**＝`flight_mode`/`trim_*` を追加する前のファームの出力で、
100Hz ログ（`R_u=800.0` を自己申告）と**同じバイナリではありえない**。
以下は**100Hz ログのみ**に基づく。**実際に書き込んだ uf2 の確認と、ベンチログの取り直しが必要。**

## 原因 / 判断根拠

### 墜落の 1 サンプル刻みの経過（確認済み）

| t | 出来事 |
|---|---|
| 19.61–19.64 | `solver_code=20` が **4 連続** ＝ TR1 の割線更新を連続して捨てている |
| **19.65** | `iter_us=37.7 ms` の**強制フル再構築**（`tr1_skip_max_run` 到達） |
| 19.66 → 19.73 | **`ulin_norm` が 0.06 → 0.65 へ単調増加**（健全時の中央値は 0.12） |
| 19.74 | `ulin_norm` **1.32**、box が有効化、`lam_norm` が 1.86 から成長開始 |
| 19.76 | `lam` 7.6、duty が **0.95 / 0.00** に張り付き始める |
| 19.78–19.83 | `lam` → 28（上限 30 でリセット）、**FR/FL=0.95、RR/RL=0.00** ＝ **フルの機首上げ** |
| | ⚠ このときのピッチ誤差は **+2.5 deg しかない**（θ +10.9 / θ_ref +13.4） |
| 19.84–19.90 | `q` +41 → **+528 → +580 deg/s**、θ +10.9 → +34.5 → +91 deg |
| 20.06 | **φ = −176 deg（背面）**、以後タンブル。`failsafe=4`(rate) |

**2.5 deg の誤差に対してフルレンジの舵が出ている。** これは空力的な姿勢崩れではなく、
**ソルバの解が発散して box の端に張り付いた**結果である。

### 「ピクつき 1 回」も同じ現象だった（確認済み）

`ulin_norm > 0.5` の区間は飛行中 **2 か所だけ**:

| 区間 | 長さ | `ulin` 最大 | 結末 |
|---|---|---|---|
| t=12.09–12.16 | 0.07 s | 2.26 | **回復** |
| **t=19.71–21.48** | 1.77 s | **6.09** | **★そのまま墜落** |

**ユーザが感じた「ピクつき 1 回」が t=12 の回復した発散、墜落が t=19.7 の回復しなかった発散。**
同じ故障が 2 回起き、2 回目が戻ってこなかっただけである。

### ソルバの健全性は直近 2 つの変更で単調に悪化していた（確認済み）

| | `ulin` p99 | `ulin` 最大 | `lam>1` | **`box_n≥4`** | 浮上 |
|---|---|---|---|---|---|
| v6（R620 積分なし） | 0.449 | 0.80 | 0 | **0** | 20.4 s |
| v9（R800 積分なし） | 0.617 | 1.72 | 6 | **0** | 9.2 s |
| v11（R620 積分あり） | 1.085 | 4.08 | 14 | **1** | 20.7 s |
| **v12（R800 積分+リーク）** | **3.469** | **6.09** | **135** | **108** | 20.5 s |

**`box_n≥4`（6 発中 4 発以上が同時に制約に張り付く）が 0 / 0 / 1 → 108 サンプル**と質的に変わった。
`R_u` 単独（v9）でも積分単独（v11）でもここまでにならず、**組み合わせで悪化している。**

**推測（未確認）**: 積分は `X_ref` を「機体が到達できない所」へずらす。到達できない目標を
毎周期与えると、RTI のウォームスタート（`U_lin` 自体が積分器のように振る舞う）が
その方向へ育ち続ける ── **外側の積分器と、ソルバ内部の暗黙の積分器が二重になっている**可能性。

### ⚠ `|U_lin|` にだけガードが無い

- `lambda`: `admm_lambda_max=30` で**リセットされる**（実際 41 回発火）
- 遅れ予測: 発散したら**棄却**される（`pred_nonfinite=23`）
- TR1 の割線更新: 大きすぎたら**捨てる**（`tr1_c_max`）
- **`U_lin`: 何も無い。0.1 → 6.1 まで誰にも止められずに育った。**

`ulin_norm` は既にログに出ている。**見えているのに誰も止めていない**のが今回の本質。

## 対応

**コード未変更。**

## 検証結果

すべて 0911_100Hz_v12.csv から直接（1 サンプル刻みの表と分位点）。
⚠ ベンチログが別ファーム由来のため、**積分トリムが実際に動いていたかは未確認**。
もし動いていなければ「積分が悪化させた」という上の比較はやり直しになる。

## 次に触る人へ

**1. `|U_lin|` のガードを入れる（最優先・これが無いと同じ墜落が再発する）。**
毎周期 `ctx.scratch.U_lin.norm()` を見て、閾値を超えたら**ソルバをリセットする**
（`nmpc_reset_request()` 相当＋ `U_lin` を 0 へ）。閾値の目安は **1.0**:
健全時の p99 が 0.45–0.62、box が効き始めたのが 1.32 なので、その間に置ける。
`lambda` と同じ「異常を検知して畳む」パターンで、**今回の 2 回とも 19.71 / 12.09 の時点で捕まえられた。**
⚠ ただし **0910 の教訓**（再構築の多発が別の害を生む）があるので、リセット回数をカウンタに出し、
頻発するなら閾値ではなく原因を疑うこと。

**2. まず飛べる設定へ戻す。** ソルバが健全だったのは **v6（`R_u=620`、積分なし、`Q_phi=500`/`Q_p=20`）**
── `ulin` 最大 0.80、`lam>1` 0、`box_n≥4` 0。ここを基準に**1 つずつ**足し直す。
v11（積分あり）の時点で既に `ulin` 最大 4.08 と不健全だったので、**積分は「効いた」と同時に
ソルバを痛めていた**可能性が高い。

**3. ⚠ 実際に書き込んだバイナリを確認すること。** 添付のベンチログは 49 列で、
`build_fresh/pico_copter.uf2`（`flight_mode`/`trim_roll` の文字列を含む）とは別物である。
`0911_v12.csv` を取り直して `trim_roll/pitch/yaw` を確認するまで、
**「積分がどう効いていたか」は分からない。**
