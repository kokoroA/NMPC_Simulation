# ベンチ加振モードを変数 1 個の切り替えで実装。姿勢の脱出条件だけ加振中に外す

- **日付**: 2026-09-06
- **種別**: design
- **対象**: `Benzen_NMPC/control.cpp`, `control.hpp`
- **タグ**: #Benzen_NMPC #sysid #ベンチ加振 #Bench_mode #開ループ #フェイルセーフ #minimum_duty #LED #Cr

## 背景

`Cr` の同定にはヨー軸吊り試験が要るが、**NMPC を通さず duty を直接書く手段がファームに無かった**
（調査済み: `Bench_mode` / `excite` / `sysid` 等の実装は 1 件も存在せず、`ESC_calib` は固定値を出すだけ）。
これが無いと [`20260905_damping_unidentifiable_flight_logs.md`](20260905_damping_unidentifiable_flight_logs.md)
で失敗した閉ループ回帰を繰り返すことになる。

## 原因 / 判断根拠

**開ループで duty を直接書けば、飛行ログ回帰の敗因 3 つが同時に消える。**

- **閉ループ共線性** → 加振は姿勢フィードバックを通らない
- **50 Hz チャタリング** → NMPC を通らないので発生しない
  （[`20260904_duty_chatter_50hz_nullspace.md`](20260904_duty_chatter_50hz_nullspace.md)）
- **モータ遅れ未同定** → ステップ応答の立ち上がりから同時に同定できる

**設計判断。切り替えはコンパイル時マクロではなく変数にした（ユーザ指示）。**
`Ftc_target_motor` と同じ流儀で、`control.cpp` の 1 ブロックを書き換えるだけで
モード・`u0`・差動量・向き・各フェーズの秒数を変えられる。既定は `BENCH_OFF`。

**設計判断。加振は「差動」であって「推力増」ではない。** `u_i = u0 + kS[i]*delta` とし、
`Sum kS = 0` なので合計推力が変わらない。ホスト検証で**フェーズ①→②の合計推力変化は −0.10 %**
（推力曲線の非線形分のみ）、`tau_z` は設計式 `6*C_QT*T'(u0)*delta = 0.002607 Nm` と完全一致した。
3 発だけ回す方式だと吊りの張力・傾きが動き、2 グループのロータ動作点が離れて
「どの回転数での係数か」が曖昧になる。

**設計判断。スロットルをデッドマンスイッチにした。** シーケンスは
`T_ref*T_ref_coe >= Flight_duty` になった時刻から始まり、下げると**頭出しに戻る**。
専用の開始ボタンを増やさずに、既存の「スロットルを下げれば止まる」直感をそのまま使える。

**設計判断。姿勢の脱出条件だけ加振中に外す。**
機体を上下逆さに吊るため `|phi|` が 180° 付近になり、`FS_ATTITUDE`（60°）が常時成立してしまう。
**機体は治具で拘束されていて飛び去らない**ので、この 1 項目だけ外す。
**角速度（300 deg/s）・過大 G・受信途絶・スロットル下限は生かしたまま。**

**設計判断。`minimum_duty`(0.1) の持ち上げも加振中は外す。**
これが効くと「フェーズ⓪＝モータ停止のままログ」も `u0` の正確な再現もできない。
FTC の `Motor_eta` ガードと同じ構造で、加振モードは clamp を素通りさせる。

**却下した案**: プロポのスイッチでモードを切り替える。
[`20260901_ftc_mode_and_failsafe.md`](20260901_ftc_mode_and_failsafe.md) でチャンネル番号と
モード値の混同がビルドを壊した前例があり、加振モードは**現場で切り替えたい種類の機能ではない**
（実験条件ごとに焼き直す）。変数のほうが取り違えが起きにくい。

**却下した案**: 100 Hz ログに `Bench_phase` 列を足す。`DATANUM` が変わると既存の解析ツールが壊れ、
記録可能秒数も減る。フェーズは時刻と duty から一意に読めるので不要。
代わりに**ダンプのヘッダに `#bench:` 行**を出して条件を残す。

## 対応

- `control.hpp`: `BENCH_OFF/BENCH_YAW_EXCITE/BENCH_MOTORS_OFF` と各変数の `extern`
- `control.cpp`: 変数ブロック / `bench_excite_update()`（4 フェーズの時刻駆動）/
  `angle_control` の分岐 / 400 Hz 出力の clamp バイパス / `failsafe_check` の姿勢判定除外 /
  LED（**全周ピンク 10 Hz 点滅**。通常飛行との取り違え防止）/ ログヘッダの `#bench:` 行
- 実施要領 [`docs/20260905_yaw_damping_experiment_protocol.md`](../../20260905_yaw_damping_experiment_protocol.md) §9 を実装済みの内容に更新

## 検証結果

- **ビルド成功。** `text 675608 → 676432 (+824)`, `bss 352212 → 352220 (+8)`。
- **`Bench_mode` / `Bench_phase` は `.bss`**（`nm` で `B`）＝ゼロ初期化＝**既定 `BENCH_OFF`**。
- **ホストでシーケンスを再現して検証**（`kS`・推力曲線・時刻分岐を同一式で実装）:
  - フェーズ遷移が設計どおり（`t=2.9→1, 3.0→2, 8.9→2, 9.0→3, 28.9→3, 29.0→4`）
  - `tau_z` はフェーズ①③④で **0**、フェーズ②で **+0.002607 Nm**（設計式と一致）
  - **合計推力の変化 −0.10 %**（差動が純ヨートルクであることの確認）
- **`kS_bench` が `nmpc_model.cpp` の `kS` と一致**することを確認（`{-1,1,1,-1,-1,1}`）。
- `Bench_mode` の参照は 6 箇所すべてが `!= BENCH_OFF` / `== BENCH_OFF` の分岐で、
  **既定値では通常飛行の経路が一切変わらない**ことを確認。
- 改行コード（CRLF）は編集前後で不変。
- **実機での動作確認は未実施。** プロペラ無しでの duty 波形確認から始めること。

## 次に触る人へ
- **`kS_bench`（`control.cpp`）と `kS`（`nmpc_model.cpp`）は別々に定義されている。**
  片方だけ直すとヨーの向きが逆になる。`nmpc_model.cpp` の `kS` は匿名 namespace にあり共有できなかった。
- **加振モード中は姿勢の脱出条件が無効**である。**必ず治具に固定した状態でだけ使うこと。**
  自由飛行で `Bench_mode != BENCH_OFF` のまま飛ばしてはならない。
- 100 Hz ログは **LOG スイッチ**（`Chdata[LOG] > 200`）で回る。加振前に必ず入れる。
- スロットルの下限判定は `angle_control` 側が `Flight_duty`(0.05)、400 Hz 出力側が
  `Disable_duty`(0.1) と食い違っている（既存の仕様）。その間はシーケンスが進むが
  モータは回らない。実害は無いが、波形の頭が欠けたら疑うこと。
