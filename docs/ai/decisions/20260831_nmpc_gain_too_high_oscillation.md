# 0831_v1: モータ振り分け修正で飛行成功。次は逆に「ゲイン過大」で 4Hz 発振

- **日付**: 2026-08-31
- **種別**: investigation | tuning
- **対象**: `Benzen_NMPC/tools/0831_v1.csv`, `nmpc_params.hpp`(cost::R_u, physical::T_max), `nmpc_model.cpp`, `nmpc.cpp`(reset_period)
- **タグ**: #Benzen_NMPC #飛行実験 #発振 #ゲイン #R_u #Q_theta #T_max #モータ遅れ #モータ振り分け #reset_period #10ms

## 背景 / 症状

モータの振り分けを修正して**飛行に成功**。ただし姿勢が崩れる。
このときの重みは `Q_phi=Q_theta=50, Q_p=Q_q=20, Q_r=6, R_u=28`（変更なし）。
併せて `mass 0.356→0.32`, `T_max 2.04→1.04` に変更されていた。

## 原因 / 判断根拠

**確認済み事実（ログ 100 点 / 12.5 s）。**

- **接地中と自由飛行で挙動が完全に分かれる。**
  接地〜低スロットル（t=5.99–9.9, 39 点）: phi rms 0.97°, theta rms 1.14°, p/q rms 4 deg/s、
  duty ばらつき 0.059、**飽和・下限への到達 0 回**。
  自由飛行（t≥9.9, 14 点）: phi rms 16.3°, theta rms 10.6°, p rms 74, q rms 99 deg/s、
  duty ばらつき 0.730、**飽和 19 回・下限 12 回**のバンバン動作。
- **`q` が 1.32 s で 11 回符号反転 → 4.2 Hz 以上の発振**（10 Hz サンプルのため折り返しの可能性あり）。
- `loop_us` は 53 点中 50 点（94 %）が 10 ms 超、平均 11.2 ms。`dt=0.01` 前提と食い違う。
- `cnt_rst_period` が 5 回増加（約 1 秒間隔）。うち t=9.63 のサンプルで
  **`iter_us = 58333 us` / `loop_us = 60497 us`** を観測。10 Hz ログなので当たったのは 1 回だが、5 回とも同じ。
- **`cnt_sr2_c = 0`, `cnt_sr2_llt = 0`** — SR2 の健全性チェックは一度も発火していない。
- 飛行中のホバー付近 `u_base ≈ 0.552–0.584`。同定した推力マップで duty 0.55 の推力は
  0.556 N ×6 = 3.33 N = **340 g**、接線 `dT/du = 0.80`。**`mass=0.32` は妥当、`T_max=1.04` は 30 % 高い。**

**判断。**

- 前回（0831.csv）の「舵が足りない」は解消。今回は**ループゲインが高すぎる側**の問題。
  `T_max` 2.04→1.04 でゲインが約 2 倍になり、さらに振り分け修正で**指令が初めて正しいモータに届いた**。
- 発振周波数 4.2 Hz 以上は、**モデルに入っていないモータ一次遅れ**（τ≈50 ms、コーナー 3.2 Hz）と一致する。
  `nmpc_model.cpp` は剛体のみでアクチュエータ動特性を持たない。
- 接地中は機体が回れないためフィードバックループが閉じず、**離陸するまで発振の兆候が出ない**。

## 対応

解析資料 [`docs/20260831_nmpc_flight_v1_gain_tuning.md`](../../20260831_nmpc_flight_v1_gain_tuning.md) と
図 `Benzen_NMPC/tools/plots/0831_v1_analysis.png` を作成。

**2026-08-31 適用済み（ユーザ承認のうえ）**:

1. `nmpc_params.hpp` `cost::R_u` を **28.0f → 120.0f**。Q 側は一切触っていない（1 回に 1 つだけ変える原則）。
2. `nmpc_params.hpp` `rti::rebuild_max_u_hover = 0.30f` を新設し、`nmpc.cpp` の `period_due` を
   `(u_hover < rebuild_max_u_hover) && (cycles_since_reset >= reset_period)` に変更。
   **周期フル再構築は離陸し得ない低スロットル域でのみ行う。**
   外部要求（着地時の `nmpc_reset_request()`）と SR2 健全性異常による再構築は**制限しない**
   ——これらは正しさに必要で、頻度も低いため。

`reset_period` 自体は 100 のまま（接地中は従来どおり 1 秒ごとに洗い流す）。
`T_max=1.04f` / `mass=0.32f` / 重み Q は**据え置き**。安定を確認してから `T_max` を 0.80 に直す
（ゲインが 1.3 倍になるので `R_u` も併せて上げる前提）。

**却下した案**: `Q_p` / `Q_q`（角速度重み）を上げて減衰を増やす。
角速度フィードバックは最も高い周波数まで効くため、**モータ遅れで位相が回っている 4 Hz 帯のゲインを増やし、
発振を悪化させる**。減衰が欲しければ全体を下げてから角度側で戻す。

**却下した案**: `T_max` を大きいまま残して発振を抑える。
`T_max` は物理量であり減衰ノブではない。**耐故障の再配分がこの値の正しさに依存する**ため、
最終的には同定値に合わせる必要がある。

**却下した案**: `reset_period` を伸ばす。頻度が下がるだけで 58 ms の停止は残り、
たまたま過渡に当たると同じことが起きる。「稀にしか起きないが起きると致命的」は最悪の形。

## 検証結果

**適用した変更の静的検証（実施済み・合格）**

- 実ビルドフラグで `static_assert`: `R_u==120.0f`, `Q_phi==Q_theta==50.0f`,
  `Q_p==Q_q==20.0f`, `Q_r==6.0f`, `reset_period==100`, `rebuild_max_u_hover==0.30f`,
  `T_max==1.04f`, `mass==0.32f` —— **すべて成立**（重みは R_u 以外変わっていない）。
- `nmpc_step` の逆アセンブルで、リテラルプールの `0x3E99999A`(=0.30f) に対する
  `vcmpe.f32` と `cmp r2,#99`(=reset_period 100) の**両方**が生成されていることを確認。
  ゲートは最適化で消えていない。
- ビルド成功。`text 674224 → 674696`（+472 B）、`bss 402456` 変化なし。**メモリ退行なし。**
- 成果物 `build_fresh/pico_copter.uf2`（2026-08-31 18:15）。

**解析そのものの限界**

- 発振の解析はすべて `0831_v1.csv` からの静的解析。**修正後の実機試験は未実施。**
- 発振周波数は 10 Hz サンプルからの推定で、**折り返している可能性がある**。真の周波数は未確定。
- モータ時定数 τ≈50 ms は SIL の `plant.py` の値であり、**実機で測ったものではない**
  （`motor_lag_sysid_analysis.md` 参照）。因果の主張はここに依存している。
- `T_max = 0.80` の飛行データによる裏付けは、ホバー付近 1 点（`u_base≈0.55`）からの推定。

## 次に触る人へ

- **接地中の静けさを「安定している」と読まないこと。** 機体が拘束されているとフィードバックループが
  閉じないので、ゲインが 10 倍でも接地中は静かに見える。**評価は自由飛行でしか成立しない。**
- **発振したときに角速度の重みを上げるのは、アクチュエータ遅れがある系では逆効果になり得る。**
  まず全体のゲインを下げ、必要なら角度側で戻す。
- **重みは 1 回に 1 つだけ変えること。** 今回 `T_max`・`mass`・モータ振り分けの 3 つが同時に変わったため、
  発振の寄与を分離できなかった。
- ⚠ **1 秒ごとの 58 ms 停止を先に潰すこと。** これがあると「重みが悪い」のか「ループが止まった」のかを
  区別できず、以後の調整結果がすべて信用できない。
