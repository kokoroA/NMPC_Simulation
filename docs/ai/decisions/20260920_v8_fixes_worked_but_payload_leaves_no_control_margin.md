- **日付**: 2026-09-20
- **種別**: investigation
- **対象**: `tools/0919_v8.txt`, `nmpc_params.hpp`(Cr, T_max), `nmpc.cpp`(安全弁3, build_hessian), `control.cpp`(ログ3列)
- **タグ**: #Benzen_NMPC #墜落 #飽和 #du_max #貨物 #発振 #PIO #U_lin #フル再構築 #検証

## 背景

`Cr` を **1.0e-4**、`T_max` を **0.750**（提案 0.68 に対しユーザ判断）にして、最初から貨物を載せて飛行。
7 秒ほど安定ホバーののち墜落。`#nmpc_log 100Hz rows=1295 cols=33 written=33`。

## 検証: 前日の修正はすべて効いた（確定）

| Δu が全発ゼロの周期 | 0 / **39** | **5**（ガード由来ではない） |

| 〃 `iter_us` 平均 | 39,258 / 39,317 | **28,299**（最大 31,478） |

- **安全弁 3 は一度も発火していない**（box 相対しきい値＝この動作点で 4.01〜4.4）。
- **ブロック下三角で `iter_us` が 39.3 → 28.3 ms（−28%）。** 演算量比の予想 −43% よりは小さいが実測で確認。
- **`tr1_skip_max_run` 8 で再構築が 1/4 以下に。** `tr1_skip_run` の実測分布
  `{1:48, 2:33, 3:22, 4:15, 5:12, 6:10, 7:6, 8:4}` は継続確率 ≈ 0.70 で、事前の外挿 0.634 と整合。
  **8 に到達したのは 4 回だけ**（旧 cap=5 なら 12+ 回）。
- **`Cr = 1e-4` でヨーの定常誤差が消えた。** v6 の −37 deg/s に対し v8 は平均 −2.3 deg/s。

## 墜落の原因（別物）

### (1) ★貨物ありでは巡航ですら上向き余地を使い切っている★

安定していた区間（t = 3.5–7.3 s）の実測:

| | 値 |
|---|---|
| `u_base` 中央値 | 0.606 |
| **上向き余地 `du_max = 0.95 − u_hover`** | **0.344** |
| `\|Δu\|` p50 / p90 / p99 / 最大 | 0.040 / 0.073 / **0.207** / **0.336** |

⚠ **`|Δu|` の最大 0.336 が余地 0.344 と一致している。安定していた区間で既に上限に触れていた。**

重量別（飛行較正推力曲線 `Tf(u) = 0.8389(−0.2265u² + 1.0525u + 0.0452)`）:

| 重量 | `u_hover` | `du_max` | p99 = 0.207 に対する余裕 |
|---|---|---|---|
| 271 g（最軽量） | 0.516 | 0.434 | 2.10× |
| 285 g（貨物なし） | 0.550 | 0.400 | 1.93× |
| **309.5 g（今回）** | **0.610** | **0.340** | **1.64×** |
| 320 g | 0.637 | 0.313 | 1.51× |

計算した `u_hover = 0.610` は実測 `u_base` 中央値 0.606 と一致する。
⚠ **貨物 24.5 g で上向き余地が 0.400 → 0.340（−15%）。** 「通常飛行時は安定していた」という報告と整合する。

### (2) 引き金: 操縦入力＋ピッチ外乱で FR が上限に張り付いた

| t [s] | 事象 |
|---|---|
| 7.31–7.58 | 操縦者が `phi_ref` を 0 → **−7.7°**。⚠ しかし `phi` は **+2.7°** と逆方向。同時に `theta` が指令なしで 0 → **−4.8°** |
| **7.59–7.65** | ⚠ **FR が 0.95 に張り付き（`box_n`=1）、`\|Δu\| = 0.306` = `du_max` ちょうど。6 周期連続。この区間の飽和率 46%** |
| **7.68** | ⚠ **フル再構築（31.5 ms）がここに落ちた。** 解が不連続にジャンプ（FR 0.95→0.67、MR 0.60→0.80、`p` 15→36） |
| 7.70–8.50 | **半周期 0.2–0.3 s の発振が振幅を倍々で拡大**（`\|p\|` 53 → 96 → 166 → 306 deg/s）。操縦者の `phi_ref`/`theta_ref` も ±13〜20° で振れており **PIO が重畳** |
| **8.54** | `q` が −371 → `FS_RATE`（360 deg/s）ラッチ → `motor_stop()` |
| 8.57–8.77 | `acc_norm` 4.0 → 0.3 = **自由落下**（モータは止まっている。ログの duty は指令値で PWM ではない） |
| 8.82 | `acc_norm` 62.9 = 接地 |

発散中の飽和率は **62%**。

### (3) ⚠ 7.68 の再構築の原因は特定できない

直前の `cycles_since_reset = 95→96`（周期 100 に未達）、`tr1_skip_run = 1`（cap 8 に未達）。
→ 残るのは `SR2_UNHEALTHY`（LLT 不健全）か `SR2_BAD_C` の NaN 経路だが、
⚠ **`reset_cause` は 10Hz ベンチログにしか無く、100Hz ログに出ていないので決定できない。**

## 対応（提案・未実装）

**この墜落はソルバの問題ではなく、推力余裕の問題。** 優先順:

1. **貨物を軽くする**、または**貨物ありでは上昇しない**（`u_base` 0.644 は巡航 0.606 より高く、上昇中は余地がさらに減る）。
2. ⚠ **貨物ありで大舵を打たない。** 巡航の p99 が既に余地の 60%。
3. **`reset_cause` を 100Hz ログの 34 列目に足す**（リング 19.8 → 19.2 s）。(3) が決定できるようになる。
4. 構造的対策（大きい）: **飽和時に共通モード `u_hover` を一時的に下げる**（高度を犠牲にして姿勢の権限を確保する）。
   現状 box は `[−u_hover, 0.95−u_hover]` 固定で、上が足りなくても下げる仕組みが無い。

**採用しない案**: `U_duty_max` を 0.95 → 1.0 に上げる。余地は 0.340 → 0.390 になるが、
ESC/モータの保護margin を削るうえ、推力曲線の上端は傾きが寝ている（`dT/du` が 0.62 まで低下）ので
見かけほど権限は増えない。

## 検証結果

すべて `0919_v8.txt` から算出。⚠ **対策は未実装、実機未検証。**
⚠ 発振周波数は窓が 0.8 s しかなく FFT の分解能が 1.25 Hz なので、
**「半周期 0.2–0.3 s」以上の精度では言えない**（過去の 3–4 Hz モードと同系か要確認）。
