# 投下後の墜落は「|U_lin| ガードが 5 周期ごとに Δu を 0 にした」こと。フル再構築は 90% が SR2 起因で飛行時間の 11% を食っていた

- **日付**: 2026-09-19
- **種別**: bugfix | investigation
- **対象**: `Benzen_NMPC/nmpc.cpp`(admm_solve の安全弁3, tr1_skip_max_run), `nmpc_params.hpp`(rti::ulin_max), `tools/0919_v5.txt` `0919_v6.txt`(=v7)
- **タグ**: #Benzen_NMPC #墜落 #U_lin #安全弁3 #ulin_max #フル再構築 #SR2 #TR1 #FS_RATE #貨物投下 #ヨー発散

## 背景 / 症状

ユーザー報告:

> 物資ありで飛行し、物資投下して墜落しました。物資投下の際は安定していましたが、
> その後姿勢が不安定になり墜落しました。

`0919_v5.txt`（飛べた便, 20.4 s）と `0919_v6.txt` = `0919_v7.txt`（墜落便, 16.4 s）。
時間軸は `loop_us` の累積で再構成した（`t` 列は行番号×0.01 で実時間ではない）。

## 原因 / 判断根拠（すべてログから確定）

### タイムライン（v6）

| t [s] | 事象 |
|---|---|
| 〜14.6 | 安定。\|φ\|,\|θ\| ≤ 4°、\|Δu\| ≈ 0.05。⚠ ただし **r ≈ −37 deg/s の定常ヨー誤差**が既にある |
| 14.55 / **14.68** / **14.81** | ⚠ **フル再構築が 3 連発**（0.13 s 間隔、各 39 ms） |
| 〜14.7 | **投下**と推定。`u_base` 0.587 → 0.512（操縦者がスロットルを絞った）、`acc_norm` 9.8 → 7.9 |
| 14.89 | \|Δu\| が 0.05 → 0.14 へ。ヨーが伸び始める（r −37 → −55） |
| 15.06 | FR が duty 上限 0.95 に張り付く（`box_n` = 1） |
| **15.07** | ⚠ **\|U_lin\| ガード初発。6 発すべて `u_base` と完全一致 = Δu が全発ゼロ** |
| 15.07〜15.72 | ⚠ **ガードが 5 周期ごとに発火（10 回）。** r −127 → −620 deg/s、θ 5.6° → 52.5° |
| **15.74** | `FS_RATE`（failsafe=4）ラッチ → `motor_stop()` |
| 15.79 | `acc_norm` 107 m/s² = 接地 |

**投下から墜落まで 1.1 秒。**

### (1) 直接の死因は `FS_RATE` のラッチ（確定）

`failsafe` 列が t=15.74 から 315 行連続で **4**。`FS_RATE_LIMIT = 360 deg/s` に対し
実測 \|q\|max = 1264、\|p\|max = 617、\|r\|max = 645 deg/s。
ラッチすると `Arm_flag` は 2 のままモータだけ止まる（＝ログは残る）。

### (2) ⚠ 発散を作ったのは `|U_lin|` ガードが**その周期の出力ごと捨てている**こと（確定）

`nmpc_step()` の出力は `U_opt(j) = clamp(ctx.ws.z(j))`。
安全弁 3 は `admm_solve()` の**末尾**で `warm_start_reset_to_ref()` を呼び、健全時は `U_ref = 0` なので
**`ws.z` が 0 になる。その値がそのまま duty に出る。**

ログでは発火周期に **6 発すべてが `u_base` と完全一致（\|Δu\| = 0.000）**。
前後の周期は \|Δu\| = 0.40（box 上限 0.403）。
**つまり「フルに効かせている周期」と「まったく効かせない周期」が 4:1 で交互に並んでいた。**

⚠ **ガードの目的は線形化点を戻すことであって、その周期の制御出力を捨てることではない。**
0915 の案 A（フル再構築を要求しない）で 39 ms のストールは消したが、
**Δu を 0 にする副作用は残っていた。**

### (3) ⚠ `ulin_max = 1.0` は正常な大操作でも超える（確定）

`|U_lin|` は NU_TOTAL = 84 要素のスタックノルム。box は \|Δu\| ≤ `0.95 − u_hover` = 0.403 なので、

```
物理的に到達しうる |U_lin| = sqrt(84) × 0.403 = 3.69
ulin_max = 1.0 は そのわずか 27%
```

| | p50 | p95 | max |
|---|---|---|---|
| v5（飛べた・穏やか） | 0.11 | 0.26 | 1.15 |
| **v6（墜落）** | 0.08 | 0.51 | **2.66** |

**v5 は一度も Δu ゼロ周期が無く、v6 は 10 回（最後の 0.65 s）。**
⚠ **数値暴走ではなく「機体が本当に大きな操作を必要とした」ことで発火している。**
一番権限が要る瞬間に制御を 20% 間引いていた。

### (4) ヨーを捨ててピッチを取った（確定）

参照はほぼ中立（`psi_ref` 最大 +7.9 deg/s、`phi_ref` −6.1〜+0.3°）なのに r は −395 deg/s まで走った。
t=15.18 の duty から各軸の寄与を計算すると、
`q̇ ∝ −0.053`（θ = +14.8° を戻す向き・正しい）に対し `ṙ ∝ −0.039`（**r = −201 をさらに負へ**）。
`Q_theta = 1000` に対し `Q_r = 40` なので、**ヨーは 25 分の 1 の値段で捨てられる。**
投下直後のピッチ過渡に権限を全部使い、ヨーが野放しになった。

### (5) フル再構築は「遅い」以前に「多すぎる」（確定・重要）

| | v5 | v6 |
|---|---|---|
| フル再構築 | **58 回 / 20.4 s** | **43 回 / 16.4 s** |
| 1 回あたり `iter_us` | 39,258 | 39,317 |
| そのときの `loop_us` | 41,871（最大 44,766） | 41,967（最大 45,052） |
| **飛行時間に占める割合** | **11.2 %** | **10.3 %** |
| うち周期起動（直前の `cycles_since_reset` ≥ 95） | **5 回** | **4 回** |
| ⚠ **SR2/TR1 起因** | **53 回 (91 %)** | **39 回 (91 %)** |

`reset_period = 100`（1 秒ごと）の設計に対し、実際は **約 0.3 秒ごと**。
`tr1_skip_max_run = 5`（TR1 を 5 周期連続で捨てたら強制再構築）が主因で、
path=2（TR1 skip）は v5 で 477/2176 = 22 %、v6 で 279/1927 = 14 % ある。

⚠ **2026-09-10 の修正（`tr1_c_max` で捨てる）でホスト再現は 5.06 回/秒 → 1.14 回/秒になったが、
実機では 2.6〜2.8 回/秒に留まっている。ホストが実機を再現できていない。**

## 対応

**このセッションではコード変更なし（分析のみ）。** 優先順に:

1. ⚠ **`|U_lin|` ガード発火時に duty をゼロにしない。** 線形化点のリセットと出力を分離する。
   ・`U_opt` は**前周期の解を保持**するか、リセット前の `ws.z` を使う。
   ・`ulin_max` を box から決める（例 `0.5 × sqrt(NU_TOTAL) × (U_duty_max − u_hover)`）。
   **今回の直接の死因なので最優先。**
2. **SR2/TR1 起因の再構築を減らす。** 91 % がこれ。`tr1_skip_max_run` を上げるだけでは
   0910 で却下された「27 周期連続スタール」に戻るので、`|c|` の分布を実機ログから取り直して
   `tr1_c_max` の妥当性から見直す。
3. **`build_hessian_from_su_w()` でブロック下三角を使う**（249,900 → 92,925 MAC、**−63 %**。
   `Su` の上側は厳密にゼロなので**結果はビット単位で同一**）。全体で 38.5 ms → 約 22 ms 見込み。
4. ヨーの重み `Q_r = 40` の見直し、または**ヨー率にフェイルセーフより手前の飽和**を入れる。

**採用しない案**（過去に却下済み。蒸し返さないこと）:
- `tr1_c_max` を上げる → 0909 の線形化点発散を再び開く。
- `rebuild_max_u_hover` で飛行中の再構築を禁止 → `20260831_rebuild_gate_reverted.md`。

## 検証結果

- タイムライン・回数・割合はすべて 2 便のログから算出。**実機での対策検証は未実施。**
- ⚠ 投下時刻は `u_base` と `acc_norm` からの**推定**。SERVO ch は 100 Hz ログに無く、
  `#dbg` ストリームは USB 接続後（着陸後）しか記録されていないため確認できない。
- ⚠ 投下前から r ≈ −37 deg/s の定常ヨー誤差があった理由は**未特定**。
