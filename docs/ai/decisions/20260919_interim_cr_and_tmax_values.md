# `Cr` は暫定 1.0e-4 で飛ばす。`T_max` は 0.7052 ではなく **0.68**（動作点での傾き）。ただし効果は −4.5% と小さい

- **日付**: 2026-09-19
- **種別**: tuning | investigation
- **対象**: `Benzen_NMPC/nmpc_params.hpp`(physical::Cr, physical::T_max)
- **タグ**: #Benzen_NMPC #Cr #T_max #ヨー減衰 #ループゲイン #推力曲線 #暫定値

## 背景

`Cr` 同定実験がしばらくできない。それまで何の値で飛ばすか。
あわせて `T_max` を飛行較正値 0.7052 に直すべきかの判定。

## `Cr`: 推奨 **1.0e-4**

### ⚠ 範囲内のどれを選ぶかはほぼ影響しない。外れ値なのは現行の 0.005 だけ

減衰は 2 乗則 `−Cr·r·|r|`。140 ms（N=14×dt）のホライズンで
「r がどこまで自己減衰するとモデルが信じるか」:

| `Cr` | r₀=50 | r₀=100 | r₀=200 | r₀=300 [deg/s] |
|---|---|---|---|---|
| **0.005（現行）** | 41.5 | **71.1** | **110.2** | **135.0** |
| 3.7e-4（実測上限） | 49.3 | 97.1 | 188.6 | 275.1 |
| **1.0e-4（推奨）** | 49.8 | 99.2 | 196.8 | 292.8 |
| 9.5e-5（実測下限） | 49.8 | 99.2 | 197.0 | 293.2 |

⚠ **実測範囲の両端（9.5e-5 と 3.7e-4、3.9 倍差）の予測差は r₀=200 で 188.6 vs 197.0 = 4%。**
一方 0.005 は同じ条件で 110.2 — **「ホライズン内にヨーが半減する」と信じている。**
これが v6 で `psi_ref` がほぼ中立のまま r が −395 deg/s まで走った理由の一つ。

### 1.0e-4 を選ぶ理由

1. 実測範囲内で**低め＝保守側**。「ヨーは勝手に止まらない」と予測するので手当てが早くなる。
   過大側に外すと v6 の再現になる。
2. ⚠ **ファームの `Relax_x_eq` / `Relax_u_eq` が既に `Cr = 1.0e-4` 前提**（`control.cpp:161` のコメント）。
   同じ値にしておけば relaxed hover を有効化したときに整合が取れる。

### ⚠ リスク

ヨー指令が増える（r=200 deg/s で予測誤差が 1.8 倍になるぶん）。
ヨーは `C_QT = 0.0296` でトルク/duty が小さいので、同じトルクを出すのに duty を多く食う。
**初回はホバーで `r` の追従と duty の広がりを確認すること。**

## `T_max`: 0.7052 ではなく **0.68**。ただし効果は小さい

### ⚠ 0.7052 は数値の取り違え

飛行較正推力曲線 `Tf(u) = 0.8389·(−0.2265u² + 1.0525u + 0.0452)`:

- `Tf(0.95) = 0.7052 N` ← これは **duty 0.95 での推力**
- `Tf(1.00) = 0.7308 N` ← モデルの `T_max`（= duty 1.0 の推力）の定義に合うのはこちら

### ⚠ さらに、姿勢制御が見るのは「動作点での傾き」

モデルは線形 `T = T_max·u` だが、姿勢制御が扱うのは `u_hover` まわりの **Δu** だけ。
効くのは `dT/du` である。

| `u_hover` | `dT/du` [N/duty] |
|---|---|
| 0.516（271 g ホバー） | 0.687 |
| 0.550 | 0.674 |
| 0.600 | 0.655 |
| 0.644（0919_v6 の最大） | 0.638 |

→ **`T_max = 0.68` が妥当**（0.81 に対し −16%）。

### 効果は予想よりずっと小さい（−4.5%）

ロール 5° 偏差に対する初手 `Δu` と、真の効き `dT/du = 0.674` で実際に出る角加速度:

| `T_max`(model) | Δu₀ | 実効 | ループゲイン比 |
|---|---|---|---|
| **0.8100（現行）** | −0.05377 | −115.4 deg/s² | **100.0%** |
| 0.7309 | −0.05240 | −112.4 | 97.5% |
| 0.7052 | −0.05190 | −111.3 | 96.5% |
| **0.6800（推奨）** | −0.05137 | −110.2 | **95.5%** |

⚠ **`T_max` を 16% 下げてもループゲインは 4.5% しか下がらない。**
`SuᵀQSu` の対角が平均 284 に対し `R_u = 620` で **R が支配的**なので `u ∝ T_max` だが、
両者が同程度の大きさなので感度が鈍っている。
**「R_u=620 は T_max=0.81 で調整済みだから触ると危険」という心配は当たらない。**

ゲインを厳密に保ちたいなら `R_u` 620 → **約 575**（560 で 102.0%、620 で 95.5%）。

### 変える価値はどこにあるか

ループゲインではなく**予測の正直さ**。現状モデルは制御権限を 16% 過大に見ているので、
**box に張り付く場面で「もっと出せる」と誤解する。** v6 のような飽和局面の予測が改善する。
FTC / relaxed hover の成立判定も `T_max` を直接使う。

## 対応（提案・未実装）

1. **`Cr` 0.005 → 1.0e-4**（必須。効果が桁違いで方向も明確）
2. **`T_max` 0.81 → 0.68**（推奨。⚠ **0.7052 ではない**）
3. `R_u` は触らない。触るなら T_max と同時に 575。

⚠ **厳密に切り分けたいなら `Cr` だけ先に飛ばす。** 2 つ同時でも
**`Cr` はヨーだけ・`T_max` は 3 軸均等**なので、ログ（`r` の追従 vs `phi/theta` の追従）で分離はできる。

## 検証結果

- 推力曲線・傾き・ホライズン予測・ループゲインはすべてホスト計算。**実機未検証。**
- ループゲインは**単軸（ロール）の凝縮 MPC を Python で再現**して求めた近似。
  実機は 6 入力 3 軸連成なので絶対値はずれるが、`T_max` に対する**感度の桁**は変わらない。
- ⚠ `Cr` の実測 9.5e-5〜3.7e-4 は**糸長を揃えない吊り実験**由来で、4 倍のばらつきがある
  （`20260914_yaw_v3v4_cqt_measured_but_cr_blocked_by_residual_torque.md`）。**同定は依然必要。**
