# Q_p を下げる提案は誤り。正弦掃引で測ったため「静的誤差ではゲインが増える」ことを見落とした

- **日付**: 2026-09-10
- **種別**: bugfix | rejected | investigation
- **対象**: `nmpc_params.hpp`(cost::Q_p, Q_q)、`0910_v2.csv`, `0910_100Hz_v2.csv`、姿勢推定(EKF)
- **タグ**: #Benzen_NMPC #Q_p #ゲイン #測定方法 #EKF #姿勢推定ドリフト #離陸失敗 #4Hz

## 背景 / 症状

前日の記録 [`20260910_residual_4hz_mode_is_the_real_blocker.md`](20260910_residual_4hz_mode_is_the_real_blocker.md)
で「4 Hz 発振の緩和として `Q_p=Q_q` を 20 → 1」を推奨した。実際に焼いた結果、
**追従が弱く感じられ、離陸すらしなかった**。2 回試して 2 回とも失敗。

## 原因 1: 推奨そのものが誤り。ゲインは下がっていなかった

**確認済み事実。**

前回の根拠はホスト周波数応答だった。しかしその測定は `phi` と `p` を**整合させて**
（`phi = A sin(wt)`, `p = A w cos(wt)`）駆動していた。角速度項が常に角度項と一緒に効くため、
低周波では角度項が支配して「追従ゲインはほぼ不変」に見えていた。

**「角度誤差はあるが角速度はゼロ」という状況を一度も測っていなかった。**
その状況では角速度項が対抗しないので、指令はむしろ増える。ホスト実測（姿勢誤差 8.6 deg, rate=0）:

| `Q_p=Q_q` | 実効 \|Δu\| | 20 に対する比 |
|---|---|---|
| **20** | **0.01643** | 1.00 |
| 10 | 0.02103 | 1.28 |
| 5 | 0.02543 | 1.55 |
| **1** | **0.03173** | **1.93** |

**`Q_p` を 20 → 1 にしたのはゲインを 1.93 倍にする変更だった。** 飛べていた 0904_v5 相当の
実効ゲインは 0.0166 なので、それに対しても約 1.9 倍である。

飛行データでも裏付けられる（姿勢誤差 1 deg あたりの指令トルク、|error| 2-10 deg・|rate|<30 deg/s）:

| ログ | roll | pitch |
|---|---|---|
| 0904_v5（飛べた、旧 R_u=120 Q_p=20） | 0.00050 | 0.00037 |
| 0909_v2（R_u=320 Q_p=20 逆算 c） | 0.00109 | 0.00103 |
| 0910_v1（R_u=320 Q_p=20 直接 c） | 0.00078 | -0.00027 |
| **0910_v2（R_u=320 Q_p=1）** | **0.00134** | **0.00187** |

**追従は弱くなっていない。飛べていた設定の 2.7〜5 倍強い。**
パイロットが感じた「追従が弱い」は、後述の偽の姿勢誤差を機体が保持し続けたためで、
指令が小さかったからではない。

## 原因 2: 2 回目は姿勢推定が壊れていた（こちらが離陸失敗の直接原因）

**確認済み事実。**

2 回目（t=17.9-21.0）で、記録された姿勢が**ジャイロと無関係に直線的にドリフトした**。

```
t=18.00  phi   0.00  theta  0.00   p  0.5  q -0.2
t=19.20  phi  -8.72  theta 11.20   p -0.4  q  0.3
t=20.24  phi -16.05  theta 18.98   p  0.9  q -2.9
```

区間全体で `dphi = -14.1 deg`、`dtheta = +17.5 deg` に対し
**ジャイロ積分は `∫p = +0.6 deg`, `∫q = +0.0 deg`**。角速度はほぼゼロなのに姿勢角だけが
毎秒 7-8 度で動いている。

全ログでドリフト率（角度変化 − ジャイロ積分）を測ると、この区間だけが桁違いである。

| ログ / 区間 | drift_phi | drift_theta |
|---|---|---|
| 0904_100Hz_v2 / v3 / v4 / v5 | -0.70 〜 +0.89 | -1.05 〜 +1.01 |
| 0909_100Hz_v2 | +0.69 | +0.34 |
| 0910_100Hz_v1（2 区間） | -0.06, +0.35 | +0.32, -0.50 |
| 0910_100Hz_v2 1 回目 | -0.06 | +0.70 |
| **0910_100Hz_v2 2 回目** | **-13.83** | **+6.83** |

単位 deg/s。他の全飛行が 1.05 以下なのに対し 13 倍以上。

記録されている `phi`/`p` は `control.cpp:2030-2034` で
`Phi - Phi_bias` / `Wp - Pbias`、つまり **NMPC が `x0` として受け取る値そのもの**である。
したがって **NMPC は本当に「19 度傾いているのに角速度ゼロ」という状態を見ていた。**

`p_rate = Wp - Pbias` の `Pbias` は起動時静止平均（`control.cpp:652`）だが、
EKF は自前のバイアス状態 `Xe(4..6)` / `Beta` を持つ（`control.cpp:2869`）。
**EKF のバイアス推定が 7-8 deg/s ずれると、姿勢出力だけが積分誤差でランプし、
ログの `p` は静止平均基準なのでゼロのまま**という、観測された通りの症状になる。

結果として NMPC は成長する偽の誤差に対して正しく大きな修正を出し、
離陸しようとする瞬間に duty が大きく非対称になった（`t=20.24` で
`FR 0.404 / FL 0.503 / MR 0.462 / ML 0.614 / RR 0.574 / RL 0.673`）。**水平に浮けない。**
`Q_p=1` によるゲイン 1.93 倍がこの非対称をさらに拡大した。

1 回目（t=9.0-14.9）はドリフト -0.06/+0.70 deg/s と正常で、`u_base=0.577` まで上げた直後に
`p = -20 deg/s` 前後のロール逸脱で破綻した。3-6 Hz 成分は 1.1% しかなく、
**4 Hz 発振モードではない**。静的ゲイン 1.93 倍と整合する挙動である。

## 判断: ADMM 周りの修正は今回も原因ではない

| 指標（0910_v2） | 値 |
|---|---|
| `lambda_reset` / `nonfinite` | **0 / 0** |
| `loop_us` 平均 / 10 ms 超過率 | 9.61 ms / 1.6% |
| 姿勢誤差 1 deg あたりの指令 | 飛べていた設定の 2.7〜5 倍 |

ソルバは静かで、速く、指令も強い。今回の失敗は
**(1) 私の `Q_p` 推奨（実質ゲイン 1.93 倍）と (2) EKF バイアス推定の発散**である。

## 対応

- `Q_p/Q_q` は飛べていた **20** に戻すべき。**本記録の時点でユーザが 10 へ編集中のため、
  こちらでは上書きしていない。** 10 は 20 比 1.28 倍のゲインである。
- ⚠ **ゲインを触るときは「正弦掃引」だけでなく「静的誤差（rate=0）での実効 \|Δu\|」も必ず測る。**
  この 2 つは別物で、片方だけ見ると符号を取り違える。
- EKF バイアス発散の可視化と検知を追加する（未実装の提案）:
  1. `Xe(4..6)` / `Beta` をテレメトリへ出す。今は EKF のバイアス推定値が一切見えない。
  2. `attitude_state_sane()` を強化する。現状は絶対値（`|phi| < 2π`, `|rate| < 40 rad/s`）しか
     見ておらず、7 deg/s のドリフトは通過する。**`d(Phi)/dt` と `Wp - Pbias` の差**を数秒窓で
     監視し、閾値（例えば 3 deg/s）を超えたら EKF 再初期化する方が直接的。

## 検証結果

- 全 100 Hz ログでドリフト率と「誤差 1 deg あたりの指令」を再計算し、上表を得た。
- 静的ゲインは実機と同一ソースをホストでビルドして測定（`gain.cpp`、8.6 deg 固定・rate 0、
  150 周期助走後 50 周期平均）。
- **EKF バイアス発散の原因は未特定。** 振動が加速度計を汚した結果という推測はあるが未確認。
  1 回目は正常で 2 回目だけ壊れているため、再現条件も不明。

## 次に触る人へ

- ⚠ **姿勢角がジャイロと整合しているかを、毎フライトの最初にチェックすること。**
  `(phi[-1]-phi[0]) - Σp·dt` が数 deg/s 以上なら、その飛行のログで制御を論じても意味がない。
- ⚠ この一件で「ソルバ修正が悪い」と 3 回連続で疑われている。毎回、指標（`lambda_reset`,
  `nonfinite`, `loop_us`, ラグ 1 自己相関, 誤差あたりの指令）は改善している。
  **症状が変わり続けるのは、別々の不具合が順番に露出しているため。**
- 4 Hz 発振モード自体は未解決のまま残っている（[`20260910_residual_4hz_mode_is_the_real_blocker.md`](20260910_residual_4hz_mode_is_the_real_blocker.md)）。
  `Q_p` はその対策にならない。根治はモータ一次遅れの予測モデル化。
