# 0909_v1 の墜落はロール逸脱。モータ固着は NaN が duty を 0.1 に固定していた。T_max=0.81 は未反映

- **日付**: 2026-09-09
- **種別**: investigation | bugfix
- **対象**: `0909_v1.csv`, `0909_v2.csv`, `0904_100Hz_v5.csv`, `control.cpp`(NaN ガード), `nmpc_params.hpp`(T_max)
- **タグ**: #Benzen_NMPC #墜落 #ロール逸脱 #NaN #モータ固着 #minimum_duty #T_max #T_ref_coe #チャタリング #ヨー過剰応答 #GEMFAN

## 背景 / 症状

F1404 + GEMFAN-3630-3、`T_ref_coe` を 0.6 → 0.85 に上げた構成での飛行。
ユーザの体感は「ロールは良好、ピッチはゲインが高い、1 回目はピッチ暴走で墜落」。
**墜落後に disarm しても、スロットルを上げてもモータが一定回転にしかならず、
バッテリの抜き差しでのみ復帰した。**

## 原因 / 判断根拠

**確認済み事実。墜落はピッチではなくロールの逸脱。**

`t = 40.84–41.53 s` で **`phi_ref` は 0.1〜1.0° しか出ていない**のに、
`phi` は +11.3 → **+139.7°** へ単調に走った。同区間の `theta` は **−23.8° までで収まっている**。
`p` は 246 deg/s に達し以後 170 deg/s で回り続けた＝**横転**。
`failsafe = 3`（姿勢 60° 超）は `t=41.23 s`、実測 74° で**正しく発火**している。
発火が遅いのではなく、**60° に達した時点で既に 170 deg/s の角速度が付いていた。**

**確認済み事実。破綻の前から出力が全振幅でバタついていた。**

`t=40.84` FR 0.950 → `41.01` **0.000** → `41.12` 0.950 のように、
連続サンプルで **0.000 と 0.950 を往復**している。既知の 50 Hz 毎周期反転チャタリング
（[`20260904_duty_chatter_50hz_nullspace.md`](20260904_duty_chatter_50hz_nullspace.md)）が
**飽和限界まで振幅を伸ばした**状態。100 Hz ログでも**変動の 72 %** が反転成分
（反転 rms 0.0832 / 滑らか 0.0522、ラグ1 自己相関 −0.66〜−0.39）。
**モータは 50 Hz を追えないので実効操作量が失われ、その状態で姿勢が崩れた。**

**確認済み事実。モータ固着の正体は NaN。**

`t=41.68 s` から duty が NaN になり、以降 26 点すべて NaN。
[`control.cpp:1579`](../../program/pico/pico-sdk2/pico-sdk/Benzen_NMPC/control.cpp) の NaN ガードは
`*duties[i] = minimum_duty`（= `Disable_duty` = **0.1**）に置き換える。
**その結果、全 6 発が duty 0.1 に固定され、スロットルに関係なく一定回転になる。**

**disarm で直らない理由**: 墜落直後に姿勢推定が発散している
（`phi = -336.6, -333.7, -329.6 deg`）。**姿勢推定が壊れたまま**なので再アームしても
`x0` が異常 → NMPC が NaN → 同じ状態に戻る。電源を抜くと EKF が初期化されるので直る。
**`control.cpp` に `isnan`/`isfinite` の使用は 0 箇所**で、姿勢推定にもソルバ状態にも復帰手段が無い。

**確認済み事実。この飛行は `T_max = 0.81` で飛んでいない。**

100 Hz ログのヘッダは **`T_max = 1.040` / `mass = 0.335`**。
現在の `nmpc_params.hpp` は `T_max = 0.81f` / `mass = 0.335f`。
**`mass` は一致し `T_max` だけ食い違う**ので、ソースは編集済みだが**この飛行のファームには未反映**。
`B_c ∝ T_max` なので、次に焼くと**全軸のループゲインが 1.28 倍**になる。

**確認済み事実。軸ごとに別のモードで暴れている。**

| 軸 | 振幅比 | 遅れ | 角速度 rms | 主帯域 |
|---|---|---|---|---|
| roll | 0.704 | 260 ms | 19.60 deg/s | **3–6 Hz が 34.8 %** |
| pitch | **1.061** | 400 ms | **26.46 deg/s** | **1–3 Hz が 55.7 %** |
| yaw | **1.415** | — | 19.64 deg/s | 0–1 Hz が 81.0 % |

**ロールは既知の 4 Hz モータ遅れモード、ピッチはそれより遅い 1–3 Hz の別モード。**
単純なゲイン過大ならロールと同じ帯域に出るはずで、そうなっていない。

**ヨーの過剰応答が悪化している**（v4 1.074 → v11 1.152 → **今回 1.415**）。
一方で**ヨーは Δu の 47.8 % を消費しているのに、実際の差動は最大値の 1.7 % しか使っていない。**
ピッチが Δu の 11.1 % しか使えていないのはこの取り合いの結果でもある。

**確認済み事実。`T_ref_coe = 0.85` でスロットル分解能が半減した。**
`u_base = 3.145 × スティック割合`（0.95 頭打ち）なので、
**ホバー（スティック 20 %）から全開（30 %）まで travel の 10 % しかない**（0.6 のときは 16 %）。
張り付き自体は稀（v1 で 0.7 %）だが、**墜落の最終局面で `u_base = 0.950` に達しており、
その瞬間 Δu の上側余裕がゼロ＝姿勢制御の権限が消えていた。**

## 対応

**コード・パラメータ変更なし（解析のみ）。** 資料
[`docs/20260909_flight_v1_v2_analysis.md`](../../20260909_flight_v1_v2_analysis.md)、
図 `Benzen_NMPC/tools/plots/0909_v1_v2_analysis.png`。

**却下した案**: 体感どおり `Q_theta` を下げてピッチのゲインを落とす。
ピッチの主峰は 1–3 Hz でロールの 4 Hz とは別モードであり、
**何が振れているのかを特定する前に重みを動かすと、原因を切り分けられなくなる。**

**却下した案**: `T_max = 0.81` を焼いてから次を飛ばす。
ピッチが発振気味・ヨーが 1.4 倍の過剰応答である状態で全軸 1.28 倍にするのは
[`20260831_nmpc_gain_too_high_oscillation.md`](20260831_nmpc_gain_too_high_oscillation.md) の再現になる。
下げるなら `R_u` か `Q` と対で調整する。

## 検証結果

- `0909_v2.csv` と `0904_100Hz_v5.csv` が**同一飛行**であることを確認
  （`seq = 100*t + 2359`、平均 `|Δphi|+|Δtheta| = 0.0002 deg`）。
- `T_ref_coe = 0.8500` を 3 本すべてのログから独立に確認。
- フェイルセーフの推移: `t=15.59` に `4`（角速度）→ `16.21` 解除、`t=41.23` に `3`（姿勢）→ `42.06` 解除。
  **再アームで解除できており、先日の解除バグ修正が実機で機能している。**
- 飽和率（100 Hz）7.0 %。`loop` 平均 8.89 ms、10 ms 超過 1.1 %、最大 38.57 ms。
- **チャタリングの原因は依然未特定。NaN 復帰手段も未実装。**

## 次に触る人へ

- **「ピッチ暴走で墜落した」という体感を鵜呑みにしない。** 本件は `phi_ref ≈ 0` のまま
  ロールが 140° まで走った**ロール逸脱**で、ピッチは −24° に収まっていた。
  体感が指していたのは、その前の区間のピッチ 1–3 Hz 振動だった可能性が高い。
- **NaN ガードが「安全側」に見えて実は固着を作る。** `NaN → minimum_duty` は
  出力を 0 にせず 0.1 で回し続けるので、**再アームでも電源を切るまで直らない。**
  最低限、姿勢推定の発散検知と再アーム時の EKF 初期化を入れること。
- **ログヘッダのパラメータと手元のソースを必ず突き合わせる。** 今回 `T_max` だけ未反映だった。
  `mass` が一致していたので「焼いてある」と誤解しやすい。
