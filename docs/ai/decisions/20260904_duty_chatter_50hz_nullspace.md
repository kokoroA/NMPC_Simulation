# 指令 duty の 91 % が 50 Hz の毎周期反転で、その 94 % は姿勢に効かない方向だった

- **日付**: 2026-09-04
- **種別**: investigation | bugfix
- **対象**: `Benzen_NMPC/tools/0904_100Hz_v4.csv`, `nmpc.cpp`(admm_solve), `nmpc_params.hpp`(R_u, admm_max_iter)
- **タグ**: #Benzen_NMPC #チャタリング #ナイキスト #50Hz #ADMM #admm_max_iter #ヌル空間 #R_u #飽和 #100Hzログ #追従

## 背景 / 症状

パイロットから「ロール・ピッチの追従をもう少し上げたい」。ユーザは `R_u` 120 → 100 を検討していた。
実測の追従振幅比は **roll 0.366 / pitch 0.452**（100 Hz ログ 19.5 s、指令 rms 10.9° / 8.9°）。

## 原因 / 判断根拠

**確認済み事実。100 Hz ログにして初めて見えた。**

- **指令 duty が 1 制御周期（10 ms）ごとに上下に振れている。** Δu のラグ 1 自己相関 **−0.82〜−0.96**。
- Δu を「毎周期反転する成分 E」と「滑らかな成分 S」に分けると **E rms 0.1379 / S rms 0.0433**。
  **指令変動の 91 % が反転成分。**
- **E の 86.7 % は 6 発ミキサのヌル空間**（力もモーメントも生まない）。
  row space に入る 13.3 % のうち 57 % は共通モードで、`B_c·1 = 0` より姿勢には効かない。
  → **E の約 94 % は機体に対して無意味**。主方向（E の 97.2 %）が生むモーメントは
  roll −0.008 / pitch −0.007（ほぼゼロ）/ yaw +0.401。
- **ログ破損ではない。** 同ログの `phi`/`theta` は 0–0.5 Hz に 66–70 % のパワーを持つ滑らかな波形で
  3–6 Hz は 0.5 % 以下。リングバッファが行を混ぜているなら姿勢も同様に振れるはず。**duty 列だけが振れている。**
- **フル再構築では消えない。** `cycles_since_reset` で層別しても |E| は不変
  （0 周期後 0.1216 / 41–100 周期後 0.1222）。**TR1/SR2 の Hessian 劣化は原因ではない。**
- **操舵量に比例する。** 同一重みの `0904_100Hz_v2` は φ指令 rms 3.89° / |Δduty|/周期 0.088 / ラグ1 −0.49、
  `v4` は 10.89° / 0.242 / −0.80。**指令 2.8 倍でチャタリング 2.8 倍。**

**帰結（確認済み）。** モータ一次遅れ（τ≈50 ms, コーナー 3.2 Hz）は 50 Hz を潰すので、
機体が感じるのは 2 サンプル平均。それで評価すると

- Δu rms 0.1447 → **0.0435**、飽和率 2.2 % → **0.0 %**、|Δu| 95 % 点 0.248 → **0.083**。
- box の上側余裕は `0.95 − u_base = 0.334`。**実効的に使っているのは 13–25 % だけ。**

**したがって追従不足の原因はアクチュエータ飽和ではなく `R_u` が舵を出させていないこと。**

**推測（未確認）。** `admm_max_iter = 2` で ADMM が収束しきらず、
姿勢に効かない方向（コストが `R_u‖Δu‖²` しか働かない部分空間）に反転が残っている可能性。
ただし `admm_rho = 1.0` / `R_u = 120` ならこの部分空間の縮小率は 1/120 と強いはずで、
**単純な ADMM 未収束だけでは説明が付かない。原因は特定できていない。**

## 対応

**この decision の時点ではコード未変更。** 解析資料
[`docs/20260904_v4_100Hz_chatter_and_Ru.md`](../../20260904_v4_100Hz_chatter_and_Ru.md)、
図 `Benzen_NMPC/tools/plots/0904_v4_100Hz_chatter.png`。

**`R_u` 120 → 100 は方向としては正しいが、単独では先に進めない**と判断した。理由:

1. 実効舵が使える範囲の 13–25 % しかないので、下げる方向自体は正しい。
2. しかし 17 % の減では追従振幅比は 0.366 → 0.42 程度で、**パイロットが体感できない公算が高い**。
3. **`R_u` はこの反転成分を抑えている唯一の項**なので、下げるとチャタリングも育つ。
   **順序を逆にすると悪化しうる。**
4. `R_u = 120` は 4 Hz 発振を止めるために 28 → 120 に上げた値で、その原因（未モデル化のモータ遅れ）は
   今も残っている。**`p` の全パワーの 33.6 %（rms 5.63 deg/s）が 3–6 Hz にある**ことを 100 Hz ログで初めて確認した。

**却下した案**: `R_u` だけ 100 にして次の飛行へ行く。上記 2–4 により、効果が出ても出なくても
原因が切り分けられない（チャタリングと 4 Hz の両方が同時に動く）。

**保留**: `Q_phi`/`Q_theta` の増加。`Q/R` 比を動かすという意味で `R_u` 低減と同じ効果なので、
1 回に 1 つの原則から同時には動かさない。

## 検証結果

- 上記はすべて `0904_100Hz_v4.csv`（1946 行, 19.5 s, 欠損なし）からの実測。
- `0904_100Hz_v2.csv` との比較で再現性を確認（重み同一）。
- **ロールに −6.65° の定常偏差。** NMPC に積分項が無いため、未モデル化の一定外乱はそのまま残る。
  重みでは消えない。`RL` モータの Δu rms 0.0657 は他（0.124–0.190）の半分以下で、偏りは継続。
- 位相遅れは 40 ms のみ。ラグ補正しても振幅比は 0.365 / 0.452 で変わらず、**遅れではなく振幅不足**。
- 指令パワーの 98 % は 1 Hz 以下。「指令が速すぎて追えない」ではない。
- **併せて渡された `0904_v12.csv` はヘッダ 4 行のみでデータ行 0。** 10 Hz テレメは何も取れていない。
- **チャタリングの原因は未特定。修正も未実施。**

## 次に触る人へ

- **飽和率を 10 Hz ログで評価してはならない。** 50 Hz 成分が折り返して混入する。
  `0904_v11.csv` で「飽和 23 %」と報告したのは、**チャタリングの山が 0.95 に当たっていたのを拾ったもの**で、
  実効的な飽和は 0 % だった。**飽和・舵余裕の判断は必ず 100 Hz ログで行う。**
- **切り分け手順**: プロペラを外して機体を固定し、スティック一定で 100 Hz ログを取る。
  それでも反転するならソルバ内部で確定（機体・センサ・空力は無関係）。
  同時に `admm_max_iter` を 2 → 4 にして消えるかを見る。
- **チャタリングを潰す前に `R_u` を下げない。** 下げると反転成分も一緒に育つ。
- ロールの定常偏差と `RL` の偏りは**重みではなく物理点検**で潰す。
