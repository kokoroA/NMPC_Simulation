# 静推力を実機モータ f1404 で再同定: T_max は現行値の 1/2.6、プロペラは GEMFAN-3630-3

- **日付**: 2026-08-28
- **種別**: investigation | tuning
- **対象**: `Benzen_NMPC/docs/sysid_thrust.py`, `Benzen_NMPC/nmpc_params.hpp`, `program/sil/host/plant.py`
- **タグ**: #sysid #推力 #thrust #T_max #Ct #C_QT #f1404 #F1408 #GEMFAN #プロペラ #NMPC #Bc #SIL

## 背景 / 症状

`nmpc_params.hpp` の `T_max = 2.04f` には「暫定値：実機ホバー測定後に更新推奨」と注記があり、
ユーザからも「未検証でおそらくもっと大きい」との指摘があった。
`docs/sysid_thrust.py` で再同定を試みた。

## 原因 / 判断根拠

**確認済み事実。**

- スクリプトは**そのままでは実行不能**だった。入出力が別セッションの絶対パス
  `/sessions/dreamy-cool-sagan/mnt/...` になっていた。
- **同定対象が実機と別モータだった。** 旧版は `F1408 Kv3950` を固定で選んでおり、
  実機は `f1404 Kv2900`。旧結果 `T_max=2.12`（→ params は 2.04）はこの誤りに由来する。
- **プロペラも違っていた。** シート右側の 6 発実験「メインミッション（510）」の総推力 **532 g** と
  各構成の「1 発最大 × 6」を突き合わせると、`GEMFAN-3630-3` が **+2.0 g（0.4 %）** で一致。
  旧版が仮定した `betaFPV-D90s-3` は 127 g 不足。**これが決め手。**
- 実機構成 `f1404 + GEMFAN-3630-3` の同定値:
  `Ct = 5.21e-7`（R²=0.998）、`T_max(duty=1) = 0.87 N`、
  **ホバー接線 `dT/du = 0.79 N/unit-duty`（M=0.356 kg）**、推力マージン 1.50。
- **`T_max = 2.04` は実機の約 2.6 倍。** `B_c ∝ T_max` なので NMPC は操作権限を過大評価しており、
  必要な Δu の 1/2.6 しか出さない。**応答が鈍る側**である。
  `20260828_nmpc_review_failsafe_tmax.md` で「過小評価→出しすぎ（発振側）」と書いたが、**誤差は逆向きだった**。
- 移植の妥当性は**回帰確認済み**。旧条件（F1408 / `--map ratio` / M=0.300）で
  `Ct=6.127e-7, T_max=1.548, u_hover=0.272, dT/du=2.116` を再現し、
  `thrust_sysid_K1.md` の記載値（6.13e-7 / 1.55 / 0.27 / 2.12）と一致した。**計算部分は変えていない。**

**未解決の不確かさ。**

- **スロットル目盛り → パルス幅の対応が未確認。** 旧版は `duty = 目盛り/20` を決め打ちしていた。
  ファーム側 duty は 1100–1900 µs で定義されるので、テスタが 1000–2000 µs を 0–20 目盛りで出すなら
  両者は一致しない。`--map pwm` / `--map ratio` を用意して比較したところ、**`dT/du` が 25 % 変わる**。
- **機体質量がリポジトリ内で 3 通り**: `nmpc_params.hpp` 0.356 / 旧同定 0.300（実測とある） / Sheet1 0.390。
  ホバー duty が 0.47–0.66 で変わる。
- `CQ = 3.0e-8` は未測定。`C_QT = CQ/Ct` なので Ct 更新でヨー権限見積もりが +60 % 動く。

## 対応

`sysid_thrust.py` を修正して実行。結果は
[`Benzen_NMPC/docs/thrust_sysid_f1404.md`](../../../program/pico/pico-sdk2/pico-sdk/Benzen_NMPC/docs/thrust_sysid_f1404.md)。
旧 `thrust_sysid_K1.md` の冒頭に「F1408 の記録であり実機ではない」旨の注記を追加（本文は残した）。

**`nmpc_params.hpp` は未変更**（ユーザ判断待ち）。反映案は `Ct = 5.21e-7f`, `T_max = 0.79f`。

**却下した案**: `T_max` に duty=1 の推力 0.87 を入れる。
線形 `B_c` はホバー近傍の微小差動推力を扱うので、入れるべきは**接線勾配**（旧文書 §2.3 の判断を踏襲）。

**環境変更**: `program/NMPC_simulation/.venv` に `openpyxl` を追加インストールした（スクリプトの依存）。

## 検証結果

- 回帰確認: 旧条件で旧記載値を再現（上記）。**合格。**
- プロペラ特定: 6 発実験 532 g と GEMFAN-3630-3 の 534 g が一致。**根拠あり。**
- 図: `Benzen_NMPC/docs/sysid_figs/thrust_sysid_f1404_Kv2900_{pwm,ratio}.png`
- **実機での検証は未実施。** ホバー duty の実測、テスタのパルス幅測定、機体質量の確定はすべて**未実施**。

## 次に触る人へ

- **同定スクリプトを信用する前に「どの構成を同定しているか」を確認すること。**
  今回は `FLIGHT = ('F1408 Kv3950', ...)` というハードコードが 2 か月間そのまま使われていた。
  出力にモータ名・プロペラ名を必ず印字させること（修正版では印字する）。
- **スロットル目盛りのような「単位が曖昧な入力」は、決め打ちせず換算方式を切り替え可能にする。**
  今回それで ±25 % の感度が見えた。
- ⚠ **`program/sil/host/plant.py` も `T_max = 2.04` を使っている。**
  SIL の姿勢応答は実機より 2.6 倍機敏に出ていた。SIL で得た数値
  （バンク角不足 47 %、Ti スイープ、自動機動の軌跡）は**係数を直してから読み直すこと。**
- **U1（テスタのパルス幅）と U2（機体質量）は、係留して `T_ref × T_ref_coe` を 1 回読めば同時に解ける。**
  そのとき使うのは `(M g/6)/hover_duty` ではなく**接線勾配**である。
