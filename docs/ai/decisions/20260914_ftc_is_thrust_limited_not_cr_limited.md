# 3 日で何をやるか：`Cr` 再同定ではなく軽量化＋FTC。FR 停止は**推力律速であって `Cr` 律速ではない**ことを厳密に示した

- **日付**: 2026-09-14
- **種別**: design | investigation
- **対象**: FTC 実験計画、`nmpc_params.hpp` の `mass`、`docs/20260905_yaw_damping_experiment_protocol.md`
- **タグ**: #FTC #relaxed_hover #推力余裕 #軽量化 #Cr #mass #優先順位 #NoGo

## 背景

残作業 3 日。「糸の長さを揃えて `Cr` を正確に同定し直す」か「現状の推定で軽量化 → FTC 実験へ進む」か。

## 判断根拠

### (1) FR を止めた静的ホバー解は**一意に決まり、実質 4 発**になる

`f_FR = 0` として、鉛直・ロール・ピッチ・ヨーの 4 拘束を実機の混合行列
（`kXm`, `kYm`, `kS`）で解く。未知は 5、拘束行列の階数は 4。解は

```
ピッチ式 : f_FL = f_RR + f_RL
ロール式 : f_MR = f_ML + f_RL
ヨー式   : 上 2 式を代入すると 3·f_RL = 0
→ **f_RL = 0**、f_FL = f_MR = f_ML = f_RR = mg/4
```

**FR を止めると対角の RL も自動的に 0 になり、残り 4 発が `mg/4` ずつ負担する。**
これは近似ではなく配置から出る厳密解。

### (2) ⚠ **回転を許しても（relaxed hover）推力余裕は 1 g も増えない**

ヨー拘束を外し（＝回転を許し）、鉛直・ロール・ピッチの 3 拘束だけにすると自由度は 2。
その 2 自由度で `max(f_i)` を最小化する数値探索（401×401 格子、`f ≥ 0`）:

| m | 最小化した `max f` | 上限比 | 得られた `Σ k_S f` |
|---|---|---|---|
| 335 g | 0.8224 N | 97.8% | +0.0044 N |
| 308 g | 0.7570 N | 90.1% | +0.0014 N |
| 291 g | 0.7148 N | 85.0% | +0.0060 N |

**最適解は勝手にヨーも釣り合い、`RL → 0`、`max f = mg/4` に戻る。**
`f_RL = c > 0` を強いると代数的に `max f = (mg + c)/4` となり**悪化する**。

→ **relaxed hover（回転ホバー）は、それが解こうとしていた推力余裕の問題を解かない。**
（傾き 0・定常回転のジャイロ項無視の範囲。傾きを入れた 2026-09-04 の探索でも
`fmax = 0.84 N` では解が無く、`duty 1.0` 相当まで許して 2 発が上限直前、という同じ結論だった）

### (3) したがって `Cr` は FTC のクリティカルパスに乗っていない

`Cr` が効くのは「回転ホバーの定常回転数 `Ω` がいくつになるか」だけ。
(2) より回転ホバーが余裕を生まない以上、**`Cr` を 2 倍精度良く知っても打てる手が変わらない。**

しかも現状の推定 `Cr ≈ 9.5e-5 (Iz=3.0e-3) 〜 3.7e-4 (Iz=11.6e-3)` は
要領書の判定（`≤ 3e-4` 成立側 / `> 1e-3` No-Go）の**成立側**に既に入っている。

### (4) 律速は質量。1 発上限 `T(0.95) = 0.8407 N` に対して

| 質量 | 必要 `mg/4` | 上限比 | 余裕 |
|---|---|---|---|
| 390 g | 0.9565 N | 113.8% | **不可** |
| 356 g | 0.8731 N | 103.9% | **不可** |
| **335 g** | 0.8216 N | **97.7%** | **+2.3%** |
| 320 g | 0.7848 N | 93.4% | +7.1% |
| **308 g** | 0.7554 N | 89.9% | +11.3% |
| **291 g** | 0.7137 N | 84.9% | +17.8% |

**4 発で 4 自由度（推力・ロール・ピッチ・ヨー）を担うので、この余裕がそのまま制御権限。**
335 g の +2.3% は「解はあるが動かす余地がゼロ」。

### (5) ⚠ 質量そのものが未確定で、しかも矛盾する証拠がある

リポジトリ内に `0.300 / 0.335 / 0.356 / 0.390` の 4 通り。
加えて [`20260904_v8_ftc_airborne_no_go.md`](20260904_v8_ftc_airborne_no_go.md) の
「健全飛行の 6 発 duty 合計 平均 **4.052**」を推力に直すと
`6·T(4.052/6) = 6·T(0.675) = 3.92 N ≈ 400 g 相当`。
姿勢制御の上乗せを引いても **335 g より重い側を示唆している。**

**356 g 以上なら FR 停止は上限超過で原理的に不可。** 質量が決まらないと計画自体が立たない。

### (6) `Cr` 側のリスク：払いが不確定

「傾き → `tau_even`」は[前回の記録](20260914_stage12_even_torque_confirmed_and_first_cr_estimate.md)の
**仮説であって実証されていない**。3 日かけて糸を直しても `tau_even` が残る可能性があり、
その場合の成果はゼロ。対して軽量化は 1 g 減らせば 1 g 分だけ確実に余裕になる。

## 対応（3 日の配分）

**軽量化 → FTC を採る。`Cr` 再同定は行わない。**

| | 内容 | 根拠 |
|---|---|---|
| **Day1 朝（最優先・10 分）** | **機体を実測して質量を確定する** | (5)。356 g 以上なら計画を組み直す必要がある。最も情報量が高い |
| Day1 午前 | **プロペラを外して FTC 経路の動作確認**（`ftc=1`, `u_fr=0`, 残り 5 発, 復帰, フェイルセーフ） | `ftc=1` の実測ログは**いまだに 0 件**。どちらの道でも必須 |
| Day1 午後〜Day2 | 軽量化。**最低 −27 g（→308 g, 上限比 90%）、目標 −44 g（→291 g, 85%）** | (4) |
| Day2 午後 | 治具固定・低 duty で再配分の向きを確認 | 下記の合否条件 |
| Day3 | 係留で **η を段階的に下げる**（1.0 → 0.8 → 0.6 → 0.4 → 0）。各段で推力余裕と姿勢過渡を実測 | 解析が予測している量を直接測る唯一の方法 |

### Day2 の合否条件（FTC の概念そのものの検証になる）

(1) の厳密解より、**`η_FR = 0` にしたら NMPC は RL も自動的に ≈0 へ落とし、残り 4 発が揃うはず。**
そうならなければ、混合行列かソルバか `U_ref` の扱いが間違っている。
**低 duty・治具固定で飛行リスクゼロのまま、FTC の中核仮説を反証できる。**

### 却下した案

- **糸を直して `Cr` を再同定する**: (3) よりクリティカルパス外。(6) より払いが不確定
- **`nmpc_params.hpp` の `Cr` を 0.005 → 1e-4、`CQ` を 1.44 で割る**: 測定に基づく変更だが、
  **FTC 実験と同時に入れてはいけない。** v10 は飛行で確認済みの構成であり、
  「1 回に 1 つだけ変える」原則（`20260831_nmpc_gain_too_high_oscillation.md` 以来）に反する。
  FTC が済んでから健全飛行で検証する
- **軽量化せずに FR 停止を試す**: 335 g で余裕 +2.3%。4 発 4 自由度が全部飽和寸前で、
  制御権限が無い。質量が 356 g 以上なら上限超過で確実に落ちる

## 検証結果

- (1) は混合行列から代数・数値の両方で確認（階数 4、解 `[mg/4,mg/4,mg/4,mg/4,0]`）
- (2) は 401×401 の格子探索。3 つの質量すべてで最適解が `RL→0`, `max f = mg/4` に収束
- (4) は `T(u) = -0.2265u² + 1.0525u + 0.0452`（`docs/thrust_sysid_f1404.md`）と `U_duty_max = 0.95`
- ⚠ (1)(2) は**傾き 0・定常回転のジャイロ項無視**。傾いた平衡は別途必要だが、
  2026-09-04 の傾き込み探索も同じ結論（`fmax=0.84` で解無し）

## 次に触る人へ

- ⚠ **質量を測る前に軽量化の設計をしないこと。** 4 通りの値が併存していて、
  そのうち 2 つ（356/390 g）では FR 停止が原理的に不可能。
- ⚠ **`Cr` を測り直さない判断は「`Cr` がどうでもいい」という意味ではない。**
  回転ホバーを本当に使うなら必要になる。いまは**回転ホバー自体が余裕を生まないと分かった**ので不要、というだけ。
