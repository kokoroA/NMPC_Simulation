# relaxed hover の可否は Cr だけで決まる。v9 は設計を検証しておらず、GEMFAN 交換でも FR 停止ホバーは成立しない

- **日付**: 2026-09-05
- **種別**: investigation | design
- **対象**: `20260904_relaxed_hover_equilibrium_design.md` の評価、`0904_100Hz_v3.csv` / `0904_v9.csv`、
  `Benzen_NMPC/docs/relaxed_hover_equilibrium.py`（新規）
- **タグ**: #FTC #relaxed_hover #spinning_hover #Cr #Cp #Cq #CQ #C_QT #推力余裕 #D90S #GEMFAN3630 #プロペラ交換 #U_ref #フェイルセーフ

## 背景

`20260904_relaxed_hover_equilibrium_design.md` を、地上 FTC ON → スロットル上昇 → 姿勢破綻の実測ログ
（`0904_100Hz_v3.csv`, 2176 行）で評価した。併せて「次回から D90S → GEMFAN-3630-3 で推力が上がる」
という条件変更を織り込んだ。

## 原因 / 判断根拠

**確認済み事実。設計の数値を独立に再現した。**

設計の 2026-09-05 追記の方法を実装した。**等式行列は「どのモータが死んでいるか」だけで決まり
`(phi,theta,Omega)` に依存しない**ため、擬似逆行列とヌル空間は 1 回だけ計算すればよい。
健全 5 発・等式 4 本でヌル空間は 1 次元なので、余裕最大化は 10 本の直線の下側包絡線の頂点を
全部評価すれば厳密に解ける（`scipy` 不要）。目的関数は設計と違う（残差最小 vs 余裕最大）が結論は一致した。

- `fmax = 0.84 N/発` → **rho = −2.1 %（解なし）**。設計の「平衡解を得られなかった」と一致。
- `fmax = 0.873 N/発` → **rho = +0.9 %**、`Omega = 20 deg/s`。設計の「上限直前の無余裕解」と一致。

**確認済み事実。v9 はこの設計を検証していない。**

- **設計の予備探索が使った `fmax = 0.84 / 0.873 N` は GEMFAN の値**（`sysid_thrust.py` 実測フィット
  `T = −0.2265u² + 1.0525u + 0.0452`）。v9 の実機 D90S は `0.0904u² + 0.5431u + 0.0243` で
  duty 0.95 なら **0.622 N**、**設計の仮定より 26 % 弱い**。
  **設計が「解なし」と判定した条件より、さらに悪い条件で飛ばした。**
- ログの duty を D90S 実測曲線で N 換算すると、**FTC 区間の最大合計推力は 3.111 N = 317 g**。
  質量 350 g に必要な 3.434 N の **91 %** にしか届かない。姿勢を保ったまま出せる上限
  （`4 × 0.622`）は **2.487 N = 253 g** で必要量の **72 %**。**そもそも浮けない。**
- **軌道が定常回転条件にまったく乗っていない。** `Omega = r/(cos phi cos theta)` と置いたときの
  `p, q` 残差は実測 `|(p,q)|` と同じ大きさ（残差/実測 = 0.91–1.22）。単に転んだだけである。
- **`Cr` はこのログから同定できない。** `Iz·rdot + (Iy−Ix)pq = tau_z − Cr·r|r|` の回帰は
  `Cr = −0.000249`（物理的にありえない負値）、`R² = 0.027`。
  理由は明確で、**`Iz·rdot` の rms 0.00911 Nm に対し指令ヨートルク `tau_z` の rms が 0.00268 Nm しかない
  （3.4 倍の食い違い）**。`C_QT` が小さすぎるか、未モデル化ヨートルクが支配的かのどちらか。

**確認済み事実。GEMFAN でも FR 停止ホバーは成立しない。**

- 静的 4 発配分の必要推力は `mg/4`。350 g で 0.858 N、383 g で 0.939 N。
  GEMFAN duty 0.95 は 0.841 N なので **350 g で rho = −2.1 %、383 g で −11.7 %**。
  duty 1.0 を使い切っても 0.871 N、350 g で **rho = +0.9 %**。
- 20 % 余裕には **fmax ≥ 1.073 N（350 g）/ 1.174 N（383 g）** が必要。GEMFAN から **+28 % / +40 %**。
  逆に GEMFAN で許される質量は **0 % 余裕で 343 g / 10 % で 309 g / 20 % で 274 g**。
- **ただし健全飛行には劇的に効く。** ホバー duty は 350 g で **0.880 → 0.571**、383 g で
  **0.956 → 0.640**。**383 g・D90S ではホバー duty が clamp 0.95 を超えており、健全 6 発でも実質飛べなかった。**
  `Delta u` の上側余裕 `0.95 − u_base` が 0.07 → 0.38 と 5 倍以上になる。

**★ 最重要。relaxed hover の可否は `Cr` 一つで決まる。**

`(phi, theta, Omega)` を `±40° × 0–800 deg/s` で全探索した。

- 現行推定値 `Cp = Cq = 0.025, Cr = 0.005` では **最適解は常に `Omega = 0`（静的 4 発配分）**。
  **この係数の下では relaxed hover の利得はゼロ。**
- `Cr` を下げると結論が反転する（GEMFAN 0.95, m=350 g）:
  `Cr = 1.0e-4` → rho **+14.9 %**（Omega 550 deg/s）、`4.9e-4` → **+8.1 %**（280 deg/s, RL = 0.773 N）、
  `8.4e-4` → +1.4 %、**`1.4e-3` 以上 → −2.1 %（Omega = 0）**。
- **境目は `Cr ≈ 1.1e-3`。現行推定値 0.005 のわずか 4.5 分の 1 の位置にある。**
- 有利側の解は合計推力 3.756 N で**静的上限 3.363 N を 12 % 上回り、RL が 0.773 N で働く**。
  狙いどおり「5 発を使う」解になっている。傾き `cos18°cos16° = 0.914` を失って鉛直 3.43 N = 350 g で釣り合う。
- ⚠ その解の **`|omega|max = 256 deg/s`。現行フェイルセーフ 300 deg/s の 85 % を定常で使う。**
  `Cr` がさらに小さければ 550 deg/s まで上がり、**成功している最中にフェイルセーフが発動する。**

**確認済み事実。FTC の `U_ref` が推力上限を自ら削っていた。**

FR 停止時の 0 トルク最適配分は **RL も 0 にする 4 発配分**（合計 `4·fmax − e`）。
しかし現行 `U_ref` は健全 5 発へ均等に `+u_hover/5` を配るため、v9 では RL が
0.239–0.273 N で回り、**上限を 2.487 → 2.21–2.25 N と 10 % 削っていた。**

## 対応

**コード・パラメータ変更なし。** 解析資料
[`docs/20260905_relaxed_hover_eval_v9.md`](../../20260905_relaxed_hover_eval_v9.md)、
図 `Benzen_NMPC/tools/plots/0904_v9_ftc_thrust_margin.png`、
再現スクリプト `Benzen_NMPC/docs/relaxed_hover_equilibrium.py`。

**却下した案**: 「GEMFAN で推力が上がるから FR 停止飛行を再試行する」。
**設計の探索は既に GEMFAN の推力で行われており、それでも解が無い。** 同じ試験を繰り返さない。

**却下した案**: `Cr` を現行値のまま relaxed hover の実装に進む。
`Cr` の 1 桁で「利得ゼロ」と「rho +8 %」が入れ替わるため、**実装しても成否を解釈できない。**

**保留**: `CQ = 5.8e-9` の見直し。v9 のヨー食い違い 3.4 倍は `C_QT ≈ 0.038`（`CQ ≈ 2.0e-8`、旧値 3.0e-8 の 66 %）
に相当し、`nmpc_params.hpp` の古いコメント `0.03614` に近い。ただし v9 は転倒・接地を含むため
これ単独では断定できない。ベンチで測り直す。

## 検証結果

- 100 Hz ログ 2176 行（NaN 4 行は破綻・フェイルセーフ・接地衝撃より後なので除外）。
- 平衡探索は `phi, theta ∈ ±40°`（2° 刻み）、`Omega ∈ 0–800 deg/s`（10 刻み）の全探索。
- 推力曲線は `sysid_thrust.py` を両プロペラで実行した実測フィット。**線形 `T_max·u` は使っていない**
  （`T_max = 1.04` は姿勢線形化用の接線ゲインであって絶対推力ではない）。
- **`Cp / Cq / Cr` は依然として未同定。実飛行可否は未確定のまま。**
- 実機での確認は未実施。

## 次に触る人へ

- **プロペラ交換を「FTC が成立する側の変化」と数えないこと。** 設計の探索は最初から GEMFAN の推力値で
  行われていた。交換で変わるのは**健全飛行の余裕**であって、故障時の可否ではない。
- **`T_max` を絶対推力に使わない。** 姿勢線形化の接線ゲインである。可否判定は実測 `T(u)` で行う。
- **`Cr` が決まるまで relaxed hover の実飛行判断はできない。** 逆に言えば、
  `Cr` の同定は「やっておくと良いこと」ではなく**唯一の律速**である。設計の追記にある
  正逆両方向・複数 common duty での回帰を先に済ませること。
- **relaxed hover が成立する条件は、同時にフェイルセーフに触れる条件でもある。**
  成立解が要求する 256–550 deg/s に対し現行しきい値は 300 deg/s。**対で設計する。**
