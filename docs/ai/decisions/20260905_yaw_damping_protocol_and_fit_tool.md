# ヨー軸吊り試験の実施要領と解析ツールを用意。3 項回帰（摩擦・線形・二乗）を必須とした

- **日付**: 2026-09-05
- **種別**: design
- **対象**: `docs/20260905_yaw_damping_experiment_protocol.md`（新規）、
  `Benzen_NMPC/tools/fit_yaw_damping.py`（新規）
- **タグ**: #sysid #Cr #C_QT #ヨー吊り試験 #実施要領 #積分形回帰 #クーロン摩擦 #ベアリング #セルフテスト

## 背景

`Cr` は FTC（relaxed hover）の可否を単独で決める値だが根拠が無く、飛行ログからの回帰は
[`20260905_damping_unidentifiable_flight_logs.md`](20260905_damping_unidentifiable_flight_logs.md) で
識別不能と確定済み。[`20260905_cr_upper_bound_and_yaw_hang_test.md`](20260905_cr_upper_bound_and_yaw_hang_test.md)
で方式を決めたので、現場で実行できる手順と解析コードに落とした。

## 判断根拠

**設計判断。回帰は必ず 3 項（定数・線形・二乗）で行う。**

- **定数項（クーロン摩擦）を入れないと `Cr` の誤差が 300–560 %** になる（モンテカルロ 40 回）。
  軸受摩擦は速度によらずほぼ一定なので、減衰区間では定数として現れる。
  **摩擦が存在すること自体は致命傷ではない。基底関数が違うので分離できる。**
- **線形項 `b` を入れないと `Cr` が約 10 % 過大**になる。ロータの `H 力` は前進比が小さいうちは
  速度に比例するので、物理的に低回転域の減衰は線形。二乗項だけで当てはめると線形分を吸い込む。

**設計判断。微分せず積分形で回帰する。** `rdot` の数値微分はノイズを増幅する。
窓 `[t0,t1]` の積分形 `r(t1)−r(t0) = −(tau_f/Iz)(t1−t0) − (b/Iz)∫r − (Cr/Iz)∫r|r|` なら
測定値の差分と積分だけで書ける。

**設計判断。`Iz` で割った比のまま扱う。** 測れるのは `rdot` と `r` だけなので出るのは比だが、
`nmpc_model.cpp` のヨー行（`B_c(4,k) = kS·C_QT·T_max/Iz`、減衰 `−Cr·r|r|/Iz`）も比の形でしか
使っていない。**`Ix/Iy/Iz` が `NMPC_REPORT.md` と `nmpc_params.hpp` で 3.4–3.9 倍食い違い、
どちらも実測記録が無い**という問題を、この試験は迂回できる。

**設計判断。フェーズ⓪（モータ OFF のベースライン）を必須にした。**
ロータが回っていなければロータ由来の減衰は無いので、得られるのは軸受摩擦＋機体空力。
本計測から差し引けばロータ由来だけが取り出せる。**軸受の良否判定も兼ねる。**

**却下した案**: 定常回転まで回して `Cr = tau_z/r_ss²` と読む。
`Delta=0.05`・`Cr=1e-4` で定常 `r` が約 300 deg/s（`Cr=1e-5` なら 900 deg/s 超）になり危険。
自由減衰なら同じ情報がより広い `r` 範囲で安全に取れる。

**却下した案**: 3 発だけ回してヨーを作る。合計推力が変わって吊りの張力・傾きが動き、
2 グループのロータ動作点が離れて「どの回転数での係数か」が曖昧になる。
`u_i = u0 + s_i·Delta`（`Σs_i = 0`）なら合計推力が一定のまま純ヨートルクだけ出せる。

## 対応

- 実施要領 [`docs/20260905_yaw_damping_experiment_protocol.md`](../../20260905_yaw_damping_experiment_protocol.md)。
  用語集、各項の物理的意味、`tau_z` の定義、フェーズ⓪〜⑤、判定基準、安全、
  「飛行ログ回帰の敗因がどこで消えているか」の対応表まで含む。
- 解析ツール `Benzen_NMPC/tools/fit_yaw_damping.py`。`--decay` / `--step` / `--baseline` の
  3 モードと、**`--selftest`（既知の真値から合成データを作って復元できるか確かめる）** を持つ。

## 検証結果

- `--selftest` が通ることを確認。真値 `tau_f=5e-5, b=2e-5, Cr=1e-4, Iz=3e-3`、
  100 Hz・25 s・ジャイロノイズ 0.5 deg/s rms から **`Cr` を 2.1 % 誤差で復元**。条件数 36.7。
- 掃引範囲と精度の関係を確認: `200→145 deg/s`(3 s) で 30.3 %、`200→122`(5 s) で 7.5 %、
  **`200→88`(10 s) で 0.9 %**。**掃引比がすべて。**
- 新規スクリプトは LF、既存ファイルの改行コードは変更なし。
- **実機での実施は未了。すべて合成データによる手法検証にとどまる。**

## 次に触る人へ
- **`--selftest` を現場に行く前に必ず通すこと。** 手法とコードの両方が一度に確認できる。
- **条件数を必ず見ること。** 50 を超えていたら掃引範囲が足りておらず、出た `Cr` は信用できない。
- `−rdot/r` を `|r|` に対してプロットすると直線になるはず。曲がったら `r|r|` というモデル形自体を疑う。
- **`p, q` をログで監視すること。** 振り子で揺れていると `(Iy−Ix)pq` が混入する。大きい区間は捨てる。
- 前提のベンチ加振モード（NMPC を通さず duty を直接書く）は**まだ実装されていない**。
