# T_max 1.04→0.81 は R_u と CQ の両方を道連れにする（B_c 全軸の一様スケールだから）

- **日付**: 2026-09-11
- **種別**: design
- **対象**: `Benzen_NMPC/nmpc_params.hpp`(T_max, R_u, Q_phi/Q_theta, CQ), `nmpc_model.cpp`(B_c)
- **タグ**: #Benzen_NMPC #T_max #R_u #Q_phi #CQ #C_QT #ループゲイン #sysid #推力

## 背景 / 症状

ユーザの提案: **`T_max` 1.04 → 0.81**、**`Q_phi`/`Q_theta` 600 → 500**。問い: **`R_u` は直す必要があるか。**
（`Q_phi=500` は本セッション中にユーザが先に適用済み。`T_max` は未変更で `//0.81` のコメントだけ入っていた。）

## 原因 / 判断根拠

### `T_max` は B_c 全軸に掛かる一様スケールで、それ以外どこにも使われていない（確認済み）

`grep -rn "T_max" *.cpp *.hpp` の結果、実体としての使用は `nmpc_model.cpp:51-53` の 3 行のみ。

```
B_c(2,k) = -kYm[k] * T_max / Ix          B_c(3,k) = kXm[k] * T_max / Iy
B_c(4,k) =  kS[k] * C_QT * T_max / Iz
```

あとはログヘッダの印字だけ。**`u_hover` はスロットル由来（`T_ref * T_ref_coe`）で `T_max` とは無関係**、
box 制約も duty 単位なので影響を受けない。よって `T_max` の変更は
**「モデルの操作権限を一律 0.81/1.04 = 0.779 倍にする」以上の意味を持たない。**

### 実機は変わらないので、モデルを縮めた分だけループゲインが落ちる

ループゲイン = 制御器ゲイン × 実機ゲイン。`T_max` を下げても実機は 1 mm も変わらないので、
**落ちた分は `R_u` で買い戻すしかない。** ただし**単純な比例則は成り立たない**。
`H = Suᵀ Q̄ Su + R̄` で、`Q_phi=500-600` では `Su` 項が無視できないため。

### ホスト実測（出荷ソース、`nmpc_params.hpp` だけ差し替え）

| | T_max | Q_phi | R_u | cr 静的ゲイン | 対 ref | **crd 外乱釣り合い剛性** | 対 ref |
|---|---|---|---|---|---|---|---|
| **ref**（0911_v4 で飛んだ設定） | 1.04 | 600 | 800 | 1.773e-3 | — | **1.0168e-3** | — |
| a（T_max だけ） | 0.81 | 600 | 800 | 1.525e-3 | −14.0 % | 1.0269e-3 | +1.0 % |
| **b（ユーザ案そのまま）** | 0.81 | 500 | 800 | 1.418e-3 | −20.0 % | **0.8815e-3** | **−13.3 %** |
| **c（採用推奨）** | 0.81 | 500 | **620** | 1.670e-3 | −5.8 % | **1.0010e-3** | **−1.6 %** |
| d | 0.81 | 500 | 520 | 1.869e-3 | +5.4 % | 1.0877e-3 | +7.0 % |

**素朴な比例則 `R_u = 800 × 0.779 × (500/600) = 519` は行き過ぎ**（d が +7 % のオーバー）。
実測では **620** が ref にほぼ一致した。`Su` 項があるぶん `R_u` は比例則より高めでよい。

**ロバスト性グリッド**（機体効き 2/3/4× × 純遅延 3/5/7 周期、tau=50 ms。
⚠ `T_max` を下げるとハーネスの plant も一緒に縮むので、`gmul` を 1.284 倍して
**物理的な実機を全 variant で同一に固定**した。これをやらないとモデルと実機を一緒に縮めた無意味な比較になる）

| | 収束 | 最悪 rms | 発散傾向フラグ | 飽和最大 |
|---|---|---|---|---|
| ref | 9/9 | 15.83 deg | 0 | 0.6 % |
| b | 9/9 | 6.39 deg | **1**（3.0×/5cyc） | 0.0 % |
| **c** | 9/9 | **4.79 deg** | **0** | 0.1 % |
| d | 9/9 | 27.56 deg | 0 | 3.2 % |

**c が全条件で最良**（ref より良い）。低効き側（0.5/1.0/1.5×）では 4 者とも差が出ない
（全セル 1.4–2.3 deg 収束）ので、判定は高効き側で決まる。

ステップ応答（ロール 30 deg、実機効きを物理的に固定）は 4 者とも 90 % 0.56–0.64 s、
行き過ぎ 0 %、整定後振動なしで**差が出ない**。ステップだけ見ていると `R_u` の必要性を見落とす。

### `CQ` も道連れになる（これが一番見落としやすい）

`B_c(4,k) = kS·C_QT·T_max/Iz` なので、**`T_max` を下げるとヨー権限も 0.779 倍**になる。
0911_v4 で飛行データから裏付けが取れたばかりの値が壊れる。

| | `C_QT·T_max/Iz` | 実測 433 deg/s²/unit に対する比 |
|---|---|---|
| v4 現行（CQ=1.2e-8, T_max=1.04） | 456.8 | **0.95**（＝合っている） |
| T_max=0.81 だけ | 355.8 | 1.22（また 22 % 過小） |
| **CQ=1.54e-8 併用** | 456.4 | **0.95** |

`C_QT·T_max` を不変に保つには **`CQ` 1.2e-8 → 1.54e-8**（`C_QT` 0.0230 → 0.0296）。

⚠ **この補償はホストでクリーンに検証できなかった。** グリッドの plant は `gmul` で全軸一律に
スケールするため、`CQ` を変えるとハーネスの**実機側ヨー権限まで 1.28 倍**になってしまう
（`gmul` 補正は `T_max` 分しか戻せない）。実際 CQ=1.54e-8 の variant は 4.0×/7cyc で
発散傾向を出したが、**これは実機を 28 % 強くした人工的な条件の結果であって、比較として無効**。
`CQ` 補償の根拠は上表の算術のみ。

### `CQ` が 5.8e-9 からさらに離れる点について

物理推定（電気入力経路・運動量理論経路の一致）は 5.8e-9 で、1.54e-8 はその **2.65 倍**。
`T_max` を下げるほどこの乖離は開く。**乖離の犯人が `CQ` ではなく `Iz` 側だという疑いが強まる**
（`20260904_cq_estimated_from_bench.md`）。`Iz=3.0e-3` を 2.65 で割ると 1.13e-3 で、
`Ix=1.8e-3`, `Iy=1.9e-3` より小さくなってしまい**平板形状のヘキサでは物理的にありえない**
（`Iz ≈ Ix + Iy` が目安）ので、`Iz` 単独では説明しきれない。`Cr`（ヨー減衰）か、
そもそも `Σ kS·u → ヨー角加速度` の回帰（R² 0.24）の偏りを疑うべき。
**吊るし試験で `C_QT·T_max/Iz` をまとめて測るまで、この 3 つは切り分けられない。**

### ついでに: `T_max` を下げる方向はロール/ピッチの同定とも整合する

0911_v4 のロール/ピッチ同定は **実測/モデル比 0.40–0.42**（R² 0.10 と低く未確定）だった。
`T_max=0.81` にするとモデルが 0.779 倍になり比は **0.51–0.54** と 1.0 に近づく。**方向は正しい。**

## 対応

推奨する組: **`T_max=0.81`, `Q_phi=Q_theta=500`, `R_u=620`, `CQ=1.54e-8`。**

`R_u` を直さない場合（ユーザ案 b のまま）は、外乱と釣り合った状態の剛性が **−13 %** になる。
致命的ではないが、0911_v2 の「レギュレータのようで舵が効かない」方向への後退であり、
`R_u` を 620 にすれば**タダで取り戻せる**ので直さない理由がない。

**却下した案**:
- **`R_u=519`（素朴な比例則）**: crd 剛性が ref より +7 %、グリッドの最悪セルが 27.6 deg（ref の 15.8 より悪い）。
- **`R_u` 据え置きで `Q_phi` を 600 のままにする**: `T_max` 単独でも cr ゲインは −14 %。
  crd では +1 % とほぼ中立に見えるが、2 指標が食い違う以上どちらか一方で決め打ちしない。
- **`Q_p`/`Q_q` も触る**: `R_u=620` にすると角速度ゲインが上がり 率/角 が 0.204 s → 0.334 s と
  **1.6 倍ダンピング寄り**になる。グリッドで c が最良なのはおそらくこれが効いている
  （遅れ限界モードに対する位相進み）。**まず飛ばして効きすぎなら触る。**先回りしない。

## 検証結果

上記のホスト実測のとおり。**実機では未検証。**
`CQ` 補償のみ、ホストで検証できず算術根拠のみ（理由は上記）。

## 次に触る人へ

- **`T_max` を動かしたら必ず `R_u` と `CQ` をセットで見直すこと。** B_c の全軸に掛かるスケールなので、
  ロール・ピッチのループゲインとヨーのモデル権限の両方が同時に動く。単独で動かしてよいノブではない。
- **ハーネスで plant 側パラメータ（`T_max`, `CQ`, 慣性）を変えるときは `gmul` で実機を固定すること。**
  忘れるとモデルと実機を一緒に縮めた比較になり、「何も変わらない」という誤った結論が出る
  （本件では `b` のステップ応答が 0.70 s → 0.64 s と逆向きに見えた）。
- **次の飛行で見ること**: `#params:` 行の `T_max=0.810 CQ=1.540e-08 C_QT=0.0296`、
  ヨードリフト（v4 は r 平均 −3.6 deg/s）、`solver_code` の path=2（TR1 skip）の割合。
  `tr1_c_max` の判定量 `c` は `Su²` に比例するので `T_max` 0.779 倍で 0.607 倍になり、
  **skip は減る側**。閾値 1e6 は据え置きでよいが、path=2 が v4 の 12 % から動くか確認する。
