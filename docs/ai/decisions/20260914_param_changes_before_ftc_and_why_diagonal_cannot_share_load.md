# FTC 前に変えるのは `mass` だけ。`Cr` と `C_QT` の誤差は逆向きで打ち消し合っている。対角を回しても荷重は分担できない

- **日付**: 2026-09-14
- **種別**: design | investigation
- **対象**: `Benzen_NMPC/nmpc_params.hpp`（`CQ`, `Cr`, `Cp`, `Cq`, `mass`）、FTC 実験計画
- **タグ**: #FTC #Cr #CQ #C_QT #Cp #Cq #mass #混合行列 #制御配分 #NMPC優位性

## 判断 1：飛行に効くパラメータで変えてよいのは `mass` だけ

### `Cr` と `C_QT` は「片方だけ直す」と壊れる

吊り試験で得た 2 つの誤差は**逆向き**である。

| | ファーム | 実測 | 比 | 指令への効き |
|---|---|---|---|---|
| ヨー権限 `C_QT·T_max/Iz` | 7.98 | 5.53 | **1.44 倍過大** | 同じ誤差への指令が **0.69 倍**（不足方向） |
| ヨー減衰 `Cr` | 0.005 | 9.5e-5 | **53 倍過大** | 「減衰で失う」見込みが増え指令 **+36%**（過剰方向） |

ホライズン `N·dt = 0.14 s` で `r` を 0.5 rad/s 動かすには 3.6 rad/s² 要る。
そのうちモデルが減衰で失うと見込む分は `r=50 deg/s` で 1.27 rad/s² = **36%**（実測は 0.7%）。

```
1.36 × 0.69 = 0.94
```

**ほぼ完全に相殺している。v10 が飛ぶのはこの相殺の内側で調整したから**、という説明が立つ。
**片方だけ直すと 30〜40% ずれる。**

### `CQ` は物理量ではなく「ループゲインの調整代」として入っている

[`20260911_cq_lumped_yaw_authority_and_delay_comp6.md`](20260911_cq_lumped_yaw_authority_and_delay_comp6.md) が
`CQ` を 2.66 倍にした根拠は飛行ログの閉ループ回帰（実測 572 / モデル 220、比 2.60）だが、
**その R² は 0.11〜0.21**＝ほとんど相関していない。同 decision 自身が
「CQ という物理量が 2 倍だったという主張ではない」と明記している。

今回のベンチは開ループ・R² = 0.998・窓感度 0.8%・3 本が 5% 一致。
**物理量としてはベンチが上位。** しかしファームに入っている値は物理量ではなく調整代なので、
**物理値へ「直す」とヨーのループゲインが 1.44 分の 1 に落ちる。**

### 対応

| 項目 | FTC 前に | 理由 |
|---|---|---|
| **`mass`** | **実測して更新する** | FTC の可否そのものを決める。飛行挙動へのリスクなし |
| `CQ` / `C_QT` | **変えない** | 上記の相殺。変えるなら `Cr` と同時＋健全飛行で再検証 |
| `Cr` | **変えない**（コメントに実測値を残す） | 同上 |
| `Cp` / `Cq` | **変えない**（⚠ を残す） | 下記 |
| オフライン平衡計算 | **実測値を使う**（`C_QT/Iz = 6.19`, `Cr ≈ 1e-4`） | 飛行に触れないので risk ゼロ。効くのはここ |

⚠ **`Cp = Cq = 0.025` は一度も測っていない。** `p = 50 deg/s` でモデルのロール減衰は
`Cp·p|p|/Ix = 606 deg/s²`。現実的な差動 `Δu = 0.1` の権限が `0.10·T_max/Ix·0.1 = 258 deg/s²` なので、
**モデルは「減衰が指令より強い」と思っている。** ヨーと同じ構図であり、同じ相殺が
ロール・ピッチ側にも成立している可能性がある。3 日では測れないので触らない。

## 判断 2：対角（RL）を回しても荷重は分担できない。**むしろ悪化する**

`f_FR = 0`、ロール・ピッチ釣り合いは保つ、ヨーは捨てる（回転を許す）として `f_RL = c` を置くと

```
ピッチ式 : f_FL = f_RR + c
ロール式 : f_MR = f_ML + c
鉛直式   : 2·f_RR + 2·f_ML + 3c = mg
最大値を最小化 → f_RR = f_ML = (mg − 3c)/4
             → f_FL = f_MR = **(mg + c)/4**      ← c について単調増加
```

`max f = max((mg+c)/4, c)` は `c = 0` で最小。**`c = 0`、すなわち `f_RL = 0` が最適。**

### 物理的な理由

RL は FR の**真向かい**にある。RL に推力を入れると機体が傾くので、
それを打ち消すために **FL と MR が RL の分以上に増える**。
`c` を足すと FL と MR が `c/4` ずつ増え、**ピーク推力が上がる。**

**直感（「5 発で分担すれば 1 発あたりが軽くなる」）が外れるのは、制約が「合計推力」ではなく
「RL を打ち消す側のモータのピーク」だから。**

### つまり平面ヘキサ X は「1 発止まると構造的に 2 発失う」

これは配置から出る性質で、制御則では回避できない。ヘキサの冗長性が見かけより弱い理由。
逃げ道は 3 つしかない。

1. **傾けて回す（relaxed hover）** — 2026-09-04 の探索で `fmax = 0.84 N` では解無し、`duty 1.0` 相当でようやく解
2. **ロール・ピッチの厳密釣り合いを捨てて振動姿勢を許す** — 現行の 5 状態 NMPC の枠外
3. **軽量化** — 3 日で効くのはこれだけ

（X8 や同軸ヘキサ、8 発機なら故障発のモーメントを複数発へ分散できるので事情が変わる）

## 判断 3：NMPC 耐故障制御の優位性は「混合行列を作らなくていい」ではない

効く順に並べると、「人手で混合行列を作らなくてよい」は**最下位**である。

| # | 優位性 | なぜ効くか |
|---|---|---|
| **1** | **制約が有効な状態での最適再配分** | 固定混合＋飽和クリップは「飽和しない」前提で作った行列を壊す。1 ch クリップすると**全軸のモーメント配分が崩れる**。NMPC は box 付き QP を解くので飽和したうえで最適に配る。**4 発が上限の 98% という FTC の状況そのもの** |
| **2** | **権限が足りないとき「何を捨てるか」を設計者が指定できる** | `Q_phi/Q_theta/Q_r` が優先順位。擬似逆行列は最小二乗の意味で犠牲を配るだけで、設計判断ではない。FTC では普通ヨーを先に捨てたい |
| **3** | **`η` が連続量でよい** | `η = 0.6` は box の縮小として自然に入る。混合行列表だと故障箇所 × 程度の組合せが要る。**Day3 の η 段階降下はこれに依存** |
| **4** | **予測（ホライズン）** | 飽和する前に再配分を始められる |
| 5 | 混合行列を人手で作らなくてよい | 事実だが、6 通りの擬似逆行列を事前計算するのは難しくない |

⚠ **正直な境界線**：1 と 2 は**制約付き制御配分**（LP/QP ベース、redistributed pseudo-inverse 等）でも
NMPC 無しに達成できる。**NMPC 固有と言えるのは 4（予測）と、姿勢の非線形ダイナミクスを
同じ最適化問題の中で扱っている点。** 主張はここへ寄せた方が強い。
