# SIL M2: 姿勢閉ループの成立と、実機パラメータの不整合の発見

- **日付**: 2026-08-25
- **種別**: investigation
- **対象**: `program/sil/host/{plant.py,sim.py,test_m2_closed_loop.py,rc.py}`
- **タグ**: #SIL #M2 #閉ループ #プラント #PID #ゲイン #T_max #ホバー #Benzen_new

## 背景 / 症状

M1 でセンサ経路が正しいことは確認したが、**制御が実際に効くかは未検証**だった。
プラントを繋いで閉ループを成立させ、姿勢制御が働くことを確認する必要があった。

## 原因 / 判断根拠

### プラントは実機ファームから取った

シミュレータ側で独自にモデルを作ると、「SIL では飛ぶが実機では飛ばない」ときに
**モデル差なのか制御なのか切り分けられなくなる**。そこで
`Benzen_NMPC/nmpc_model.cpp` の `model_f` と `model_B_const` をそのまま Python に写した。

```
kXm = [0.085, 0.085, 0.0, 0.0, -0.085, -0.085]   (FR,FL,MR,ML,RR,RL)
kYm = [0.050, -0.050, 0.10, -0.10, 0.050, -0.050]
kS  = [-1, +1, +1, -1, -1, +1]
```

`Benzen_new` のミキサ（`control.cpp:1130-1135`）の係数比が
`3.0562/1.7655 = 1.731 ≈ √3`、`3.5311/1.7655 = 2.0` であり、
上記の幾何と一致することを確認した。**両ファームは同一機体**である。

符号整合も確認: `+P_com → +ロール`、`+Q_com → 機首上げ`、`+R_com → +ヨー`。

### 「姿勢を直接書き換える」外乱テストは誤り（M1 と同じ罠を再度踏んだ）

初期姿勢を 15°/-10° に瞬間移動させたところ、収束せず
**周期 20 秒級の緩い振動**になった。原因は制御ではなく、
角速度を伴わない姿勢変化を EKF が**ジャイロバイアス**と解釈して
`Xe(4..6)` が汚染されるため。

→ 突風相当の**角速度インパルス**（姿勢は連続）に変更したところ、
ピーク 3.01°、5 秒後 0.068° できれいに収束した。
`sim.py` に `disturb_rates()` として、この作法を強制する形で残した。

## 対応

- `host/plant.py`: 実機由来の姿勢ダイナミクス（RK4）。位置・速度は**可視化専用の開ループ積分**で、制御には一切戻さない（実機に位置制御が無いため）。
- `host/sim.py`: `ClosedLoop`。プラント → センサ生値 → ファーム(400Hz) → duty → プラント。実機と同じアーム手順（ウォームアップ 6000 tick + `lock_com` ジェスチャ）を `arm()` に実装。
- `host/rc.py`: `with_roll_ref` / `with_pitch_ref`（`control.cpp:1299,1304` の写像の逆算）。
- `host/sil_bridge.py`: **2 個目の `Sil()` を作ると例外**にした。ファームはグローバル状態を持つため、2 個目は初期化されず 1 個目の続きを掴む（実際に踏んだ）。

## 検証結果

**M2 全項目 PASS。**

| 項目 | 結果 |
|---|---|
| 水平保持 5 秒 | phi=+0.000, theta=+0.000 deg |
| ロール ステップ ±10deg | 誤差 -0.221 / +0.416 deg |
| ピッチ ステップ ±10deg | 誤差 -0.066 / +0.094 deg |
| 突風 (p=+120, q=-80 deg/s) | ピーク 3.01deg → 5 秒後 0.068deg |
| EKF 推定誤差（整定後） | phi 0.019deg, theta 0.021deg |

### 発見 1: ロール軸とピッチ軸のゲインが非対称

```
control.cpp:699  phi_pid.set_parameter(1.0,  100000.0, 0,      0.125, 0.01)
control.cpp:700  theta_pid.set_parameter(1.6, 10000.0, 0.0007, 0.125, 0.01)
```

ロールは **Kp が 1.6 分の 1、Ti が 10 倍（実質積分なし）、微分なし**。
このためロール軸だけ定常偏差が残る（ステップ応答の誤差がピッチの数倍）。
**実機の挙動そのものであり SIL のバグではない。** チューニング時の既知事項として記録する。

### 発見 2: ホバー点がモータ始動閾値より下にある

| | 値 |
|---|---|
| ホバーに必要な duty（`T_max=2.04 N`） | 0.2853 |
| それに要るスロットル比 | 0.0918 |
| モータが回り始める最小スロットル比（`Disable_duty=0.1`） | 0.1429 → duty **0.4440** |

`T_ref = 0.7 × BATTERY_VOLTAGE × ratio`、`duty = T_ref × T_ref_coe(0.6)` より、
**モータが回った瞬間に duty 0.444 になり、ホバー必要値 0.285 を大きく超える**。
つまり `T_max = 2.04 N` が正しいなら、この機体は**最小スロットルでも上昇し続ける**。

`nmpc_params.hpp` の `T_max` には「暫定値：実機ホバー測定後に更新推奨」とコメントがある。
最小飛行 duty でホバーする逆算値は **T_max ≈ 1.311 N**。
どちらが正しいかは**実機のホバー duty 実測でしか決まらない**。

**未検証**: どちらの `T_max` が正しいか。ESC 遅れ・電圧降下・推力非線形は未モデル（`motor_tau=0`）。

## 次に触る人へ

- ⚠ **プラントの状態を直接書き換えないこと。** 外乱は `disturb_rates()` で角速度に与える。
  姿勢だけ動かすと EKF のバイアス推定が汚染され、制御を誤診する（M1・M2 で 2 回踏んだ）。
- ⚠ **`Sil()` / `ClosedLoop()` は 1 プロセスに 1 つだけ。** 別条件を試すならプロセスを分ける。
- **実機のホバー duty を測ったら `PlantParams.T_max` を必ず更新すること。**
  ここが違うと M5 の自動機動の軌道がまるごとずれる。
- 位置・速度は開ループ積分であり**制御には戻していない**。3D 可視化のための見かけの軌跡にすぎない。
