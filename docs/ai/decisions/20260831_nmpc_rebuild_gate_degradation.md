# 飛行中のフル再構築を止めたら、飛行時間とともに操作性が劣化した（自分の修正の副作用）

- **日付**: 2026-08-31
- **種別**: investigation | rejected
- **対象**: `Benzen_NMPC/nmpc.cpp`(period_due ゲート), `nmpc_params.hpp`(rti::rebuild_max_u_hover, secant_min_norm), `tools/0831_v3.csv`
- **タグ**: #Benzen_NMPC #飛行実験 #TR1 #SR2 #Hessian #数値漂流 #reset_period #rebuild_max_u_hover #R_u #N #10ms

## 背景 / 症状

`R_u` 28→120 と「周期フル再構築を `u_hover < 0.30` に限定」を適用して飛行（0831_v3.csv）。
**空中に居る時間が長いほど操作性が悪くなる。**
ユーザの見立ては「飛行中に周期フル再構築をしていないのが原因」。

## 原因 / 判断根拠

**確認済み事実。**

- `R_u = 120` は明確に効いた。自由飛行の比較（v1 R_u=28 → v3 前半 R_u=120）:
  phi rms 15.71°→**7.15°**、theta 10.25°→**2.24°**、q rms 95.5→**13.3 deg/s**、
  duty ばらつき 0.688→0.216、飛行時間 1.5 s→7.1 s。**4 Hz 発振は消えた。**
- 58 ms の停止は飛行中から消えた（`iter_us` 最大 8965 µs、`loop_us` 最大 10867 µs）。**ゲートは意図どおり動作。**
- **`cycles_since_reset` と姿勢誤差の相関 +0.704**、角速度と +0.667。
  ビン別: cycles 0–150 で姿勢誤差 rms 4.48°／duty ばらつき 0.110、
  450–600 で **17.34°／0.671**、600–800 で **18.04°／0.571**。**単調悪化。**
- **`cnt_tr1 = cnt_tr1_ok = 888`, `cnt_tr1_skip = 0`。**
  `secant_min_norm = 1.0e-6f` のガードは**一度も働いていない**。
  ホバー中は割線対 (s, y) がノイズ同然に小さいはずで、それを 888 周期連続で float32 のランク更新に
  流し込んでいる。`Su`/`H` が真値から離れる機構として整合的。
- **`cnt_sr2_c = 1`（888 周期で 1 回のみ）。** SR2 健全性チェックは漂流を検出できていない。
- 後半の振動は約 1 Hz で、v1 の 4 Hz 発振（ゲイン過大）とは**別の性質**。

**⚠ 因果は未確定。** `cycles` と経過時間はこのログでは同一直線上にある（t=8.99 以降 再構築ゼロ）。
経過時間との相関も **+0.713** とほぼ同じで、
「Hessian の漂流」と「電池電圧低下・機体が離陸点から離れる・地面効果離脱・操縦者の疲労」を
**このデータでは切り分けられない。**

**判断。** ユーザの見立ては最有力。ただし決着には次の飛行が要る。

## 対応

解析資料 [`docs/20260831_nmpc_v3_rebuild_degradation.md`](../../20260831_nmpc_v3_rebuild_degradation.md)、
図 `plots/0831_v3_analysis.png`, `plots/0831_v3_cycles_vs_error.png` を作成。**コードは未変更。**

推奨: **次の飛行で `rebuild_max_u_hover` を 0.30f → 1.0f に戻す（定数 1 つだけ）。**
これは決定的な実験であると同時に、そのまま対策になる可能性が高い。

**なぜ今なら 58 ms に耐えられる見込みがあるか**: v1 で 58 ms が危険だったのは
**その時点で既に 100–200 deg/s で発振していたから**（58 ms × 150 deg/s ≈ 9°）。
`R_u=120` で q rms 13 deg/s まで下がったので、同じ 58 ms は **約 0.8°** の漂流にしかならない。

**却下した案**: `reset_period` を短くする。停止 1 回あたり 58 ms は変わらず、頻度だけ増えて悪化する。

**却下した案**: ゲートを残したまま重みで押さえ込む。
劣化の原因が Hessian の漂流なら、重みをどう振っても時間とともに悪化する。**症状ではなく原因を潰す。**

## 検証結果

- 上記はすべて `0831_v3.csv`（155 点 / 10 Hz）の静的解析。**修正後の実機試験は未実施。**
- **因果は未確定**（§原因の ⚠）。
- 「割線対がノイズ同然」という機構は `cnt_tr1_skip = 0` からの**推論であり、|s|/|y| を実測していない。**
  計装が要る。

## 次に触る人へ

- ⚠ **これは 2026-08-31 の自分の修正（飛行中のフル再構築停止）の副作用。**
  「58 ms のストールは危険」という判断自体は正しかったが、**その停止が担っていた役割
  （TR1/SR2 の数値漂流を洗い流す）を代替せずに止めた**のが誤り。
  **安全のために何かを止めるときは、それが何をしていたのかを先に確認すること。**
- **危険性は絶対値ではなく機体の状態で決まる。** 同じ 58 ms でも、
  発振中（150 deg/s）なら 9°、静穏時（13 deg/s）なら 0.8°。
  「常に危険」と決めつけたのが早すぎた。
- **`cnt_*` 系カウンタが「0 のまま」の項目は、機能していない可能性を疑うこと。**
  `cnt_tr1_skip = 0` は「ガードが健全」ではなく「ガードが一度も効いていない」と読む。
- 根治の本命は **`N` の短縮**。フル再構築コストは概ね `N³` で、17→12 で約 20 ms、17→10 で約 12 ms。
  **`loop_us` の 10 ms 超過問題と同じノブ**で両方解ける。
- core0 でシャドウ再構築してアトミック差し替えする案は停止をゼロにできるが、
  `H`+LLT だけで約 83 kB のシャドウが要る。bss 402 kB / SRAM 520 kB、core0 スタック 32 kB を引くと
  **残り約 86 kB**。**成立するかは未検証。**
