# `|U_lin|` ガードを原点基準で書いたため、耐故障飛行では 100% 誤発火して墜落した

- **日付**: 2026-09-15
- **種別**: bugfix | investigation
- **対象**: `Benzen_NMPC/nmpc.cpp`（安全弁 2/3・warm start 再起動点）, `control.cpp`（400 Hz clamp）, ログ `tools/0915_100Hz_v1.csv`
- **タグ**: #FTC #U_lin #ガード #ADMM #ヨー発散 #minimum_duty #対角 #ランク落ち #フル再構築 #R_u #墜落

## 背景 / 症状

地上で FTC（FR 停止）を ON にしてから離陸。**2 回とも墜落。**
1 回目は離陸直後に転倒（`φ = −135°`）、2 回目は姿勢が流れて `r` が単調に発散し衝突。

⚠ **ログの `t` 列は実時間ではない。** `t = 行番号 × 0.01` で作っているだけで、
締切を落とした周期は詰まって見える。`loop_us` から実周期を再構成すると
**10 ms × 1186 / 20 ms × 2 / 40 ms × 78 = 実時間 15.01 s（平均 84 Hz）**。

## 原因

### (1) 根本原因 — ガードの座標系が違った（確認済み）

`nmpc.cpp` 安全弁 3 は `ws.z.squaredNorm() < ulin_max²` を **原点基準**で判定していた。
健全時は `U_ref = 0` なので原点が正しい参照だが、**耐故障時は `U_ref ≠ 0`**：

```
u_ref_shift = [-u_h, +u_h/2 ×4, -u_h] を N=14 段
|U_ref| = u_h·sqrt(N·(2·1² + 4·0.5²)) = sqrt(42)·u_h = 6.48·u_h
```

**実測の回帰係数 6.256**（n=378, R=0.87）で理論と一致。よって

| | |
|---|---|
| `ulin_max = 1.0` を超える条件 | `u_hover > 0.160` |
| 313 g を 4 発で支える `u_hover` | 0.558 → `|U_lin| = 3.49` = **閾値の 3.5 倍** |
| 実測 `ulin_norm` | 中央値 2.68 / 最大 4.27 / **80% の時間で > 1.0** |
| ヘッダ | **`ulin_reset=198`** |

**離陸できる推力では必ず発火する。**
⚠ このガードは FTC のために作ったのに、**FTC の無い健全便 6 本で較正した**のが誤り
（[`20260911_ulin_guard_and_revert_to_v10_for_ftc.md`](20260911_ulin_guard_and_revert_to_v10_for_ftc.md)）。

### (2) 誤発火の帰結 — 「故障を忘れた配分」を飛行時間の 50% 出していた

発火 → `ws.U/z/lambda` をゼロ → その周期の出力は `Δu = 0` ＝ **健全 5 発すべて `u_hover`**。
この配分のヨートルクは `Σk_S·u = +u_hover` ＝ **+194 deg/s²**。
さらに次周期が **39 ms のフル再構築**で、その間 core0 は ZOH でこの誤配分を出し続ける。

| | |
|---|---|
| 発火間隔 | **50 ms 固定**（`ulin_max_run = 5` そのもの） |
| 誤配分の保持時間 | 1 回あたり **40 ms** |
| 飛行 4.34 s のうち誤配分を出していた時間 | **2.16 s = 50%** |

### (3) ヨー収支（実時間ベース、符号はすべて `+`）

| 寄与 | ṙ |
|---|---|
| ガード誤発火の誤配分 | +194 deg/s²（保持率 50%） |
| `minimum_duty = 0.1` が健全な対角 RL を床上げ | +46 deg/s² |
| ZOH 重み付き合計（指令から再構成） | **+208 deg/s²** |
| **実測 `dr/dt`** | **+135 deg/s²** |

`psi_ref` は −0.3〜0.0 deg/s ＝ **パイロットはヨーを指令していない。**

### (4) 構造的な制約 — FR と RL を両方 0 にするとヨーが制御不能（確認済み）

残り 4 発 `{FL,MR,ML,RR}` のモーメント行列は **rank 2**（第 3 特異値が厳密に 0）:

```
健全 6 発            rank 3   σ = [2.24, 0.172, 0.132]
FR 停止（5 発）      rank 3   σ = [2.24, 0.172, 0.132]
FR + RL を 0（4 発） rank 2   σ = [2.00, 0.172, 0.000]
```

左零ベクトルから `ṙ = 0.331·q̇ − 0.178·ṗ` が導かれ、
**実ログで相関 0.999998 / 最大誤差 8.9e−3 rad/s²** で成立していた。

→ ヨートルクが 0 になる方向は `Mx : My = −1.765 : 1` の 1 本だけ。実指令は `+0.61` で外れていた。
**姿勢を動かせば必ずヨートルクが出る。** 打ち消すには対角を持ち上げるしかない。

⚠ [`20260915_uref_must_point_at_the_balanced_allocation.md`](20260915_uref_must_point_at_the_balanced_allocation.md) の
「対角は健全なので必要なら solver がいつでも持ち上げられる」は**楽観的すぎた。訂正する。**
`R_u=620` vs `Q_r=40` では実際上持ち上がらず、全飛行で RL が 0 を離れたのは **1 サンプル（0.10）だけ**。

### (5) 1 回目の転倒は別原因 — box 天井

`U_ref` が担当 4 発に `1.5 × u_hover` を指すので **`u_hover = 0.95/1.5 = 0.633` で 4 発同時に飽和**。
313 g のホバーが `u_hover = 0.558` なので**使える幅は 13% しかない**。
実測は `t=2.26` で 1 発、`t=2.30` で 2 発飽和 → 30 ms 後に `q = −247 deg/s` → 転倒。

## 対応

### 実装 1: ガードを `U_ref` 基準にした（`nmpc.cpp`）

```
if (!((ctx.ws.z - U_ref).squaredNorm() < ulin_max²))
```

`admm_solve()` に `U_ref` を渡すよう signature を変更（内部関数のみ。ヘッダ非公開）。

### 実装 2: warm start の再起動点も `U_ref` にした（`nmpc.cpp`）

安全弁 2 / 安全弁 3 / `!ws.valid` の 3 か所が `setZero()` していたのを
`warm_start_reset_to_ref()`（`z = clip(U_ref, box)`, `U = z`, `lambda = 0`）に統一。
⚠ **これが (2) の 39 ms 中の誤配分を直接消す。** 閾値だけ直しても発火時の出力は誤ったままだった。

### 実装 3: `minimum_duty` を対角発に適用しない（`control.cpp` 400 Hz clamp）

`floor_i = (Motor_eta[kDiag[i]] <= 0.5f) ? 0.0f : minimum_duty` を NaN ガードにも適用。

### 実装 4: 安全弁 3 はフル再構築を要求しない（案 A、`nmpc.cpp`）

`need_full_rebuild` / `rebuild_cause_pending` を立てるのをやめた。
このガードが止めたいのは**線形化点**であって Hessian は壊れていない。
warm start を `U_ref` に戻せば次周期は通常の TR1/SR2 パス（9.5 ms）で再線形化される。
⚠ TR1 が大ジャンプを捉えきれない場合は secant ガードが skip し、
本当に壊れたときだけ SR2 健全性チェックがフル再構築を要求する。
安全弁 2（非有限）と LLT 不健全は今まで通り再構築する。

### 却下した案

- **`ulin_max` を引き上げる**: FTC の `|U_lin|` はスロットルに比例するので閾値を上げると
  健全時の暴走検出まで鈍る。座標系を直すのが筋
- **`R_u` を 620 → 500 に下げる**: ヨーのループゲイン比は `Q_r/(R_u·|w|²)` で **1.24 倍にしかならない**。
  一方でロール・ピッチのループゲインは 12 便かけて詰めた値。**費用対効果が悪い**（下記「次に触る人へ」）
- **フル再構築を分割して複数周期に散らす**: 通常周期が既に **中央値 9.48 ms / 10 ms** で
  **余裕がほぼゼロ**。1 周期 0.5 ms 以内に収めるには 54 分割必要で、その間はどのみち古い Hessian を使う。
  それなら TR1/SR2 に任せる（＝再構築しない）のと変わらない
- **⚠ `minimum_duty = 0.1` を box の下限として solver に教える**（`du_min = minimum_duty - u_hover`）:
  **やってはいけない。ヨー外乱が 3 倍になる。**
  対角 RL はヨー軸専用ではなくロール・ピッチにも効く（`k_Ym = −.05`, `k_Xm = −.085`）。
  RL を 0.1 に縛ったうえで残り 4 発にロール・ピッチを厳密に打ち消させると、
  rank 2 の従属関係（`ṙ = 0.331·q̇ − 0.178·ṗ`）により**ヨートルクが 2 単位追加され**、
  `Σk_S·u = 3 × 0.1 = 0.3` になる。
  ⚠ ロール・ピッチのモーメントは**平衡では 0 でなければならない**（角度に復元力が無く発散するため）
  ので、重みで逃がすことはできない。`Q` をどう振ってもこの 3 倍は避けられない
- **フル再構築を「要求しない」のを安全弁 2（非有限）にも広げる**: あちらは Hessian そのものが
  使えない可能性があるので 39 ms を払う価値がある。安全弁 3 だけに留める

## 検証結果

- **ビルド成功**（`arm-none-eabi-gcc`, `make -j8`, 警告ゼロ）。`text 683552 / bss 422408`（+200 B）
- **健全時はビット一致**: `U_ref = 0` かつ `du_min < 0 < du_max` なので
  `clip(0, box) = 0`、`(z − 0).squaredNorm() = z.squaredNorm()`。
  v12 墜落の検出能力（`t=19.78` 発火、`q` の跳ねの 0.08 s 前）は保たれる
- **新フォールバック配分のモーメント検査**: 全 6 故障 × 6 スロットル = 36 ケースで
  `Σk_Xm = Σk_Ym = Σk_S = 0`（非ゼロ 0 件）。box で頭打ちになっても 4 発が等しく頭打ちになるため
- **ガードのリプレイ**（0915 ログ、stage-0 を N 段に外挿した近似）:
  `|z|` 中央値 2.46 → `|z−U_ref|` 中央値 1.20。⚠ **発火はゼロにはならない**
  （破綻区間では参照から離れるのが正当なため）。近似なので実機で `ulin_reset` を見ること
- ⚠ **実機未検証**

  根治は `N` 短縮か再構築の分割であって、ゲートではない
- **フル再構築 39 ms の内訳**（演算回数からの推定）: `build_hessian_from_su_w` 249,900 回 ≈ 26 ms、
  `llt.compute(84×84)` 98,784 ≈ 10 ms、`Su` 構築 ≈ 3 ms。

  **92,925 回（2.69 倍速）= 約 10 ms** になり、合計 23 ms。**それでも 10 ms には入らない。**
  N=10 まで落として初めて 0.37 倍（約 9 ms）。未実装

  `cd.rbar` は既にモータごとの対角ベクトル（`rbar(k*NU+j) = R_u`）なので 1 行で入る。
  ⚠ ただし `ctx.M.diagonal() += cd.rbar` なので **`rbar` を変えると Hessian の再構築が要る**。
  FTC スイッチ投入時（地上）にやれば問題ない
- **対角の権限は物理的には安い**: 純ヨートルクの最小ノルム配分で
  **RL を +0.042 動かすだけで 57 deg/s²** 作れる。効かないのは重み比のせいであって権限不足ではない
- ⚠ **実装 3 の代償**: 対角の ESC が完全停止するので、solver が後から対角を使いたくなっても
  即座には立ち上がらない。代案は「下限 0.1 を box の下限として solver に教える」
  （`delta_u_bounds_eta` の `du_min = minimum_duty - u_hover`）で、
