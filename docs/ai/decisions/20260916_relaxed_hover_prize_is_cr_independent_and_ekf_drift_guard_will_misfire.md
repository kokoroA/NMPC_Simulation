# relaxed hover の「旨み」は `Cr` に依存しない。動く のは動作点だけ。⚠ EKF ドリフト監視が回転中に誤発火する

- **日付**: 2026-09-16
- **種別**: investigation | design
- **対象**: 平衡の `Cr` 感度、`control.cpp`（EKF ドリフト監視 / failsafe ゲート / ジャイロ設定）
- **タグ**: #relaxed_hover #Cr #EKF #ドリフト監視 #FS_RATE_LIMIT #ジャイロ #Ftc_mode #事前作業

## 背景

`Cr` 同定実験は翌日。**それまでに Cr に依存せず進められる作業があるか**を調べた。

## 判断根拠

### (1) ★新規★ 余地（＝旨み）は `Cr` にほとんど依存しない

各 `Cr` で最適平衡（揚力 = `mg` を満たし peak duty 最小）を解き直した:

| `Cr` | Ω [deg/s] | φ / θ | peak duty | **余地** | 静的 4 発比 |
|---|---|---|---|---|---|
| 9.5e-5 | 775 | −4 / −6 | 0.731 | **0.219** | ×20.6 |
| 1.0e-4 | 775 | −4 / −6 | 0.733 | 0.217 | ×20.4 |
| 1.5e-4 | 650 | −6 / −6 | 0.749 | 0.201 | ×19.0 |
| 2.0e-4 | 525 | −8 / −8 | 0.735 | 0.215 | ×20.3 |
| 3.0e-4 | 425 | −10 / −10 | 0.748 | 0.202 | ×19.1 |
| 3.7e-4 | 400 | −10 / −10 | 0.744 | 0.206 | ×19.5 |
| 6.0e-4 | 325 | −14 / −12 | 0.763 | 0.187 | ×17.6 |
| 9.0e-4 | 300 | −14 / −14 | 0.804 | **0.146** | ×13.8 |

**`Cr` が 9.5 倍変わっても余地は 0.15〜0.22（静的 4 発の 14〜21 倍）でほぼ一定。**
変わるのは**動作点だけ**（Ω が 775 → 300、傾きが 4° → 14°）。

⚠ 前日の記録で「`Cr` が relaxed hover の成否を決める」と書いたが、**決めるのは成否ではなく動作点**である。
「やる価値があるか」は `Cr` を測らなくても確定している。**訂正する。**

### (2) ただし参照値は `Cr` 依存で、しかも外すと危険

- 誤った `Cr` で設計した参照は劣化する（既記録: r 723 → 533 deg/s、duty 飽和 0 → 15%）
- ⚠ **`Cr = 3.7e-4` では `Ω = 700 deg/s` に解が存在しない。**
  速すぎる参照は「最適でない」ではなく **実現不能**
- 「Ω 追従参照（`r_ref = r_meas`）で `Cr` をループから外す」案も検討したが、
  **`Ω` を固定しても最適な傾きが `Cr` で変わる**（Ω=300 で −4°/−6° vs −10°/−10°）ので外しきれない

### (3) ★新規・要対処★ EKF ドリフト監視が回転中に誤発火する

`ekf_drift_watch()`（`control.cpp:1256-1270`）は
**EKF の姿勢変化率**と**ジャイロから作ったオイラー角速度**の残差を見て、
`EKF_DRIFT_LIMIT = 5 deg/s` を `0.2 s` 連続で超えると `ekf_bias_reset()` する。

```
phi_dot_g = p + sinφ·tanθ·q + cosφ·tanθ·r
```

⚠ **`Ω = 775 deg/s`, `θ = −6°` では `cosφ·tanθ·r` だけで −76 deg/s** になる。
この大きさに対して閾値は 5 deg/s ＝ **6.6%**。数 % の不整合で即発火する。

**実測の裏付け**: `0916_100Hz_FTC_v1` は `ekf_bias_reset = 6`、健全便 `0916_100Hz_normal_v1` は **0**。
静的 FTC（r は最大 88 deg/s）ですら既に発火している。

### (4) Cr 非依存の阻害要因チェック（本日実施）

| 項目 | 結果 |
|---|---|
| ジャイロのフルスケール | ✅ `LSM9DS1_2000dps`（`sensor.cpp:80`）。775 deg/s に余裕あり |
| `Rbias` が回転を吸わないか | ✅ 起動時の静止平均で固定。飛行中は更新されない |
| `FS_RATE_LIMIT` | ⚠ 360 deg/s < Ω。ゲートが要る |
| EKF ドリフト監視 | ⚠ (3) のとおり誤発火する |
| `\|cosθ\| < 0.5` で監視を諦める枝 | ✅ 傾き 4〜14° なので無関係 |

## 対応（`Cr` 待ちにせず今できる作業・優先順）

1. **`FS_RATE_LIMIT` と `EKF_DRIFT_LIMIT` を `Ftc_mode` 中だけ緩める。**
   ⚠ どちらも `Cr` の値に関係なく必要で、無いと実験がその場で止まる。
   ゲートの書き方は既存の `if (Bench_mode == BENCH_OFF)`（`control.cpp:1441`）を踏襲すればよい。
   ⚠ **`Bench_mode` のように全部外すのは不可**（治具固定ではないため）
2. **翌日の `Cr` 同定を 1 セッションで終わらせる準備**（要領書の現機体向け更新、フィットスクリプトの事前確認）
3. **参照生成の配管**（`control.cpp:2332` の `x_ref` に `p_ref`,`q_ref` を通す／`U_ref = u_eq − u_hover`）。
   **値は表で後から差し替えられる形にしておく**
4. **`T_max` の再較正**（ベンチ 0.81 は実飛行より 19% 過大）。⚠ `B_model` が小さくなる方向なので
   ループゲインは下がる（安全側）が、v2 で見つかった `ζ = 0.25` と合わせて要検討
5. プロペラ無し → 治具固定の段階実施（`ftc = 1` の実ログは 0916 でようやく 2 本）

### 却下した案

- **Ω 追従参照（`r_ref = r_meas`）で `Cr` を外す**: (2) より、傾きの最適値が `Cr` で変わるので外しきれない
- **`Cr` を実測範囲の中間値で決め打ちして先に飛ばす**: (2) より、高い `Cr` では高 Ω が**実現不能**。
  範囲の端で「解が無い」側に落ちる

## 検証結果

- 平衡探索は `model_f()` と同一式。9 通りの `Cr` について再計算
- ⚠ EKF ドリフト監視の誤発火は**コード読解と実ログの `ekf_bias_reset` 計数からの推定**であり、
  回転中の実測はしていない
- ⚠ すべて机上。コード変更は行っていない
