# ロール/ピッチが「もっさり」する原因はヨーが Δu の 85% を食っていたこと

- **日付**: 2026-09-04
- **種別**: investigation
- **対象**: `Benzen_NMPC/control.cpp`(update_attitude_refs_from_sticks), `nmpc_params.hpp`(Q_r, C_QT, mass), `tools/0904_v1.csv`
- **タグ**: #Benzen_NMPC #飛行実験 #ヨー #Psi_ref #飽和 #Q_phi #Q_r #C_QT #mass #スティック感度 #failsafe

## 背景 / 症状

1 分間の飛行（`0904_v1.csv`）。ヨーが少し流れ、ロール/ピッチの追従が弱く「もっさり」する。
ロール/ピッチの指令スケールは ±54° に統一済み。

## 原因 / 判断根拠

**確認済み事実。**

- **Δu を common / roll / pitch / yaw の直交基底へ最小二乗分解すると、ヨーが分散の 84.7 %**
  （roll 6.4 % / pitch 7.6 % / common 1.3 %）。Δu rms はヨー 0.262 に対しロール 0.072、ピッチ 0.078。
- 指令トルク rms はヨー 0.0326 N·m でロール 0.0130 の **2.5 倍**。
  必要な duty 差動はヨー **0.214** に対しロール 0.062 / ピッチ 0.078。
- `u_base` 平均 **0.640** → 上向き余裕 **0.31** / 下向き 0.64（2.1:1 の非対称）。
  **ヨーに 0.214 使うとロール/ピッチには 0.1 も残らない。**
- **どれかのモータが上限 0.95 に達している時刻が 39 %。下限 0.005 到達は 3 回のみ**（上側だけ飽和）。
- ロールの追従振幅比は **飽和なし 0.125 / 飽和あり 0.013** と 10 分の 1 に崩れる。
- 追従振幅比は 0.2 Hz まで低域を取っても 0.06 のまま → **帯域ではなくゲインと権限の問題**。
- **NMPC 自体は正しく動いている。** 姿勢誤差と指令トルクの相関はロール **+0.75**、ピッチ +0.52。
  誤差 30° に対し 555 deg/s² 相当を指令している。
- ヨーは **指令中立時に +16 deg/s のドリフト**があり、追従振幅比は 0.24。
  **勝てない相手に力を注ぎ続けている。**
- **`Psi_ref` のスケールが `0.8f*π` = ±144 deg/s のまま。**
  ロール/ピッチを ±54° に下げたときにヨーだけ取り残されていた。
- `u_base` 0.640 を同定推力マップに当てると **機体 383 g**。`nmpc_params.hpp` の `mass=0.32f` より 20 % 重い。
  推力マージンは 1.50 → **1.39**。
- `failsafe=4`(FS_RATE) が **着陸後**（`nmpc=0`, `u_base=0`）に 1 回作動。接地バウンドと思われ、飛行中ではない。

**判断。** 重みの前に**ヨーの要求量**を減らす。`Q_phi` を上げても、飽和している間は効果を測れない。

## 対応

解析資料 [`docs/20260904_nmpc_yaw_starves_roll_pitch.md`](../../20260904_nmpc_yaw_starves_roll_pitch.md)、
図 `plots/0904_v1_analysis.png`, `plots/0904_v1_summary.png`。**コードは未変更。**

推奨（1 回に 1 つ）:
1. **`Psi_ref` の係数 `0.8f → 0.3f`**（±144 → ±54 deg/s）。重みを触らずヨー要求を 2.7 分の 1 に。
2. ヨードリフト +16 deg/s を源から潰す（プロペラ回転方向、`C_QT`、機体の非対称）。
3. 飽和が減ってから `Q_phi`/`Q_theta` 100 → 300。

**却下した案**: `Q_r` を下げてヨーを諦めさせる。ロール/ピッチは楽になるがドリフトが悪化し、
ユーザの不満の片方を悪化させる。**指令スケールを下げれば両方に効く。**

**却下した案**: `Q_p`/`Q_q` を下げて姿勢応答を速くする。
これは角速度の減衰項で、0831_v1 の 4 Hz 発振はこの減衰不足で起きた。**角度側だけ上げる。**

**却下した案**: `R_u` を下げる。高周波までゲインが上がり発振に直結する。最後の手段。

## 検証結果

- すべて `0904_v1.csv` の静的解析。**推奨した変更の実機検証は未実施。**
- ヨードリフトの原因（`C_QT` か物理的非対称か）は**切り分けていない**。
  `CQ = 3.0e-8` は未測定の仮値。`Ct` は既に 5.21e-7 に更新済みで、
  `C_QT = 0.0576` に対し推定値は 0.011（**5.2 倍の過大評価**、`20260904_cq_estimated_from_bench.md`）。
- 機体重量 383 g は `u_base` からの逆算で**実測ではない**。

## 次に触る人へ

- **「追従が悪い」ときは、まず制御量が何に使われているかを分解して見ること。**
  今回は Δu を common/roll/pitch/yaw の直交基底へ最小二乗分解しただけで原因が出た。
  重みを触る前にこれをやれば 1 回の飛行で済む。
- **追従の振幅比を低域に絞っても改善しないなら、帯域ではなくゲインか権限の問題。**
  帯域不足なら低周波では追従するはず。
- **感度（指令スケール）を軸ごとに変えたら、必ず全軸を見直すこと。**
  今回ロール/ピッチだけ ±54° に下げ、ヨーが ±144 deg/s のまま取り残されていた。
- **`failsafe` 列がないと、瞬間値の超過は 10 Hz ログに写らない。**
  今回 `p` 最大 55.9 / `q` 最大 110.8 しか見えていないのに FS_RATE(300 deg/s) が作動していた。
