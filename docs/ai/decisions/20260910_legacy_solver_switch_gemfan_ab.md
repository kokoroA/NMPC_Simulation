# 旧ソルバ（勾配バグ入り ADMM）への切替スイッチを実装し、既定を旧ソルバにした — GEMFAN で 35 s 飛んだ唯一の記録に基づく A/B

- **日付**: 2026-09-10
- **種別**: design | rejected(私の反対意見を記録) 
- **対象**: `nmpc_params.hpp`(`NMPC_LEGACY_SOLVER`, R_u, Q_p, admm_max_iter)、`nmpc.cpp`(`compute_neg_gradient_legacy`, U_lin)
- **タグ**: #Benzen_NMPC #ADMM #旧ソルバ #勾配バグ #ディザ #GEMFAN #A/B #NMPC_LEGACY_SOLVER #revert

## 背景

ユーザの方針: 1 発停止時の推力余裕のためプロペラは GEMFAN のまま。その状態で飛ぶには
「ソルバのバグが残る旧版 ADMM」に戻すしかない、と判断。問題ないか調査のうえ、問題なければ戻せ、という依頼。

## 調査

**支持する証拠（実機）。**
`0909_v1`（10 Hz テレメ）= 旧ソルバ（右辺に勾配 g）＋ GEMFAN ＋ `R_u=120, Q_p=20, iter=2` ＋ `T_ref_coe=0.85`。
`t=6.6–41.4 s` の **約 35 秒**飛行。7–30 s は `phi` ±6°（最大 −16°）、パイロットが飛ばせている。
31 s 以降は duty が 0.00↔0.95 を毎周期往復する全振幅チャタリング（box 有効で λ が発散した状態）になり、
それでも約 10 s 飛んで、41 s にロール逸脱 → NaN 固着で終了。
**今日の 8 飛行（修正版）はいずれも離陸後 2–6 s で墜落**。GEMFAN で最も長く飛んだ記録は旧ソルバのものである。

**反対する根拠（机上）。**
- ループゲイン: 旧ソルバの静的整合ゲインはホストで K角 0.90e-3（R_u=120、`U_lin=ws.U`）。GEMFAN の機体 ~700 で
  ループ 0.63 — 今日落ちた設定（0.23–0.40）より**大きい**。
- 正弦掃引: 3–5 Hz の振幅は旧 5.2–6.2、現行 2.5（2 倍）、位相進みは旧 +89–94°、現行 +103°（旧の方が少ない）。
- 閉ループ（機体 2.0×、モータ 50 ms、遅延 1 周期）: 両方収束。機体 2.5×・遅延 3 周期: 現行は収束、旧は 1° で横ばい。
- 旧ソルバは 50 Hz ディザで推力を浪費し、box 有効時に λ が発散する（0909_v1 の末期）。

**机上と実機が食い違う。** 私のモデルは「旧が 35 s 飛んだ」を説明できない。ディザが実機のモータ／ESC に
与える効果（小信号の応答性、不感帯の線形化）は 50 ms 一次遅れモデルに入っていない。
**説明できない以上、机上の反対より実機 1 本の記録を優先する**のが今日の教訓
（[`20260910_v6_why_old_flew_and_revert_verdict.md`](20260910_v6_why_old_flew_and_revert_verdict.md) で
ホストは実機の代わりにならないと結論済み）。

## 判断

A/B 実験として旧ソルバへ戻すことを**容認**する。ただし**戻すのは右辺と線形化点と重みだけ**で、
今日までに入れた安全弁と記録は残す。これで 0909_v1 の終わり方（λ 発散 → 全振幅チャタリング → NaN 固着）は緩和される。

私の反対意見: 旧ソルバが飛ぶ理由が分かっていないので、飛べても「なぜ」が残り、耐故障制御の設計には戻せない。
飛べたら**次はその理由を測る**（ディザ有無で実機のモータ応答を比べる）ことを条件にしたい。

## 対応

`NMPC_LEGACY_SOLVER`（`nmpc_params.hpp` 先頭、既定 **1**）で切替:

| | 1（旧ソルバ再現、既定） | 0（現行） |
|---|---|---|
| ADMM 右辺 | 勾配 g = H·U_lin + c（固有値 −1、不動点は解の半分、50 Hz ディザ） | 定数項 c を直接計算 |
| 線形化点 | `ws.U`（射影前） | `ws.z`（射影後） |
| `R_u / Q_p=Q_q / admm_max_iter` | 120 / 20 / 2（0904・0909_v1 当時） | 1200 / 30 / 4 |
| 安全弁（λ 上限 30・非有限・EKF ガード）、TR1 過大更新棄却＋連続 5 で再構築、100 Hz 内部状態ログ | **残す** | 残す |
| `T_max=1.04`, N=14 | 同じ | 同じ |
| `T_ref_coe` | **0.7（現行 control.cpp）— 0909_v1 は 0.85 だった。ホバー時のスティック位置と box の余裕が当時と異なる** | 0.7 |

## 検証結果（ホスト、実機ソースそのもの）

- 旧モードでチャタリングを再現: duty ラグ 1 自己相関 **−0.98**、1 周期跳び 0.087（現行 +1.00 / 0.000）。
- 旧モードの静的ゲイン K角 0.899e-3 / K率 0.504e-3。
- 記録状態リプレイ（0910_v4/v7/v8）: `nonfinite` 0/0/1、λ リセットは v7 の受信機 FAILSAFE 区間に集中、`|U_lin|max` 4.0–10.4。
  安全弁は旧モードでも機能する。
- ビルド成功（下記サイズ）。**実機未検証。**

## 次に触る人へ

- 飛べたら、`0909_v1` と同じく 30 s 以降に box 有効 → 全振幅チャタリングへ移行するかを見る（λ 上限で抑えられるはず）。
- 飛べなかったら、「旧ソルバが飛んだのは 0909_v1 の 1 本だけで、機体状態（左トリム、受信機）が当時と違う」ことも疑う。
- `NMPC_LEGACY_SOLVER=0` に戻すだけで現行へ戻る。両方のビルドを保存しておくこと。
