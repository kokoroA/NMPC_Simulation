# |U_lin| ガードの発火で duty を捨てるのをやめ、しきい値を box 相対にした。あわせて Hessian 構築で Su のブロック下三角を使った

- **日付**: 2026-09-19
- **種別**: bugfix | tuning
- **対象**: `Benzen_NMPC/nmpc.cpp`(admm_solve, nmpc_step, build_hessian_from_su_w), `nmpc.hpp`(NmpcScratch), `nmpc_params.hpp`(rti::ulin_*)
- **タグ**: #Benzen_NMPC #U_lin #安全弁3 #ulin_max #box #フル再構築 #Hessian #ブロック下三角 #最適化

## 背景 / 症状

[`20260919_payload_drop_crash_ulin_guard_zeroes_du.md`](20260919_payload_drop_crash_ulin_guard_zeroes_du.md) の対策 1 と 3 の実装。

## 原因 / 判断根拠

### (1) 発火がその周期の制御出力ごと捨てていた

`nmpc_step()` の出力は `U_opt(j) = clamp(ctx.ws.z(j))`。安全弁 3 は `admm_solve()` の末尾で
`warm_start_reset_to_ref()` を呼ぶので、健全時（`U_ref = 0`）は **`ws.z` が 0 になり、それがそのまま duty に出る**。
0919_v6 では最後の 0.65 秒に 10 回発火し、`|Δu| = 0.403` と `0.000` が 4:1 で交互に並んだ。

⚠ **ガードの目的は「次周期の線形化点を戻すこと」であって「この周期の制御を捨てること」ではない。**
安全弁 2（非有限）は逆に**出力にも効かせないといけない**（NaN をモータに流せない）ので、
両者を分ける必要がある。

### (2) しきい値 1.0 は box の 27% しかない

`ws.z` は ADMM の各反復で box へ射影されるので、**構造的に**

```
|ws.z| ≤ sqrt(NU_TOTAL) × max(u_hover, U_duty_max − u_hover)
      = 9.165 × 0.547 = 5.01     (u_hover = 0.547, 0919_v6 の動作点)
```

を超えられない。固定 `ulin_max = 1.0` はその **27%**。
⚠ **これは「数値暴走の検出器」ではなく事実上の権限リミッタになっていた。**

| | ulin_norm p50 | p95 | max | Δu ゼロ周期 |
|---|---|---|---|---|
| 0919_v5（飛べた） | 0.11 | 0.26 | 1.15 | **0 回** |
| 0919_v6（墜落） | 0.08 | 0.51 | **2.66** | **10 回** |

⚠ `nmpc_params.hpp` の既存コメントは「発火が頻発するならしきい値を上げるのではなく原因を疑うこと」と
書いている。**その指示には従っている**: 原因は (1) の破壊的な副作用であり、そちらを先に潰した。
しきい値のほうは「上げた」のではなく、**機体が重くなれば正当な `|Δu|` も大きくなるのに固定値が
それを追えない**という構造を直した（0919_v6 は貨物ぶん `u_hover` が 0.55〜0.64 と高い）。

### (3) Hessian 構築が Su のブロック下三角を無視していた

`full_rebuild_sx_su()` は `Su.setZero()` のあと `j <= k` のブロックにしか書かないので、
入力 `i` が属する段 `ki = i/NU` より前の行は**厳密にゼロ**。
`build_hessian_from_su_w()` は毎回 `NX_TOTAL = 70` 行すべてを舐めていた。

## 対応

1. **`NmpcScratch` に `z_applied` を追加**（84 float = 336 B）。
   安全弁 1・2 の**後**、安全弁 3 の**前**で `ws.z` をコピーし、`nmpc_step` はこれを出力に使う。
   → 安全弁 3 が発火しても **duty は捨てない**。warm start のリセットだけが残る。
2. **しきい値を box 相対に**。`ulin_max`（固定 1.0）を廃し、
   `ulin_box_frac = 0.8` / `ulin_min_abs = 1.0`（下限の保険）を追加。
   `ulin_lim = 0.8 × sqrt(84) × max(u_hover, 0.95 − u_hover)`。
3. **`build_hessian_from_su_w()` の内側ループを `k = (i/NU)*NX` から開始**。

**採用しなかった案**: しきい値をそのまま 1.0 で残す。
(1) を直せば発火のコストは「ADMM warm start を失う」だけになるので許容できる、という考え方もあるが、
大操作中に 5 周期ごとに warm start を捨てると **4 反復の ADMM が毎回コールドスタート**になり、
一番権限が要る場面で解の質が落ちる。検出器として意味を成していない以上、放置しない。

## 検証結果

**(3) はビット単位で同一であることをホストで確認した。**

```
$ c++ -O2 hess_test.cpp && ./hess_test
PASS: 50 試行すべて M がビット単位で一致
積和回数  密 = 249900   疎 = 92925   (37.2%, -62.8%)
```

（`Su.setZero()` → `j<=k` ブロックのみ乱数で埋める、を 50 回。
足していた項は `+0.0f` なので `x + 0.0f == x` により部分和が完全一致する。）

**(2) のしきい値の実値:**

| `u_hover` | `half_span` | `\|ws.z\|` の構造的上限 | 新しきい値 | 旧 |
|---|---|---|---|---|
| 0.20 | 0.750 | 6.87 | **5.50** | 1.0 |
| 0.40 | 0.550 | 5.04 | **4.03** | 1.0 |
| 0.475（最小） | 0.475 | 4.35 | **3.48** | 1.0 |
| 0.516（271 g ホバー） | 0.516 | 4.73 | **3.78** | 1.0 |
| **0.547（0919_v6）** | 0.547 | 5.01 | **4.01** | 1.0 |
| 0.644（v6 の最大） | 0.644 | 5.90 | **4.72** | 1.0 |
| 0.95 | 0.950 | 8.71 | **6.97** | 1.0 |

**新しきい値は 3.48〜6.97。0919_v6 の動作点で 4.01 であり、実測の `ulin_norm` 最大 2.66 を上回るので
あの飛行では一度も発火しない。**

- ビルド: `text 687168 → 687360`、`bss 422436 → 422772`（+336 B = `z_applied`）。
- ⚠ **実機未検証。フル再構築の実時間が 38.5 ms からどこまで下がったかも未測定。**
  演算量比（363,959 → 206,984 MAC）から**約 22 ms**を見込むが、
  実測は 15.9 cycle/MAC と演算量から予想される 3〜4 cycle/MAC の 4〜5 倍なので、
  **比例するとは限らない。次の飛行で `iter_us` の path=1 を必ず確認すること。**

## 次に触る人へ

- ⚠ **`build_hessian_from_su_w()` を TR1 更新後の `Su` に対して呼ばないこと。**
  TR1 はランク 1 更新なので上側ブロックを埋めうる。現状は `full_rebuild_chol()` からの 1 か所だけで、
  その直前に必ず `full_rebuild_sx_su()` が走るので成立している。
- ⚠ **v12 型（`|U_lin|` が 8 周期かけて単調増加）の検知は鈍くなった。** 発火してもその周期の duty を
  捨てなくなったぶんでコストは下がっているが、**検知能力の再確認はできていない**（当時の生ログが無い）。
