# 飽和時に共通モードを下げる（推力デサチュレーション）の設計方針。⚠ 先に「はみ出し量」を観測できるようにする

- **日付**: 2026-09-20
- **種別**: design
- **対象**: `Benzen_NMPC/control.cpp`(rate_control の NMPC 出力段, mix_duty, logging), `nmpc.cpp`(box)
- **タグ**: #Benzen_NMPC #飽和 #デサチュレーション #共通モード #B_c1=0 #ヌル空間 #FTC #設計

## 背景

[`20260920_v8_fixes_worked_but_payload_leaves_no_control_margin.md`](20260920_v8_fixes_worked_but_payload_leaves_no_control_margin.md)
の対策 4。貨物ありでは `du_max = 0.95 − u_hover` が 0.34 しかなく、巡航の `|Δu|` 最大 0.336 が
それに触れていた。「上が足りないなら全体を下げて差分の余地を作る」機構の設計方針。

## 原理: なぜ「全部下げる」が正しいのか

`repository_rules` §3 のとおり **`B_c · 1 = 0`**。全モータを同じ量 `s` だけ下げても

| | 6 発すべてを s=0.10 下げたとき |
|---|---|
| roll | **−0.0 deg/s²** |
| pitch | **−0.0 deg/s²** |
| yaw | **−0.0 deg/s²** |

**モーメントは厳密に不変。** 推力だけが減る。
⇒ **共通モードは姿勢ダイナミクスのヌル空間**であり、下げても姿勢指令を一切損なわない。

### ⚠ ソルバが自分で下げない理由

box は既に `Δu ∈ [−u_hover, 0.95 − u_hover]` で、**下げる自由はある**。
下げないのは**コスト**のせい: 共通モードは `B_c·1 = 0` により予測状態にまったく影響しないのに
`R_u‖Δu‖²` では等しく罰せられる。**したがって最適解の共通モード成分はちょうど 0 になる。**
⇒ **ソルバは構造的に絶対に下げない。外から与えるしかない。**

### ⚠⚠ 故障時（FTC）は成り立たない

FR 故障で健全 5 発だけを `s = 0.10` 下げると、`Σ_healthy kYm = −kYm_FR ≠ 0` なので

| | FR 故障・健全 5 発を s=0.10 下げたとき |
|---|---|
| roll | **−119.4 deg/s²** |
| pitch | **+192.2 deg/s²** |
| yaw | **−42.4 deg/s²** |

**モーメント中立ではない。FTC 中は無効化するか、ヌル空間方向を解き直す必要がある。**

## 実装場所の比較

| 案 | 場所 | 長所 | 短所 |
|---|---|---|---|
| **A 事後デサチュレーション** | **400 Hz の clamp 段** | ソルバ不変（TR1/SR2/ADMM の整合が壊れない）。**ZOH の 4 回すべてに効く**。モーメント厳密保存 | 高度が落ちる。⚠ FTC で無効化が要る |
| B 静的キャップ | 100 Hz の `u_hover` | 最も単純で安全 | ⚠ 常時スロットルを制限する |
| C 適応 sag（リーク付き） | 100 Hz | 必要な時だけ効く | ⚠ **新しいフィードバックループ**。2–3 Hz の発振モードと干渉するリスク |
| E `R` の共通モード緩和 | コスト関数 | 理論的に最も正しい | ⚠ `R` が非対角になり、`M.diagonal() += rbar` / SR2 のランク 2 更新 / LLT が全部壊れる。**大改修** |

**推奨は A。** E が本筋だが、いま触るべき規模ではない。C は発振と干渉しうるので却下寄り。

## A のアルゴリズム（2 段）

```
段 1: 共通モードで吸収する（モーメント不変）
  hi   = max_j duty_j            （健全モータのみ）
  lo   = min_j duty_j
  over = hi - U_duty_max                      // >0 ならはみ出し
  room = lo - floor_j                         // 下げられる量
  s    = min(over, room, SAG_MAX)
  全健全モータから s を引く

段 2: それでも収まらなければ差分をスケールする（向きは保ち、大きさだけ縮める）
  u_c = 共通モード（健全モータの平均）
  α   = (U_duty_max - u_c) / (hi - u_c)
  duty_j = u_c + α (duty_j - u_c)
```

⚠ 段 2 は「モーメントの**向き**を保つ」。現状のモータごとクリップは**向きごと歪める**ので、
段 2 だけでも改善になる。

## 実測による裏づけ（0919_v8）

| 区間 | duty min / max の中央値 | **sag に使える余地 `min_j duty − 0.1`** | box_n≥1 |
|---|---|---|---|
| **FR 張り付き (7.55–7.70 s)** | 0.487 / 0.928 | **中央 0.387（最小 0.306）** | 46% |
| 発散中 (8.40–8.55 s) | 0.424 / 0.950 | 中央 0.324（**最小 −0.100**） | 62% |

⚠ **張り付き区間には共通モードで吸収できる余地が 0.387 もあった。** 段 1 だけで足りた可能性が高い。
発散中は最小が −0.100（下端にも当たっている）ので **段 2 が必須**。

## ⚠ Step 0（先にやること）: はみ出し量が観測できない

`mix_duty()` が `[0, U_duty_max]` にクリップしてからログに入るので、
**「どれだけはみ出したか」は現在のログから一切分からない。**
`box_n` は「当たったかどうか」しか言わない。

→ **クリップ前の `max_j(u_hover + Δu_j)` と `min_j(...)` を 2 列追加する**（`du_hi` / `du_lo`）。
これがあれば **実装前に「s がいくつ必要だったか」をオフラインで確定できる。**

## 設計上の注意（実装時に必ず読むこと）

- ⚠ **FTC 中は無効化する。** 上表のとおりモーメント中立でない。
- ⚠ **`SAG_MAX` を置く。** 沈下量の見積り:

  | `s` | 推力減 | 重量比 | 下向き加速度 | 0.2 s での沈下 |
  |---|---|---|---|---|
  | 0.05 | 0.195 N | 6.4% | 0.63 m/s² | 0.013 m |
  | 0.10 | 0.390 N | 12.8% | 1.26 m/s² | 0.025 m |
  | 0.15 | 0.585 N | 19.3% | 1.89 m/s² | 0.038 m |

  短時間なら無視できるが**持続すると沈む**。`SAG_MAX = 0.10〜0.15` を上限に。
- ⚠ **下限は `floor_i`（対角発は 0、他は `minimum_duty`）と整合させる。** 既存の 400 Hz clamp と同じ規則。
- ⚠ **推力曲線の非線形性**: 下げると `dT/du` が上がる（`u`=0.644 で 0.638 → `u`=0.54 で 0.678）ので、
  実際のモーメントは **5% ほど増える**。モデルはこれを知らない。安全側。
- ⚠ **ソルバは sag を知らない。** 次周期の `u_hover` は据え置きで、毎周期 sag をやり直す（静的写像なので安定）。
  `U_lin` は sag 前の解なので実出力と**共通モードだけ**ずれるが、姿勢モデルは共通モードを見ないので実害はない。
- ⚠ **`duty_hist_push()` は 100 Hz 側にある。** 400 Hz で sag すると履歴と実出力がずれるが、
  遅れ補償は姿勢モデルで積分するので共通モードは効かない → 実害なし。**この前提が崩れる変更をしないこと。**

## 段階的な進め方

| Step | 内容 | 規模 |
|---|---|---|
| **0** | `du_hi` / `du_lo`（クリップ前）を 100 Hz ログに 2 列追加。`reset_cause` も足すなら計 3 列 → 33→36 列、リング 19.8 → 18.1 s | 小 |
| 1 | 段 1（共通モード吸収）のみ。**健全モード限定**、`SAG_MAX` 付き | 小 |
| 2 | 段 2（差分スケーリング） | 小 |
| 3 | FTC 対応（ヌル空間方向を解き直す） | 中 |

⚠ **Step 0 を飛ばさないこと。** 実装しても効いたかどうかを確認する手段が無い。

## 検証結果

**設計のみ。コード変更なし。** モーメント中立性・FTC での非中立性・沈下量はすべて計算値。
sag 余地は `0919_v8.txt` の実測。⚠ **必要な `s` そのものは現状のログからは求められない**（Step 0 の理由）。
