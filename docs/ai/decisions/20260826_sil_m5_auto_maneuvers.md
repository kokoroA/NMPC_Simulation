# SIL M5: 自動機動を検証し、バンク角が指令の 47% しか出ないことを発見

- **日付**: 2026-08-26
- **種別**: investigation
- **対象**: `Benzen_new/control.cpp`（Flight_duty 判定）, `program/sil/host/test_m5_auto_maneuvers.py`
- **タグ**: #SIL #M5 #auto_maneuver #自動旋回 #8の字 #上昇旋回 #バンク角 #カップリング #ロールゲイン

## 背景 / 症状

`20260824_benzen_new_auto_maneuvers.md` と `20260825_benzen_new_pitch_sign_figure8.md` に
**「実機軌道は未検証」**と残っていた自動機動 3 種を、墜落リスクなしで確かめるのが SIL の第一目的だった。

あわせて M4 で見つかった「モータは回るが姿勢制御が効かない帯域」を潰す必要があった。

## 対応

### 1. 姿勢ゼロ点判定も common_duty 基準へ統一

`Flight_duty` の判定は **2 か所**（`apply_auto_maneuver_refs` と PID Control）にあり、
どちらも `T_ref / BATTERY_VOLTAGE`（電圧比）と `Flight_duty`（duty）を比較していた。
停止判定と同じく `common_duty = T_ref * T_ref_coe` 基準に揃えた。**値 0.05 は変えていない。**

| | 条件 | スロットル比 |
|---|---|---|
| 姿勢制御が生きる | `common_duty >= 0.05` | **0.023** |
| モータ始動 | `common_duty >= 0.10` | **0.045** |

`Flight_duty(0.05) < Disable_duty(0.1)` なので**姿勢制御がモータ始動より先に生きる**。
M4 の危険帯域（モータは回るが姿勢制御が効かない）は消滅した。

> ⚠ **事故を起こしかけた。** 中断された試行が `control.cpp` の**ミキサ本体と
> duty クランプ処理 約 55 行を削除**していた（差分 107 行）。
> 元のバックアップから復元し、意図した 3 行だけを入れ直した。
> **編集後は必ずバックアップとの全差分を確認すること。** CRLF ファイルなので
> Python のテキストモードで書き戻すと全行が差分化する点も併せて注意。

### 2. SIL から実行時にモードを設定できるようにした

実機は `MOCK_AUTO_FLIGHT_MODE`（コンパイル時定数）かプロポでモードに入るが、
SIL では条件を変えて何度も試したい。`Flight_mode` は非 static のグローバルなので
`sil_set_flight_mode()` で直接書き込む形にした。
`g_thrust_delta_ratio` は `static` で読めないため、`T_ref` から逆算している。

## 発見: バンク角が指令の 47% しか出ない

| | 値 |
|---|---|
| 指令バンク | 17.98 deg |
| 実バンク | **8.40 deg** |
| 達成率 | **47 %** |

### 原因（数値で裏取り済み）

旋回中の運動学的カップリングである。

```
phi_dot = p + q sin(phi) tan(theta) + r cos(phi) tan(theta)
```

機首下げ（`theta < 0`）でヨーを回すと `r cos(phi) tan(theta)` が**バンクを倒す向きの
定常外乱**になる。ロール角度 PID は `Kp = 1.0`・**積分なし**（`control.cpp:699` の
`Ti = 100000`）なので、この定常外乱を打ち消せず偏差が残る。

定常では次で釣り合う:

```
Kp * (phi_ref - phi)  ≈  -(q sin(phi) + r cos(phi)) tan(theta)
     +0.1671 rad/s     ≈   +0.1526 rad/s        （相対差 9.5 %）
```

→ **偏差 ≈ 外乱 / Kp**。Kp=1.0 では約 9.6deg の偏差が構造的に残る。

### 実機への影響

- **旋回半径が設計より大きくなる。** バンクが半分なら旋回に必要な横加速度も半分。
- ピッチは逆に指令 -12deg に対し **-15.1deg** と行き過ぎている（ピッチ側は Kp=1.6 かつ
  弱い積分があるため、カップリングを押し返した結果）。
- **duty は 0.29 前後で飽和していない**（上限張り付き 0%）ので、
  制御余裕はある。ゲインの問題であって推力不足ではない。

### 対策の候補（未実施・判断待ち）

1. **ロール角度 PID に積分を入れる**（`Ti` を 100000 から現実的な値へ）。定常偏差を消せる。
2. **ロール Kp を上げる**（ピッチと同等の 1.6 付近へ）。偏差は 1/1.6 に減るが消えはしない。
3. **`auto_maneuvers` 側でバンク指令を先行補償する**（必要バンクから逆算して上乗せ）。
   ただし機体依存の補正になるので 1 か 2 が筋。

**どれも実機ゲイン変更を伴うので、SIL で効果を確認してから実機へ持っていくべき。**
