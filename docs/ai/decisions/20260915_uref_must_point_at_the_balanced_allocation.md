# `U_ref` は「残りで均等に肩代わり」ではなく「故障発とその対角を落とした釣り合い点」を指さねばならない

- **日付**: 2026-09-15
- **種別**: bugfix | design
- **対象**: `Benzen_NMPC/control.cpp` の `u_ref_shift` 生成（旧 2360-2372 付近）
- **タグ**: #FTC #U_ref #制御配分 #対角 #R_u #耐故障 #地上試験

## 背景 / 症状

「地上で FTC スイッチを入れてからスロットルを上げたとき、対角モータも止まるか」を確認するため、
実機と同条件（`N=14, dt=10 ms, Q_φ=1000, Q_p=80, Q_r=40, R_u=620`, box, `Motor_eta`, `U_ref` シフト）で
閉ループを解いたところ、**止まらなかった。**

`u_hover = 0.60`、FR 故障、姿勢誤差ゼロ（地上）での収束解:

```
u = [FR 0.000, FL 0.855, MR 0.859, ML 0.581, RR 0.585, RL 0.333]
```

⚠ **RL が 0.333 で回り続け、FL/MR が 0.86（上限 0.95 の間際）まで上がり、ML/RR と 0.27 の差がつく。**
内側反復を 50 → 20000 に増やしても同じ値なので、**ソルバの精度不足ではなく真の最適解**である。

離陸させると RL は **2.5〜3 秒**かけて 0 へ落ちるが、その過渡で
**ヨー率 +182 deg/s、φ +5.4°、θ −10.8°** が出た。

## 原因

旧実装（`control.cpp`）は

```cpp
const float up = u_hover * (float)n_lost / (float)n_healthy;
u_ref_shift[j] = (Motor_eta[j] > 0.5f) ? up : -u_hover;   // 健全発すべてに均等配分
```

＝「止まった分を**残り 5 発で均等に**肩代わり」を参照点にしていた。**この点はモーメントが釣り合っていない。**

`u_hover = 0.496` で評価すると

| | ピッチ `Σk_Xm·u` | ロール `Σk_Ym·u` | ヨー `Σk_S·u` |
|---|---|---|---|
| 旧 `U_ref` が指す点 | **−0.0506** | **−0.0298** | **+0.5955** |

`R_u` はこの点へ引き続け、`Q` は釣り合い点へ引く。
**姿勢誤差がまだ無い地上では `R_u` が勝つ**ので、対角は止まらない。空中で姿勢が崩れ始めて
初めて `Q` が勝ち、そこから再配分が始まる ── 観測された挙動そのもの。

### 正しい参照点は混合行列から一意に決まる

`f_FR = 0` としてロール・ピッチ・ヨーを釣り合わせると

```
ピッチ式 : f_FL = f_RR + f_RL
ロール式 : f_MR = f_ML + f_RL
ヨー式   : 上 2 式を代入すると 3·f_RL = 0   →  **f_RL = 0**
```

⚠ **鉛直（推力）式を使っていない。** つまり**姿勢だけを見ている NMPC にとっても
対角を落とすのが唯一の釣り合い点**であり、これは「推力も含めて解いたら偶然そうなった」話ではない。

## 対応

`u_ref_shift` の生成を書き換えた。

```
荷重を担う発 carry[j] = （j が健全） かつ （j の対角が健全）
n_carry 発で NU 発分を担う:  up = u_hover * (NU - n_carry) / n_carry
u_ref_shift[j] = carry[j] ? up : -u_hover
対角表 kDiag[6] = {5,4,3,2,1,0}   // FR↔RL, FL↔RR, MR↔ML
```

⚠ **変えたのは参照だけで box は触っていない。** 対角発は健全なままなので、
姿勢を保つのに必要なら solver はいつでも持ち上げられる。

### 却下した案

- **対角発も `Motor_eta` で殺す**: box を縮めると**本当に使えなくなる**。
  対角は健全であり、外乱に対しては使いたい。参照だけ 0 を指せば十分
- **`U_ref` に推力の逆関数を入れて厳密に揚力を保つ**: 実装が重い割に、
  モーメント釣り合いは「4 発が等しい」ことだけで決まるので不要。
  揚力不足はスロットルで足せばよい（⚠ 下記）

## 検証結果

- **ビルド成功**（`arm-none-eabi-gcc`, `make -j8`, 警告なし）
- **新ロジックをソースから機械的に抜き出してホストで全故障パターンを検査**（`/tmp/uref_test.cpp`）。
  健全・単発 6 通り・対角 2 発・隣接 2 発の **9 ケースすべてで
  `Σk_Xm·u = Σk_Ym·u = Σk_S·u = 0`（float 精度）、duty 合計も保存**

```
  FR 故障   u = *0.000  0.744  0.744  0.744  0.744 *0.000   pitch 0  roll 0  yaw 0   OK
  MR 故障   u =  0.744  0.744 *0.000 *0.000  0.744  0.744   pitch 0  roll 0  yaw 0   OK
  FR+FL     u = *0.000 *0.000  1.488  1.488 *0.000 *0.000   pitch 0  roll 0  yaw 0   OK（box で頭打ちになる）
```

- **閉ループ再シミュレーション**: 地上の時点で既に `u = [0, 0.900, 0.900, 0.900, 0.900, 0]`、
  **離陸時の過渡が完全に消えた**（φ, θ, r すべて 0 のまま）
- ⚠ **実機未検証。** 線形化モデル（`Cr` 等の空力項なし）でのシミュレーション

## 次に触る人へ

- ⚠ **`minimum_duty = 0.1` が残っている。** 400 Hz の clamp は
  `Motor_eta <= 0.5` の発だけを 0 にし、**健全な対角発は 0.1 へ持ち上げる**。
  solver は「RL = 0」で解いているのに実機は 0.1 を出すので、
  **`0.1 × C_QT·T_max/Iz ≈ 46 deg/s²` のヨートルクがモデル外の外乱として乗る。**
  残り 4 発で打ち消せる大きさだが、`Q_r = 40` は弱いので定常ヨー率が残る。**未対処**
- ⚠ **同じスロットルでは揚力が約 12% 減る**（duty 合計は保存するが推力が非線形なため）。
  故障後はスロットルを足す必要がある。313 g なら 4 発 0.837 ＝ `u_hover ≈ 0.558` が釣り合い
- ⚠ 隣接 2 発故障では参照が `1.5 × u_hover` を超えて box で頭打ちになる。
  これは「その故障が推力的に不可能」という既知の事実の反映であって、参照の誤りではない
