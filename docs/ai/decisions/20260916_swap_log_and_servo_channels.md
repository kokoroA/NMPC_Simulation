# `LOG` と `SERVO` のチャンネルを入れ替え、マクロを経由していなかった 1 箇所としきい値の流儀を直した

- **日付**: 2026-09-16
- **種別**: bugfix | design
- **対象**: `Benzen_NMPC/radio.hpp`, `control.cpp`（`logdata_out_com` / `logging` / `unique_mission`）
- **タグ**: #radio #SBUS #Chdata #LOG #SERVO #しきい値 #ログ

## 背景

送信機側の割り当て変更に合わせ、`radio.hpp` の `LOG` と `SERVO` のチャンネル番号を入れ替える
（`LOG 6 → 4`、`SERVO 4 → 6`）。

## 原因 / 判断根拠

マクロ経由の参照は入れ替えるだけで追随するが、**2 つ追随しない箇所があった。**

### (1) `logdata_out_com()` が `Chdata[4]` と直書きしていた（`control.cpp:1126`）

ログ吸い出し（`Arm_flag = 4` → `Logoutputflag = 1`）のトリガ。
直書きなので入れ替えの影響を受けず、**物理 ch4 のまま**になる。
従来 ch4 は `SERVO` だったので「ペイロード投下スイッチが下 ＋ スティック操作」で発火していた。

→ **ユーザ判断で `Chdata[LOG]` に合わせた。**
「ログを止めてから吸い出す」という自然な操作になり、直書きは元々の書き間違いだったと解釈する。

### (2) ⚠ しきい値の流儀がチャンネルごとに違う

`Chdata` は全チャンネルとも SBUS 生値（11 bit, 0–2047）で、スケールは共通。
しきい値だけが慣習で分かれていた。

| 用途 | 従来のしきい値 |
|---|---|
| `logging()`（旧 ch6） | `> 200` |
| `servo_control()`（旧 ch4） | `> (SERVO_MAX+SERVO_MIN)/2` = 1024 |
| `logdata_out_com()`（ch4 直書き） | `< (CH5MAX+CH5MIN)*0.5` = 1003 |
| `Chdata[FTC]`（ch5） | `> 500` / `< 200` |

**`> 200` は「OFF で 172 付近まで落ちる 2 ポジションスイッチ」を前提にした値。**
ch4 は既存の 2 箇所がどちらも**中央しきい値**で扱ってきたチャンネルで、
下限が 172 まで落ちない（3 ポジション / ボリューム）可能性がある。

⚠ **`> 200` のまま ch4 へ移すと、下限が 368 付近なら常に真になり、リングログが回りっぱなしになる。**

→ **ユーザ判断で中央しきい値へ変更した。** 中央しきい値は 2 ポジション・3 ポジション・
ボリュームのいずれでも正しく効くので、前提が外れても壊れない。

## 対応

| 箇所 | 変更 |
|---|---|
| `radio.hpp` | `#define LOG 4` / `#define SERVO 6`（入れ替えの経緯をコメントに明記） |
| `control.cpp:1129` | `Chdata[4]` → `Chdata[LOG]` |
| `control.cpp:2656` | `Chdata[LOG] > 200` → `> (CH5MAX + CH5MIN) / 2` |
| `control.cpp:3581` | `unique_mission()` の `Chdata[LOG] < 200` も同じ流儀へ（⚠ この関数はどこからも呼ばれていない。将来復活させたときの罠を残さないため） |

### 触らなかったもの

- **`servo_control()` のしきい値**: `(SERVO_MAX+SERVO_MIN)/2` = 1024。
  SBUS の中央（約 991）に近く、ch6 でもそのまま妥当。変える理由がない
- `Chdata[FTC]`（ch5）の `>500 / <200`: 入れ替えと無関係

## 検証結果

- **ビルド成功、警告ゼロ**。`text 684544 / bss 422428`（入れ替え前と同一＝コード量は不変）
- **生インデックス参照の残りを grep で確認**: スティック（0–3）以外に `Chdata[4..7]` の
  直書きは**コメント内の 1 件のみ**で、有効行には残っていない
- しきい値の対を数値で確認:

| `Chdata[LOG]` | 記録（`>1003`） | 吸い出し（`<1003`） |
|---|---|---|
| 172 / 368 / 500 | off | armed |
| 1003 | off | − |
| 1004 / 1500 / 1811 | **ON** | − |

  **記録と吸い出しが排他になり、「スイッチ上で記録 → 下ろしてスティック操作で吸い出し」という
  一貫した操作になった。** 1003 ちょうどの 1 値だけ両方 false（不感帯）だが実害なし
- ⚠ **実機未検証。** ch4 / ch6 の実際のスイッチ種別と生値は未確認で、
  上記は「中央しきい値ならどれでも効く」という設計上の保証に依っている
