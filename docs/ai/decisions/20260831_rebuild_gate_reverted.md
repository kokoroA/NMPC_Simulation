# フル再構築の飛行中禁止を撤回（`rebuild_max_u_hover` 0.30f → 1.0f）

- **日付**: 2026-08-31
- **種別**: rejected | design
- **対象**: `Benzen_NMPC/nmpc_params.hpp` (`rti::rebuild_max_u_hover`)
- **タグ**: #Benzen_NMPC #reset_period #rebuild_max_u_hover #TR1 #SR2 #数値漂流 #N #撤回

## 背景 / 症状

2026-08-31 に「フル再構築（58 ms）は制御周期 10 ms の 6 倍なので飛行中に入れるべきでない」と判断し、
`u_hover < 0.30` に限定した。結果、`0831_v3.csv` で**飛行時間とともに操作性が単調に劣化**
（`cycles_since_reset` と姿勢誤差の相関 +0.70、duty ばらつき 0.02→0.84）。

## 原因 / 判断根拠

**判断を誤っていた点は 2 つ。**

1. **周期フル再構築が担っていた役割（TR1/SR2 の数値漂流の洗い流し）を代替せずに止めた。**
   `nmpc.cpp` のコメントに「差分更新の数値誤差累積対策」と明記されていたにもかかわらず、
   停止コストだけを見て止めた。
2. **危険性を絶対値で評価した。** 58 ms の停止が危険かどうかは**その時の機体の状態で決まる**。
   `0831_v1`（R_u=28）では 100–200 deg/s で発振中だったため 58 ms × 150 deg/s ≈ 9° になったが、
   `R_u=120` にした後は q rms 13 deg/s で、同じ 58 ms は **約 0.8°** にとどまる。
   **「常に危険」と一般化したのが早すぎた。**

代替手段が用意できていない以上、**元に戻すのが正しい。**

## 対応

`rebuild_max_u_hover` を **0.30f → 1.0f**（常時許可）に戻した。
判断の経緯はヘッダのコメントに残し、`docs/20260831_nmpc_status_and_actions.md` へリンクした。
`reset_period = 100` / `R_u = 120` / `N = 17` / `T_max` / `mass` は不変。

**却下した案**: ゲートを残したまま重みで押さえ込む。
劣化の原因が数値漂流なら、重みをどう振っても時間とともに悪化する。症状ではなく原因を潰す。

**却下した案**: いきなり core0 シャドウ再構築を実装する。
`H`+LLT だけで約 83 kB のシャドウが必要で、bss 402 kB / SRAM 520 kB、core0 スタック 32 kB を引くと
残り約 86 kB。**成立するか未検証**。まず戻して切り分けるほうが速い。

## 検証結果

- `static_assert` で確認: `rebuild_max_u_hover == 1.0f`, `R_u == 120.0f`, `reset_period == 100`,
  `N == 17`, `T_max == 1.04f`, `mass == 0.32f`。**すべて成立。**
- ビルド成功。`text 674696 → 674624`、`bss 402456` 変化なし。
- 成果物 `build_fresh/pico_copter.uf2`（2026-08-31 19:05）。
- **実機での効果は未検証。** 次の飛行が切り分け実験そのもの。
- ⚠ **`Q_phi`/`Q_theta` が 50→100、`Q_r` が 6→20 にユーザによって変更されている。**
  `0831_v3.csv`（18:47）がどちらの値で飛んだかは**ビルド成果物が上書きされており判別不能**。
  v3 の解析は 50/6 前提で書かれている。**要確認。**

## 次に触る人へ

- **「安全のために何かを止める」前に、それが何をしていたのかを確認すること。**
  今回はコメントに役割が書いてあったのに読み落とした。
- **リアルタイム系の「危険な処理時間」は絶対値で判断しない。**
  同じ 58 ms でも、発振中なら 9°、静穏時なら 0.8°。閾値は機体の状態と対で決める。
- **`cnt_*` が 0 のままの項目は「健全」ではなく「機能していない」を疑う。**
  `cnt_tr1_skip = 0` は secant ガードが一度も効いていないことを示していた。
- 根治の本命は **`N` の短縮**（再構築コストは概ね `N³`、17→12 で約 20 ms、17→10 で約 12 ms）。
  **`loop_us` の 10 ms 超過と同じノブ**で両方解ける。
