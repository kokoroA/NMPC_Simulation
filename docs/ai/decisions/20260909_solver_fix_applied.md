# ソルバ修正を実装。勾配→定数項、admm_max_iter 2→10、安全弁 3 段。rho は上げない

- **日付**: 2026-09-09
- **種別**: bugfix | design
- **対象**: `Benzen_NMPC/nmpc.cpp`, `nmpc.hpp`, `nmpc_params.hpp`, `control.cpp`
- **タグ**: #Benzen_NMPC #ADMM #勾配 #チャタリング #NaN #安全弁 #admm_rho #admm_max_iter #EKF再初期化

## 背景

[`20260909_admm_gradient_bug_root_cause.md`](20260909_admm_gradient_bug_root_cause.md) で特定した
2 つのバグ（勾配の使い方 / ADMM 双対の発散）を実装で潰した。

## 原因 / 判断根拠

**① 勾配ではなく定数項を使う。** `admm_solve` の U 更新は `(H+ρI)U = -c + ρ(z-λ)` であり、
必要なのは `c` であって `compute_gradient` が返す `g = H·U_lin + c` ではない。
`g` を使うと `U_new ≈ -U_lin - H⁻¹c` となり**固有値がちょうど −1** の減衰しない周期 2 振動になる。
`H·U_lin = M·U_lin - ρ·U_lin` なので追加は matvec 1 回。反復間で不変なのでループ外で 1 回だけ作る
（`NmpcScratch::admm_neg_c` を新設、120 float = 480 B）。

**② `ρ` は上げず、反復回数を増やす。** 当初は `ρ` を `diag(M) ≈ 186` と同桁に上げる方針だったが、
**実ファイルで掃引したら追従が壊れた**。`ρ` を大きくすると近接項が支配し、有限反復では
主変数が最適解へ届かず過減衰になる。

| `ρ` (iter=5) | 追従相関 R/P/Y | 飽和 |
|---|---|---|
| **1.0** | **0.45/0.40/0.89** | **4.5 %** |
| 10 | −0.17/0.15/0.84 | 10.1 % |
| 186 | −0.06/−0.03/0.10 | 27.5 % |
| 1000 | −0.14/0.14/0.67 | 17.4 % |

`ρ = 1.0` 据え置きで `admm_max_iter` を 2 → **10**（5 → +0.810 / 10 → **+0.998** / 20・40 も同じ＝頭打ち）。

**③ 安全弁 3 段。** バグを直しても想定外で壊れる可能性は残るので、
**「壊れても電源を切るまで戻らない」状態を作らない**ことを目的に入れた。

- `|λ| > admm_lambda_max` で `λ` をゼロに。`!(x < 上限)` と書き **NaN も同時に捕まえる**。
  しきい値 30 は掃引で決定（非有限の発生回数: 1e3→16, 1e2→31, **30→7**, 10→34）。
- 解が非有限なら `U/z/λ` を捨て `ws.valid=false` + `need_full_rebuild`。
  **`Δu = 0`＝水平ホバー指令に落ちる**（モータ停止ではない）。
- 姿勢推定の破綻検出（`|phi|,|theta| > 2π` / `|p,q,r| > 40 rad/s` / 非有限）→ `ekf_reinit()`。
  0909_v1 では墜落の衝撃で `phi = -336 deg` になり、**再アームでも直らなかった**。
  `control.cpp` の `isnan`/`isfinite` 使用はこれまで **0 箇所**だった。
- 発動回数をログダンプの `#solver:` 行に出す。**発動していること自体が異常の兆候。**

**却下した案**: `ρ` を 200–1000 に上げる。当初のホスト実験（スクラッチのコピー）では良く見えたが、
**実ファイルで再現しなかった**。過減衰で追従相関が負になる。
⚠ 最初の実験で `-I` によるヘッダ差し替えが効いていなかった可能性があり、
**「実際に編集したファイルで測り直す」ことでしか気づけなかった。**

**却下した案**: `T_max = 0.81` を同時に入れる。修正で実効ゲインが約 2 倍、`T_max` でさらに 1.28 倍＝
合計 2.6 倍。ホスト実験では修正後でも `T_max` 1.28 倍で 538 周期後に NaN。

## 対応

実装資料 [`docs/20260909_solver_fix_implementation.md`](../../20260909_solver_fix_implementation.md)（用語集つき）。

- `nmpc.cpp`: `admm_neg_c` による定数項の算出、安全弁 1・2
- `nmpc.hpp`: `NmpcScratch::admm_neg_c`、`cnt_admm_lambda_reset` / `cnt_nonfinite`
- `nmpc_params.hpp`: `admm_max_iter` 2 → **10**、`admm_lambda_max = 30.0f` 新設、`admm_rho` は **1.0 のまま**
- `control.cpp`: `attitude_state_sane()` / `ekf_reinit()` と `angle_control` の分岐、`#solver:` ログ行

## 検証結果

**ビルド成功。** `text 676432 → 678224 (+1792)`, `bss 352220 → 352560 (+340)`。

ホスト閉ループ（実機のソルバをそのままビルド、プラント＝同じ剛体モデル + モータ遅れ 50 ms）:

| | ラグ1 | 振幅比 R/P/Y | 相関 R/P/Y | 飽和 |
|---|---|---|---|---|
| 修正前 | **−0.962** | 0.42/0.48/0.53 | 0.24/0.27/0.51 | **23.4 %** |
| 修正後 | **+0.998** | 0.53/0.52/**0.91** | 0.44/0.43/**0.92** | **0.5 %** |

- 全ファイルの改行コード（`nmpc.*` は LF、`control.*` は CRLF）が編集前後で不変であることを確認。
  ⚠ 作業中に一度 `nmpc_params.hpp`（LF）へ CRLF を 10 行混入させ、検出して戻した。
- ⚠ **安全弁は今も発動する。** 指令が大きい条件では 1500 周期あたり `lambda_reset` 7–155 回、
  `nonfinite` 7–38 回。**ADMM の双対が健全になったわけではなく、安全弁が固着を防いでいる状態。**
- **実機では一切未検証。** `admm_max_iter` が 2 → 10 で **LLT solve が 5 倍**になるため、
  **`iter_us` の実測が最初の関門**（現状平均 6.4 ms / 予算 10 ms）。

## 次に触る人へ

- **`iter_us` を測るまで飛ばさない。** 10 ms に収まらなければ `admm_max_iter` を 5 に落とせる
  （安全弁の発動が増えるが破綻はしない）。
- **`T_max = 0.81` を一緒に入れない。** 合計 2.6 倍のゲイン増になる。
- **`#solver:` 行が全部 0 であることを毎回確認する。** 0 でなければ数値が壊れかけている。
- **チューニング値は「実際に編集したファイル」で測り直す。**
  コピーを patch して測った値が本物と一致するとは限らない（本件で `ρ` の結論が逆転した）。
- **安全弁 1・2 は根治ではない。** ADMM 双対の挙動は改善余地が残っている
  （over-relaxation、λ の要素ごとクリップ、ρ の適応調整など）。
