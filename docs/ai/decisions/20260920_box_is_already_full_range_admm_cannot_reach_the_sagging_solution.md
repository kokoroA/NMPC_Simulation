# box は既に `[0, 0.95]` そのもの。共通モードが下がらないのは制約ではなく **ADMM 4 反復が最適解に届かない**から

- **日付**: 2026-09-20
- **種別**: investigation
- **対象**: `Benzen_NMPC/nmpc.cpp`(delta_u_bounds_eta, admm_solve), `control.cpp`(mix_duty, logging), `nmpc_params.hpp`(admm_rho, admm_max_iter)
- **タグ**: #Benzen_NMPC #ADMM #box #admm_rho #飽和 #共通モード #ログの解釈

## 問い

1. 議論してきた duty は実際に出た値か、クリップ前か。
2. box を `[0, 0.95]` にすれば済むのではないか。

## (1) ログの duty は「ADMM が box へ射影した後の指令値」

```
nmpc_step : U_opt(j) = clamp(z_applied(j), du_min(j), du_max(j))   ← box で確定済み
mix_duty  : d = u_hover + du; clamp [0, duty_max]                   ← ⚠ 冗長。何もしていない
FR_duty.. : ここが logging() でログに入る                            ← ★議論してきたのはこれ
400Hz     : floor_i / maximum_duty の clamp、NaN ガード、η→0、ベンチ素通し
          : Failsafe / ゲート閉 / common_duty<Disable_duty / OverG なら motor_stop()(=0)
```

- ⚠ **クリップ前の「本当はいくら出したかったか」はどこにも残っていない。**
- ⚠ **実際に PWM へ出た値でもない。** 400 Hz 段が上書きしうる（v8 の墜落後の 0.1 表示がその例）。
- ⚠ **`mix_duty()` の clamp は冗長。** `du_max = η·0.95 − u_hover` なので `u_hover + du ≤ 0.95` は既に保証されている。
  **実質のクリップは ADMM の射影 `ws.z = (ws.U + λ).cwiseMin(du_max).cwiseMax(du_min)`。**
  → 前回提案した「`mix_duty` のクリップ前を出す」は**誤り**。出すべきは **`ws.U`（射影前の主変数）**。

## (2) box は既に `[0, 0.95]`

```c
du_min = -u_hover;                       // → u = u_hover + du = 0
du_max = eta * U_duty_max - u_hover;     // → u = 0.95
```

`u_j = u_hover + Δu_j ∈ [0, 0.95]`。**「box を [0,0.95] にする」は同じ集合の別表示にすぎず、何も変わらない。**

### では何が共通モードの低下を妨げているのか

`Δu = c·1 + d`（共通 + 差分）と分解する。確認済みの事実:

- `B_d = dt · B_c` かつ `B_c · 1 = 0`（健全時）→ **`Su · 1 = 0`** → 状態コストは `d` にしか依存しない。
- `rbar(k·NU+j) = R_u` で**全モータ一様** → `‖Δu‖²_R = R_u(6c² + ‖d‖²)`（直交分解）。

⇒ **制約が効いていなければ最適な `c` はちょうど 0。**
⇒ ⚠ **制約が効いていれば最適な `c` は負になりうる**（下げれば `d` の余地が増えるので）。
**つまり「飽和時に共通モードが下がる」解は、今の box + コストの定式化の最適解に既に含まれている。**

### ⚠⚠ しかし ADMM 4 反復ではその解に届かない

`ρ = 1.0` に対し `diag(M) ≈ SuᵀQSu(≈284) + R_u(620) ≈ 900`。**ρ は対角の 0.1%。**
近接項がほとんど効かないので、実質「無制約で解いて最後に射影」に近い。
共通モードを下げるという協調は**双対 λ が育って初めて現れる**ので、4 反復では出ない。

実測（`0919_v8`）:

| | `lam_norm` |
|---|---|
| `box_n == 0` | p50 0.000 / p99 0.000 |
| `box_n == 1` | p50 1.400 / max 3.467 |
| `box_n == 3` | p50 5.547 / max 6.526 |
| ★飽和区間 7.55–7.70 s | 0 → 1.63 → 0（**育ち切る前に終わっている**） |

## ⚠ 自然な 2 案はどちらも却下済み

| 案 | 却下の根拠 |
|---|---|
| **`ρ` を上げる** | [`20260909_solver_fix_applied.md`](20260909_solver_fix_applied.md) の**実ファイル掃引**: ρ=1.0 で追従相関 R/P/Y = 0.45/0.40/0.89・飽和 4.5% → **ρ=10 で −0.17/0.15/0.84・飽和 10.1%**、ρ=186 で壊滅。⚠ **過減衰で有限反復では主変数が最適解へ届かない** |
| **反復回数を増やす** | `admm_max_iter` は **2 → 10 → 4**。`nmpc_params.hpp` のコメントに「旧 2 -> **10(墜落)** -> 4」 |

⚠ **当時から変わったのは `N` 17→14 程度で、ρ の過減衰という性質は変わっていない。再提案しない。**

⇒ **だから明示的なデサチュレーション（[`20260920_collective_sag_desaturation_design.md`](20260920_collective_sag_desaturation_design.md) の案 A）が筋。**
ADMM のチューニングを触らずに、最適解が持っているはずの「共通モードを下げる」成分を外から与える。

## ⚠ 補足: `Su · 1 = 0` は厳密には「フル再構築直後だけ」

TR1 は `Su += u_rk1 · s_uᵀ` のランク 1 更新なので、`s_u` に共通モード成分があると
`(u_rk1 s_uᵀ)·1 = u_rk1 (s_uᵀ·1) ≠ 0` となり、**更新後の `Su` はわずかに共通モード感度を持つ**。
効果は小さいが、「共通モードは厳密にヌル空間」という主張はフル再構築直後にのみ厳密。

## 対応

**調査のみ。コード変更なし。**
Step 0 の内容を訂正: `mix_duty` 前ではなく **`ws.U` の第 1 ブロック 6 個の max/min** をログに出す。
