# 50 Hz チャタリングの正体は勾配の使い方のバグ（写像の固有値が −1）。NaN は ADMM 双対の発散

- **日付**: 2026-09-09
- **種別**: investigation | bugfix
- **対象**: `Benzen_NMPC/nmpc.cpp`(`compute_gradient` / `admm_solve`), `nmpc_params.hpp`(`admm_rho`, `admm_max_iter`, `T_max`)
- **タグ**: #Benzen_NMPC #チャタリング #ADMM #勾配 #RTI #固有値-1 #NaN #双対発散 #admm_rho #T_max #ホスト検証

## 背景

50 Hz 毎周期反転チャタリング、NaN によるモータ固着、`T_max` の焼き込み可否、ピッチ 1–3 Hz の 4 件を調査した。
**実機のソルバ（`nmpc.cpp` + `nmpc_model.cpp`）をそのまま macOS でビルドして閉ループ実験**を行った。

## 原因 / 判断根拠

**確認済み事実（ホスト再現）。チャタリングはソルバ内部の問題。**

プラントをモデルと同じ式（＝モデル誤差ゼロ）にしても**チャタリングが完全に再現した**
（ラグ1 自己相関 **−0.962**）。**状態は完全に滑らかで Δu だけが毎周期反転する。**
機体・センサ・空力は無関係。

**確認済み事実。原因は勾配の使い方。**

`compute_gradient` は `U_lin` における**完全な勾配 `g = H·U_lin + c`** を返す
（`H = Suᵀ Q̄ Su + R̄`、`c = Suᵀ Q̄ (Sx x0 − X_ref) − R̄ U_ref`）。
ところが `admm_solve` はそれを**絶対解の右辺として** `rhs = -g + rho(z-lambda)`, `U = M⁻¹ rhs` に使う。
ADMM の U 更新は本来 `(H+rho I) U = -c + rho(z-lambda)` で、**`c` であって `g` ではない**。

`M = H + rho·I` かつ `rho=1` に対し **`diag(M) ≈ 186`（ホストで実測）**なので `M ≈ H`。よって

```
U_new ≈ -U_lin - H⁻¹c        固有値ちょうど -1 → 減衰しない周期 2 振動
不動点 U = -H⁻¹c / 2          → 実効ゲインが正しい解の半分
```

**これまでの観測がすべて説明できる**: ラグ1 ≈ −1 / フル再構築で消えない（`H` を作り直しても固有値は −1）/
指令の大きさに比例（振幅 ∝ `|U_lin|`）/ 追従振幅比が 0.4–0.7 と低い（平均が正解の半分）。

⚠ [`20260904_duty_chatter_50hz_nullspace.md`](20260904_duty_chatter_50hz_nullspace.md) で
「ADMM 未収束だけでは説明が付かない」と書いたのは正しかったが、
**当たりを ADMM に置いていた点が誤り。原因は勾配の使い方である。**

**確認済み事実。ADMM 双対 λ が box 有効化と同時に発散する。**

勾配だけ直すと **43 周期で NaN**。λ のノルムを追うと box に当たった瞬間から
`0.15 → 3.9 → 45.6 → 2372 → NaN` と **1 周期で 10–50 倍**に発散する。
`rho=1` に対し `diag(M)≈186` なので U 更新は λ を 1/186 にしか見ないのに、
`lambda += U - z` はフルに足し込む。**主変数が追いつけず双対だけが走る。**

**現行コードで λ が 0 のままなのは、勾配バグのチャタリングが `|U|` を小さく保ち box に当たらないから。
片方だけ直すと必ず NaN になる。**

**これが実機の NaN 固着の機構でもある。** 飛行中の飽和 7–23 % で λ が育ち、
墜落時の連続飽和で溢れて NaN → `control.cpp:1579` の NaN ガードが `minimum_duty=0.1` に置換 →
**全 6 発が duty 0.1 で回り続ける**。`do_full_rebuild()` は `ws.lambda` を触らないので
周期再構築ではリセットされず、λ が消えるのは `nmpc_mark_external_rebuild()`（スロットルを下げたとき）だけ。

**確認済み事実。ピッチ 1–3 Hz は操縦者由来ではない。**
`theta_ref` の 1–3 Hz は **1.1 %（rms 0.95°）**なのに `theta` は **23.3 %（rms 2.17°）**、
その帯域の相関は **−0.08**（ロールは +0.40）。**PIO ではない。**

## 対応

**コード変更なし（調査のみ）。** 資料
[`docs/20260909_solver_gradient_bug_and_admm_divergence.md`](../../20260909_solver_gradient_bug_and_admm_divergence.md)。

**修正案（ホストで検証済み、実機未適用）。3 つで 1 組。片方だけ入れない。**

1. `rhs = (M*U_lin) - rho*U_lin - g + rho*(z - lambda)`（＝ `c` を使う）。
   追加コストは 120×120 matvec 1 回で LLT solve 1 回分程度。
2. `admm_rho` を `diag(M)` と同桁の **200–1000**、`admm_max_iter` を **2 → 5**。
3. 無条件の安全弁: `|λ|` 上限で `λ.setZero()` / 非有限検出で `ws.valid=false` /
   姿勢推定の非有限・発散検出で EKF 再初期化（現状 `control.cpp` の `isnan`/`isfinite` 使用は **0 箇所**）。

**却下した案**: `T_max = 0.81` を先に焼く。
**現行は勾配バグで実効ゲインが半分**なので、直すとゲイン 2 倍、`T_max` でさらに 1.28 倍＝**合計 2.6 倍**。
実験では**現行のまま `T_max` を焼くとチャタリングが悪化**（ラグ1 −0.485 → −0.718）、
**修正後でも `T_max` 1.28 倍を重ねると 538 周期で NaN**。`R_u` を上げる等の手当と対でしか入れられない。

**却下した案**: ピッチの `Q_theta` を下げる。1–3 Hz は指令と無相関で、②の影響下の閉ループモード。
**バグを抱えたまま重みを合わせ込むと、直した瞬間に全部やり直しになる。**

## 検証結果

ホスト閉ループ（プラント＝同じ剛体モデル + モータ一次遅れ 50 ms）:

| 設定 | ラグ1 | 振幅比 R/P/Y | 相関 R/P/Y | 飽和 | NaN |
|---|---|---|---|---|---|
| 現行 | −0.485 | 0.50/0.49/0.60 | 0.32/0.30/0.68 | 0.0 % | なし |
| 現行 + `T_max` ×1.28 | **−0.718** | 0.51/0.50/0.67 | 0.38/0.31/0.74 | 0.9 % | なし |
| 勾配修正のみ | — | — | — | — | **k=43** |
| **勾配修正 + `rho=1000`,`iter=5`** | **+0.999** | 0.52/0.51/**0.81** | 0.40/0.38/**0.84** | 0.0 % | なし |
| 勾配修正 + 上記 + `T_max` ×1.28 | — | — | — | — | **k=538** |

モデル誤差ゼロのプラントでは、勾配修正だけで **\|Δduty\|/周期が 0.4289 → 0.0006（715 分の 1）**、
飽和 23.4 % → 0.0 %。

- `diag(M)` の実測: min 157.7 / max 221.8 / mean **185.9**（`R_u=120`, `admm_rho=1.0`）。
- λ の発散は `rho=200,iter=5` で `|λ|max = 20.8`、`rho=1000,iter=5` で `3.4` に収まる。
- **実機では一切未検証。** `admm_max_iter` を 5 にすると LLT solve が 2 → 5 回になるので、
  **実機での `iter_us` 計測が必須**（現状平均 6.4 ms）。

## 次に触る人へ

- **「勾配」と「線形化点からの増分」を混ぜない。** `∇J(U_lin)` を絶対解の右辺に使うと
  写像の固有値が −1 になり、**コンパイルも通り数値も発散せず、ただ毎周期反転し続ける。**
  症状は「制御が効かない」「振幅が半分」であって、ソルバのエラーとしては何も出ない。
- **ソルバの疑いはホストで再現するのが最短。** `nmpc.cpp` / `nmpc_model.cpp` は
  Eigen だけに依存するのでそのまま `c++` でビルドできる（`-DEIGEN_NO_MALLOC` は外す）。
  **プラントをモデルと同一にして症状が残れば、機体側の可能性は完全に消える。**
- ⚠ **`#include "..."` は「そのヘッダのあるディレクトリ」を最優先する。**
  `-I` でヘッダを差し替えたつもりの掃引が全部同じ結果になったら、これを疑う。
  ソース一式をコピーしてから差し替えること（本調査で一度この罠に落ちた）。
- **`do_full_rebuild()` は warm-start（`U`/`z`/`lambda`）を触らない。** 状態の持ち越しに注意。
