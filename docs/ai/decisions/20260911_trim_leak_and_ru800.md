# 積分トリクにリークを入れ、上限を「安全弁」に降格。R_u 620→800。ヨーは帯が狭すぎて一度も動けていなかった

- **日付**: 2026-09-11
- **種別**: bugfix | tuning
- **対象**: `Benzen_NMPC/nmpc_params.hpp`(namespace trim, R_u), `control.cpp`(att_trim_update)
- **タグ**: #Benzen_NMPC #積分作用 #リーク #アンチワインドアップ #トリム飽和 #R_u #ヨー #チャタリング

## 背景 / 症状

[`20260911_v11_twitch_is_yaw_not_rebuild_and_trim_saturated.md`](20260911_v11_twitch_is_yaw_not_rebuild_and_trim_saturated.md)
の対処 1（積分器を張り付かせない）と 3（`R_u` 620→800）の実装。

## 原因 / 判断根拠

### (1) リークを入れて、上限を「挙動を決める値」から「安全弁」へ降格した

0911_v11 では `trim_roll` が t=12 で上限 +6 deg に達し**飛行終了まで張り付いた**。
張り付いた積分はもう誤差を消しておらず、操縦者の指令から 5–6 deg ずれた目標を追い続けるだけだった。

毎周期 `trim *= (1 − dt/leak_tau)` を入れると、積分路の直流ゲインが `G = ki·leak_tau` に**有限化**される。
定常誤差は `e_open/(1+G)`、トリムは `G·e_open/(1+G)` に落ち着く ── **上限に頼らずに決まる。**
⚠ 交換条件として**定常誤差は完全には消えない**（`att` 側で G=2.5 → 71 % 減）。意図的な選択である。

### (2) ⚠ 軸ごとにリークの強さを変えた — 張り付いていないヨーに強くかけたら性能だけ落ちた

最初は共通 `leak_tau = 10 s` にした。ホストで**ヨーが明確に悪化**した:
ヨー外乱 46 deg/s² での追従が **100 %（v11 設定）→ 51 %**。
`trim_yaw` は 0911_v11 でも −11.6…+12.1 deg/s で**上限 25 に一度も触れていない**＝張り付いていない。
**リークは「張り付きを防ぐ」機構なので、張り付かない軸に強くかけるとただ削るだけ。**
→ `att_leak_tau = 10 s`（G=2.5）、`yaw_leak_tau = 30 s`（G=7.5）に分けた。

### (3) ⚠ ヨーの積分帯が「直したい誤差」より狭く、一度も動けていなかった

`yaw_err_max = 20 deg/s` にしていたが、ホストでヨー外乱 80 deg/s² を与えると
**無補正の定常誤差が 27 deg/s** あり、**帯の外なので積分が凍結したまま**だった。
`trim_yaw` は −0.2 deg/s しか育たず、追従は −172 % のまま（＝積分を入れた意味がゼロ）。

**帯が誤差より狭いと、その積分器は永久に仕事をしない。** 45 deg/s へ広げた。
巻き上がりの歯止めは (1) のリーク側が持っているので、帯は緩めてよい。

### (4) ⚠ 上限を予想される定常値のすぐ下に置くと、直したはずの張り付きが再発する

一度 `att_max = 2.5 deg` / `yaw_max = 12 deg/s` にしたが、リークで決まる定常値
（外乱 100 で 3.7 deg、ヨー外乱 46 で 14.8 deg/s）が**その上**にあるため、
ホストで**常時クランプ**していた。上限は予想値より明確に上に置く必要がある。
→ `att_max = 4 deg`、`yaw_max = 20 deg/s`（0911_v11 の実使用は 12 deg/s）。

### (5) `R_u` 620 → 800

単独では 0911_v9 で「水平を保てない」となった値だが、**あのときは積分作用が無かった**。
`R_u` を上げると実機 K角 が 0.852→0.665e-3 と落ち、定常外乱に負けて垂れるのが原因だった。
定常分を積分が持つようになったので、比例ゲインを下げても垂れないはず。
狙いは v11 のピクつき（指令外のヨーの蹴り、1.9 秒に 1 回）の低減で、
`R_u` はヌル空間に残る毎周期反転成分を抑える**唯一の項**である
（[`20260904_duty_chatter_50hz_nullspace.md`](20260904_duty_chatter_50hz_nullspace.md)）。

## 対応

| | 旧 | 新 |
|---|---|---|
| `att_ki` / `yaw_ki` | 0.5 | **0.25**（時定数 4 s） |
| リーク | なし | **`att_leak_tau`=10 s / `yaw_leak_tau`=30 s** |
| `att_max` / `yaw_max` | 6 deg / 25 deg/s | **4 deg / 20 deg/s** |
| `yaw_err_max`（積分帯） | 20 deg/s | **45 deg/s** |
| `R_u` | 620 | **800** |

## 検証結果

ホスト（出荷ソース、`control.cpp` の積分ロジックを同じ式でハーネスに再現）。

| 外乱 | ロール +12 deg 保持 なし → **あり** | ヨー率 −10 deg/s なし → **あり** |
|---|---|---|
| 0 | 100 % → 100 % | 97 % → **100 %** |
| 46 | — | **−63 %** → **77 %** |
| 50 | 122 % → **107 %** | — |
| 80 | — | **−174 %** → **7 %**（上限 20 で頭打ち） |
| 100 | 143 % → **113 %** | — |

**安全確認**: 実機がモデルの 0.7 / 2.0 / 3.0 倍（外乱 100）で**破綻なし**、
いずれも積分なしより改善（156→126, 121→107, 114→104 %）。
**外乱が 8 s で消えた場合**トリムは −3.66 → **−0.24 deg** まで解け、定常 95 %。
ヨー外乱 80・実機 2 倍でも −174 % → **81 %**。

ビルド **警告・エラー ゼロ**、`text 683408 / bss 422388`、CRLF 維持。**実機では未検証。**

## 次に触る人へ

- ⚠ **本便は「トリクの作り直し」と「R_u の変更」が同時に入っている。**
  結果が読めなければ **まず `R_u` を 620 へ戻す**（1 行）。トリム側は前便より確実に穏やかなので、
  切り分けの順序はこちらが先。
- **ベンチログ（10Hz）を必ず取ること。** `trim_roll/pitch/yaw` が直接読める。
  - 上限（4 deg / 20 deg/s）に張り付くなら、その外乱は定常ではない。**上限を上げずに原因を疑う。**
  - リークのおかげで張り付きは起きにくいはずなので、起きたら情報価値が高い。
- 積分が効いても**定常誤差は 71 % 減までで 0 にはならない**（リークとの交換）。
  それが不満なら `att_leak_tau` を伸ばす（張り付きリスクと引き換え）。
