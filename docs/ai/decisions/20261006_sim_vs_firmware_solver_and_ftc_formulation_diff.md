# シミュ（nmpc_simulation.py）と実機（Benzen_NMPC）は同じ RTI+TR1+SR2+ADMM だが、故障の表し方とガードが違う

- **日付**: 2026-10-06
- **種別**: investigation
- **対象**: `program/NMPC_simulation/nmpc_simulation.py`（NX=8 追随版）、`Benzen_NMPC/nmpc.cpp`・`nmpc_params.hpp`
- **タグ**: #NMPC_simulation #Benzen_NMPC #FTC #ADMM #TR1 #SR2 #B_eff #案B #η #box #乖離

## 背景
「シミュの FTC は実機と同じモデル・同じ最適化手法か」という質問に答えるため、両者を突き合わせた。

## 確認した事実

**同じもの**
- 凝縮形 + RTI（1 周期 1 回の線形化）+ TR1（Sx/Su の Broyden ランク 1 更新）+ SR2（H のランク 2 更新）+ ADMM（box）。
  `reset_period=100`、`admm_max_iter=4`、`admm_rho=1.0`、TR1 の `|c|>1e6` 棄却。
- ADMM の右辺は定数項 `c = Suᵀ Q (Sx x0 − X_ref) − R U_ref` を定義から作る（実機の 0909 修正後と同じ形。
  シミュは最初からこの形で、実機の勾配バグ・逆算バグはシミュには無かった）。
- 物理・コスト: Ix/Iy/Iz, Cp=Cq=0.025, Cr=1e-4, mass 0.285, C_QT=CQ/Ct, T_max 0.75, tau_act 0.045,
  Q=1000/1000/80/80/40, R_u=620, terminal ×10, NX=8, N=12, Q_a=0。

**違うもの**
| | シミュ | 実機 |
|---|---|---|
| 部分故障 η の入れ方 | **予測モデルの入力行列 `B_eff = B·diag(η)`**。box は η≈0 のときだけ上限 0 | **box だけ**（`du_max = η·0.95 − u_hover`）。B には掛けない（NX8 設計でも明記） |
| 入力コスト | 案B: 故障機ほど `R_u/max(η,0.1)` | 全モータ均一 `R_u` |
| 故障時の再構築 | 強制フル再構築 | 不要（H は box に依存しない） |
| SR2 | H にランク 2 を足して再 Cholesky（数学的には同値、O(n³)） | LLT に固定長の rank±1 update/downdate |
| TR1 棄却時 | **即フル再構築** | 連続 8 回で 1 回だけ再構築（`tr1_skip_max_run`） |
| 安全弁 | 無し | λ 上限、非有限リセット、`\|U_lin\|` ガード（box 相対、出力とは分離） |
| 数値型・時間 | float64、計算時間ゼロ | float32、フル再構築 28 ms が周期を食う |

## 判断 / 含意
- 完全故障（η=0）では両方とも「そのモータは 0」なので一致する。**部分故障（0<η<1）では別の問題を解いている**
  （シミュ: 効きが η 倍／実機: 上限が η 倍）。シミュの S2a/S2b（η=0.5）の成功は実機の定式化の裏付けにならない。
- シミュは再構築を即時・無償で行うので、実機の「近似 H のまま数周期走る」状態や再構築の停滞を再現しない。
  実機で問題になったバグの多く（2 章の表、`docs/20261006_pre_nx8_crash_causes.md`）はシミュでは原理的に出ない。
- `nmpc_simulation_report.md` の S1〜S8 検証は 2026-06-02 時点の設定（N=30, R_u=14, ADMM 1 反復, NX=5）での結果。
  現行の NX=8/N=12/R_u=620/iter=4 で S1〜S8 を再実行したかは未確認。

## 追記: なぜ違いが生まれたか（同日の追加調査）
- **η の表し方**: 実機の NMPC コアは Python シミュの翻訳ではなく、既存 C++（4 発版）の `NU` を 4→6 にしたもの（`Benzen_NMPC/plan.md` §0）。
  旧シミュ（`memo/研究メモ/nmpc_simulation_report.md` §4.7）は「U_max 縮減 + U_ref シフト + SR2 リセット」で、部分故障の `B_eff` は**未実装と明記**。
  その後シミュだけが Λ スケーリング（2026-05-25）と案B（06-02）へ進んだ。`repository_rules.md` §3（08-20 作成）と
  実機 FTC（`20260901_ftc_mode_and_failsafe.md`）は旧方式のまま。🔶 §3 が旧メモから書かれたというのは文言の一致による推定。
  実機側の利点: box だけなら H が変わらずフル再構築（34 ms）不要。対象実験は完全故障 η=0 のみで、そこでは両者一致。
- **安全弁・TR1 の棄却上限**: 実機の墜落（0909〜0919）を受けて実機にだけ足したもの。シミュはその失敗を経験していない。
- **float32・計算時間**: RP2350 の制約。

## 追記: シミュの「飛ぶ」が実機の「飛ぶ」を予言しなかった理由（確認済み事実）
- シミュは x_meas から計算した u を**同じ 1 ms ステップで即適用**（`nmpc_simulation.py` の `nmpc.step` → `apply_actuator_dynamics`）。
  計算遅延 0、アクチュエータ遅延 2 ms。実機は最低 1 周期（10 ms）、再構築中は 3 周期。
- プラントの誤差は ±20 %（`plant_I*_ratio`）。実機ソースのホスト閉ループ（50 ms 遅れ + 純遅延 + 雑音）では、
  遅れ補償なしでも 1.0–1.5× では発振せず、発散は 2–4× かつ 3–7 周期遅延の組み合わせでだけ起きた（`20260910_delay_compensation_new_solver.md`）。
- 状態は真値 + 白色雑音（ジャイロバイアスのランダムウォークは既定 0）。EKF の偽の傾きは起きない。
- ADMM の定数項はシミュでは最初から定義どおり。実機の勾配バグ・逆算バグはシミュに無い。
