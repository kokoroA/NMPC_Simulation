# ソルバ修正がバックアップ復元で巻き戻り、ビルド済み uf2 とソースが乖離していた

- **日付**: 2026-09-09
- **種別**: bugfix | investigation
- **対象**: `Benzen_NMPC/nmpc.cpp`, `nmpc.hpp`, `nmpc_params.hpp`, スクラッチパッド運用
- **タグ**: #Benzen_NMPC #ADMM #勾配バグ #作業手順 #バックアップ #スクラッチパッド #コンパイル不能

## 背景 / 症状

ユーザから「実装したはずの `R_u = 320.0f` / `admm_max_iter = 4` が
`Benzen_NMPC/nmpc_params.hpp` に反映されていない」と指摘された。

実ファイルを確認すると:

- `nmpc_params.hpp` = `R_u = 120.0f`, `admm_max_iter = 2`, `admm_lambda_max` 無し
- `nmpc.cpp` = `ctx.scratch.rhs = -g + rho * (ctx.ws.z - ctx.ws.lambda);` （勾配バグそのまま）
- `nmpc.hpp` = `admm_neg_c` / `cnt_admm_lambda_reset` / `cnt_nonfinite` 無し

つまり**ソルバ修正一式が実機ソースに一切入っていなかった**。

## 原因 / 判断根拠

**確認済み事実。**

- 実ファイル 3 点は、スクラッチパッドの修正前バックアップ `bk3/` と **バイト単位で一致**した。
  復元コピーが後から上書きしたことを示す。
- mtime の前後関係が決定的:

  | 時刻 | 対象 |
  |---|---|
  | 16:23:11 | `build_fresh/.../nmpc.cpp.o` |
  | 16:23:13 | `build_fresh/pico_copter.uf2` |
  | **16:24:08** | `nmpc.cpp`, `nmpc.hpp` ← 巻き戻り |
  | **16:32:26** | `nmpc_params.hpp` ← 巻き戻り |

  **ビルドの後にソースが戻っている。**
- `build_fresh/pico_copter.dis` に `43a00000`（= `320.0f`）が 5 箇所あり、`42f00000`（= `120.0f`）は
  0 箇所。**ビルド済み uf2 は修正版だった**。ソースだけが戻った。
- `control.cpp:2175-2176` は `diag.cnt_admm_lambda_reset` / `cnt_nonfinite` を参照しているが、
  巻き戻った `nmpc.hpp` にそのメンバは無い。**この状態のソースツリーはコンパイルすら通らない。**
  「ビルドが通っている」ことを再ビルドで確かめていれば即座に気付けた。

**原因（確度: 高いが直接の証跡は残っていない）。**

`nmpc_params.hpp` に CRLF を 10 行混入させた事故の後始末として、バックアップと比較して
LF へ戻す作業を行った。このときバックアップを**丸ごとコピーで書き戻した**ため、
行末だけでなく修正内容ごと消えたと考えられる。`nmpc.cpp` / `nmpc.hpp` が 16:24:08 に
同一秒で戻っていることも、一括コピーによる復元と整合する。

**なぜ気付かなかったか（本質）。**

`#include "..."` のディレクトリ優先の罠を回避するため、ホスト掃引ではソース一式を
スクラッチパッドへコピーして作業していた。その結果**「編集して測る場所」と
「実機が焼かれる場所」が分離**し、最終結果を実機ツリーへ戻す工程が暗黙になった。
掃引の結果（`R_u = 320`）は**どのファイルにも書かれておらず**、会話の中にしか存在しなかった。

## 対応

- `scratchpad/c/nmpc.cpp`, `nmpc.hpp` を実機ツリーへ復元（`bk3` + 修正差分そのもので、LF、他の差分なし）。
- `nmpc_params.hpp` は現行ファイルに対して `R_u = 320.0f` / `admm_max_iter = 4` /
  `admm_lambda_max = 30.0f` を適用。スクラッチパッドの `c/` は掃引中の変種（`R_u = 400`、
  「iter=10 が頭打ち」という古いコメント）なのでそのまま持ち込まず、コメントは最終判断で書き直した。
- 巻き戻り状態のファイルは `scratchpad/revert_backup/` に退避。

**採用しなかった案。**

- `scratchpad/c/nmpc_params.hpp` をそのままコピー → `R_u = 400` と、墜落前の古い推奨値を
  書いたコメントが入るため却下。
- ソースを直さずビルド済み `uf2` だけ使う → ソースと成果物が乖離した状態を固定化するため却下。

## 検証結果

- 再ビルド成功（巻き戻り状態では `control.cpp` がコンパイル不能だったので、これ自体が回帰試験になる）。
- `arm-none-eabi-size` = **text 678224 / bss 352560**。16:23 のビルドと完全一致。再構成が正しいことの裏付け。
- `pico_copter.dis`: `43a00000`(=320.0f) 5 箇所、`42f00000`(=120.0f) 0 箇所、
  `44610000`(=900.0f = `admm_lambda_max²`) 1 箇所。
- `nmpc.cpp:382` が `admm_neg_c + rho * (z - lambda)`、`:398` `cnt_admm_lambda_reset++`、
  `:412` `cnt_nonfinite++` であることを確認。
- CRLF 混入なし（3 ファイルとも CR 0 個）。
- **実機での飛行検証は未実施。** `iter_us` / `loop_us` の実測は依然として未取得。

  **「コンパイルすら通らない」という壊れ方**をすることがある。
