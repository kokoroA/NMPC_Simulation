## 0. 結論

**前回の「舵が足りない」問題は解消し、今度は逆に「ゲインが高すぎる」問題になっています。**
重みは**下げる**方向に振ってください。

| | 接地〜低スロットル<br>(t=5.99–9.9, 39 点) | **自由飛行**<br>(t≥9.9, 14 点) |
|---|---|---|
| phi rms | 0.97° | **16.26°** |
| theta rms | 1.14° | **10.59°** |
| p rms | 4.1 deg/s | **74.2 deg/s** |
| q rms | 3.6 deg/s | **98.9 deg/s** |
| duty ばらつき | 0.059 | **0.730** |
| duty 飽和(0.95) / 下限(0.00) 到達 | **0 回 / 0 回** | **19 回 / 12 回** |

- **接地中は完璧に静か。離陸した瞬間（`u_base` が 0.552 を超えた t≈9.9）から発振。**
- 自由飛行中の `q` は **1.32 秒で 11 回符号反転** → **4.2 Hz 以上**の振動（10 Hz サンプルなので折り返しの可能性あり）。
- duty は 0.00 と 0.95 を往復する **バンバン動作**になっている。

## 1. なぜ発振したか

### 1-1. ループゲインが約 2 倍になった

`T_max` を 2.04 → 1.04 に下げました。`B_c ∝ T_max` なので、
**モデルが操作権限を小さく見積もる → 同じ誤差に対して約 2 倍の Δu を出す**ようになります。
さらにモータ振り分けの修正で、**その指令が初めて正しいモータに届くようになりました。**

前回は「舵が届いていない＋量が 1/2」で、たまたま安定側に転んでいただけです。

### 1-2. モータの一次遅れがモデルに入っていない

`nmpc_model.cpp` は剛体のみで、**モータの応答遅れ（時定数 τ ≈ 50 ms）を持っていません。**
τ=50 ms のコーナー周波数は **3.2 Hz**。観測された発振は **4.2 Hz 以上**で、ちょうどここに乗っています。

高ゲイン＋未モデル化の遅れ ＝ 教科書どおりの発振です。

### 1-3. 制御周期が 10 ms を常時超えている

`loop_us` は **53 点中 50 点（94 %）が 10 ms 超**、平均 11.2 ms。
`dt = 0.01` を前提に設計しているのに、実際は 90–100 Hz で走っています。
これも位相遅れとして効きます。

## 2. 調整方針 — まず「1 つだけ」下げる

### 【第一手】`R_u` を上げてゲインを落とす

```cpp
constexpr float R_u = 120.0f;   // 28 → 120
```

- LQR のゲインは概ね **√(Q/R)** に比例します。`R` を 4.3 倍 → ゲインは約 1/2。
- **他は一切触らないでください。** 2 つ同時に変えると、どちらが効いたか分からなくなります。

| 結果 | 次の手 |
|---|---|
| まだ発振する | `R_u = 300` |
| 発振は止まったが姿勢が流れる | `R_u = 60` に戻す |
| 発振も止まり姿勢も保つ | ここを基準に `Q_phi/Q_theta` を上げていく |

### 【やってはいけない】`Q_p` / `Q_q` を上げる

「発振したから減衰を増やす」で角速度の重みを上げたくなりますが、**今回は逆効果**です。
角速度フィードバックは最も高い周波数まで効くので、モータ遅れの位相が回っている
4 Hz 帯でゲインを増やすことになり、発振が悪化します。

減衰が欲しくなったら、**まず全体を下げてから**、角度側（`Q_phi` / `Q_theta`）で戻してください。

### 【第二手】duty のレート制限（バンバン動作の抑制）

`mix_duty` の後に、1 周期あたりの変化量を制限します。

```cpp
static float u_prev[6] = {0};
const float du_rate_max = 0.05f;      // 1 周期(10ms)あたり。実効 5 duty/s
d = clamp(d, u_prev[i] - du_rate_max, u_prev[i] + du_rate_max);
u_prev[i] = d;
```

- モータが物理的に追従できない速さの指令を止めるので、**未モデル化の遅れに起因する発振に直接効きます。**
- 実装が小さく、`nmpc_step` を触りません。
- ⚠ 故障時の急速な再配分も鈍るので、**値は控えめに始めて詰めること。**

### 【本来の解】モータ一次遅れをモデルに入れる

状態を `[φ, θ, p, q, r]` から `[φ, θ, p, q, r, u₁..u₆]` に拡張（NX 5 → 11）。
物理的に正しく、レート制限のような当て物が要らなくなります。
**ただし計算時間が 10 ms に収まらないので、周期の問題を解いてからにしてください。**

## 3. `T_max` について — 飛行データが同定値を支持しています

飛行中のホバー付近で `u_base ≈ 0.552–0.584`。
[同定した推力マップ](../program/pico/pico-sdk2/pico-sdk/Benzen_NMPC/docs/thrust_sysid_f1404.md)
（f1404 + GEMFAN-3630-3）で duty 0.55 のときの推力は

```
T(0.55) = 0.556 N  →  6 発で 3.33 N = 340 g
dT/du|0.55 = 0.80 N/unit-duty
```

**機体質量 340 g 前後、`T_max`（接線勾配）は 0.80** という計算になります。
`mass = 0.32f` はほぼ妥当、**`T_max = 1.04f` は 30 % ほど高い**値です。

⚠ ただし **`T_max` を 1.04 → 0.80 にするとゲインがさらに 1.3 倍**になります。
**発振を止めてから直してください。** 直すときは `R_u` も併せて 1.3 倍する前提で。

`T_max` は物理量であって減衰の調整ノブではありません。
**耐故障の再配分はこの値の正しさに依存する**ので、最終的には正しい値を入れること。

## 4. ご質問への回答 — フル再構築の修正はマストか

### **マストです。ただし「今回の発振の犯人だから」ではありません。**

このログで確認できた事実:

- `cnt_rst_period` が **5 回**増えている（t = 6.64 / 7.66 / 8.69 / 9.63 / 10.75、約 1 秒間隔）。
- そのうち **t=9.63 のサンプルで `iter_us = 58333 us`、`loop_us = 60497 us`** を観測。
  ログは 10 Hz なので**当たったのは 1 回だけ**ですが、**5 回とも同じことが起きています。**
- 58 ms は制御周期の **約 6 倍**。その間 `angle_control` は次の周期に進めず、
  core0 は最後の duty を ZOH で出し続けます。自由飛行中の 100–200 deg/s では **6–12° の無制御時間**。

**マストである理由は 3 つ:**

1. **重みの評価ができなくなる。** 1 秒ごとに 58 ms の穴が空いている状態では、
   「重みが悪い」のか「ループが止まった」のかを区別できません。**今後の調整がすべて信用できなくなります。**
2. **warm start が壊れる。** TR1/SR2 の割線対 (s, y) は周期が `dt = 0.01` である前提で作られます。
   6 倍の飛びが入ると Hessian 近似が劣化します。
3. **失うものが無い。** このログで `cnt_sr2_c = 0`, `cnt_sr2_llt = 0` ——
   **SR2 の健全性チェックは一度も発火していません。** 定期再構築は「今まで一度も必要になっていない保険」です。
   接地中（`nmpc_run == false`）＋健全性異常時のみに変えても、実質的に何も失いません。

### `reset_period` を伸ばすだけでは駄目な理由

頻度が下がるだけで、**58 ms の停止そのものは残ります。**
たまたま離陸直後の過渡に当たれば同じことが起きます。
「稀にしか起きないが起きると致命的」は、デバッグが最も困難な種類の不具合です。

### 実装（小さい）

`angle_control` の `!nmpc_run` 側（接地・低スロットル）で `nmpc_reset_request()` を呼び、
`nmpc.cpp` の**周期リセット判定を無効化**します。飛行中の再構築は SR2 健全性異常時のみ。

## 5. 次の飛行の手順

1. **`R_u = 120` だけ**変更して再ビルド（他は触らない）
2. フル再構築を接地中のみに変更（§4）
3. 係留またはごく低高度で、**`loop_us` と `iter_us` に 20 ms 超が出ないこと**を先に確認
4. ホバーさせて `phi`/`theta` の rms を測る
   - rms < 3° → OK。`Q_phi`/`Q_theta` を上げて追従を詰める
   - まだ発振 → `R_u = 300`
   - 姿勢が流れる → `R_u = 60`
5. 安定してから `T_max` を 0.80 に直し、`R_u` を 1.3 倍して再確認
