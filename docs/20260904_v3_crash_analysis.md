# 0904_v3.csv 墜落解析 — ヨードリフトが育ち、t=31.03 のロール指令異常で破綻

- **ログ**: `Benzen_NMPC/tools/0904_v3.csv`（10 Hz、318 点 / 32.5 s、自由飛行 20.8 s）
- **図**: `plots/0904_v3_crash.png`
- **この版**: `mass=0.35`, `Cp=0.02`, `Cq=0.02`, `Q_phi=Q_theta=200`, `Psi_ref` 係数 0.3（±54 deg/s）
- **前回**: [`20260904_nmpc_yaw_starves_roll_pitch.md`](20260904_nmpc_yaw_starves_roll_pitch.md)

## 0. 結論

**`Psi_ref` の変更は意図どおり効きました。墜落は別の原因です。**

| | 0904_v1 | **0904_v3** |
|---|---|---|
| `Psi_ref` スケール | ±144 deg/s | **±54 deg/s** |
| `Q_phi`/`Q_theta` | 100 | 200 |
| **飽和した時刻の割合** | 39 % | **1 %**（墜落前） |
| **Δu のうちヨーが占める割合** | 84.7 % | **67.9 %** |
| ヨードリフト（指令中立時の平均） | 16.1 deg/s | 11.9 deg/s |

**しかしヨードリフトは飛行中に単調に育ちました。**

| 時刻 | 8–12 s | 12–16 | 16–20 | 26–30 | **30–34** |
|---|---|---|---|---|---|
| 指令中立時の `r` | +8.5 | +13.4 | +20.4 | +27.3 | **+39.8 deg/s** |

そして **t=31.03 にロールの指令が異常な値を出し**、0.2 秒で機体が破綻しました。

## 1. 墜落の経過

| t [s] | 状態 | 指令ロール角加速度 | 備考 |
|---|---|---|---|
| 30.55–30.83 | phi −10〜−13°、誤差 +10〜+13° | **+134 〜 +419 deg/s²** | 正しい向き。復帰中 |
| 30.93 | 誤差 +7.8°、p=+41 | **−84 deg/s²** | 符号が反転（角速度の減衰） |
| **31.03** | **誤差 +5.0°、p=+20** | **−1199 deg/s²** | **逆向き・直前の 14 倍。2 発が飽和** |
| 31.13 | **p = −169 deg/s** | −670 | 破綻 |
| 31.24 | **p = −307 deg/s** | +86 | **フェイルセーフ作動（FS_RATE）** |
| 31.34– | phi −70 → −180° | — | 転覆 |
| 31.89– | — | — | NMPC の出力が **NaN** |

**誤差 +5°・角速度 +20 deg/s という穏やかな状態に対して −1199 deg/s² を指令する理由が、
状態のどこにもありません。** 直前 4 サンプルの指令は +134〜+419 deg/s² でした。

### ⚠ 原因は 10 Hz ログでは特定できません

2 つの可能性があり、**このデータでは分離できません。**

- **(a) ソルバの解が破綻した。** この瞬間に 2 発が box 制約に張り付いています。
  `admm_max_iter = 2` は制約が効いていないときは十分ですが、
  **解が box の頂点に移る瞬間は 2 反復では収束しません。**
- **(b) サンプル間の外乱に過反応した。** 30.93 と 31.03 の間には制御周期が 10 回あります。
  突風やジャイロのスパイクが入り、それに対して過剰なゲインで反応した可能性があります。
  `Q_phi` を 100 → 200 にしてループゲインが約 1.4 倍になっているので、過反応しやすくなっています。

**→ 100 Hz のログが取れないと、この種の破綻は原因が確定できません（§4-1）。**

## 2. フェイルセーフは正しく働きました

- **t=31.24 に `FS_RATE`（p = −307 deg/s）で作動。** 実飛行で作動した初めての記録です
- NMPC の出力が NaN になったのは **t=31.89 で、フェイルセーフより後**。
  `rate_control` の NaN ガードより先に、フェイルセーフがモータを止めていました
- ログに出ている 0.95 などの duty は **`angle_control` が計算した値**で、
  実際に PWM へ書かれた値ではありません（`Failsafe_flag` が立っている間は `motor_stop()`）

⚠ **ただしフェイルセーフ後に NMPC の内部状態はリセットされていません。**
`Failsafe_flag` が立ったときに `nmpc_reset_request()` を呼ぶべきです（§4-4）。

## 3. ヨードリフトについて

**制御器は正しい向きに打っています。**

```
τ_z の平均 = -0.0134 N·m   （ドリフト r の平均 = +11.9 deg/s に対して逆向き）
corr(ヨー率誤差, 指令ヨートルク) = +0.12
```

Δu の平均ベクトル `[+0.037, -0.040, -0.031, +0.032, +0.031, -0.054]` は
`kS = [-1,+1,+1,-1,-1,+1]` にきれいに沿っており、**純粋なヨートリムになっています。**

**それでも勝てていません。** 原因の第一候補は **`C_QT` の過大評価**です。

| | CQ | C_QT |
|---|---|---|
| 現行 | 3.0e-8（未測定の仮値） | **0.0576** |
| 推定（ベンチの電流と推力から） | 5.8e-9 | **0.0111** |

モデルがヨーの効きを **5.2 倍**大きく見積もっているため、**制御器は必要量の 1/5 しか出しません。**
詳細は [`thrust_sysid_f1404.md §7`](../program/pico/pico-sdk2/pico-sdk/Benzen_NMPC/docs/thrust_sysid_f1404.md)。

**飽和が 39 % → 1 % に下がった今なら、`C_QT` を直しても duty の余裕があります。**

## 4. 対処（優先順）

### 4-1【最優先】100 Hz のログを取れるようにする

**10 Hz では 0.1 秒で起きる破綻の原因が特定できません。** 今回まさにそれで詰まりました。

- ファームには `Logdata` と `log_output()`（USB シリアルダンプ）が既にあります
- あるいは Wi-Fi テレメの送信レートを上げる（帯域と core0 の負荷は要確認）
- **最低でも墜落の前後 2 秒だけでも 100 Hz で残せれば、(a)/(b) の切り分けができます**

### 4-2 `Q_phi` / `Q_theta` を 200 → 100 に戻す

- **今回の飛行では効果を評価できていません。** 操縦者のロール指令 rms は **2.6°**、
  ピッチ 2.1° しかなく、ほぼホバリングでした。追従性能を測れる入力が入っていません
- 一方でループゲインは約 1.4 倍になり、**発振境界に近づいています**
- **評価できていない変更は戻す。** 効果を測るなら、意図的にステップ状の指令を入れて飛ぶこと

### 4-3 `CQ` を 3.0e-8 → 5.8e-9 に（`C_QT` 0.0576 → 0.011）

ヨードリフトの根本。飽和に余裕ができた今が入れどきです。
**ヨーの duty 消費は増えるので、飽和率を必ず確認してください。**

### 4-4 フェイルセーフ時に NMPC をリセットする

```cpp
if (cause != FS_NONE) {
  Failsafe_flag = 1; Failsafe_cause = cause;
  motor_stop();
  nmpc_reset_request();   // ← 追加。warm start と Hessian を捨てる
}
```

今回 NaN が出たのは姿勢が ±180° に達したあとですが、**破綻した状態のまま
warm start を持ち越すのは危険**です。

### 4-5 RL モータを物理的に点検する

**RL だけ Δu の変動が他 5 本の 2.8 倍あります。**

| ログ | fr | fl | mr | ml | rr | **rl** | rl / 他5本平均 |
|---|---|---|---|---|---|---|---|
| 0831_v4 | 0.102 | 0.070 | 0.065 | 0.067 | 0.069 | 0.110 | 1.47 |
| 0904_v1 | 0.078 | 0.149 | 0.113 | 0.211 | 0.229 | 0.235 | 1.51 |
| **0904_v3** | 0.047 | 0.069 | 0.062 | 0.065 | 0.039 | **0.159** | **2.82** |

v3 では他の 5 本が静かになったのに **RL だけ静かになっていません**（全時間帯で 2.6–3.6 倍）。

- プロペラの緩み・破損、モータのコギング、ESC のチャンネル差
- あるいは配分の零空間が RL に落ちている（`admm_max_iter = 2` で零空間成分が掃き切れていない）

**まず物理点検を。** 異常が無ければ `admm_max_iter` を 3 にして再現するか見る価値があります。

## 5. 変更しなかったことの確認

- **`Cp` 0.01→0.02 / `Cq` 0.025→0.02 は今回の墜落の原因ではありません。**
  `cnt_sr2_c = 13` はすべて **t ≥ 31.89（墜落後）** に発生しており、飛行中は 0 でした
- `iter_us` 平均 7311 / `loop_us` 平均 9220 µs。**周期は健全**（10 ms 超は 7/238 点でフル再構築時のみ）
