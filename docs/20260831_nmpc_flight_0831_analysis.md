## 2. 未モデル化トルクの定量

t=6.27 → 6.37 の 0.1 s:

```
実測 q̇        = +19.1 rad/s²  (+1094 deg/s²)
実測トルク    = Iy·q̇ = 1.9e-3 × 19.1 = +0.0363 N·m   (機首上げ)
指令トルク    = Σ kXm·T_max·u = -0.0198 N·m          (機首下げ・T_max=0.79 で計算)
--------------------------------------------------------
未モデル化    = +0.0561 N·m   ← 機首上げ
```

総推力 3.49 N（= 0.356 kg × 9.81）で割ると **重心オフセット 16 mm 後方**に相当。

このトルクを NMPC が定常でトリムするには、前後で **duty 差 ±0.21** が必要:

```
Δu = 0.0561 / (0.085 [m] × 0.79 [N/duty] × 4 [発]) ≈ 0.21
```

**実際に出ていた duty のばらつきは平均 0.051、最大 0.160。** 必要量の 1/4 しか出していない。

## 3. なぜ足りなかったか

### 3-1. `T_max` の過大評価（2.6 倍）

`B_c ∝ T_max`。モデルが「Δu を少し出せば大きく効く」と誤認しているため、
同じ姿勢誤差に対して出す Δu が **1/2.6** になる。
`T_max` を 0.79 に直すだけで、指令量はおよそ 2.6 倍になる。

### 3-2. NMPC に積分器が無い

一定外乱（重心オフセット）に対しては、比例的なコストでは**必ず定常偏差が残る**。
偏差の大きさは概ね √(R/Q) に比例する。現行 `Q_theta=50, R_u=28` では 2° 程度残る計算で、
実際に離陸直前の theta = +2.14° と一致する。

### 3-3. 制御余裕が非対称で薄い

ホバー duty 0.583、上限 0.95 → **上向き 0.367 / 下向き 0.583**。
トリムだけで上向き余裕の 57 % を使う。残りで姿勢制御をすることになる。

### 3-4. 1 秒ごとの 59 ms 停止

`reset_period = 100` により 100 周期（1 s）ごとにフル再構築が入り、**59 ms** かかる。
その間 `angle_control` は次の周期に進めず、core0 は最後の duty を ZOH で出し続ける。
通常時なら 59 ms で 1° 程度だが、**離陸直後の過渡でこれが入ると致命的**。

## 4. 調整方針（この順で）

### 【Step 1】重みを触る前に直すもの

| # | 内容 | 期待効果 |
|---|---|---|
| **A** | **機体の重心を合わせる。** 16 mm 後方にずれている | 外乱そのものが消える。**最も効果が大きく、最も簡単** |
| **B** | **`T_max = 2.04f` → `0.79f`**（併せて `Ct = 6.13e-7f` → `5.21e-7f`） | 同じ誤差に対する指令量が 2.6 倍 |
| **C** | **フル再構築の 59 ms を飛行中に入れない。** `reset_period` を大きくするのではなく、**`nmpc_run == false`（接地・低スロットル）のときだけ再構築**する。飛行中は SR2 健全性チェック起因の再構築のみに任せる | 1 秒ごとの制御ホールが消える |
| **D** | **姿勢ゼロ点を水平で取り直す。** 現状は脚で接地した姿勢で `Theta_bias` を latch している | 離陸時の初期誤差が減る |
| **E** | **脱出条件を入れる。** \|theta\| or \|phi\| > 45°、または \|q\|,\|p\| > 300 deg/s で `motor_stop()`。**現状 OverG は数値的に発火しない**（[レビュー §S2](20260828_benzen_nmpc_review.md)） | 横転前に切れる |

**A〜E を入れずに重みだけ触っても、同じ発散を繰り返す可能性が高い。**

### 【Step 2】そのうえで重み

B を入れた時点で**実効ゲインが 2.6 倍になる**ので、**まず重みは現状のまま**で係留試験をすること。
そのうえで定常偏差が残るなら、次の順で。

```cpp
// nmpc_params.hpp  namespace cost
constexpr float Q_phi   = 100.0f;  // 50 → 100   姿勢の定常偏差を半減
constexpr float Q_theta = 100.0f;  // 50 → 100
constexpr float Q_p     = 20.0f;   // 据え置き
constexpr float Q_q     = 20.0f;   // 据え置き
constexpr float Q_r     =  6.0f;   // 据え置き
constexpr float R_u     = 14.0f;   // 28 → 14    指令を出しやすくする
```

- **定常偏差は √(R/Q) に比例する。** `Q` を 2 倍・`R` を 1/2 にすると比は 4 倍 → 偏差はおよそ 1/2。
  B と合わせて 2.14° → 0.4° 程度が狙い。
- **`Q_q` / `Q_p`（角速度）を先に上げないこと。** 今回は発振ではなく**定常偏差からの発散**なので、
  効くのは角度側の重み。角速度の重みは減衰を作るが、`loop_us` が 10 ms 前後で
  すでに 1 周期分の遅れがあるため、上げすぎると逆に発振する。
- `terminal_scale = 10` は据え置き。`N = 17` も据え置き（計算時間が先に破綻する）。

### 【Step 3】本来の解 — 定常外乱の推定

一定トルク外乱を状態に加えて推定し、フィードフォワードする（offset-free MPC）のが正攻法。
重みで押さえ込むより素直で、重心が完全には合わせられない場合にも効く。
**ただし状態次元が増えて計算時間に効くため、10 ms 問題を解いてからにすること。**

暫定策として、`U_ref_stack` に前後差動のトリム項を定数で入れる手もある
（`Δu_ref = [-0.1, -0.1, 0, 0, +0.1, +0.1]` のような形）。**実装は小さいが、値は実測で決めること。**

## 5. 次の試験の進め方

1. 重心を合わせる（A）→ **プロペラを外して手で機首を上げ、後ろのモータが加速することを確認**
   （モータ配置と符号の検証。基板のコネクタ `GP4`/`GP5` は実体が GP14/GP15 なので混乱しやすい）
2. B・C・D・E を入れて再ビルド
3. **係留**して、ホバー直前まで上げ、`u_base` と `theta` を記録
   → ここで `T_max` の実測値が確定する（[同定資料 §5](../program/pico/pico-sdk2/pico-sdk/Benzen_NMPC/docs/thrust_sysid_f1404.md)）
