- **検証**: 実機のソルバをそのまま macOS でビルドした閉ループ実験（**実機では未検証**）

## 0. 用語

| 用語 | 意味 |
|---|---|
| **NMPC** | 非線形モデル予測制御。「今の状態から N ステップ先までの入力列」を毎周期解き直し、その先頭だけを使う |
| **ホライズン `N`** | 何ステップ先まで見るか。本機は `N = 14`（0.14 秒先） |
| **凝縮形（condensed）** | 状態を消去して**入力だけの最適化問題**に潰した形。変数は `NU × N = 6 × 14 = 120` 個 |
| **`U`** | 最適化変数。ここでは**絶対 duty ではなく `Δu`**（ホバー duty `u_hover` からのずれ）。実際の指令は `duty = u_hover + Δu` |
| **`U_lin`（線形化点）** | 非線形モデルを直線で近似する「基準点」。前周期の解を 1 ステップずらして使う（warm start） |
| **`H`（ヘシアン）** | コストの 2 階微分。`H = Suᵀ Q̄ Su + R̄`。「入力をどれだけ動かすとコストがどれだけ増えるか」の曲がり具合 |
| **`g`（勾配）** | コストの 1 階微分。`∇J(U_lin) = H·U_lin + c`。**「今の点での傾き」であって「解」ではない** |
| **`c`（定数項）** | 勾配のうち `U` に依らない部分。`c = Suᵀ Q̄ (Sx x0 − X_ref) − R̄ U_ref` |
| **box 制約** | 各モータの `Δu` の上下限。`Δu ∈ [−u_hover, 0.95 − u_hover]`。duty が 0〜0.95 に収まるという物理的な制限 |
| **ADMM** | box のような制約つき問題を「制約なしの解 `U`」と「制約を満たす解 `z`」に分け、両者を**双対変数 `λ`** で近づけていく反復解法 |
| **`ρ`（`admm_rho`）** | ADMM のペナルティ係数。`U` と `z` をどれだけ強く一致させにいくかの重み。`M = H + ρI` の `ρ` |
| **`λ`（双対変数）** | 「`U` と `z` がどれだけずれてきたか」の累積。ずれ続けると増え、それが `U` を制約側へ押し戻す |
| **warm start** | 前周期の解を初期値として使い回すこと。毎周期ゼロから解くより速い |
| **固有値** | 「1 周期でどれだけ拡大・縮小するか」の倍率。`−1` は「大きさそのままで符号だけ反転」＝**減衰しない振動** |
| **非有限（non-finite）** | `NaN`（Not a Number）や `Inf`。0/0 やオーバーフローで出る。**NaN はあらゆる比較が false になる** |

## 1. 修正① 勾配ではなく定数項を使う（50 Hz チャタリング）

### 何が起きていたか

コストは `U` の 2 次式なので、その勾配は

```
∇J(U) = H·U + c
```

と書ける。`compute_gradient()` は**線形化点における完全な勾配** `g = H·U_lin + c` を返す
（コメントにもそう書いてある）。ところが `admm_solve()` はそれを**そのまま「解を求める右辺」**に使っていた。

```cpp
rhs = -g + rho * (z - lambda);      // ← 旧
U   = M⁻¹ rhs;                       // M = H + rho*I
```

ADMM の `U` 更新は本来

```
(H + ρI) U = −c + ρ(z − λ)          ← 必要なのは c であって g ではない
```

である。`g` を入れると余計に `−H·U_lin` が乗る。`ρ = 1` に対し `diag(M) ≈ 186`（ホストで実測）なので
`M ≈ H` とみなせて、

```
U_new  ≈  −U_lin − H⁻¹c
```

**この写像の固有値はちょうど −1。** 減衰も発散もしない周期 2 振動が必ず出る。
100 Hz 制御の周期 2 = **50 Hz**。これが「毎周期 duty が反転する」現象の正体だった。

さらに、この振動の中心（不動点）は `U = −H⁻¹c / 2`、つまり**正しい解のちょうど半分**である。
**実効的な制御ゲインが半分になっていた。**

> **なぜ気づきにくいか**: コンパイルも通り、数値も発散せず、ソルバは毎周期「解けた」と返す。
> 症状は「なんとなく効きが弱い」「出力がガタつく」という曖昧な形でしか出ない。

### 修正

`c = g − H·U_lin` を作って使う。`H = M − ρI` なので追加は**行列ベクトル積 1 回**で済む。

```cpp
// H*U_lin = M*U_lin - rho*U_lin
admm_neg_c  = M * U_lin;      // = H*U_lin + rho*U_lin
admm_neg_c -= rho * U_lin;    // = H*U_lin
admm_neg_c -= g;              // = H*U_lin - g = -c
...
rhs = admm_neg_c + rho * (z - lambda);   // = -c + rho(z - lambda)
```

反復の中で変わらない量なので、**ループの外で 1 回だけ**計算する
（`NmpcScratch` に `admm_neg_c` を追加。120 float = 480 バイト）。

## 2. 修正② ADMM の反復回数（NaN の元）

### 何が起きていたか

`admm_max_iter = 2` は**少なすぎた**。box が有効になると

```
lambda += U - z        （U と z のずれを毎回ためこむ）
```

で `λ` が増える。増えた `λ` は `rhs = -c + ρ(z − λ)` を通じて `U` を押し戻すはずだが、
`ρ = 1` に対し `diag(M) ≈ 186` なので **`λ` の影響は 1/186 に薄まる**。
一方 `λ` はフルに足し込まれる。**主変数が追いつけず双対だけが走る。**

ホスト実験では box に当たった瞬間から

```
|λ| = 0.15 → 3.9 → 45.6 → 2372 → NaN     （1 周期で 10〜50 倍）
```

と 4 周期で float を溢れた。**これが実機の NaN 固着の発生源。**

> **なぜ今まで出なかったか**: 修正①前は、チャタリングが `|U|` を小さく保っていて box にほとんど当たらず、
> `λ` は 0 のままだった。**片方だけ直すと必ず NaN になる。2 つはセットでしか入れられない。**

### 修正

`admm_max_iter` を **2 → 10**。`ρ` は **1.0 のまま**据え置いた。

> **`ρ` を上げなかった理由**: `ρ` を大きくすると `M = H + ρI` の近接項が支配して `λ` は安定するが、
> 有限回の反復では主変数が最適解へ届かず**過減衰**になる。ホスト掃引で確認した:

| `ρ` (iter=5) | 追従相関 R/P/Y | 飽和 |
|---|---|---|
| **1.0** | **0.45 / 0.40 / 0.89** | **4.5 %** |
| 10 | −0.17 / 0.15 / 0.84 | 10.1 % |
| 186 | −0.06 / −0.03 / 0.10 | 27.5 % |
| 1000 | −0.14 / 0.14 / 0.67 | 17.4 % |

`ρ = 1.0` のまま反復を増やすほうが素直だった。

| `admm_max_iter` (ρ=1.0) | ラグ1 | 追従相関 | 飽和 |
|---|---|---|---|
| 5 | +0.810 | 0.45/0.40/0.89 | 4.5 % |
| **10** | **+0.998** | **0.44/0.43/0.92** | **0.8 %** |
| 20 | +0.998 | 0.44/0.43/0.92 | 0.5 % |
| 40 | +0.998 | 0.44/0.43/0.92 | 0.4 % |

**10 回で頭打ち。**

⚠ **LLT solve が 1 周期 2 回 → 10 回になる。実機の `iter_us` を必ず測り直すこと。**
10 ms に収まらなければ **5 回まで落とせる**（安全弁の発動が増えるが破綻はしない）。

## 3. 修正③ 安全弁（3 か所）

**バグを直しても、想定外の入力で数値が壊れる可能性は残る。**
壊れたときに「電源を切るまで戻らない」状態にしないための保険を 3 段入れた。

### 安全弁 1 — 双対変数 `λ` の上限（`nmpc.cpp`）

```cpp
if (!(ctx.ws.lambda.squaredNorm() < rti::admm_lambda_max * rti::admm_lambda_max)) {
    ctx.ws.lambda.setZero();
    ctx.diag.cnt_admm_lambda_reset++;
}
```

> **`!(x < 上限)` と書く理由**: **`NaN` はあらゆる比較が false になる**ので、
> `x > 上限` では NaN を取りこぼす。否定形にすると NaN も同時に捕まる。

しきい値 `admm_lambda_max = 30` はホスト掃引で決めた（正常時 `|λ|` は 3〜20）。

| `admm_lambda_max` | 非有限の発生回数 |
|---|---|
| 1e3 | 16 |
| 1e2 | 31 |
| **30** | **7** |
| 10 | 34 |

高すぎると `U` が溢れてから止めることになり、低すぎると正常な双対まで捨てる。

### 安全弁 2 — 解が非有限なら warm start ごと捨てる（`nmpc.cpp`）

```cpp
if (!ctx.ws.z.allFinite() || !ctx.ws.U.allFinite() || !ctx.ws.lambda.allFinite()) {
    ctx.ws.U.setZero(); ctx.ws.z.setZero(); ctx.ws.lambda.setZero();
    ctx.ws.valid = false;            // 次周期は初期化から
    ctx.need_full_rebuild = true;    // Hessian も作り直す
    ctx.diag.cnt_nonfinite++;
}
```

**`Δu = 0` に落ちる＝「全モータを `u_hover` のまま」＝水平ホバー指令**になる。
モータ停止ではなく、いちばん無難な指令へ落ちる。

> これが無いと NaN が duty まで流れ、`control.cpp` の NaN ガードが `minimum_duty = 0.1` に置き換える。
> 結果として**スロットルに関係なく全 6 発が duty 0.1 で回り続ける**。0909_v1 の症状そのもの。

### 安全弁 3 — 姿勢推定（EKF）の破綻検出と再初期化（`control.cpp`）

```cpp
static bool attitude_state_sane(void)
{
  const float ang_lim  = 2.0f * (float)M_PI;   // 一周を超えたら壊れている
  const float rate_lim = 40.0f;                // rad/s ≈ 2290 deg/s（ジャイロ ±2000dps 超）
  if (!(fabsf(Phi) <= ang_lim) || !(fabsf(Theta) <= ang_lim)) return false;
  if (!(fabsf(Wp) <= rate_lim) || !(fabsf(Wq) <= rate_lim) || !(fabsf(Wr) <= rate_lim)) return false;
  return true;
}
```

壊れていたら `ekf_reinit()`（四元数 `Xe`/`Xp` と共分散 `P` を初期値に戻す。`Q`/`R`/`G` は定数なので触らない）
を呼び、その周期は baseline duty を出して次周期からやり直す。

> **なぜ必要か**: 0909_v1 では墜落の衝撃で EKF が発散し（**`phi = −336 deg`**）、
> 異常な `x0` が NMPC に入って NaN になった。**再アームしても EKF が壊れたままなので直らなかった。**
> `control.cpp` にはこれまで `isnan`/`isfinite` の使用が **0 箇所**だった。

### 発動回数はログに出る

ダンプの先頭に 1 行追加した。**発動していること自体が異常の兆候**なので必ず見ること。

```
#solver: lambda_reset=0 nonfinite=0 ekf_reset=0 admm_rho=1 admm_iter=10
```

## 4. 効果（ホスト閉ループ、モータ遅れ 50 ms、指令 ±14 deg / ±34 deg/s）

| | ラグ1 自己相関 | 振幅比 R/P/Y | 相関 R/P/Y | 飽和 |
|---|---|---|---|---|
| **修正前** | **−0.962** | 0.42/0.48/0.53 | 0.24/0.27/0.51 | **23.4 %** |
| **修正後** | **+0.998** | 0.53/0.52/**0.91** | 0.44/0.43/**0.92** | **0.5 %** |

- **ラグ1 が −0.96 → +1.00。毎周期反転が完全に消えた。**
- **ヨーの追従相関が 0.51 → 0.92**、振幅比 0.53 → 0.91。
- **飽和が 23.4 % → 0.5 %**（チャタリングの山が上限に当たっていた分が消えた）。

⚠ **安全弁は今も発動する。** 指令が大きくモータ遅れがある条件では 1500 周期あたり
`lambda_reset` 7〜155 回、`nonfinite` 7〜38 回。
**ADMM の双対が完全に健全になったわけではなく、安全弁が固着を防いでいる状態**である。
発動 1 回につき 1 周期だけ Δu = 0（水平ホバー指令）に落ちる。

## 5. 実機に持っていく順序

```
1. iter_us / loop_us を測る            ← LLT solve が 2 回 -> 10 回。ここが最初の関門
   10ms に収まらなければ admm_max_iter を 5 に落とす
        ↓
2. プロペラ無しで duty 波形を 100Hz ログで確認
   → 毎周期反転が消えていること、#solver 行が全部 0 であること
        ↓
3. 係留 → 自由飛行。100Hz ログでラグ1 自己相関と飽和率を再測定
        ↓
4. ピッチ 1-3Hz が残るか再評価（残って初めて Q_theta を検討）
        ↓
5. 最後に T_max = 0.81 を R_u と対で
```

⚠ **`T_max` は絶対に一緒に入れないこと。** 修正で実効ゲインが約 2 倍になっており、
`T_max` 1.04 → 0.81 でさらに 1.28 倍＝**合計 2.6 倍**になる。
ホスト実験では修正後でも `T_max` 1.28 倍を重ねると 538 周期で NaN になった。
