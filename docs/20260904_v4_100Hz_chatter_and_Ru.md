# 0904_100Hz_v4 分析 — 指令 duty の 91 % が 50 Hz チャタリング。R_u=100 は方向は正しいが小さすぎる

- **対象ログ**: `Benzen_NMPC/tools/0904_100Hz_v4.csv`（100 Hz オンボードログ, 1946 行 = 19.5 s）
- **重み（ログのヘッダ）**: `Q_phi=Q_theta=150, Q_p=Q_q=20, Q_r=40, R_u=120, N=14`
- **図**: `Benzen_NMPC/tools/plots/0904_v4_100Hz_chatter.png`

> ⚠ 併せて渡された `0904_v12.csv` は**ヘッダ 4 行のみでデータ行が 0**。10 Hz テレメは今回何も記録できていない。

## 1. パイロットの体感は数値と一致している

| 軸 | 指令 rms | 応答 rms | **振幅比** | 相関 | 誤差 rms | 平均誤差 |
|---|---|---|---|---|---|---|
| roll | 10.89° | 3.98° | **0.366** | +0.62 | 8.99° | **−6.65°** |
| pitch | 8.88° | 4.01° | **0.452** | +0.55 | 7.46° | +2.27° |
| yaw | 5.77 deg/s | 6.19 deg/s | 1.074 | +0.75 | — | +4.8 deg/s |

**指令の 4 割弱しか出ていない。** 位相遅れは 40 ms しかなく、遅れを補正しても振幅比は改善しない
（0.365 / 0.452 のまま）ので、**遅れではなく「振幅が足りない」**。
指令パワーの 98 % は 1 Hz 以下なので、「速すぎる指令だから追えない」でもない。

ロールには **−6.65° の定常偏差**がある。NMPC に積分項は無いので、
未モデル化の一定外乱（重心ずれ・モータ／プロペラ差）はそのまま定常誤差として残る。
これは重みでは消えない種類の誤差で、**機体側のトリムで潰すべきもの**。

## 2. ★ 決定的な発見 — 指令 duty が毎周期反転している

100 Hz ログにして初めて見えた。生データ（t=10.00–10.09 s, `u_base=0.593`）:

```
 t      FR      FL      MR      ML      RR      RL
10.00  0.520   0.480   0.683   0.698   0.463   0.546
10.01  0.692   0.694   0.489   0.500   0.734   0.612
10.02  0.564   0.450   0.675   0.707   0.492   0.502
10.03  0.699   0.711   0.482   0.506   0.718   0.606
10.04  0.554   0.465   0.662   0.721   0.475   0.511
10.05  0.698   0.724   0.467   0.520   0.706   0.608
```

**1 制御周期（10 ms）ごとに全モータが上下に振れている = 50 Hz（ナイキスト）の振動。**

- Δu のラグ 1 自己相関は **−0.82 〜 −0.96**（まともな制御なら +0.9 以上）。
- Δu の変動を「毎周期反転する成分 E」と「滑らかな成分 S」に分けると
  **E rms 0.1379 / S rms 0.0433 → 変動の 91 % が反転成分**。
- **E の 86.7 % は 6 発ミキサのヌル空間**にあり、力もモーメントも生まない。
  さらに row space に入る 13.3 % のうち 57 % は共通モード（推力）で、
  `B_c·1 = 0` より**姿勢ダイナミクスには効かない**。
  → **E の約 94 % は機体に対して完全に無意味な出力**。
- 主方向（E の 97.2 %）は `[−0.63, −0.80, +0.81, +0.65, −1.00, −0.26]`。
  この方向が生むモーメントは roll −0.008 / pitch −0.007（ほぼゼロ）/ yaw +0.401。

### ログの破損ではない

同じログの `phi` / `theta` は 0–0.5 Hz に 66–70 % のパワーを持つ**完全に滑らかな波形**で、
3–6 Hz は 0.5 % 以下。**リングバッファが行を混ぜているなら姿勢も同じように振れるはず。**
duty 列だけが振れているので、**指令そのものが振れている**。

### フル再構築では消えない

`cycles_since_reset` で層別しても反転成分の大きさは変わらない（0 周期後 0.1216 / 41–100 周期後 0.1222）。
**TR1/SR2 による Hessian の劣化が原因ではない。** フル再構築の直後から同じだけ振れている。

### 他の飛行との比較（重みは 3 本とも同一）

| ログ | 自由飛行点数 | u_base | 1 周期あたり平均 \|Δduty\| | Δu ラグ1相関 | φ指令 rms |
|---|---|---|---|---|---|
| `0904_100Hz_v2.csv` | 2122 | 0.674 | 0.088 | −0.49 | 3.89° |
| **`0904_100Hz_v4.csv`** | 1946 | 0.616 | **0.242** | **−0.80** | 10.89° |

**操舵量が 2.8 倍になるとチャタリングも 2.8 倍**になっている。常時ある現象で、指令が大きいほど育つ。

## 3. だから「使える舵」がほとんど使われていない

モータ一次遅れ（τ≈50 ms, コーナー 3.2 Hz）は 50 Hz をほぼ完全に潰すので、
**機体が実際に感じるのは 2 サンプル平均**。それで評価し直すと:

| 量 | 生の値 | 2 サンプル平均後 |
|---|---|---|
| Δu rms | 0.1447 | **0.0435**（30 %） |
| 飽和率（duty ≥ 0.95） | 2.2 % | **0.0 %** |
| \|Δu\| の 95 % 点 | 0.248 | **0.083** |

**box の上側余裕は `0.95 − u_base = 0.334` あるのに、実効的には 0.083 しか使っていない（25 %）。**
rms で見れば 0.0435 / 0.334 = **13 %**。

**アクチュエータは全く飽和していない。追従が足りないのは舵が足りないからではなく、
`R_u` が舵を出させていないから。**

（前回 `0904_v11.csv` の 10 Hz ログで「飽和 23 %」と報告したが、あれは**チャタリングの山が
0.95 に当たっていたのを拾っていた**。10 Hz では 50 Hz 成分が折り返すので飽和率は信用できない。
**飽和の評価は必ず 100 Hz ログで行うこと。**）

## 4. `R_u = 100` への回答

### 方向は正しい。ただし小さすぎる

`R_u` は Δu を罰する項。実効 Δu が使える範囲の 13–25 % しかない以上、
**`R_u` を下げるのが正しい方向**であることは間違いない。

しかし `120 → 100` は **17 % の減**にすぎない。線形近似では振幅も同程度しか増えないので、
追従振幅比は **0.366 → 0.42 程度**。パイロットが体感できる差にはならない可能性が高い。

`Q/R` 比で見ると `150/120 = 1.25` → `150/100 = 1.50`。ここは `Q_phi` を上げるのと同じ効果なので、
**どちらか一方だけを動かす**こと（1 回 1 つの原則）。

### ただし下げる前に必ず確認すべきこと

**`R_u = 120` は 4 Hz 発振を止めるために `28 → 120` に上げた値である**
（[`20260831_nmpc_gain_too_high_oscillation.md`](ai/decisions/20260831_nmpc_gain_too_high_oscillation.md)）。
原因はモデルに入っていない**モータ一次遅れ（τ≈50 ms, コーナー 3.2 Hz）**で、これは今も未モデル化のまま。

**その 4 Hz モードは今も生きている。** 100 Hz ログで初めて直接測れた:

| 信号 | 全帯域 rms | **3–6 Hz 成分** | 割合 |
|---|---|---|---|
| `p` (ロールレート) | 12.49 deg/s | **5.63 deg/s** | **33.6 %** |
| `q` (ピッチレート) | 10.57 deg/s | 3.10 deg/s | 14.6 % |

**ロールレートの全パワーの 1/3 が発振帯に残っている。** `R_u` を下げるとここが太る。
`100` 程度なら急に破綻はしないと考えられるが、**下げた後は必ず 100 Hz ログで
`p` の 3–6 Hz 成分を測り直すこと**（10 Hz ログでは折り返して見えない）。

### 推奨する順序

1. **先にチャタリングを潰す。** 実効舵が 4 倍近く増えるので、`R_u` を触らなくても
   追従はかなり改善する可能性がある。しかも `R_u` を下げるとチャタリングも一緒に育つ
   （`R_u` はこの反転成分を抑えている唯一の項）ので、**順序を逆にすると悪化しうる。**
2. チャタリングを潰したうえで、まだ足りなければ `R_u` を下げる。そのとき `100` ではなく
   **`80` 程度まで一度に動かして効果を測る**方が、判断が付きやすい。
3. `p` の 3–6 Hz 成分が 5.6 deg/s より明確に増えたら行き過ぎ。戻す。

### ロールの −6.65° 定常偏差は重みでは直らない

これは未モデル化の一定外乱に対する定常誤差。**プロペラ／モータの物理点検とトリムで潰す。**
`RL` モータの Δu rms は 0.0657 で他（0.124–0.190）の **1/2 以下**という偏りも続いている。

## 5. `u_base` と `T_ref` の関係

### 定義（コードそのまま）

```cpp
// control.cpp:1258
T_ref = 0.5f * BATTERY_VOLTAGE * (Chdata[2] - CH3MIN) / (CH3MAX - CH3MIN);
// control.cpp:129
float T_ref_coe = 0.6;
// control.cpp:1780
u_hover = clamp(T_ref * T_ref_coe, 0.0f, U_duty_max /* = 0.95 */);   // ← これが u_base
```

`BATTERY_VOLTAGE` は `control.hpp:23` の**定数 7.4**で、実測電圧ではない。したがって

```
T_ref  = 3.7 × スティック割合          (0 … 3.7)
u_base = 0.6 × T_ref = 2.22 × スティック割合、ただし 0.95 で頭打ち
```

**ログで検証済み**: `|u_base − 0.6 × T_ref|` の最大値は `6.0e-06`（float 丸め）。
今回の飛行は `T_ref` 0.842–1.212 → `u_base` 0.505–0.727。

### `u_base` が制御で果たす 3 つの役割

**① 加算合成の基準点。** NMPC が最適化するのは絶対 duty ではなく `Δu`。
実際の指令は `duty_i = clamp(u_base + Δu_i, 0, 0.95)`。
つまり **`u_base` が「高さ」を、NMPC が「傾き」を担当**する。
高度制御を NMPC に入れないのは `B_c·1 = 0`（共通モードは姿勢に効かない）が根拠
（`repository_rules §3`）。**スロットルと姿勢は原理的に分離している。**

**② box 制約の位置を決める（ここが重要）。**

```
Δu ∈ [ −u_base , 0.95 − u_base ]
```

`u_base` が上がるほど**上側の余裕が減る**。今回の平均 `u_base = 0.616` では

```
下向き 0.616  ←──────────●──────→ 上向き 0.334      非対称 1.84 : 1
```

姿勢を作るには「片側を上げて反対側を下げる」必要があるので、**効くのは狭い方（上側）**。
`u_base = 0.95` になると上向きの余裕がゼロになり、**姿勢制御の権限が完全に消える**。

**③ 動作ゲート。**
`nmpc_run = (T_ref * T_ref_coe >= Flight_duty)`（=0.05）で NMPC の起動を決め、
`common_duty < Disable_duty`（=0.1）でモータを止める。どちらも `u_base` と同じ量で判定している。

### ⚠ スロットルスティックの分解能が悪い

`u_base` は `0.95` で頭打ちになるので、`T_ref = 1.583`、すなわち**スティック 42.8 % で上限に達する**。

| スティック | `T_ref` | `u_base` |
|---|---|---|
| 0 % | 0.00 | 0.00 |
| **27 %** | 1.00 | **0.60（今回のホバー付近）** |
| **42.8 %** | 1.58 | **0.95（上限）** |
| 100 % | 3.70 | 0.95（変わらない） |

- **スティック上半分（43–100 %）は完全に無効。**
- **ホバーから全開までがスティック travel のわずか 16 %。**

パイロットが「高度が合わせにくい」と感じるなら原因はここ。
`0.5f` の係数か `T_ref_coe = 0.6` を見直せば分解能は 2 倍以上にできる。
ただし**ホバー点のスティック位置が動く**ので、変えたら必ず係留から試すこと。
なお `T_ref_coe` を変えると `Flight_duty` / `Disable_duty` の判定点も一緒に動く。

## 6. 次にやること（優先順）

1. **チャタリングの原因を切り分ける。** プロペラを外して機体を固定し、
   スティックを一定にして 100 Hz ログを取る。それでも反転するなら**完全にソルバ内部の問題**で、
   機体・センサは無関係と確定できる。`admm_max_iter` を 2 → 4 にして消えるかも同時に見る。
2. チャタリングを潰してから `R_u` を触る。
3. ロールの定常偏差 −6.65° と `RL` モータの偏りは**物理点検**で潰す。
4. スロットル分解能（§5 末尾）はパイロットと相談して決める。

⚠ 未解決の持ち越し: `mass = 0.35` vs 実測 ≈0.383 kg、`T_max = 1.04` vs 同定値 0.79–0.82、
`Iz = 3.00e-3` の出所、モータ一次遅れがモデルに入っていないこと。
