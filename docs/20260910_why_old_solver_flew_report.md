# 報告書：なぜ「バグの残る旧ソルバ」は飛び、「正しく直した新ソルバ」は飛べなかったのか

- 日付: 2026-09-10
- 対象機体: ヘキサコプタ Benzen（F1404 モータ、GEMFAN-3630-3 プロペラ、Pico 2 W、姿勢 NMPC）
- 想定読者: 制御工学を学んでいる学部生・大学院生
- 根拠となる記録: `docs/ai/decisions/20260909_*` 〜 `20260910_*`（本文中で参照）

> **一言でいうと**: 旧ソルバは「バグのせいで制御ゲインが半分に落ち、さらに当時は弱いプロペラだった」ため、
> 設計値の約 0.3 倍という**弱い制御**で飛んでいた。弱いので鈍かったが、モータの遅れに対する**位相余裕**があった。
> バグを直してゲインが設計値に戻り、同時にプロペラが強くなったことで、ループゲインが旧の約 2〜6 倍になり、
> モデルに入っていない**アクチュエータの遅れ（40〜50 ms）**に対する位相余裕を失って 3〜5 Hz で発振するようになった。
> さらに旧ソルバの「バグ」は、正しい制御器にはない**ディザ**（毎周期反転する成分）を出しており、
> それが実機ではなぜか発振を抑えていた。この効果はまだ説明できていない。
> 遅れ補償（40 ms 先の状態を予測して制御する）を入れると、新ソルバでも 3〜5 Hz の発振は消えた。
> 残っている墜落原因は、ソルバとは別の**姿勢推定器（EKF）の間欠的な発散**である。

## 0. 用語の準備（本文で使う言葉）

| 用語 | 意味 |
|---|---|
| **NMPC**（非線形モデル予測制御） | 機体の運動方程式を使って「これから N 周期先まで」の姿勢を予測し、予測誤差とモータ入力の大きさを合わせたコスト J を最小にする入力列を毎周期解き直す制御。先頭の入力だけをモータへ出す。 |
| **状態 x** | ここでは `[φ, θ, p, q, r]`（ロール角、ピッチ角、3 軸角速度）の 5 次元。 |
| **入力 u / Δu** | 6 発モータの duty（0〜0.95）。本機はホバー duty `u_hover` からの差分 Δu を最適化する（加算合成）。 |
| **重み Q, R** | コスト J = Σ(状態誤差ᵀ Q 状態誤差 + Δuᵀ R Δu)。Q が大きいと姿勢誤差を嫌い、R が大きいと入力を嫌う。`R_u` を上げると制御が穏やかになる。 |
| **RTI**（Real-Time Iteration） | 毎周期、ニュートン法を 1 回だけ回す NMPC の実装法。前周期の解を初期値（**ウォームスタート**）にして 1 ステップだけ進める。 |
| **凝縮形（condensed）と Sx, Su** | 予測式を `X = Sx·x0 + Su·U` の形にまとめたもの。Su は「入力列 U が予測姿勢列 X にどう効くか」の感度行列。 |
| **ヘシアン H** | コストの 2 階微分。`H = Suᵀ Q Su + R`。ニュートン法の「曲率」。本機は毎周期作り直さず、**準ニュートン更新**（TR1, SR2）で近似的に追従させる。 |
| **勾配 g と定数項 c** | J(U) = ½UᵀHU + cᵀU + const と書けるとき、∇J(U) = H·U + c。**c は U に依らない定数項**、g = ∇J(U_lin) は「線形化点 U_lin における勾配」。この 2 つの取り違えが本件の発端。 |
| **ADMM** | 入力の上下限（**box 制約**）を扱う反復法。主変数 U、射影変数 z（box に押し込んだ U）、双対変数 λ（制約を守らせる圧力）を交互に更新する。 |
| **固有値と安定性（離散系）** | 毎周期 `U_{k+1} = A·U_k + b` で更新される量は、A の固有値の絶対値が 1 未満なら収束、1 ちょうどなら減衰も発散もしない、1 超なら発散する。固有値 −1 は「符号を毎周期反転しながら振幅が変わらない」振動。 |
| **ループゲイン** | 「制御器の出す指令の大きさ（姿勢誤差 1 度あたり）」×「機体がその指令にどれだけ反応するか」の積。**制御器だけ見ても分からない**。 |
| **位相余裕・遅れ** | フィードバックループの信号が一周して戻るときの遅れ。遅れが大きいほど、ある周波数で「戻ってきた信号が逆向きに効く」ようになり発振する。ゲインを上げるとその周波数（交差周波数）が上がり、遅れの影響が増える。 |
| **むだ時間 T の位相遅れ** | 周波数 f [Hz] で `2π f T`[rad]。T = 50 ms なら 4 Hz で 72°、これは大きい。 |
| **零空間（null space）** | 6 発モータの入力のうち、ロール・ピッチ・ヨー・総推力の**どれにも効かない**方向（6 − 4 = 2 次元）。ここに入力を出しても機体は何も感じないが、モータは動く。 |
| **ディザ** | 平均はゼロだが高周波で振れている成分。ここでは毎周期符号が反転する 50 Hz 成分。 |
| **EKF**（拡張カルマンフィルタ） | ジャイロ・加速度計・磁気センサから姿勢（四元数）とジャイロバイアスを推定する。 |

## 1. 旧ソルバの「バグ」は何をしていたか

### 1.1 バグの中身

ADMM の主変数更新は理論上

```
(H + ρI) U_new = −c + ρ (z − λ)
```

で、右辺に必要なのは**定数項 c** である。ところが旧実装は右辺に**勾配 g = H·U_lin + c** をそのまま使っていた
（U_lin は前周期の解、ウォームスタート）。すると `H + ρI ≈ H` のとき

```
U_new ≈ −U_lin − H⁻¹c
```

という写像になる。**固有値が −1** なので、解は毎周期符号を反転しながら減衰しない。
不動点（振動の中心）は `−½ H⁻¹c`、つまり**本来の最適解のちょうど半分**である。
（記録: `20260909_admm_gradient_bug_root_cause.md`）

### 1.2 実機で何が起きていたか

- モータには「正しい解の半分」＋「毎周期反転する成分（50 Hz ディザ）」が出る。
- モータは時定数 ~50 ms の一次遅れなので 50 Hz には追従できず、**機械的に平均**される。機体が実際に受けるのは半分の解だけ。
- 反転成分の大半（約 94%、のちの解析で 65〜70%）は**零空間**にあり、姿勢には効かない。ただし推力を浪費し、ESC とモータには負担になる。
- 零空間成分は固有値 −1 の写像で**減衰も励起もされない**ので、雑音で積み上がった分が**時間とともに単調に育つ**。
  やがて box（duty 0〜0.95）に当たり、そこで ADMM の双対変数 λ が暴走して NaN になり、モータが固着した（0909_v1 の最後）。

つまりバグは **(a) 実効ゲインを ½ にする、(b) 姿勢に効かない大きなディザを出す、(c) 時限爆弾を抱える** の 3 つを同時にやっていた。

## 2. なぜ旧ソルバは飛べたか — ループゲインで見る

### 2.1 制御器のゲインだけ見ると足りない

飛行ログから「姿勢誤差 1 度あたりの整合した指令トルク」（制御器ゲイン K角）と、
「指令トルク 1 単位あたりの角加速度」（機体ゲイン B）を同定した。**ループゲイン = K角 × B**。

| 時期 | ソルバ | プロペラ | K角 [/deg] | B [rad/s²/unit] | ループゲイン K角×B | 結果 |
|---|---|---|---|---|---|---|
| 0904 | 旧（バグ有, R_u=120） | D90S | 0.61e-3（½ 込み） | **393** | **0.24** | 飛べた（鈍い） |
| 0909 | 逆算 c 版（バグ違い, R_u=320） | GEMFAN | 1.1e-3 | **852** | 0.93 | 数秒で墜落 |
| 0910 | 新（R_u=320） | GEMFAN | 0.86e-3 | 640 | 0.55 | 4.5 Hz 発振 |
| 0910 | 新（R_u=1200, Q_p=30） | GEMFAN | 0.34e-3 | 700 | **0.23** | 3.3 Hz 発振 |

（記録: `20260910_v7_prop_change_doubled_plant_gain.md`, `20260910_v8_lag_limited_mode_persists_at_old_loop_gain.md`）

ポイントは 2 つある。

1. **プロペラ交換で機体ゲイン B が約 2 倍になっていた。** D90S（0904）→ GEMFAN（0909 以降）。
   モデルの `T_max` はそのままだったので、「制御器を旧に合わせた」つもりでもループゲインは 2 倍だった。
   私はこれを 3 回見落とし、制御器側だけを旧に合わせ続けた。
2. それを含めて **ループゲインを旧と同じ 0.23 まで落としても（R_u=1200）、新ソルバは 3.3 Hz で発振した。**
   ゲインだけでは説明が完結しない。

### 2.2 遅れとの関係 — 位相余裕

同定した機体の実効遅れは **40〜50 ms**（計算 ~8 ms ＋ ZOH ~5 ms ＋ モータ一次遅れ ~35 ms）。
NMPC の予測モデルにはこの遅れが**入っていない**（剛体だけ）。
4 Hz では `2π·4·0.045 ≈ 65°` の位相遅れになる。姿勢ループは二重積分（−180°）を角速度フィードバックで持ち上げているが、
そこへ 65° の遅れが乗ると、交差周波数が 3〜5 Hz に達した時点で余裕が尽きる。

**旧が飛べた理由の第 1 層**は「ループゲインが 0.24 と低く、交差周波数が低かったから遅れが致命傷にならなかった」である。
ゲインが低いので追従は鈍く（旧ログの姿勢 rms 12〜20 deg/s）、パイロットの体感は「もっさり」だった。

### 2.3 それでも説明できない差 — ディザ

ループゲインを揃えても新ソルバだけが発振する。飛行中の角速度スペクトルで比べると:

| 飛行 | ソルバ | ループゲイン | 浮上秒 | p の 2–5 Hz 帯占有率 |
|---|---|---|---|---|
| 0904_v4 | 旧（D90S） | 0.24 | 19.4 | 52% |
| 0910_v7 | 新 R_u=500 | 0.40 | 3.5 | **82%** |
| 0910_v8 | 新 R_u=1200 | 0.23 | 2.5 | 53% |
| **0910_v9** | **旧（GEMFAN, R_u=300）** | ~0.6 | **16.0** | **7%** |
| 0910_v10 | 新 ＋ 遅れ補償 | 0.23 | 5.5 | 23% |

0910_v9 は旧ソルバを GEMFAN で飛ばしたもので、ループゲインは新より**高い**のに 2–5 Hz 成分がほとんど無く、
今日最長の 16 秒を飛んだ。**旧が飛べた理由の第 2 層は、ディザそのものが実機の 3–5 Hz モードを抑えていること**である。
ホストのモデル（モータ一次遅れ 50 ms）ではこの効果は出ないので、機構は未特定。
仮説は「毎周期 ±0.1〜0.4 の duty 反転が ESC／モータの不感帯や小信号遅れを線形化し、実効的な遅れを減らしている」。
検証には、ディザ有無でモータ応答をベンチで測る必要がある。

今日（0910）の 10 飛行は、**別々の原因が順番に露出した**。1 つ潰すと次が見える、を繰り返した。

| 飛行 | 設定 | 直接原因 | 教訓 |

| v2 | Q_p=1 | EKF の偽の傾き ＋ 私の Q_p 推奨が静的ゲインを 1.93 倍にしていた | 正弦掃引だけでゲインを測ってはいけない |

## 4. 遅れ補償とは何をしたか（v10）

制御周期ごとに、**直近 4 周期に出した duty 列でモデルを 40 ms ぶん積分し、「新しい指令が効き始める時刻」の状態を x0 として NMPC に渡す**。
標準的な「むだ時間補償」で、4 Hz で約 58° の位相を取り戻す。予測が物理的にあり得ない値（角度 20° 超、角速度 573 deg/s 超）になったら補償を切る。

ホストの閉ループ試験では、補償なしで発散した 9 条件（機体ゲイン 2〜4 倍 × 純遅延 3〜7 周期）が全て収束した。
実機 v10 では 2–5 Hz 帯の占有率が 82% → 21〜32% に落ち、**新ソルバで初めて遅れ限界モードが消えた**。
（記録: `20260910_delay_compensation_new_solver.md`）

## 5. いま残っている問題

1. **EKF の偽の傾き（最優先）。** 今日 5 回の飛行で、ジャイロがゼロなのに姿勢角が毎秒 3〜8 度で流れた。
   ジャイロバイアス状態をリセットしても止まらない → 加速度計／磁気の観測更新が四元数を引いている。
   磁気の基準（起動時平均 `MN/ME/MD`）が場所・向き・電流で狂う、が第一候補。
   検証: 旧ファームでも地上でモータを回して同じ現象が出るか（ソフト非依存の確認）、プロペラ無しで出るか（磁気か振動か）。
2. **旧ソルバがなぜ 3–5 Hz を抑えるのか**（ディザの実機効果）。分かれば、正しい制御器に同じ効果を明示的に実装できる。
3. 左右の推力差（左−右 duty +0.02、0910_v5 以降）。プロペラ／腕の点検。
4. 受信機 FAILSAFE（0910_v7 で 4.4 秒）。アンテナ点検。

## 6. 学んだこと（制御の一般則として）

- **ゲインを合わせるなら「制御器 × 対象」で合わせる。** 対象（プロペラ）が変わっていることは制御器のパラメータに一切現れない。
- **バグが安定化装置になっていることがある。** 直すときは「直した後の系が発散しないか」を先に確かめる。
  「1 回に 1 つ変える」原則が、この場合だけは逆に危険（修正とゲイン戻しは 1 つの変更として扱う）。
- **遅れで限界にあるループは、ゲインを下げても直らない。** 比例側と一緒に減衰側も下がり、位相余裕は増えない。位相を作る変更（遅れ補償）に切り替える。
- **ホストで再現しない実機の挙動は、ホストを増やしても解けない。** 実機に内部状態のログを入れ、記録入力を実機で再生する仕組みを作る。
- **異常検知の閾値は「正常だった全記録」で誤発火率を測ってから決める。** 異常事例で発火するだけなら、ほとんどの閾値で発火する。
