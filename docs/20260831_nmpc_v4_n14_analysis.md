## 1. 検証できたこと

### 1-1. 時間とともに劣化する問題は解消した

`cycles_since_reset` は **0–100 に張り付き**、姿勢誤差との相関は **+0.704 → −0.070**。
**関係が消えました。** 経過時間との相関も +0.713 → +0.302 まで下がっています。

**v3 の劣化の原因は TR1/SR2 の数値漂流だった、という仮説が支持されました。**
（残る +0.302 は電池電圧の低下・機体が離陸点から離れる等で説明できる範囲です。）

### 1-2. `N³` の見積もりは当たっていた

| | 予測 | 実測 |
|---|---|---|
| フル再構築（58 ms × (14/17)³ = ×0.558） | **32 ms** | **34 ms** |

`iter_us` は 8.5 ms → **6.43 ms**、`loop_us` は 10.3 ms → **8.27 ms**。
**制御周期 10 ms の予算内に初めて収まりました。**

### 1-3. 34 ms のフル再構築は姿勢を乱していない

ログに当たった 4 回（t = 8.06 / 14.12 / 55.23 / 61.29）の前後を追いましたが、
**姿勢・角速度に段差は出ていません。**

```
t=  7.99 phi= +1.0 theta= +0.8 p= +1 q= -1   iter= 6ms
t=  8.06 phi= +1.1 theta= +0.7 p= +0 q= +1   iter=34ms  ← フル再構築
t=  8.17 phi= +1.1 theta= +0.8 p= -2 q= -7   iter= 6ms
```

→ **「機体が静かな時だけ再構築する」（前回資料の 4-D）は不要です。** N=14 で十分に短くなりました。

### 1-4. ヨーの片流れは止まった

`r` の平均が **−16.7 → +0.5 deg/s**。`Q_r` を 6 → 20 にした効果と考えられます。
（`psi_ref` rms 30 deg/s で操縦者がヨーを積極的に振っているため、rms 24.9 自体は追従の結果です。）

### 1-5. 前回の宿題（Q1）が解けた

ログの `Q_phi_eff` 列に**ファーム内の実効 `Q_phi` が記録されていました**。

| ログ | `Q_phi_eff` |
|---|---|
| `0831_v1.csv` | **50** |
| `0831_v3.csv` | **50** |
| `0831_v4.csv` | **100** |

→ **v1 と v3 はどちらも `Q_phi = 50` で飛んでいました。** これまでの解析の前提は正しかったことになります。
`Q_phi/Q_theta = 100`、`Q_r = 20` が入ったのは v4 が初めてです。

## 3. 次に効くのは重みではない — スティック指令のスケール

`control.cpp` の `update_attitude_refs_from_sticks()`:

```cpp
Phi_ref   = Phi_trim   + 0.8f * M_PI * (Chdata[3]-ail_c) * 2 / (CH4MAX-CH4MIN);   // ±144°
Theta_ref = Theta_trim + 0.3f * M_PI * (Chdata[1]-ele_c) * 2 / (CH2MAX-CH2MIN);   // ±54°
Psi_ref   = Psi_trim   + 0.8f * M_PI * (Chdata[0]-rud_c) * 2 / (CH1MAX-CH1MIN);   // ±144 deg/s
```

**フルスティックでロール ±144°、ピッチ ±54°。ロールがピッチの 2.67 倍です。**

これがログの非対称をそのまま説明します:

| | 指令 rms | 指令 max | 実姿勢 rms | 追従誤差 rms |
|---|---|---|---|---|
| ロール | **20.13°** | **107.04°** | 10.34° | **18.85°** |
| ピッチ | 8.30° | 28.56° | 4.19° | 8.32° |

**ロール軸の制御が悪いのではなく、2.67 倍強く指令されているだけです。**
そして **107° の指令は、姿勢 NMPC の線形化モデル（小角度・重力結合なし）の有効範囲を大きく超えています。**
モデルの外へ出た状態で最適化しているので、追従できないのは当然です。

### 対策

```cpp
// ロールとピッチを同じスケールに揃え、モデルの有効範囲（±25–30°）に収める
Phi_ref   = Phi_trim   + 0.15f * M_PI * ... ;   // ±27°  (0.8f → 0.15f)
Theta_ref = Theta_trim + 0.15f * M_PI * ... ;   // ±27°  (0.3f → 0.15f)
Psi_ref   = Psi_trim   + 0.5f  * M_PI * ... ;   // ±90 deg/s (0.8f → 0.5f)
```

- **これは重みの調整ではなく、操縦感度の設定です。** 重みを触る前にこちらを直してください
- **1 回に 1 つだけ**の原則からは、まず `Phi_ref` の `0.8f → 0.3f`（ピッチと同じに揃える）だけでも十分に効くはずです
- ⚠ 感度を下げると**同じスティック操作で機体が緩慢に感じます**。これは劣化ではなく設計変更です
