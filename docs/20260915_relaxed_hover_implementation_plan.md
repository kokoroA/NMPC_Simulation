## 【2026-09-16 改訂】⚠ 第 0 章の数値は無効。結論は「やる」に変わった

2 つの前提が変わった。

### (a) ベンチ推力曲線は実飛行の推力を 19% 過大評価していた

健全便 `0916_100Hz_normal_v1`（21 s 安定、静穏 1089 サンプル）の実測ホバーは **`u_base` = 0.5506**。
ベンチ曲線だと 340 g を持ち上げている計算になるが実機は 285.3 g。
→ **`fmax = T(0.95) = 0.8407 N` は使えない。実飛行較正後は `fmax = 0.7052 N`**
（[`20260916_bench_thrust_curve_overstates_flight_thrust_ftc_has_no_authority.md`](ai/decisions/20260916_bench_thrust_curve_overstates_flight_thrust_ftc_has_no_authority.md)）。

### (b) 質量 335 g → 285.3 g

### 再計算（実飛行較正 `fmax = 0.7052 N`, `m = 285.3 g`, 揚力 = `mg` を満たす平衡のうち最大 duty を最小化）

| 構成 | Ω | φ / θ | 最大 duty | **0.95 までの余地** |
|---|---|---|---|---|
| 健全 6 発 | 0 | 0 | 0.551 | 0.399 |
| **静的 4 発（現行 FTC）** | 0 | 0 | **0.939** | **0.011** |
| **relaxed hover（`Cr = 3.7e-4`）** | **400 deg/s** | −10° / −10° | **0.742** | **0.208** |
| **relaxed hover（`Cr = 9.5e-5`）** | **775 deg/s** | −4° / −6° | **0.738** | **0.212** |
| relaxed hover（`Cr = 0.005` ファーム値） | 0 | 0 | 0.939 | 0.011 |

> **余地が 0.011 → 0.21 に 19 倍**。健全機（0.399）の **52%** まで戻る。

**第 0 章の「軽量化のほうが得」という結論は撤回する。**
軽量化は 335 → 285.3 g で既に実施済みで、それでも静的 4 発の余地は 0.011 しかない
（`0916_100Hz_FTC_v1` は 2 回とも姿勢を保てず壁に衝突）。**relaxed hover 以外に道が無い。**

### ⚠ 新たに判明した最重要の前提条件 — `Cr`

上表の最下行が示すとおり、**ファームの `Cr = 0.005` のままでは平衡は `Ω = 0`（＝静的 4 発）に退化し、
relaxed hover は 1 ポイントも生まない。** モデルが「回しても得しない」と言うので solver は回さない。

さらに実測 `Cr` の 4 倍のばらつき（9.5e-5 〜 3.7e-4）が、必要な `Ω` を **400 vs 775 deg/s** に振り分ける。
これは EKF の遠心誤差（10 mm オフセットで 2.8° vs 10.6°）が許容できるか否かの境目である。

→ **`Cr` の同定が Step 0 になった。** 詳細は下記「改訂した実施順序」。

## 0. 先に判断材料 — やるべきか  ⚠【2026-09-16: この章の数値は無効。上の改訂を見ること】

FR 停止時の推力余裕（`fmax = T(0.95) = 0.8407 N`、実測 `C_QT/Iz = 6.19`、`Cr = 9.5e-5`）:

| 方法 | 質量 | 余裕 | 必要な工数 | 危険度 |
|---|---|---|---|---|
| **何もしない（水平・静的）** | 335 g | **+2.3%** | 0 | 低 |
| **軽量化のみ** | 308 g | **+11.3%** | 機械工作のみ | 低 |
| **relaxed hover（`Ω ≤ 300` に制限）** | 335 g | +4.0% | 大 | 中 |
| **relaxed hover（`Ω = 680 deg/s`）** | 335 g | **+21%** | 大 | **高** |
| relaxed hover ＋ 軽量化 | 308 g | +33% | 大 | 高 |

**判断のポイント。**

- **旨みがあるのは `Ω = 680 deg/s`（毎秒 1.9 回転）の側だけ。** 安全側に `Ω ≤ 300` で制限すると
  +1.8 ポイントしか増えず、工数に見合わない
- **軽量化は確実・低リスクで +9 ポイント。** 先にこちらを済ませるべき
- relaxed hover の価値は「余裕」よりも **研究としての新規性**（安価な MCU 上で回転ホバー FTC）にある。
  そこを取りに行くかは工学ではなく研究方針の判断

⚠ **本計画は 2 週間規模。3 日では終わらない**（§5）。

## 1. 前提 — 検算済みの事実

実装に入る前に、以下は数値で確認してある（`m = 335 g`, FR 停止）。

### 1-1. 平衡は実在する固定点である

`φ = −6°, θ = −6°, Ω = 680 deg/s` で

```
body rates : p = +71,  q = −71,  r = +673  [deg/s]
推力        : f[FL,MR,ML,RR,RL] = [0.678, 0.698, 0.616, 0.697, 0.634] N
max f       = 0.698 N = 上限の 83%   → 余裕 +21%
ẋ(平衡点)  = [0, 0, 0, 0, 0]        （数値で確認）
```

### 1-2. ★重要★ 現行の状態 `[φ, θ, p, q, r]` で表現できる

**平衡では `φ, θ, p, q, r` がすべて一定**である（回っているのは状態に持っていない `ψ` だけ）。
したがって **RTI の 1 点線形化は「静止した動作点まわり」の線形化になり、成立する。**
オイラー角を捨てる必要は**無い**。

> ⚠ 本計画の初期検討では「ホライズン 0.14 s に 95° 回るから線形化が壊れる」と考えたが、
> **誤りだった。** 回るのは `ψ` で、状態は動かない。
> （[クアッド側の資料](20260915_quad_ftc_with_nmpc.md) の該当記述も訂正済み）

### 1-3. 開ループは「中立不安定」で、暴れる種類ではない

平衡点で線形化した `A_c` の固有値:

```
  0.000 ± 11.868 j      ← 回転そのもの（Ω = 11.87 rad/s）。中立
 −0.744
−33.464 ±  7.223 j      ← よく減衰している
```

**最大実部は 0.000。** 制御は要るが、指数的に発散する平衡ではない。

### 1-4. 可制御だが方向によって効きが桁違い

可制御行列の階数 **5/5**、特異値 `[1.45e8, 9.17e7, 5.14e3, 4.56e3, 2.00e1]`、
**条件数 7.2e6**。制御できるが、効きにくい方向がある。重み設計で配慮が要る。

### 1-5. ⚠ EKF が壊れる — これが最大の実装課題

IMU が回転軸から外れていると遠心加速度が重力基準を汚す。

| IMU オフセット | 遠心加速度 | **重力方向の誤差** | `‖a‖` |
|---|---|---|---|
| 5 mm | 0.70 m/s² | 4.1° | 9.84 |
| 10 mm | 1.41 m/s² | **8.2°** | 9.91 |
| 20 mm | 2.82 m/s² | **16.0°** | 10.21 |
| 30 mm | 4.23 m/s² | **23.3°** | 10.68 |

⚠ **`‖a‖` はほとんど変わらない**（遠心力は水平向きで直交合成になるため）。
`ekf_reinit_on_arm()` の `|‖a‖ − g| < 2.0` という判定は **これを検出できない。**
20 mm のずれで姿勢推定が 16° 傾いたまま「正常」と判断される。

## 2. 実装 — ファイル単位の変更計画

### Step 1. オフライン平衡表の生成（実機に触らない）

**新規** `tools/gen_relaxed_hover_table.py`

- 入力: `m`, `Ix/Iy/Iz`, `C_QT`, `Cr`, `Cp/Cq`, `fmax`, 故障モータ
- 処理: `(φ, θ, Ω)` を外側探索、`f` は零空間 1 次元の minimax（本書の計算と同じ）
- **出力: 推力水準 `u_hover` でパラメータ化した 1 次元テーブル**
  （`20260904_relaxed_hover_equilibrium_design.md` 追記3 の設計判断）

```
u_hover | phi_eq | theta_eq | Omega_eq | u_eq[5] | rho（余裕）
```

⚠ 形状だけ（`u_eq − mean(u_eq)`）を持つ案は却下済み。
**余裕がどこで消えるかを機体が知らないまま飛ぶことになる**ため（同追記3）。

**成果物**: `nmpc_params.hpp` に `constexpr` で貼れる C 配列（16〜32 点）。

### Step 2. 平衡点の安定性・到達可能性をシミュレーションで確認（実機に触らない）

**ここが本計画の最大の未知**であり、実機に進む前の関門。

1. 平衡点まわりで NMPC を閉じ、擾乱に対して戻るか（§1-3 の中立モードが閉ループで安定化されるか）
2. **ホバー → 平衡への遷移**が通るか。動作点が大きく動くので
   **TR1/SR2 の warm start が追随するか**がここで出る（`reset_period = 100` では遅い恐れ）
3. `Cr` を 3e-5〜3e-4 で振っても遷移が成立するか（`Ω` が 470〜960 deg/s で動く）

**判定**: 3 のいずれかで遷移が破綻するなら、**実機に進まない**。

### Step 3. 参照生成の切り替え（`control.cpp`）

現状は [`control.cpp:2332`](../program/pico/pico-sdk2/pico-sdk/Benzen_NMPC/control.cpp) で

```cpp
x_ref(0) = Phi_ref;  x_ref(1) = Theta_ref;
x_ref(2) = 0.0f;     x_ref(3) = 0.0f;      // ← p_ref, q_ref は 0 固定
x_ref(4) = Psi_ref;
```

**変更**: `Ftc_mode == 1` のとき、テーブル補間した平衡を入れる。

```cpp
if (Ftc_mode) {
    RelaxedEq eq = relaxed_hover_lookup(u_hover);     // Step 1 のテーブル
    float a = relaxed_fade();                          // 0 → 1 のフェード
    x_ref(0) = (1-a)*Phi_ref   + a*eq.phi;
    x_ref(1) = (1-a)*Theta_ref + a*eq.theta;
    x_ref(2) = a*eq.p;   x_ref(3) = a*eq.q;   x_ref(4) = a*eq.r;
}
```

- **`p_ref`, `q_ref` が初めて非零になる。** 現行構造がそのまま使える（NX・NU の変更不要）
- `U_ref` は [`control.cpp:2357`](../program/pico/pico-sdk2/pico-sdk/Benzen_NMPC/control.cpp) の
  `u_ref_shift[]` に `eq.u[j] − u_hover` を入れる。
  ⚠ **絶対 duty を入れてはならない**（`U` は `Δu` なので。同 decision 追記2 の落とし穴）
- フェード時定数は **1〜2 秒**から。速すぎると過渡で飽和する

### Step 4. フェイルセーフの再設計

| 項目 | 現状 | 変更 |
|---|---|---|
| `FS_RATE` | 360 deg/s | **`Ftc_mode` 中は 1200 deg/s**（平衡 680 の 1.8 倍） |
| `FS_ATTITUDE` | 90° | 平衡の傾きは 6° なので **据え置きでよい** |
| 過大 G | 150 m/s² | 遠心 2.8 m/s² は問題なし。**据え置き** |
| 新規 | — | **`\|Ω − Ω_eq\| > 300 deg/s` が 1 秒継続で中止**（平衡から外れた検知） |

⚠ `Bench_mode` のように「全部外す」のは**やってはいけない**。治具に固定されていないため。

### Step 5. EKF の遠心力補正（§1-5）

加速度計の測定値から、既知の遠心成分を引く。

```
a_corrected = a_measured − ω × (ω × r_imu)
```

- `r_imu` は IMU の重心からのオフセット [m]。**実測が要る**（基板図面かノギス）
- `ω` は既にある（`Wp, Wq, Wr`）
- ⚠ **`r_imu` を 5 mm 間違えると 4° の姿勢誤差が残る。** 精度がそのまま効く
- **代替案**: `Ftc_mode` 中は加速度による姿勢補正の重みを下げ、ジャイロ積分に寄せる。
  こちらは `r_imu` が不要だが、バイアスドリフトが乗る。**まずこちらで様子を見るのが安全**

### Step 6. ログ列の追加

現在 30 列 / 2176 行 = 21.8 s。追加したい列:

`phi_eq, theta_eq, r_eq, rho（余裕）, fade, Omega_est`

⚠ 列を増やすとリング時間が減る（30 → 36 列で 21.8 → 18.1 s）。
**遷移の観測が主目的なので、10 Hz シリアルではなく 100 Hz リングで撮る必要がある。**
遷移が 2 秒なら 18 s でも足りる。

## 4. 中止条件（やめどき）

次のいずれかに当たったら**この計画を中止し、軽量化だけで進む**。

1. Step 2-3 のシミュで、**ホバー → 平衡の遷移が成立しない**（`Cr` の不確かさ範囲内で）
2. IMU オフセットの実測が **20 mm を超える**（姿勢誤差 16°。補正しても `r_imu` の精度が足りない）
3. 段階 6 で **回転数が予測から 2 倍以上外れる**（平衡モデルが機体を表していない）
4. 質量の実測が **356 g 以上**（そもそも FTC が成立しない。
   [`20260914_ftc_is_thrust_limited_not_cr_limited.md`](ai/decisions/20260914_ftc_is_thrust_limited_not_cr_limited.md)）

## 6. 未評価のリスク

- ⚠ **平衡の「到達可能性」は未評価。** 平衡が存在し、そこで可制御であっても、
  ホバーからそこへ行けるとは限らない。Step 2-3 がこれを見る唯一の機会
- ⚠ **`Cp`, `Cq` は一度も測っていない**（`0.025` は仮値）。平衡は `Cp/Cq` に依存する。
  `Cr` と同じく、平衡の「形」より「回転数」に効くと予想されるが**未確認**
- ⚠ 質量が未確定（0.300 / 0.335 / 0.356 / 0.390 の 4 説）。**最初に秤に載せること**
- ⚠ 毎秒 1.9 回転する機体の**プロペラは切創のリスクが桁違いに上がる**。
  段階 6 以降は保護ケージか十分な離隔を前提にすること
- ⚠ **relaxed hover は上昇能力をほとんど持たない**（`az = +1 m/s²` で余裕が消える。
  `20260904_relaxed_hover_equilibrium_design.md` 追記3）。**高度を上げられない飛行**になる
