# クアッドコプタの耐故障制御に NMPC を使えるか — 現行アルゴリズムの何が壊れ、どう直すか

- **日付**: 2026-09-15
- **対象**: `Benzen_NMPC`（ヘキサ向け姿勢 NMPC）をクアッドコプタへ適用する場合の可否
- **関連**: [アルゴリズム解説と修正遍歴](20260912_benzen_nmpc_algorithm_and_history.md) §9 / Phase 9

---

## 0. 結論

**現行アルゴリズムのままでは不可能。** ただし理由は「NMPC だから」ではない。

| | ヘキサ（現行機） | クアッド |
|---|---|---|
| 1 発停止後の**水平ホバー解** | **存在する**（残り 4 発が `mg/4`、ヨーも自動的に釣り合う） | **存在しない**（後述） |
| 成立させる方法 | そのまま（推力が足りれば） | **回転平衡しかない**（機体が毎秒 2 回転する） |
| 現行の状態表現 `[φ,θ,p,q,r]` | 使える | **使える**（平衡は固定点。2026-09-15 訂正） |
| 高度を NMPC の外に出す設計 | 故障時は苦しいが動く | **成立しない**（`B_c·1 ≠ 0`） |

**クアッド FTC は「NMPC を諦める」話ではなく、「推力を扱う場所」と「参照の作り方」を作り直す話である。**

---

## 1. なぜクアッドは 1 発止まると水平に浮けないのか

ヘキサで使ったのと**まったく同じ代数**で、結論だけが正反対になる。

クアッド X（腕長 `L = 0.12 m`、`a = L/√2 = 0.0849`）、モータ順 `[FR, FL, RR, RL]`:

```
kXm = [ +a, +a, −a, −a ]     （前後位置＝ピッチの腕）
kYm = [ +a, −a, +a, −a ]     （左右位置＝ロールの腕）
kS  = [ −1, +1, +1, −1 ]     （反トルクの符号。対角が同じ向き）
```

**FR を止めて、鉛直・ロール・ピッチを釣り合わせる**（ヨーは一旦問わない）:

```
ピッチ式 :  +a·f_FL − a·f_RR − a·f_RL = 0   →  f_FL = f_RR + f_RL
ロール式 :  −a·f_FL + a·f_RR − a·f_RL = 0   →  f_RR = f_FL + f_RL
2 式を足すと                                 →  **f_RL = 0**
鉛直式   :  f_FL + f_RR = mg                 →  f_FL = f_RR = **mg/2**
```

ここまではヘキサと同じ形（**対角が自動的に 0 になる**）。違うのは次の 1 行である。

```
ヨー :  Σ k_S·f = (+1)·f_FL + (+1)·f_RR − (−1 の相手が居ない)
     =  f_FL + f_RR = **mg**        ← 合計推力がまるごとヨートルクになる
```

生き残った FL と RR は**同じ回転方向**なので、反トルクが打ち消し合わずに**足し算になる**。
`m = 250 g` なら `τ_z = C_QT · mg = 0.0296 × 2.453 = 0.0726 N·m`。
**これを打ち消す相手が機体に居ない。**

さらに推力でも破綻している。

```
必要 mg/2 = 1.226 N  vs  1 発の上限 T(0.95) = 0.841 N  →  146%
```

**ヨーでも推力でも二重に不可能。**

### ヘキサとの違いはどこから来るのか

| | 生き残る発 | 回転方向の内訳 | ヨーの釣り合い |
|---|---|---|---|
| ヘキサ 1 発停止 | 4 発（対角 RL も落ちる） | **CW 2・CCW 2** | **自動的に釣り合う** |
| クアッド 1 発停止 | 2 発（対角 RL も落ちる） | **同じ向き 2** | **合計推力 × `C_QT` が丸ごと残る** |

**ヘキサの冗長性の本質は「発数」ではなく「生き残った発の回転方向が割れること」だった。**

## 2. 回転平衡なら成立する — Mueller & D'Andrea 型の解

ヨー制御を**完全に放棄**し、機体が重力軸まわりに定常回転することを許すと解が現れる。
Phase 9.3 と同じ定式化（`ω̇ = 0` でもジャイロ項が残るので必要モーメントが非零になる）:

```
p = −Ω sinθ,  q = Ω sinφ cosθ,  r = Ω cosφ cosθ
τ_x = (Iz−Iy)·q·r + Cp·p|p|
τ_y = (Ix−Iz)·r·p + Cq·q|q|
τ_z = (Iy−Ix)·p·q + Cr·r|r|
Σf·cosφ·cosθ = mg
```

未知は `f`（3 個）＋ `φ, θ, Ω`（3 個）で 6、式は 4 本 → **2 パラメータ族**。
`(φ,θ)` ごとに「`f` について可解になる `Ω`」を求根で拾い、`0 ≤ f ≤ fmax` かつ
ピーク推力が最小になる点を選んだ（`L=0.12 m`, `Ix=Iy=1.2e-3`, `Iz=2.4e-3`, `C_QT=0.0296`,
`Cp=Cq=0.025`, `Cr=9.5e-5`, `fmax=0.841 N`）。

| 質量 | 非回転なら `mg/2` | 回転平衡 `φ` | `θ` | **`Ω`** | `max f` | 上限比 | 余裕 |
|---|---|---|---|---|---|---|---|
| 300 g | 1.472 N（175%） | −4° | −8° | 933 deg/s | 1.074 | 128% | −21.7% |
| 250 g | 1.226 N（146%） | −4° | −8° | 852 deg/s | 0.895 | 106% | −6.1% |
| **220 g** | 1.079 N（128%） | −4° | −8° | **799 deg/s** | 0.788 | 94% | **+6.7%** |
| 200 g | 0.981 N（117%） | −4° | −8° | 762 deg/s | 0.716 | 85% | +17.4% |
| 180 g | 0.883 N（105%） | −4° | −8° | 723 deg/s | 0.644 | 77% | +30.5% |

**読み取れること。**

1. **回転させると荷重が 2 発 → 3 発に散る。** 250 g で 146% → 106% まで下がる
2. **傾きは小さい**（`φ=−4°, θ=−8°`）。効いているのは傾きではなく**回転数**
3. **必要回転数は 720〜930 deg/s ＝ 毎秒 2〜2.6 回転**
4. 250 g では**まだ足りない**。この諸元だと **220 g 以下**が必要

### `Cr` は「成立するか」ではなく「何回転するか」を決める（`m = 200 g`）

| `Cr` | 3e-5 | **9.5e-5**（ヘキサ実測） | 3e-4 | 1e-3 |
|---|---|---|---|---|
| `Ω` [deg/s] | **1373** | **762** | 463 | 302 |
| `max f` | 83% | 85% | 85% | 88% |

**`Cr` が 33 倍動いても推力余裕はほぼ不変（83〜88%）なのに、回転数は 4.5 倍動く。**
ヘキサで得た結論（[`20260914_ftc_is_thrust_limited_not_cr_limited.md`](ai/decisions/20260914_ftc_is_thrust_limited_not_cr_limited.md)）
──「可否は推力律速、`Cr` は回転数を決めるだけ」── がクアッドでも同じ形で成り立つ。

## 3. 現行アルゴリズムの何が壊れるか

回転平衡（`Ω ≈ 800 deg/s`）を前提にすると、v10 の実装は次の 7 か所で破綻する。

| # | 壊れるもの | 理由 | 深刻度 |
|---|---|---|---|
| **1** | **高度を NMPC の外に置く設計** | 健全時は `B_c·1 = 0` で共通モード（推力）と差分モード（姿勢）が分離する。**FR を落とすと残り 3 発の `Σk_S = +1`**（`ΣkXm = ΣkYm = −0.0849`）で、**スロットルを上げるだけでヨーとロール・ピッチが出る**。分離の前提が消える | ★★★ |
| **2** | ~~状態 `[φ,θ,p,q,r]`（オイラー角）~~ → **訂正: 致命的ではない** | 当初「ホライズンに 112° 回るので線形化が壊れる」と書いたが**誤り**。**平衡では `φ,θ,p,q,r` がすべて一定**で、回るのは状態に持っていない `ψ` だけ。RTI の 1 点線形化は「静止した動作点まわり」の線形化として成立する。残る実害はジンバルロック（`θ→±90°`）の回避だけで、平衡の傾きは `−8°` なので当面問題にならない | ★☆☆ |
| **3** | **ヨーを「追従」する設計** | 回転平衡ではヨーは制御量ではなく**結果**。`Q_r` と `psi_ref` をそのまま残すと平衡を壊しにいく | ★★☆ |
| **4** | **参照 `φ_ref, θ_ref` を独立に与える設計** | 平衡は `(φ, θ, Ω, f)` が一体で決まる。独立に指令できない。オフライン平衡表が要る | ★★☆ |
| **5** | **`FS_RATE = 360 deg/s`** | 平衡回転数が 800 なので即ラッチ。しきい値の再設計が必須（ジャイロ ±2000 dps 自体は足りる） | ★★☆ |
| **6** | **TR1 / SR2 の warm start** | ホバー → 800 deg/s は動作点の巨大な移動。ランク 1・ランク 2 更新は「小さな変化」を前提にしている。`reset_period = 100`（1 秒に 1 回）では追随しない恐れ | ★☆☆ |
| **7** | **EKF と遅れ補償** | 100 Hz で 800 deg/s は **1 周期 8°**。加速度による姿勢補正は遠心力に埋もれ、`delay_comp_steps = 6`（60 ms）の前方予測は **48° 分**の外挿になる | ★★☆ |

⚠ **1 は実はヘキサにも効いている。** ヘキサでも FR を落とせば残り 5 発の `ΣkXm = −0.085 ≠ 0` なので、
「高度は NMPC に入れない」という設計判断（`repository_rules` §3）の根拠
`B_c·1 = 0` は**健全な機体でしか成り立たない**。ヘキサでは余裕を食うだけで済むが、
クアッドでは `Σk_S = +1` でヨーに直結するため致命的になる。

## 4. どう直すか（優先順）

### 4-1. 状態を reduced attitude（縮約姿勢）にする（★推奨だが必須ではない）

> ⚠ **2026-09-15 訂正**: 当初これを「最重要・前提条件」と書いたが、根拠にしていた
> 「ホライズン内に 112° 回る」が誤りだったため**格下げする**。
> 現行のオイラー 5 状態でも平衡は表現できる（第 3 節 #2 の訂正）。
> reduced attitude は**ジンバルロック回避と見通しの良さのための改善**であって、
> クアッド FTC の必要条件ではない。**必要条件は 4-2（推力を最適化の中に入れる）の方である。**


> 📘 **reduced attitude（縮約姿勢）**
> 機体の向きを「完全な姿勢（3 自由度）」ではなく、**機体 z 軸が慣性空間でどちらを向いているか**
> という単位ベクトル `n`（2 自由度）だけで表すこと。機首方位（ヨー）を最初から持たない。

ホバーに必要なのは「推力の向きが上を向いていること」だけで、機首がどちらを向いているかは要らない。
`n` は単位ベクトルなので自由度 2、これに角速度 `ω`（3）を足して **NX = 5 のまま**である。

- ヨーが**状態から消える**ので #3 が自動的に解決する
- オイラー角の特異点（`θ = ±90°`）が無くなるので大きな傾きでも破綻しない
- `Ω` が大きくても `n` はゆっくり動くため、#2 のホライズン問題が大幅に緩む
  （速く回っているのは機体であって、**推力の向きは回っていない**）

`repository_rules` §5 が「四元数化（特異点回避）は将来課題」と書いているのと同じ方向だが、
**クアッド FTC では将来課題ではなく前提条件**になる。

### 4-2. 推力を最適化の中に入れる

#1 より、故障後は共通モードと差分モードが分離しない。
合計推力を制御量に加える（`n` 2 ＋ `ω` 3 ＋ 推力方向の運動 → 実装上は
「合計推力をコスト・制約の対象にする」）か、少なくとも
**スロットル由来の `u_hover` が姿勢に与える寄与をモデルに含める**必要がある。

### 4-3. オフライン平衡表を持つ

第 2 節の `(φ, θ, Ω, f)` を**推力水準でパラメータ化した 1 次元テーブル**として持ち、実機は補間する。
ヘキサの relaxed hover で出したのと同じ設計判断
（[`20260904_relaxed_hover_equilibrium_design.md`](ai/decisions/20260904_relaxed_hover_equilibrium_design.md) 追記3）。
`U_ref` は絶対 duty ではなく `u_eq − u_hover` で与える（同記録 追記2 の落とし穴）。

### 4-4. フェイルセーフとログの再設計

- `FS_RATE` を平衡回転数の上に置き直す（例: 1200 deg/s）
- ジャイロのレンジ確認（LSM9DS1 ±2000 dps は足りる）
- 100 Hz ログでは 1 周期 8° 回る。回転位相を復元したいなら記録レートを上げる

### 4-5. ソルバ側

- 故障遷移時に **SR2 を即時リセット**する（`repository_rules` §3 の方針だが
  [`20260904_v8_ftc_airborne_no_go.md`](ai/decisions/20260904_v8_ftc_airborne_no_go.md) の時点で未実装のまま）
- 遷移中は `reset_period` を縮めるか、フル再構築を 1 回強制する

### 4-6. 変えなくてよいもの

**ADMM による box 制約の扱い、TR1/SR2 の計算量削減、`η` を box の縮小で表す FTC の入れ方は
そのまま使える。** クアッド化で壊れるのは**モデルと参照の作り方**であって、ソルバではない。

## 5. 検証の順序（もし着手するなら）

1. **オフラインで平衡表を作る**（本書 第 2 節のコードでよい）。可解な質量・回転数の範囲を確定
2. **reduced attitude モデルをホストで実装**し、平衡点まわりの線形化が
   ホライズン `N·dt` の間で妥当かを数値で確認（#2 が本当に解消したか）
3. **シミュレータで健全飛行 → 故障 → 回転平衡への遷移**を通す。
   遷移が最難関（動作点が巨大に移動するので #6 がここで出る）
4. 実機はプロペラ無し → 治具固定 → 係留 の順。**毎秒 2 回転する機体を自由飛行させる前に、
   遷移の再現性を必ず確認すること**

## 6. 前提と未検証

- ⚠ 第 2 節の諸元（`L = 0.12 m`, `Ix = Iy = 1.2e-3`, `Iz = 2.4e-3`, `m`）は**仮定した架空のクアッド**。
  実機があるなら測り直すこと。`Iz = Ix + Iy`（平板の垂直軸定理）を使っている
- ⚠ `Cp = Cq = 0.025` はヘキサの**未測定の仮値**をそのまま流用した。`Cr` はヘキサの実測値
- ⚠ **平衡の存在と推力余裕だけを見ている。** 可制御性・安定性・到達可能性は未評価。
  平衡点で線形化した制御効果行列の最小特異値の確認が要る
- ⚠ 第 1 節の代数は傾き 0・非回転の場合。**厳密**だが、これは「水平解が無い」ことを示すだけで、
  回転解の可否とは別物
- ⚠ Mueller & D'Andrea (2014) の結果と定性的に一致することは確認したが、
  彼らの数値と直接照合はしていない

## 7. 一行でまとめると

> **ヘキサは「1 発止まっても水平に浮ける機体」で、クアッドは「回らないと浮けない機体」である。**
> NMPC はどちらでも使えるが、後者では**推力を最適化の中に入れ、参照を平衡表から与える**必要がある。
