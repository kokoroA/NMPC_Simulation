# NX=8 / N=12 以前の Benzen_NMPC が墜落していた原因

- **作成日**: 2026-10-06
- **対象期間**: 2026-08-31 〜 2026-09-19（`x=[φ,θ,p,q,r]` の NX=5、N=14〜20、遅れ補償 DC0/DC4/DC6 の各版）
- **根拠**: `docs/ai/decisions/` の各記録（本文中にファイル名を示す）と 100 Hz オンボードログ
- **記法**: ✅ = ログ・再現実験で確認済み／🔶 = 有力だが未確定／❌ = 検討して否定した仮説

---

## 0. 結論（3 行）

1. **根本原因は、予測モデルにモータの遅れ（実効 40–50 ms、帯域 3–4 Hz）が入っていなかったこと。** 🔶
   NMPC は「指令した瞬間に角加速度が出る」と仮定して解くため、2–5 Hz 付近で位相が足りなくなり、
   ゲインを下げても上げても **3–5 Hz の発振**が残った。1 か月間、墜落の主犯候補として一貫して現れている。
2. **その上に、ソルバの実装バグが次々と重なった。** ✅（すべて修正済み）
   勾配の式の誤り、ADMM 定数項の逆算、線形化点 `|U_lin|` の暴走とそのガードの誤作動、再構築の嵐。
   個々の墜落の「直接の死因」はこちらであることが多い。
3. **最後の墜落（0919_v8、貨物あり）は、1 が飽和をきっかけに顕在化したもの**と見ている。 🔶
   遅れ補償 DC6 が有効な状態でも 2–3 Hz で発散した。純遅延の前方予測では一次遅れの位相を表せない
   — これが NX=8（遅れ状態をモデルに入れる）へ移行した直接の理由である。

## 1. 根本原因: 予測モデルにアクチュエータ遅れが無い 🔶

### 1.1 何が起きていたか

NX=5 のモデルは `ṗ = Σ (−kYm)·T_max/Ix · Δu + …` で、**指令 `Δu` がその周期のうちに角加速度になる**と仮定している。
実機ではモータ・ESC・プロペラの応答に 40–50 ms かかる。ループで見ると、
4 Hz で約 72° の位相が「モデルが知らないまま」失われている（`20260910_v8_lag_limited_mode_persists_at_old_loop_gain.md`）。

### 1.2 証拠の積み上がり

| 日付 / 便 | 観測 | 記録 |
|---|---|---|
| 0831 | 自由飛行でだけ 4 Hz 発振。接地中は出ない | `20260831_nmpc_gain_too_high_oscillation.md` |
| 0904_100Hz_v4 | 4.32 Hz 成分が 54.9 %（ソルバ修正前から存在） | `20260910_residual_4hz_mode_is_the_real_blocker.md` |
| 0910_v1 | ソルバ修正後も 4.1–4.8 Hz 発振で墜落。**入力遅れ 40–50 ms を実測** | 同上 |

| 0910_v8 | ループゲインを旧ソルバと同じ 0.23 に下げても 3.3–4.7 Hz で墜落。**ピッチ回帰の角度ゲインが負＝位相限界を超えている** | `20260910_v8_lag_limited_mode_persists_at_old_loop_gain.md` |

### 1.3 なぜ「ゲイン調整」では直らなかったか

- `R_u`（入力の重み）を上げると P も D も同じ割合で下がるので、位相の不足は解消しない。
  実際 0910_v8 では旧ソルバと同じループゲインに戻しても発振が残った。
- 遅れ補償（DC4→DC6）は効いたが、これは**純遅延**の近似である。純遅延の位相遅れは周波数に比例して増え続けるが、
  一次遅れの位相遅れは 90° で頭打ちになる。周波数ごとに位相の誤差が残る
  （`20260920_nx8_aggregate_actuator_lag_design.md`）。
- 0910 時点で、**ホストのシミュレータは実機の 3–5 Hz モードを再現できなかった**
  （`20260910_delay_compensation_new_solver.md`）。机上でゲインを詰めても、実機でしか確かめられない状態が続いた。

### 1.4 確度について

「遅れが根本原因」は**最も多くの観測と矛盾しない仮説**であって、単独で証明されたわけではない。
特に 0919_v8 の発散は窓が 0.8 s しかなく周波数分解能が 1.25 Hz なので、
過去の 3–4 Hz モードと同じものかは断定できない（同記録）。

## 2. 直接の死因になったソルバの実装バグ ✅（すべて修正済み）

| 日付 / 便 | 症状 | 原因 | 対応 | 記録 |
|---|---|---|---|---|
| 0904 | 指令 duty が毎周期反転（50 Hz チャタリング、ラグ 1 相関 −0.9） | 下の勾配バグ | 下 | `20260904_duty_chatter_50hz_nullspace.md` |
| 0909_v1 | ロールが 140° まで逸脱、全振幅チャタリング、disarm 後 NaN 固着 | `compute_gradient` の完全勾配 `g=H·U_lin+c` を絶対解の右辺に使い、写像の固有値が −1（不動点が正解の半分） | 3 点セットで修正 | `20260909_admm_gradient_bug_root_cause.md` |

## 4. 最後の墜落 0919_v8（貨物あり）🔶

| t [s] | 事象 |
|---|---|
| 1.0–7.3 | 安定ホバー。\|φ\|, \|θ\| ≤ 4° |
| 7.31–7.58 | 操縦者がロール −7.7° を指令。φ は逆方向 +2.7°、同時に指令なしで θ が −4.8° |
| 7.59–7.65 | FR が上限 0.95 に 6 周期張り付き（Δu = 上向き余地ちょうど） |
| 7.68 | 31.5 ms のフル再構築が落ち、解が不連続に跳ぶ（原因は 100 Hz ログに `reset_cause` が無く特定不能） |
| 7.70–8.50 | 半周期 0.2–0.3 s の振動が倍々に拡大（\|p\| 53→96→166→306 deg/s）。操縦者の入力も振れて PIO が重なる |
| 8.54 | \|q\| 371 deg/s で角速度フェイルセーフ → 全停止 → 自由落下 |

### 4.1 飽和に寄与した要因

- **推力は足りていた。** 6 発合計 532–534 g、309.5 g で T/W = 1.72
  （`20260920_plant_gain_is_1_6_to_2x_the_model_not_a_thrust_shortage.md`、`20260920_tmax_mapping_and_curve_shape_closed_plant_gain_retracted.md`）。
- **貨物で上向き余地が 0.400 → 0.344（−15 %）に減った。** ✅
- **指令の大部分が、モータが追従できない帯域にあった。** ✅ 巡航中の指令 du の交流パワーのうち **約 69 % が 5 Hz 超**
  （Welch・窓 5.0–10.3 s。設定次第で 67–84 %）。FR の生の最大 0.336 は、4 Hz の LPF 後は 0.110 しかない。
  ⇒ 機体を動かさない高周波の指令が、上限に当たる確率だけを上げていた
  （`20261006_du_above_5hz_85pct_not_reproducible_69pct.md`、図 [`figs/20261006_du_spectrum_v8.svg`](figs/20261006_du_spectrum_v8.svg)）。
  遅れを知らないモデルが、効かない帯域まで指令を出す — 1 章と同じ根を持つと見ている。🔶
- **飽和時の配分歪み。** モータごとに独立に射影されるので、モーメントの「向き」ごと歪む。
  共通モードを下げれば向きを保ったまま余地を作れるが、ADMM 4 反復ではその解に届かない
  （`20260920_box_is_already_full_range_admm_cannot_reach_the_sagging_solution.md`、`20260920_collective_sag_desaturation_design.md`）。

### 4.2 否定した仮説 ❌

| 仮説 | 否定の根拠 |
|---|---|
| 推力不足 | 上記。計算ホバー duty 0.610 と飛行実測 0.606 が一致 |
| PWM の換算ミス | 目盛り 18 → firmware duty 1.000 ちょうど、6 発実験と −0.4 % で一致 |
| 推力曲線が凸で、貨物によりループゲインが上がった | 実測は**凹**（`T=0.883·u^0.789`）。貨物で `dT/du` は 3.4 % **下がる** |
| プラントゲインがモデルの 1.6〜2 倍 | **撤回**。閉ループ飛行ログからゲインは同定できない（説明率 1–7 %） |
| ADMM の ρ を上げる／反復を増やす | 実機で追従が悪化（ρ=10 で相関 0.45→−0.17）、反復 10 は墜落実績あり |

## 5. 未解明のまま残っていること

1. **0919_v8 の発散が遅れ由来だと証明されていない。** 窓が短く、周波数の同定精度が足りない。
2. **7.68 s のフル再構築の原因**（`SR2_UNHEALTHY` か `SR2_BAD_C` の NaN 経路か）。`reset_cause` が 100 Hz ログに無い。
3. **入力ゲインと減衰 `Cp, Cq` は未測定。** 閉ループ飛行ログからは同定できないことが確定しており、ベンチ加振が要る。
4. **慣性モーメントは 335 g のときの実測値**を 285–310 g で使い続けている。
5. **貨物の振り子**（2–3 Hz は長さ 3–7 cm の振り子と同程度）。取り付けの剛性は未確認。

## 6. NX=8 / N=12 で何が変わり、何が変わらないか

| | NX=5（〜0919） | NX=8 / N=12（0920〜） |
|---|---|---|
| 状態 | `[φ,θ,p,q,r]` | `[φ,θ,p,q,r, a_p,a_q,a_r]`（3 軸の角加速度＝モータ遅れの状態） |
| 遅れの扱い | DC6（純遅延の前方予測） | 一次遅れ `τ=45 ms` を exact ZOH でモデル内に持つ。DC は 0 |
| 入力スタック | 84（=6×14） | 72（=6×12）。Hessian 84²→72² |
| 遅れ状態の推定 | なし | 400 Hz 段で**実際に PWM へ出した duty** から observer で推定 |

- **狙い**: 1 章の根本原因（位相不足）を、モデルの側で直す。
- **変わらないもの**: 2 章のバグ修正はすべて引き継ぐ。4.1 の飽和余地・配分歪みは NX=8 だけでは解決しない。
- `τ=45 ms` は暫定値で、同定済みの真値ではない。`Q_a=0` なので遅れ状態そのものは追従コストに入れていない。
- **現状**: 実装・クロスビルド・ホスト回帰は完了（`20260920_nx8_n12_actuator_lag_implementation.md`）。
  NX=8 の飛行ログ `Benzen_NMPC/tools/0920_v1〜v5.txt` は取れているが、**まだ解析していない**。
