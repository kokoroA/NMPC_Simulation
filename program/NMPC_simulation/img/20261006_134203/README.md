# 耐故障制御（FTC）試験 — 230 g, T_max = 0.75

- **実行日**: 2026-10-06
- **プログラム**: `program/NMPC_simulation/nmpc_simulation_stress.py --suite ftc --mass 230 --seeds 42,7,123 --throttle both`
- **NMPC**: NX=5, N=14, Q=1000/1000/80/80/40, R_u=620, ADMM ρ=1・4 反復（実機 `nmpc_params.hpp` と同値）、T_max=0.75
- **機体**: 0.230 kg、推力は飛行較正曲線 `Tf(u)=0.8389(−0.2265u²+1.0525u+0.0452)` N/モータ、モータ一次遅れ 50 ms
- **試験**: 高度 2 m でホバー → **t=5 s に FR（M1）が完全停止** → t=15 s まで。打ち切り条件は姿勢 90°・角速度 360 deg/s・高度 0 m

## 条件（4 × 3 方式 × 3 シード = 36 本）

| 方式 | 中身 |
|---|---|
| 実機方式・高度PID | 実機 control.cpp と同じ FTC。故障発の duty を box で 0 に固定、参照は「故障発と対角 RL を 0、残り 4 発を 1.5×u_hover」。スロットルは高度 PID（積極的な操縦者） |
| 実機方式・スロットル固定 | 同じ FTC。故障後のスロットルを静的釣り合い値（担当 4 発 duty 0.702）に固定（理想的な操縦者） |
| 元シミュ方式・高度PID | 元の nmpc_simulation.py の FTC。B に η を掛ける・故障発の R を大きく・即時再構築・生存 5 発に均等配分 |

| 補償 × 悪条件 | 中身 |
|---|---|
| 遅れ補償なし / あり（DC6） | 実機の nmpc_delay_predict() の有無 |
| 悪条件なし / 実機相当 R1 | R1 = 計算遅延 1 周期 + 再構築中の指令保持 3 周期 + ジャイロバイアス |

## 結果

| 方式 | 墜落 | 故障後の姿勢誤差 RMS | ヨー率の最大 | 担当 4 発の 0.95 張り付き | 高度の低下 |
|---|---|---|---|---|---|
| 実機方式・高度PID | **11/12** | 33–47° | 75–112 deg/s | **48–52 %** | 1.1–2.0 m（生存 1 本も 0.9 m まで落下） |
| 実機方式・スロットル固定 | **9/12** | 21–24° | 79–143 deg/s | 2–4 % | **1.8–1.95 m**（生存 3 本も地上 5〜20 cm まで落下） |
| 元シミュ方式・高度PID | **12/12** | 43–51° | 114–276 deg/s | 49–54 % | 2.0 m |

**230 g でも、どの方式でも高度を保てた例は 1 本もない。**
推力の余地は十分ある（故障後の担当 4 発 duty 0.702、上方向の余地 0.248。285 g の 0.012 の 20 倍）のに落ちる。

## なぜ落ちるか（`ftc230_mechanism.png`）

1. **故障の瞬間の衝撃**: FR の推力は即座に 0、残りはモータ遅れ 50 ms でしか追従しない → ピッチ角速度が −30 deg/s 前後まで振れる。
2. **立て直しが弱い**: NMPC は担当 4 発の差を ±0.02〜0.04 しか使わない（R_u=620 の重みが大きい）。ピッチが 20〜30° まで倒れる。
3. **ヨーを捨てる**: 担当 4 発だけではロール・ピッチを直す差動が必ずヨーを生む。Q_r=40 は弱いのでヨーが犠牲になり **50〜140 deg/s で回り始める**。
   回りながら傾いているので、オイラー角ではロールがピッチへ移り続け（θ̇ = q cosφ − r sinφ）、傾きが戻らない。
4. **傾き 20〜40° で揚力が足りなくなる**: スロットル固定では補えず落下。高度 PID は推力を上げて担当 4 発を 0.95 に張り付かせ、姿勢を直す差動が消えて墜落を早める。

⇒ **230 g では、律速は推力ではなく「ヨーを捨てた結果の回転 × 傾き」と「高度ループ」に移っている。**

## 補足
- 遅れ補償（DC6）の効果は一貫しない。高度PID では DC6 のほうが墜落が早い（故障から 2.3〜2.5 s、補償なし悪条件なしは 7.7 s）。
- 元シミュ方式は均等配分の基準点がヨーで釣り合っていないため、ヨー率が最大 276 deg/s とさらに悪い。
- 不安定な条件の数値は実行ごとにずれる（`ftc230_mechanism.png` のシード 7 は再実行で墜落 8.65 s、バッチでは 7.69 s）。結論は「墜落した／しない」の水準で読むこと。

## 前提の限界
- 故障は**推力の瞬時消失**（最悪側）。実機の停止指令ならモータの減速遅れぶん穏やかになる。
- Q・R は健全飛行用の値のまま（FTC 用に再調整していない）。relaxed hover（回転を許容して対角も使う）は実機同様に無効。
- 故障の認識は瞬時（スイッチ操作相当）。
